맥이 잠들지 않게, Caps Lock으로 켜고 끄기 — caffeinate와 Hammerspoon

정해진 시각에 도는 자동 작업이 맥이 잠든 사이 통째로 건너뛰어졌습니다. 유휴 잠자기와 덮개 잠자기를 따로 막고, 덮개 쪽은 Caps Lock으로 켜고 끌 수 있게 만든 과정을 코드와 함께 정리합니다.

매일 아침 정해진 시각에 도는 자동 작업(크론)이 있습니다. 맥이 잠들어 있으면 그 시각을 그냥 지나쳐 버리고, 작업은 통째로 돌지 않습니다. 해결 방법을 찾다 보니 맥의 잠자기는 한 종류가 아니었습니다. 이 글은 잠자기 두 종류를 각각 막고, 그중 하나를 Caps Lock으로 켜고 끄게 만든 과정입니다.

잠자기는 두 종류입니다

맥이 잠드는 이유는 pmset -g log에 남습니다. 이 맥의 기록에는 다음 두 줄이 섞여 있었습니다.

Entering Sleep state due to 'Idle Sleep'
Entering Sleep state due to 'Clamshell Sleep'

첫 줄은 한동안 입력이 없어서 잠든 경우(유휴 잠자기, idle sleep)이고, 둘째 줄은 덮개를 닫아서 잠든 경우(덮개 잠자기, clamshell sleep)입니다. pmset -g custom은 전원별 설정을 보여 주는데[2], 이 맥은 배터리일 때 sleep 1, 전원 어댑터일 때 sleep 0이었습니다. sleep 값의 단위는 분이고 0이면 끄는 것이니[2], 배터리로 쓰다가 1분만 손을 떼도 잠들 수 있었던 셈입니다.

두 잠자기는 막는 장치가 다릅니다.

구분 언제 잠드나 막는 장치
유휴 입력 없이 일정 시간이 지나면 caffeinate -i의 전원 단언
덮개 덮개를 닫으면 pmset -a disablesleep 1 (root 필요)

이 글에서는 유휴 잠자기는 늘 막아 두고, 덮개 잠자기는 필요할 때만 Caps Lock으로 켜고 끄게 했습니다. 덮개를 닫고 가방에 넣을 때까지 깨어 있으면 배터리가 계속 닳기 때문입니다.

유휴 잠자기: caffeinate를 LaunchAgent로 띄우기

caffeinate는 시스템 잠자기 동작을 바꾸는 단언(assertion)을 만드는 도구입니다. -i는 시스템이 유휴 상태로 잠드는 것을 막는 단언을 만들고, 실행할 명령 없이 띄우면 단언은 caffeinate가 끝날 때까지 유지됩니다[1]. 화면이 꺼지는 것은 막지 않습니다(화면은 -d가 따로 맡습니다)[1]. 비슷한 -s는 전원 어댑터에 연결됐을 때만 유효하므로[1], 배터리일 때도 막아야 하는 이 경우에는 -i를 골랐습니다.

남은 문제는 이 프로세스를 늘 살려 두는 것입니다. 터미널에서 띄우면 창을 닫거나 재부팅할 때 끝납니다. 그래서 로그인할 때 launchd가 띄우는 LaunchAgent로 등록했습니다.

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key><string>ai.hermes.caffeinate</string>
  <key>ProgramArguments</key>
  <array><string>/usr/bin/caffeinate</string><string>-i</string></array>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><true/>
</dict>
</plist>

RunAtLoad는 작업을 불러올 때 한 번 실행하게 하고, KeepAlive를 true로 두면 launchd가 작업을 무조건 계속 살려 둡니다[6]. 프로세스가 죽어도 다시 뜨는 이유입니다. 파일은 ~/Library/LaunchAgents/에 두고, 사용자 로그인 도메인 gui/<uid>에 올립니다[7].

launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/ai.hermes.caffeinate.plist

pmset -g assertions | grep caffeinate
# PreventUserIdleSystemSleep named: "caffeinate command-line tool"
# Details: caffeinate asserting forever

pmset -g assertions는 지금 걸린 전원 단언을 보여 줍니다[2]. 위처럼 PreventUserIdleSystemSleep이 보이면 동작하는 것입니다. 이때 pmset -g의 sleep 줄에도 sleep prevented by caffeinate가 붙었습니다.

$HOME 아래 LaunchAgent 파일은 불러오는 사용자가 소유해야 하고, 그룹·다른 사용자의 쓰기를 막아야 합니다. launchctl 매뉴얼은 이 제한을 보안 때문이라고 설명합니다[7].

이 단언이 막는 것은 유휴 잠자기뿐입니다[1]. 덮개를 닫을 때 잠드는 것은 다음 장치가 맡습니다.

덮개 잠자기: disablesleep과 좁힌 sudo 권한

덮개를 닫아도 잠들지 않게 하는 데는 pmset -a disablesleep 1을 썼습니다. 적용하면 pmset -g 출력에 SleepDisabled 1이 나타나고, 0으로 돌리면 원래대로 덮개를 닫을 때 잠듭니다. -a는 배터리·전원 어댑터·UPS 모든 전원에 적용하라는 뜻입니다[2].

한 가지 짚어 둘 점이 있습니다. 이 맥(macOS 26.3)에서 man pmset의 설정 목록을 찾아보면 disablesleep이 나오지 않습니다. 매뉴얼에 없는 설정이므로 macOS 버전이 바뀌면 동작이 달라질 수 있다고 보고, 적용할 때마다 pmset -g로 실제 값을 확인하게 만들었습니다.

비밀번호 없이 허용하는 범위

pmset으로 설정을 바꾸려면 root로 실행해야 합니다[2]. 키를 누를 때마다 비밀번호를 칠 수는 없으니 sudoers 규칙으로 비밀번호를 생략했습니다. 다만 pmset 전체가 아니라 이 두 명령만 허용합니다.

<사용자명> ALL=(root) NOPASSWD: /usr/bin/pmset -a disablesleep 1, /usr/bin/pmset -a disablesleep 0

NOPASSWD 태그는 뒤에 오는 명령들에 대해 인증을 생략하게 합니다[3]. 범위를 좁히는 핵심은 인자입니다. sudoers에서 명령에 인자를 적어 두면 사용자가 입력한 인자가 그대로 일치해야 하고, 인자를 적지 않으면 어떤 인자로든 실행할 수 있습니다[3]. 경로만 적었다면 pmset의 다른 설정까지 비밀번호 없이 바꿀 수 있었다는 뜻입니다.

이 규칙으로 남는 위험도 적어 둡니다. 이 사용자 계정으로 도는 프로그램은 무엇이든 비밀번호 없이 잠자기를 켜고 끌 수 있습니다. 할 수 있는 일이 잠자기 설정 두 가지뿐이라 받아들였습니다.

파일을 설치하고 검사하기

규칙은 /etc/sudoers.d/에 따로 둡니다. sudoers가 @includedir /etc/sudoers.d로 이 디렉터리를 읽을 때, 이름에 .이 들어 있거나 ~로 끝나는 파일은 건너뜁니다[3]. 작업 파일 이름은 hermes-pmset.sudoers였지만 설치할 때 hermes-pmset으로 바꾼 이유입니다.

visudo -cf ~/.hermes/scripts/hermes-pmset.sudoers
# parsed OK

sudo install -m 0440 -o root -g wheel ~/.hermes/scripts/hermes-pmset.sudoers /etc/sudoers.d/hermes-pmset

ls -l /etc/sudoers.d/
# -r--r-----  1 root  wheel  95 ... hermes-pmset

visudo -c는 문법만 검사하는 모드이고, -f로 검사할 파일을 지정합니다[8]. 시스템 디렉터리에 넣기 전에 작업 파일을 먼저 검사합니다. 권한은 sudoers 매뉴얼이 기본값으로 밝힌 0440(소유자·그룹 읽기만, 쓰기 없음)에 맞췄습니다[3]. 설치는 비밀번호를 직접 입력해야 하므로 사람이 한 번 실행했습니다.

증상토글을 누르자 "잠자기 설정 실패: sudo 권한 확인 필요"

규칙을 설치하기 전이라 sudo -n이 비밀번호를 묻는 대신 오류를 내고 끝난 것입니다[9]. ls -l /etc/sudoers.d/로 파일이 있는지, sudo -n /usr/bin/pmset -a disablesleep 1이 a password is required 없이 끝나는지 확인합니다.

Caps Lock 토글: Hammerspoon

덮개 잠자기는 상황에 따라 켜고 꺼야 하니 단축키가 필요했습니다. 고른 키는 Caps Lock입니다. 한/영 전환을 오른쪽 Command+Space로 하고 있어서 Caps Lock은 거의 쓰지 않는 키였습니다. 단축키를 잡는 데는 Lua 스크립트로 macOS를 자동화하는 Hammerspoon을 썼습니다[10].

전체 설정 파일은 다음과 같습니다. 아래에서 부분별로 나눠 봅니다.

require("hs.ipc")
-- Caps Lock = 덮개를 닫아도 잠들지 않는 '항상 켜짐' 모드 토글
-- Caps Lock을 F18로 바꾼 뒤(hidutil) F18을 단축키로 잡는다. 한/영은 오른쪽 command+space라 Caps Lock은 비어 있다.
-- 잠자기 차단은 `sudo pmset -a disablesleep 1` (sudoers.d/hermes-pmset로 비밀번호 없이 이 두 명령만 허용).
-- 유휴 잠자기는 LaunchAgent ai.hermes.caffeinate가 따로 늘 막고 있다.

local CAPS_TO_F18 = [[/usr/bin/hidutil property --set '{"UserKeyMapping":[{"HIDKeyboardModifierMappingSrc":0x700000039,"HIDKeyboardModifierMappingDst":0x70000006D}]}']]
local LOW_BATTERY_PERCENT = 15 -- 배터리로 버티다 꺼지는 것을 막기 위해 이 밑이면 자동 해제

hs.execute(CAPS_TO_F18)
hs.autoLaunch(true)

local menu = hs.menubar.new()

local function isAwakeModeOn()
  local out = hs.execute("/usr/bin/pmset -g | /usr/bin/grep SleepDisabled")
  return out:match("SleepDisabled%s+1") ~= nil
end

local function refreshMenu()
  if isAwakeModeOn() then
    menu:setTitle("☕︎")
    menu:setTooltip("항상 켜짐: 덮개를 닫아도 잠들지 않음 (Caps Lock으로 끄기)")
  else
    menu:setTitle("💤")
    menu:setTooltip("일반 모드: 덮개를 닫으면 잠듦 (Caps Lock으로 켜기)")
  end
end

local function setAwakeMode(on)
  local flag = on and "1" or "0"
  local _, ok = hs.execute("/usr/bin/sudo -n /usr/bin/pmset -a disablesleep " .. flag)
  if not ok then
    hs.alert.show("잠자기 설정 실패: sudo 권한 확인 필요", 3)
    return
  end
  refreshMenu()
  hs.alert.show(on and "ON" or "OFF", 1)
end

local function toggleAwakeMode()
  setAwakeMode(not isAwakeModeOn())
end

hs.hotkey.bind({}, "f18", toggleAwakeMode)
menu:setClickCallback(toggleAwakeMode)

batteryWatcher = hs.battery.watcher.new(function()
  local onBattery = hs.battery.powerSource() == "Battery Power"
  local lowBattery = (hs.battery.percentage() or 100) <= LOW_BATTERY_PERCENT
  if onBattery and lowBattery and isAwakeModeOn() then
    setAwakeMode(false)
    hs.notify.new({ title = "항상 켜짐 자동 해제", informativeText = "배터리 " .. LOW_BATTERY_PERCENT .. "% 이하라 일반 모드로 돌렸습니다." }):send()
  end
end)
batteryWatcher:start()

refreshMenu()

Caps Lock을 F18로 바꾸는 이유

Caps Lock을 그대로 단축키로 쓰면 누를 때마다 대문자 고정도 함께 켜지고 꺼집니다. 그래서 키보드 단계에서 아예 다른 키로 바꿔 보냅니다. hidutil의 UserKeyMapping은 원래 키(Src)를 다른 키(Dst)로 바꾸고, 값은 0x700000000에 HID 사용 코드를 OR 한 수입니다[4]. Caps Lock은 0x39, F18은 0x6D라서[4] 각각 0x700000039, 0x70000006D가 됩니다. 맥북 내장 키보드에는 F18 키가 없어서 다른 용도와 겹칠 가능성이 낮습니다.

hidutil property --get UserKeyMapping
# HIDKeyboardModifierMappingDst = 30064771181;  (0x70000006D)
# HIDKeyboardModifierMappingSrc = 30064771129;  (0x700000039)

이 매핑은 시스템을 다시 시작하거나 마지막 키보드 연결이 끊기면 사라집니다[4]. 그래서 설정 파일 맨 위에서 Hammerspoon이 켜질 때마다 hidutil을 다시 실행하고, hs.autoLaunch(true)로 Hammerspoon이 로그인할 때 자동으로 켜지게 했습니다[5]. 키 매핑 자체에는 특별한 권한이 필요하지 않습니다[4].

그다음 hs.hotkey.bind({}, "f18", toggleAwakeMode)가 수식키 없이 F18만 눌렀을 때 함수를 부릅니다[11]. 메뉴바 아이콘도 setClickCallback으로 같은 함수를 걸어 두어, 클릭해도 토글됩니다[12].

상태는 pmset에서 읽습니다

isAwakeModeOn()은 따로 변수를 두지 않고 매번 pmset -g에서 SleepDisabled 줄을 읽습니다. 터미널에서 직접 pmset을 바꾸거나 재부팅해도 메뉴바 아이콘과 실제 상태가 어긋나지 않게 하려는 선택입니다. 토글은 지금 값을 읽어서 반대로 쓰는 것뿐입니다.

setAwakeMode()는 실패를 숨기지 않습니다. hs.execute는 표준 출력과 함께 성공 여부를 돌려주고, 명령이 실패하면 그 값이 nil입니다[5]. sudo -n은 비밀번호가 필요하면 묻지 않고 오류로 끝나므로[9], 규칙이 없을 때는 앞 절의 경고가 뜨고 아이콘은 바뀌지 않습니다. 성공하면 hs.alert.show(on and "ON" or "OFF", 1)로 1초만 띄웁니다. 시간 인자를 생략하면 2초이고, 숫자를 넘기면 표시 시간으로 쓰입니다[13]. 처음에는 "☕︎ 항상 켜짐 ON (덮개 닫아도 안 잠듦)"처럼 길게 띄웠다가, 누를 때마다 읽기엔 길어서 ON/OFF만 남겼습니다.

메뉴바 아이콘은 setTitle로 글자를 넣어야 보입니다[12]. ☕︎는 덮개를 닫아도 깨어 있는 상태, 💤는 원래대로 잠드는 상태입니다.

배터리 감시와 전역 변수

hs.battery.watcher.new()는 배터리 상태가 바뀔 때마다 콜백을 부르는데, 콜백에는 인자가 없어서 무엇이 바뀌었는지는 직접 확인해야 합니다[14]. 그래서 콜백 안에서 hs.battery.powerSource()와 hs.battery.percentage()를 다시 읽습니다[15]. 전원이 "Battery Power"이고 15% 이하인데 ON이면 OFF로 돌리고 알림을 보냅니다.

batteryWatcher에 local을 붙이지 않은 것은 의도한 것입니다. Hammerspoon 문서에 따르면 init.lua 전체가 하나의 범위라서 마지막 줄이 실행되면 끝나고, 변수에 담지 않은 객체는 언젠가 가비지 컬렉션으로 조용히 사라집니다[10]. 전역 변수는 범위를 벗어나지 않으므로 설정을 다시 불러오거나 앱을 끌 때까지 남습니다[10].

증상hs -c "hs.reload()"가 can't access Hammerspoon message port로 실패

터미널의 hs 명령은 hs.ipc 모듈이 먼저 불러와져 있어야 동작하므로 init.lua에 require("hs.ipc")를 넣습니다[16]. 이 줄을 넣고 Hammerspoon을 한 번 다시 실행하자 CLI가 붙었습니다.

정리

단계 막는 것 핵심 설정 확인 명령
1 유휴 잠자기 LaunchAgent + caffeinate -i[1][6] pmset -g assertions
2 덮개 잠자기 pmset -a disablesleep 1 + 두 명령만 허용한 sudoers[3] pmset -g → SleepDisabled
3 켜고 끄기 Caps Lock → F18(hidutil) → Hammerspoon[4][11] hidutil property --get UserKeyMapping

되돌릴 때는 거꾸로 하나씩 지웁니다.

sudo pmset -a disablesleep 0                       # 덮개 잠자기 원래대로
sudo rm /etc/sudoers.d/hermes-pmset                # 비밀번호 생략 규칙 삭제
launchctl bootout gui/$(id -u)/ai.hermes.caffeinate # 유휴 잠자기 방지 끄기
  • ON인 채로 덮개를 닫아 가방에 넣으면 맥은 계속 깨어 있습니다. 15% 자동 해제는 마지막 안전장치일 뿐이니, 들고 나갈 때는 Caps Lock으로 먼저 끕니다.
  • disablesleep은 매뉴얼에 없는 설정입니다. macOS를 올린 뒤에는 pmset -g에 SleepDisabled가 여전히 보이는지 확인합니다.

프론트엔드 팀이 해 볼 것

  1. pmset -g log | grep "Entering Sleep"으로 내 맥이 어떤 이유로 잠드는지 확인한다
  2. 비밀번호 없이 쓰는 sudo 규칙이 있다면 명령 인자까지 적혀 있는지 sudo -l로 살펴본다
  3. 자주 쓰지 않는 키 하나를 골라 hidutil property --get UserKeyMapping으로 현재 매핑부터 확인한다
