17:T66fc,<h2 id="캐시를-고르는-모델">캐시를 고르는 모델</h2>
<p>이전 App Router는 요청하지 않아도 알아서 캐시했습니다. Cache Components는 반대입니다. 데이터 패칭은 기본이 동적이고, 페이지·컴포넌트·함수 단위로 캐시할 대상을 직접 고릅니다<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup>. Next.js 블로그는 <code>'use cache'</code>를 컴포넌트 단위의 <code>Cache-Control</code> 헤더처럼 생각하라고 설명하고, 이 표시들이 이전 App Router의 암묵적 캐시 동작을 대체한다고 밝힙니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</p>
<h3 id="164에서-달라진-것">16.4에서 달라진 것</h3>
<p>이전까지는 기존 모델만큼 비용·성능을 보장하지 못하는 경우가 있어 모든 앱에 권하지 않았습니다. 16.4는 그 빈틈을 메우고 Cache Components를 모든 Next.js 앱에 권장합니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>. <code>create-next-app</code>으로 만든 새 앱은 기본으로 켜져 있고, Next.js 17에서는 기본 동작이 됩니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</p>
<p>기존 앱에서는 설정 두 개를 켭니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup><sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup>.</p>
<pre data-lang="ts"><code class="hljs language-ts"><span class="hljs-comment">// next.config.ts</span>
<span class="hljs-keyword">import</span> <span class="hljs-keyword">type</span> { <span class="hljs-title class_">NextConfig</span> } <span class="hljs-keyword">from</span> <span class="hljs-string">'next'</span>

<span class="hljs-keyword">const</span> <span class="hljs-attr">nextConfig</span>: <span class="hljs-title class_">NextConfig</span> = {

<p><code>partialPrefetching</code>을 비워 두면 경고가 찍히니 명시적으로 적습니다<sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup>. Cache Components는 Node.js 런타임이 필요해서 <code>runtime</code> 내보내기는 모두 지워야 합니다<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup>. 기존 앱을 옮길 때는 마이그레이션 가이드와 codemod를 에이전트에게 넘겨 주는 <code>npx next@canary upgrade --agent=latest</code>도 쓸 수 있습니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</p>
<h2 id="use-cache-무엇을-어떤-키로">use cache — 무엇을, 어떤 키로</h2>
<p><code>'use cache'</code>는 async 함수와 컴포넌트의 반환값을 캐시하는 지시어입니다. 함수·컴포넌트 본문이나 파일 맨 위에 두며, 대상은 반드시 async여야 합니다<sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup><sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup>.</p>
<h3 id="데이터-수준과-ui-수준">데이터 수준과 UI 수준</h3>
<p>함수에 붙이면 데이터를 여러 컴포넌트가 나눠 쓰고, 컴포넌트에 붙이면 UI 자체가 캐시됩니다<sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup>.</p>
<pre data-lang="ts"><code class="hljs language-ts"><span class="hljs-comment">// app/lib/data.ts — 데이터 수준</span>

<h3 id="캐시-키는-자동으로-만들어진다">캐시 키는 자동으로 만들어진다</h3>
<p>캐시 키는 빌드 ID, 함수 위치와 시그니처의 해시인 함수 ID, 직렬화 가능한 인자(컴포넌트라면 props)로 만들어집니다. 개발 중에는 HMR 해시도 들어갑니다<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup>. 바깥 스코프의 변수를 참조하면 그 변수도 인자처럼 키에 들어가므로, 클로저로 <code>userId</code>를 잡은 함수는 사용자마다 별도 항목을 가집니다<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup>.</p>
<p>인자와 반환값은 직렬화할 수 있어야 합니다. 반환값으로는 JSX를 돌려줄 수 있지만, 클래스 인스턴스·URL 인스턴스는 쓸 수 없습니다<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup>. <code>children</code>처럼 읽지 않고 그대로 넘기기만 하는 값은 예외라서, 캐시된 래퍼 안에 동적 컴포넌트를 넣을 수 있습니다<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup>.</p>
<h3 id="자주-하는-실수-캐시-안에서-쿠키-읽기">자주 하는 실수: 캐시 안에서 쿠키 읽기</h3>
<p>캐시된 함수는 <code>cookies()</code>, <code>headers()</code>, <code>searchParams</code>에 접근할 수 없습니다. 이 제한은 호출 스택을 따라가서, 캐시 함수가 부른 헬퍼가 쿠키를 읽어도 <code>next-request-in-use-cache</code> 오류가 납니다<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup>. 동적 라우트에서는 <code>next build</code>를 통과하고 <code>next start</code>에서 실패할 수 있어 늦게 발견됩니다<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup>.</p>
<p>해결책은 바깥에서 읽고 값만 인자로 넘기는 것입니다<sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup><sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup>.</p>

<h2 id="cachelife와-cachetag-수명과-무효화">cacheLife와 cacheTag — 수명과 무효화</h2>
<h3 id="세-개의-숫자">세 개의 숫자</h3>
<p><code>cacheLife</code>는 캐시 범위 안에서 수명을 정합니다. 수명은 세 값으로 이뤄집니다<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup>.</p>
<ul>
<li><code>stale</code>: 클라이언트가 서버에 묻지 않고 캐시를 쓰는 시간</li>
<li><code>revalidate</code>: 이 시간이 지난 뒤 요청이 오면 캐시를 먼저 내주고 백그라운드에서 다시 만듦</li>
<li><code>expire</code>: 이 시간 동안 요청이 없으면 다음 요청은 새 결과를 기다림</li>
</ul>

<p><code>next.config.ts</code>의 <code>cacheLife</code> 옵션에 이름 붙인 프로필을 정의할 수도 있고, 빠뜨린 속성은 <code>default</code>에서 물려받습니다<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup>.</p>
<p><code>cacheLife</code>를 빼면 <code>default</code> 프로필이 조용히 적용되므로, 공식 문서는 모든 캐시 범위에 <code>cacheLife</code>를 함께 쓰라고 권합니다<sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup><sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup>. 모듈 최상위에서 부르면 오류가 나고, <code>expire</code>는 <code>revalidate</code>보다 길어야 합니다<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup>.</p>
<h3 id="자주-하는-실수-짧은-수명은-셸에서-빠진다">자주 하는 실수: 짧은 수명은 셸에서 빠진다</h3>
<p>수명은 결과가 어디서 나갈지도 정합니다. <code>revalidate</code>가 0이거나 <code>expire</code>가 5분 미만이면 프리렌더에서 빠져 요청 때 채우는 "동적 구멍(dynamic hole)"이 됩니다. <code>stale</code>이 30초 미만이어도 프리렌더에서 빠집니다<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup>. <code>cacheLife('seconds')</code>는 expire가 1분이라 셸에 들어가지 않습니다<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup>.</p>
<p><code>stale</code>은 <code>Cache-Control</code> 헤더가 아니라 클라이언트 라우터 캐시를 조절하며, 프리페치한 링크가 클릭 전에 만료되지 않도록 최소 30초가 강제됩니다<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup>.</p>
<h3 id="태그로-골라서-지우기">태그로 골라서 지우기</h3>
<p><code>cacheTag</code>는 캐시 항목에 문자열 태그를 하나 이상 붙이며, 가져온 데이터의 ID로 태그를 만들 수도 있습니다<sup class="cite"><a href="#source-7" aria-label="출처 7">[7]</a></sup>. 한 호출에 태그는 128개까지, 태그 하나는 256자까지입니다<sup class="cite"><a href="#source-7" aria-label="출처 7">[7]</a></sup>.</p>
<p>지우는 함수는 두 가지입니다. <code>updateTag</code>는 Server Action 안에서만 쓸 수 있고, 다음 요청이 오래된 캐시 대신 새 데이터를 기다립니다. 사용자가 쓴 글을 바로 보여 줘야 하는 경우에 맞습니다<sup class="cite"><a href="#source-8" aria-label="출처 8">[8]</a></sup>.</p>

<p><code>revalidateTag</code>는 Route Handler에서도 쓸 수 있고, 권장 프로필 <code>'max'</code>를 넘기면 오래된 데이터를 내주면서 백그라운드에서 새로 가져옵니다<sup class="cite"><a href="#source-9" aria-label="출처 9">[9]</a></sup>.</p>

<p>인자 하나짜리 <code>revalidateTag(tag)</code>는 지원 중단(deprecated)됐으니 두 번째 인자를 꼭 넘깁니다<sup class="cite"><a href="#source-9" aria-label="출처 9">[9]</a></sup>.</p>
<h2 id="정적-셸과-동적-영역의-경계">정적 셸과 동적 영역의 경계</h2>
<h3 id="한-페이지-안의-세-가지-콘텐츠">한 페이지 안의 세 가지 콘텐츠</h3>

<p>한 페이지 안에 정적·캐시·런타임 콘텐츠가 함께 있을 수 있습니다<sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup>.</p>
