17:T6fec,<h2 id="llm-답변-화면을-맡았다고-가정해-봅시다">LLM 답변 화면을 맡았다고 가정해 봅시다</h2>
<p>문서 도우미의 답변 화면입니다. 아래는 실제 서비스 수치가 아니라 방법을 고르기 위한 가정입니다.</p>
<ul>
<li>질문을 본문에 담아 보내고, 도착한 답변부터 보여 줍니다.</li>
<li>중단을 누르면 받은 글은 남기고, 서버의 생성 작업도 취소하도록 연결합니다.</li>
<li>사용자가 위로 올려 읽는 동안에는 화면을 아래로 끌어내리지 않습니다.</li>
<li>마크다운이 덜 도착해도 읽을 수 있게 표시합니다.</li>
<li>도중에 실패하면 완료와 구별하고, 읽던 답변을 지우지 않습니다.</li>
</ul>
<p>브라우저와 애플리케이션 서버 사이만 다룹니다. 실행 결과와 화면은 고정 답변을 잘라 보내는 가짜 토큰 서버의 기존 재현 기록입니다. 코드는 그 구현을 재구성했으며, 유료 모델의 속도나 과금 특성을 검증한 결과는 아닙니다.</p>
<p><code>fetch()</code>의 응답에는 본문을 읽을 수 있는 <code>ReadableStream</code>이 있고, <code>getReader()</code>로 얻은 읽개(reader)의 <code>read()</code>를 반복해 조각을 받습니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup><sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup> 생성이 끝나기 전부터 읽을 기회를 주는 방식입니다.</p>

<h2 id="바이트와-이벤트의-경계는-다릅니다">바이트와 이벤트의 경계는 다릅니다</h2>
<p>서버 전송 이벤트(Server-Sent Events, SSE)는 <code>text/event-stream</code> 형식의 텍스트이며, 메시지를 빈 줄로 구분합니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup> <code>event</code>는 이벤트 종류, <code>data</code>는 내용이고, 여러 데이터 줄은 개행으로 이어 붙입니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup> <code>delta</code>, <code>error</code>, <code>done</code>은 예제 서버의 계약입니다.</p>
<p>글자는 온전해도 JSON이 덜 왔을 수 있고, 이벤트가 끝나도 마크다운은 미완성일 수 있습니다. 각 경계에서 남은 조각을 보관해야 합니다.</p>

<p>읽개를 붙이면 스트림이 잠기므로 다른 읽개를 동시에 붙일 수 없습니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 중간 종료 시에도 읽기 취소와 잠금 해제를 정리합니다.</p>

<p>비동기 반복은 앞서 만든 생성자를 순회합니다. 스트림은 파서 안에서 읽습니다. 모르는 이벤트는 무시하고 완료 이벤트에서 반환합니다.</p>
<h3 id="중단했는데-계속-생성된다면-서버-쪽-연결을-확인합니다">중단했는데 계속 생성된다면 서버 쪽 연결을 확인합니다</h3>
<p><code>AbortController</code>의 <code>abort()</code>는 요청뿐 아니라 응답 본문의 소비도 중단할 수 있습니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup> <code>AbortSignal</code>은 중단한 뒤 재사용할 수 없으며, 그 신호를 넘긴 다음 요청은 즉시 거절됩니다.<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup> 요청마다 새 컨트롤러를 만듭니다.</p>
<pre data-lang="js"><code class="hljs language-js"><span class="hljs-keyword">function</span> <span class="hljs-title function_">startAnswer</span>(<span class="hljs-params">onDelta, onStatus</span>) {
  <span class="hljs-keyword">const</span> controller = <span class="hljs-keyword">new</span> <span class="hljs-title class_">AbortController</span>();
  <span class="hljs-keyword">const</span> finished = <span class="hljs-title function_">receiveAnswer</span>({
    <span class="hljs-attr">signal</span>: controller.<span class="hljs-property">signal</span>,
    onDelta,
  }).<span class="hljs-title function_">then</span>(
    <span class="hljs-function">() =></span> <span class="hljs-title function_">onStatus</span>(<span class="hljs-string">"완료"</span>),
    <span class="hljs-function">(<span class="hljs-params">error</span>) =></span> <span class="hljs-title function_">onStatus</span>(
      error.<span class="hljs-property">name</span> === <span class="hljs-string">"AbortError"</span> ? <span class="hljs-string">"중단됨"</span> : error.<span class="hljs-property">message</span>
    ),

  <span class="hljs-keyword">return</span> { <span class="hljs-attr">stop</span>: <span class="hljs-function">() =></span> controller.<span class="hljs-title function_">abort</span>(), finished };

<span class="hljs-comment">// 중단 버튼에서는 run.stop()을 호출합니다.</span>
</code></pre>
<p>기존 중단 실험의 클라이언트 출력입니다.</p>
<pre data-lang="text"><code class="hljs language-text">잡힌 오류: AbortError · This operation was aborted
</code></pre>
<p>서버 로그에서도 연결 종료와 생성 정지를 확인했습니다. 브라우저가 직접 멈춘 것이 아니라, 서버가 연결 종료를 감지해 다음 조각을 만들지 않도록 구현한 결과입니다.</p>
<p>실제 서비스에서도 서버의 모델 요청에 취소를 전달하고 작업 종료를 확인해야 합니다. 브라우저의 취소 표시만으로 공급자의 작업이나 과금까지 즉시 멈췄다고 판단하지 않습니다.</p>
<h3 id="정상-응답으로-시작했는데-중간에-실패할-수-있습니다">정상 응답으로 시작했는데 중간에 실패할 수 있습니다</h3>
<p><code>fetch()</code>는 오류 상태 응답을 받았다는 이유만으로 거절되지 않으므로 <code>response.ok</code>를 확인해야 합니다.<sup class="cite"><a href="#source-7" aria-label="출처 7">[7]</a></sup> 그러나 그것만으로 생성 완료를 판단하지는 않습니다. 이 예제는 시작 후 장애를 응답 본문의 오류 이벤트로 보내고 연결을 닫도록 만들었습니다.</p>
<p>기존 장애 실험에서는 답변 뒤에 다음 이벤트가 왔고, 완료 이벤트는 오지 않았습니다.</p>
<pre data-lang="text"><code class="hljs language-text">event: error
data: {"type":"error","error":{"type":"overloaded_error","message":"Overloaded"}}
</code></pre>
<p>오류 이벤트나 완료 표시 없는 종료는 실패로 처리합니다. 전송 종료와 답변 완료를 구별하지 않으면 일부만 받은 답변을 완성본처럼 저장하게 됩니다.</p>
<p>중간 실패에서는 글을 유지하고 재시도를 사용자에게 맡깁니다. 고정 문자열 서버는 받은 길이 뒤부터 재전송했지만, 새 모델 요청에 길이만 보내서는 같은 답변이 이어진다고 보장할 수 없습니다. 이어 받기는 작업 식별자와 저장된 이벤트, 재전송 범위를 서버 계약으로 정해야 합니다.</p>
<h2 id="사용자가-읽는-위치와-미완성-문법을-지킵니다">사용자가 읽는 위치와 미완성 문법을 지킵니다</h2>
<p>화면은 읽는 위치와 다시 그릴 범위를 따로 결정합니다.</p>
<h3 id="위로-올려-읽는데-바닥으로-끌려-내려갑니다">위로 올려 읽는데 바닥으로 끌려 내려갑니다</h3>
<p>기존 데모에서는 스크롤 이벤트에 저장한 바닥 여부가 뒤늦게 갱신돼 사용자를 아래로 보냈습니다. 대응은 <strong>DOM 변경 직전에 현재 위치를 재는 것</strong>입니다.</p>
<p><code>scrollHeight</code>는 보이지 않는 부분까지 포함한 콘텐츠 높이입니다.<sup class="cite"><a href="#source-10" aria-label="출처 10">[10]</a></sup> 바닥 판단에는 <code>scrollTop</code>, <code>clientHeight</code>도 사용하며, 스크롤 위치가 소수일 수 있으므로 정확한 등식 대신 허용 범위를 둡니다.<sup class="cite"><a href="#source-10" aria-label="출처 10">[10]</a></sup> 아래 <code>threshold</code>는 제품이 정하는 바닥 근처의 거리이고, 문서가 권장한 고정 수치가 아닙니다.</p>
<pre data-lang="js"><code class="hljs language-js"><span class="hljs-keyword">function</span> <span class="hljs-title function_">renderKeepingPosition</span>(<span class="hljs-params">log, jump, draw, threshold</span>) {
  <span class="hljs-keyword">const</span> distance = log.<span class="hljs-property">scrollHeight</span> - log.<span class="hljs-property">scrollTop</span> - log.<span class="hljs-property">clientHeight</span>;
  <span class="hljs-keyword">const</span> stick = distance &#x3C; threshold;
  <span class="hljs-title function_">draw</span>(); <span class="hljs-comment">// 여기에서만 새 답변을 DOM에 반영합니다.</span>
  <span class="hljs-keyword">if</span> (stick) log.<span class="hljs-property">scrollTop</span> = log.<span class="hljs-property">scrollHeight</span>;
  jump.<span class="hljs-property">hidden</span> = stick;
}
</code></pre>
<p>기존 재현에서는 이 순서로 바꾼 뒤 읽는 위치가 유지되고 새 내용 보기 버튼이 나타났습니다. 캡처의 수치는 데모 상태값입니다.</p>
<figure><img src="/development-digest/figures/llm-stream-scrolled-up.png" alt="생성 중 위쪽 답변을 읽을 때 새 내용 보기 버튼이 표시된 데모" loading="lazy"><figcaption>그림 1 · 새 답변의 도착이 사용자의 읽는 위치를 바꾸지는 않습니다</figcaption></figure>
<h3 id="코드-블록이-덜-왔는데-화면-모양이-계속-바뀝니다">코드 블록이 덜 왔는데 화면 모양이 계속 바뀝니다</h3>
<p>완성된 문서만 받는다고 가정하면 미완성 문법을 다루기 어렵습니다. 데모는 코드 블록 밖의 빈 줄까지를 확정하고 쓰는 중인 꼬리만 다시 그렸습니다.</p>
<pre data-lang="js"><code class="hljs language-js"><span class="hljs-keyword">function</span> <span class="hljs-title function_">stableBoundary</span>(<span class="hljs-params">text</span>) {
  <span class="hljs-keyword">let</span> pos = <span class="hljs-number">0</span>, inFence = <span class="hljs-literal">false</span>, boundary = <span class="hljs-number">0</span>;
  <span class="hljs-keyword">const</span> lines = text.<span class="hljs-title function_">split</span>(<span class="hljs-string">"\n"</span>);
  <span class="hljs-keyword">for</span> (<span class="hljs-keyword">let</span> i = <span class="hljs-number">0</span>; i &#x3C; lines.<span class="hljs-property">length</span> - <span class="hljs-number">1</span>; i++) {
    <span class="hljs-keyword">const</span> fence = <span class="hljs-string">"\u0060\u0060\u0060"</span>; <span class="hljs-comment">// 백틱 세 개</span>
    <span class="hljs-keyword">if</span> (lines[i].<span class="hljs-title function_">startsWith</span>(fence)) inFence = !inFence;
    pos += lines[i].<span class="hljs-property">length</span> + <span class="hljs-number">1</span>;
    <span class="hljs-keyword">if</span> (lines[i] === <span class="hljs-string">""</span> &#x26;&#x26; !inFence) boundary = pos;
  }
  <span class="hljs-keyword">return</span> boundary;
}
</code></pre>
<p>이 함수는 단순한 문단과 백틱 코드 블록용입니다. 참조 링크나 중첩 문법까지 고려하면 앞부분이 불변이라고 보장하지 못합니다. 범용 마크다운은 증분 렌더러를 검토하거나 완료 시 전체를 다시 해석합니다.</p>
<p>기존 화면에서는 닫는 기호가 오기 전에도 코드 영역이 유지됐습니다. 미완성 꼬리를 별도 표시한 결과입니다. 기호를 잠시 숨기더라도 누적 원문은 보존합니다.</p>
<figure><img src="/development-digest/figures/llm-stream-open-fence.png" alt="닫는 기호가 오기 전에도 코드 영역으로 표시되는 생성 중 화면" loading="lazy"><figcaption>그림 2 · 미완성 코드는 오류가 아니라 작성 중인 상태로 표시합니다</figcaption></figure>
<p>화면 갱신은 <code>requestAnimationFrame()</code>의 다음 다시 그리기 전 콜백으로 묶을 수 있습니다.<sup class="cite"><a href="#source-11" aria-label="출처 11">[11]</a></sup> 예약 중에는 원문만 누적하고, 종료 시 남은 표시를 마무리합니다.</p>
<p>원문을 HTML로 바로 삽입하지 않습니다. 데모의 이스케이프 처리는 범용 마크다운 보안 처리를 대체하지 않습니다.</p>
<h2 id="정리">정리</h2>
<p>다른 선택지인 <code>EventSource</code>는 연결이 닫히면 기본적으로 재연결하며, <code>close()</code>로 종료할 수 있습니다.<sup class="cite"><a href="#source-9" aria-label="출처 9">[9]</a></sup> 예제 서버의 완료 이벤트에 종료를 연결하면 다음처럼 쓸 수 있습니다. <code>addEventListener()</code>로 이름 있는 이벤트를 받는 방법은 MDN 예제와 같습니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></p>
<pre data-lang="js"><code class="hljs language-js"><span class="hljs-keyword">const</span> events = <span class="hljs-keyword">new</span> <span class="hljs-title class_">EventSource</span>(<span class="hljs-string">"/api/chat-es"</span>);
