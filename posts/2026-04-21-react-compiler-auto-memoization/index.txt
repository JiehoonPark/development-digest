17:T6205,<h2 id="손으로-하는-메모이제이션이-어려운-이유">손으로 하는 메모이제이션이 어려운 이유</h2>
<p>메모이제이션(memoization)은 입력이 같으면 이전 계산 결과를 다시 쓰는 기법입니다. React에서는 컴포넌트의 state가 바뀌면 그 컴포넌트와 모든 자식이 다시 렌더링되고, 이를 막으려면 <code>useMemo()</code>, <code>useCallback()</code>, <code>React.memo()</code>로 직접 메모이제이션해야 했습니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup></p>
<h3 id="의존성을-다-맞춰도-깨지는-경우">의존성을 다 맞춰도 깨지는 경우</h3>
<p>React 공식 문서의 예제는 <code>memo</code>, <code>useMemo</code>, <code>useCallback</code>을 모두 씁니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup></p>

<p><code>handleClick</code>은 <code>useCallback</code>으로 감쌌지만, JSX 안의 화살표 함수는 렌더링마다 새로 만들어져 <code>Item</code>은 항상 새 <code>onClick</code>을 받습니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup> 참조는 마지막 지점까지 유지돼야 하고, 인라인 함수 하나만 끼어도 효과가 사라집니다. 문서가 수동 메모이제이션을 "틀리기 쉽다"고 하는 이유입니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup></p>
<h2 id="컴파일러는-무엇을-하는가">컴파일러는 무엇을 하는가</h2>
<p>React Compiler는 빌드 단계에서 컴포넌트와 훅에 메모이제이션을 자동으로 넣는 컴파일러입니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> Babel 플러그인으로 동작하지만, 추상 구문 트리(AST)를 자체 중간 표현(HIR)으로 바꿔 데이터 흐름과 값의 변경 가능성(mutability)을 분석합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>
<h3 id="빌드-결과에-캐시-코드가-들어간다">빌드 결과에 캐시 코드가 들어간다</h3>
<p>컴파일러를 쓰면 같은 컴포넌트를 메모이제이션 API 없이 씁니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup></p>

<h3 id="조기-반환-뒤에서도-메모이제이션한다">조기 반환 뒤에서도 메모이제이션한다</h3>
<p>훅은 조기 반환(early return) 뒤에서 부를 수 없습니다.<sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup> 그래서 <code>useMemo</code>는 <code>return null</code> 아래에 둘 수 없지만, 컴파일러는 이런 조건부 메모이제이션도 합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>

<h3 id="무엇을-메모이제이션하는가">무엇을 메모이제이션하는가</h3>
<p>컴파일러는 업데이트 성능에 집중합니다. 부모가 바뀔 때 자식 트리가 연쇄로 다시 렌더링되는 것과, 렌더링 중 호출하는 비싼 계산을 건너뜁니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup> 다만 컴포넌트와 훅만 메모이제이션하고, 그 결과는 여러 컴포넌트 사이에서 공유되지 않습니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup> 여러 컴포넌트가 같은 비싼 함수를 부른다면 먼저 프로파일링하고, 필요하면 React 밖에서 따로 메모이제이션합니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup></p>
<h3 id="어떤-함수가-컴파일-대상인가">어떤 함수가 컴파일 대상인가</h3>
<p>기본 <code>compilationMode</code>는 <code>'infer'</code>입니다. 이름이 PascalCase(컴포넌트)이거나 <code>use</code>로 시작하면서(훅), JSX를 만들거나 다른 훅을 호출하는 함수가 대상입니다.<sup class="cite"><a href="#source-7" aria-label="출처 7">[7]</a></sup> 그래서 <code>function button()</code>처럼 소문자로 지은 컴포넌트나 훅을 하나도 부르지 않는 <code>use</code> 함수는 조용히 최적화에서 빠집니다.<sup class="cite"><a href="#source-7" aria-label="출처 7">[7]</a></sup></p>
<h3 id="기존-usememousecallbackmemo는">기존 useMemo·useCallback·memo는</h3>
<p>React 팀은 컴파일러의 메모이제이션이 대부분 직접 쓴 것만큼 또는 그보다 정밀하다고 설명합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 그래도 <code>useMemo</code>와 <code>useCallback</code>은 계속 쓸 수 있고, 메모이제이션할 값을 직접 정하는 탈출구(escape hatch)가 됩니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>

<aside class="poster" aria-label="이미 있는 useMemo는 지우지 말고 둔다"><span class="poster-line" aria-hidden="true">이미 있는 useMemo는</span><span class="poster-line poster-accent" aria-hidden="true">지우지 말고 둔다</span></aside>
<p>컴파일러를 켜자마자 <code>useMemo</code>를 일괄 삭제하면 컴파일 결과가 달라질 수 있습니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 그 값이 <code>useEffect</code> 의존성이었다면 이펙트 실행 횟수가 바뀔 수 있습니다. 지우려면 컴포넌트 단위로 테스트와 함께 진행합니다.</p>
<h2 id="도입하기">도입하기</h2>
<p>React 팀에 따르면 Meta Quest Store에서 첫 로드와 페이지 간 이동이 최대 12% 개선됐고, 일부 상호작용은 2.5배 넘게 빨라졌으며, 메모리 사용량은 그대로였습니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 앱마다 결과는 다를 수 있다는 단서가 붙어 있습니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>
<h3 id="설치와-빌드-설정">설치와 빌드 설정</h3>
<p>React 19에 맞춰 설계됐지만 17과 18도 지원합니다.<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup> 블로그는 버전을 고정해 설치하라고 안내합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>
<pre data-lang="bash"><code class="hljs language-bash">npm install --save-dev --save-exact babel-plugin-react-compiler@latest
</code></pre>
<p>Babel을 쓴다면 플러그인을 등록합니다. 컴파일러는 원래 소스 정보로 분석해야 하므로 Babel 플러그인 파이프라인에서 <strong>가장 먼저</strong> 실행돼야 합니다.<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup></p>
<pre data-lang="js"><code class="hljs language-js"><span class="hljs-comment">// babel.config.js</span>
<span class="hljs-variable language_">module</span>.<span class="hljs-property">exports</span> = {
  <span class="hljs-attr">plugins</span>: [
    <span class="hljs-string">'babel-plugin-react-compiler'</span>, <span class="hljs-comment">// 반드시 첫 번째</span>
  ],
};
</code></pre>
<p>React 17·18이라면 <code>target: '18'</code>처럼 문자열로 버전을 지정하고 <code>react-compiler-runtime</code>을 설치합니다. 이 패키지는 런타임에 필요하므로 <code>devDependencies</code>가 아닌 <code>dependencies</code>에 둡니다.<sup class="cite"><a href="#source-8" aria-label="출처 8">[8]</a></sup></p>
<p>Next.js는 15.3.1 이상에서 swc로 컴파일러를 호출할 수 있고, Expo는 SDK 54부터 기본으로 켜져 있으며, <code>create-vite</code>와 <code>create-next-app</code>에는 컴파일러를 켠 템플릿이 있습니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup><sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup></p>
<p>설치 후 개발 모드의 React DevTools를 열면 최적화된 컴포넌트에 "Memo ✨" 배지가 붙습니다.<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup></p>
<h3 id="조금씩-켜기">조금씩 켜기</h3>
<p>기존 앱은 Babel <code>overrides</code>로 디렉터리별로 켜거나, <code>compilationMode: 'annotation'</code>으로 <code>"use memo"</code>를 붙인 함수만 컴파일하거나, <code>gating</code> 옵션으로 기능 플래그에 따라 런타임에 켜고 끄며 조금씩 넓힐 수 있습니다.<sup class="cite"><a href="#source-9" aria-label="출처 9">[9]</a></sup></p>
<pre data-lang="js"><code class="hljs language-js"><span class="hljs-comment">// babel.config.js — 표시한 함수만 컴파일</span>
<span class="hljs-variable language_">module</span>.<span class="hljs-property">exports</span> = {
  <span class="hljs-attr">plugins</span>: [
    [<span class="hljs-string">'babel-plugin-react-compiler'</span>, {
      <span class="hljs-attr">compilationMode</span>: <span class="hljs-string">'annotation'</span>,
    }],
  ],
};
</code></pre>
<pre data-lang="jsx"><code class="hljs language-jsx"><span class="hljs-keyword">function</span> <span class="hljs-title function_">TodoList</span>(<span class="hljs-params">{ todos }</span>) {
  <span class="hljs-string">"use memo"</span>; <span class="hljs-comment">// 이 컴포넌트만 컴파일 대상</span>
  <span class="hljs-keyword">const</span> sortedTodos = todos.<span class="hljs-title function_">slice</span>().<span class="hljs-title function_">sort</span>();
  <span class="hljs-keyword">return</span> (
    <span class="xml"><span class="hljs-tag">&#x3C;<span class="hljs-name">ul</span>></span>
      {sortedTodos.map(todo => (
        <span class="hljs-tag">&#x3C;<span class="hljs-name">TodoItem</span> <span class="hljs-attr">key</span>=<span class="hljs-string">{todo.id}</span> <span class="hljs-attr">todo</span>=<span class="hljs-string">{todo}</span> /></span>
      ))}
    <span class="hljs-tag">&#x3C;/<span class="hljs-name">ul</span>></span></span>
  );
}
</code></pre>
<p>annotation 모드에서는 새로 만드는 컴포넌트와 커스텀 훅에도 <code>"use memo"</code>를 빠짐없이 붙여야 합니다.<sup class="cite"><a href="#source-9" aria-label="출처 9">[9]</a></sup></p>
<h3 id="린트-먼저">린트 먼저</h3>
<p>컴파일러 기반 린트 규칙은 <code>eslint-plugin-react-hooks</code>의 <code>recommended</code> 프리셋에 들어 있고, 컴파일러 없이도 쓸 수 있습니다. <code>eslint-plugin-react-compiler</code>를 썼다면 지우고 이쪽으로 옮깁니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 렌더링 중 <code>setState</code>로 생기는 루프(<code>set-state-in-render</code>), 이펙트 안의 비싼 작업(<code>set-state-in-effect</code>), 렌더링 중 안전하지 않은 ref 접근(<code>refs</code>) 같은 패턴을 잡아 줍니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 린트가 오류를 보고한 컴포넌트나 훅은 컴파일러가 최적화를 건너뛰고 나머지는 계속 최적화하므로, 위반은 천천히 고쳐도 됩니다.<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup></p>
<h2 id="react-규칙을-어기면-생기는-일">React 규칙을 어기면 생기는 일</h2>
<p>React 규칙(Rules of React)은 컴포넌트와 훅은 순수해야 하고, 컴포넌트는 React가 호출하며, 훅은 최상위에서만 부른다는 세 묶음입니다.<sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup> 어기면 앱에 버그가 있을 가능성이 높아서 가이드라인이 아니라 규칙이라고 부릅니다.<sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup></p>
<h3 id="감지되면-건너뛰고-못-하면-런타임-문제">감지되면 건너뛰고, 못 하면 런타임 문제</h3>
<p>컴파일러는 규칙을 어겼을 수 있는 코드를 만나면 최적화를 건너뜁니다. 그래서 빌드 오류는 드물고, 문제는 대부분 감지하지 못한 미묘한 위반이 있는 컴포넌트를 컴파일했을 때 런타임에 나타납니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup></p>
<p>렌더링 중 컴포넌트 밖의 값을 바꾸는 코드가 대표적인 위반입니다.<sup class="cite"><a href="#source-10" aria-label="출처 10">[10]</a></sup></p>
<pre data-lang="jsx"><code class="hljs language-jsx"><span class="hljs-keyword">const</span> items = []; <span class="hljs-comment">// 컴포넌트 바깥</span>

<span class="hljs-keyword">function</span> <span class="hljs-title function_">FriendList</span>(<span class="hljs-params">{ friends }</span>) {
  <span class="hljs-keyword">for</span> (<span class="hljs-keyword">let</span> i = <span class="hljs-number">0</span>; i &#x3C; friends.<span class="hljs-property">length</span>; i++) {
    <span class="hljs-keyword">const</span> friend = friends[i];
    items.<span class="hljs-title function_">push</span>(<span class="xml"><span class="hljs-tag">&#x3C;<span class="hljs-name">Friend</span> <span class="hljs-attr">key</span>=<span class="hljs-string">{friend.id}</span> <span class="hljs-attr">friend</span>=<span class="hljs-string">{friend}</span> /></span></span>);
  }
  <span class="hljs-keyword">return</span> <span class="xml"><span class="hljs-tag">&#x3C;<span class="hljs-name">section</span>></span>{items}<span class="hljs-tag">&#x3C;/<span class="hljs-name">section</span>></span></span>;
}
<span class="hljs-comment">// 결과: 렌더링할 때마다 items에 친구가 계속 쌓여 중복 표시</span>
</code></pre>
<p><code>const items = []</code>를 함수 안으로 옮기면 렌더링마다 새로 만들어지므로 지역 변경(local mutation)이 되고, 규칙에 맞는 코드가 됩니다.<sup class="cite"><a href="#source-10" aria-label="출처 10">[10]</a></sup></p>
<h3 id="메모이제이션에-정확성을-기댄-코드">메모이제이션에 정확성을 기댄 코드</h3>
<p>더 찾기 어려운 경우는 특정 값이 메모이제이션돼 있어야만 올바르게 동작하는 코드입니다. 컴파일러는 직접 쓴 것과 다르게 메모이제이션할 수 있어서 이펙트 과다 실행, 무한 루프, 업데이트 누락이 생길 수 있습니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup> 컴파일러 버전을 올릴 때도 메모이제이션 방식이 달라질 수 있습니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>
<pre data-lang="jsx"><code class="hljs language-jsx"><span class="hljs-keyword">function</span> <span class="hljs-title function_">SearchResults</span>(<span class="hljs-params">{ query }</span>) {
  <span class="hljs-keyword">const</span> options = <span class="hljs-title function_">useMemo</span>(<span class="hljs-function">() =></span> ({ query }), [query]);
  <span class="hljs-title function_">useEffect</span>(<span class="hljs-function">() =></span> {
    <span class="hljs-title function_">fetchResults</span>(options);
  }, [options]); <span class="hljs-comment">// options 참조가 바뀌면 다시 실행</span>
}

<span class="hljs-comment">// 참조 대신 원시값에 의존하면 메모이제이션 방식과 무관</span>
<span class="hljs-keyword">function</span> <span class="hljs-title function_">SearchResults</span>(<span class="hljs-params">{ query }</span>) {
  <span class="hljs-title function_">useEffect</span>(<span class="hljs-function">() =></span> {
    <span class="hljs-title function_">fetchResults</span>({ query });
  }, [query]);
}
</code></pre>
<p>첫 번째처럼 이펙트가 참조에 기대고 있다면 <code>useMemo</code>를 지우지 말고 남겨 두는 것이 공식 권장입니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 두 번째처럼 원시값에 의존하게 바꾸면 메모이제이션 방식이 달라져도 이펙트 실행 횟수는 그대로입니다.</p>
<h3 id="use-no-memo로-범위-좁히기">"use no memo"로 범위 좁히기</h3>
<p><code>"use no memo"</code>는 함수 하나를 컴파일 대상에서 빼는 지시어입니다. 함수 본문 맨 처음에 작은따옴표나 큰따옴표로 써야 하고(백틱 불가), 어떤 <code>compilationMode</code>보다 우선합니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></p>
<p>지시어를 붙여 문제가 사라지면 React 규칙 위반일 가능성이 높습니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup> 원인을 고친 뒤에는 지시어를 지우고 DevTools에서 ✨ 배지가 다시 붙는지 확인합니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup> 문서는 이 지시어를 영구 해결책이 아니라 임시 디버깅 도구로 규정합니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></p>
<p>테스트 커버리지가 부족하다면 컴파일러를 <code>^1.0.0</code> 같은 범위가 아니라 <code>1.0.0</code>처럼 정확한 버전으로 고정하고, 업그레이드는 직접 확인하며 진행하라고 React 팀은 권합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>
