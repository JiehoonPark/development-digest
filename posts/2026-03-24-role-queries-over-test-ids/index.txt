17:T63b6,<h2 id="테스트-id가-놓치는-것">테스트 ID가 놓치는 것</h2>
<p>테스트 ID는 <code>data-testid</code> 같은 속성에 테스트 전용 값을 넣고, 테스트에서 그 값으로 요소를 찾는 방식입니다. 클래스 이름이나 DOM 구조가 바뀌어도 깨지지 않으니 안정적으로 보입니다. 문제는 이 값이 화면에도, 스크린 리더에도 나타나지 않는다는 점입니다.</p>
<h3 id="테스트-id로-버튼-찾기">테스트 ID로 버튼 찾기</h3>
<p>대화 상자를 여는 버튼이 하나 있다고 하겠습니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>
<pre data-lang="tsx"><code class="hljs language-tsx"><span class="hljs-keyword">function</span> <span class="hljs-title function_">WidgetDialogTrigger</span>(<span class="hljs-params">{ onClick }: <span class="hljs-title class_">Props</span></span>) {

    <span class="xml"><span class="hljs-tag">&#x3C;<span class="hljs-name">button</span> <span class="hljs-attr">data-testid</span>=<span class="hljs-string">"widget-dialog-trigger"</span> <span class="hljs-attr">onClick</span>=<span class="hljs-string">{onClick}</span>></span>
      Open Widget
    <span class="hljs-tag">&#x3C;/<span class="hljs-name">button</span>></span></span>
  )
}
</code></pre>
<p>테스트에서는 ID로 버튼을 찾아 클릭합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>
<pre data-lang="tsx"><code class="hljs language-tsx">screen.<span class="hljs-title function_">getByTestId</span>(<span class="hljs-string">'widget-dialog-trigger'</span>).<span class="hljs-title function_">click</span>()

<h3 id="버튼을-div로-바꿔도-통과한다">버튼을 div로 바꿔도 통과한다</h3>
<p>이제 누군가 <code>&#x3C;button></code>을 <code>&#x3C;div></code>로 바꿨다고 해 봅시다. 속성 값은 그대로이니 위 테스트는 여전히 통과합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>
<pre data-lang="tsx"><code class="hljs language-tsx"><span class="hljs-keyword">function</span> <span class="hljs-title function_">WidgetDialogTrigger</span>(<span class="hljs-params">{ onClick }: <span class="hljs-title class_">Props</span></span>) {
  <span class="hljs-keyword">return</span> (
    <span class="xml"><span class="hljs-tag">&#x3C;<span class="hljs-name">div</span> <span class="hljs-attr">data-testid</span>=<span class="hljs-string">"widget-dialog-trigger"</span> <span class="hljs-attr">onClick</span>=<span class="hljs-string">{onClick}</span>></span>
      Open Widget
    <span class="hljs-tag">&#x3C;/<span class="hljs-name">div</span>></span></span>
  )
}
<span class="hljs-comment">// getByTestId 테스트: 여전히 통과</span>
</code></pre>
<p>마우스로는 똑같이 동작하지만, 이 <code>div</code>는 키보드로 조작할 수 없고 버튼이라는 역할도 없어서 스크린 리더가 제대로 알려 주지 못할 수 있습니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> MDN도 의미 없는 요소인 <code>&#x3C;div></code>와 <code>&#x3C;span></code>에는 역할이 없다고 설명합니다.<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup> 테스트는 초록불인데 일부 사용자는 버튼을 쓸 수 없는 상태가 된 것입니다.</p>
<h3 id="역할로-찾으면-테스트가-실패한다">역할로 찾으면 테스트가 실패한다</h3>
<p>같은 버튼을 역할과 이름으로 찾으면 결과가 달라집니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>
<pre data-lang="tsx"><code class="hljs language-tsx">screen
  .<span class="hljs-title function_">getByRole</span>(<span class="hljs-string">'button'</span>, { <span class="hljs-attr">name</span>: <span class="hljs-string">'Open Widget'</span> })

<span class="hljs-comment">// &#x3C;button>이면 통과</span>
<span class="hljs-comment">// &#x3C;div>로 바꾸면 에러: button 역할을 가진 요소가 없음</span>
</code></pre>
<p><code>getBy...</code> 쿼리는 일치하는 요소가 없으면 설명이 담긴 에러를 던집니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup> 그래서 <code>div</code>로 바꾸는 순간 테스트가 깨지고, 접근성 회귀가 리뷰 전에 드러납니다. 덤으로 "Open Widget 버튼을 클릭한다"처럼 테스트가 사람이 읽는 문장에 가까워집니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>
<p>버튼 문구가 바뀌면 테스트도 고쳐야 한다는 걱정이 있습니다. 원문 필자는 문구가 생각만큼 자주 바뀌지 않고, 문구에 묶이는 것 자체가 문제는 아니라고 봅니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>

<h2 id="역할과-접근-가능한-이름">역할과 접근 가능한 이름</h2>
<p><code>getByRole</code>이 기대는 두 가지 정보는 역할과 접근 가능한 이름입니다. 둘 다 브라우저가 접근성 트리(accessibility tree)에 올려 보조 기술에 전달하는 값입니다.<sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup><sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></p>
<h3 id="역할-이-요소가-무엇인가">역할: 이 요소가 무엇인가</h3>
<p>역할(role)은 요소가 버튼인지, 링크인지, 대화 상자인지를 나타내는 의미입니다. 많은 HTML 요소는 기본 역할을 갖고 있어서, <code>&#x3C;input type="radio"></code>는 따로 지정하지 않아도 <code>radio</code> 역할입니다.<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup> <code>getByRole</code>도 이 기본 역할을 고려하므로 <code>&#x3C;button></code>은 <code>role</code> 속성 없이 <code>button</code>으로 찾힙니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup></p>
<pre data-lang="html"><code class="hljs language-html"><span class="hljs-tag">&#x3C;<span class="hljs-name">button</span>></span>저장<span class="hljs-tag">&#x3C;/<span class="hljs-name">button</span>></span>        <span class="hljs-comment">&#x3C;!-- 역할: button --></span>
<span class="hljs-tag">&#x3C;<span class="hljs-name">a</span> <span class="hljs-attr">href</span>=<span class="hljs-string">"/docs"</span>></span>문서<span class="hljs-tag">&#x3C;/<span class="hljs-name">a</span>></span>     <span class="hljs-comment">&#x3C;!-- 역할: link --></span>
<span class="hljs-tag">&#x3C;<span class="hljs-name">nav</span>></span>...<span class="hljs-tag">&#x3C;/<span class="hljs-name">nav</span>></span>              <span class="hljs-comment">&#x3C;!-- 역할: navigation --></span>
<span class="hljs-tag">&#x3C;<span class="hljs-name">form</span> <span class="hljs-attr">aria-label</span>=<span class="hljs-string">"가입"</span>></span>...<span class="hljs-tag">&#x3C;/<span class="hljs-name">form</span>></span> <span class="hljs-comment">&#x3C;!-- 역할: form --></span>
<span class="hljs-tag">&#x3C;<span class="hljs-name">div</span>></span>저장<span class="hljs-tag">&#x3C;/<span class="hljs-name">div</span>></span>              <span class="hljs-comment">&#x3C;!-- 역할 없음 --></span>
</code></pre>
<p><code>&#x3C;nav></code>는 <code>navigation</code>, <code>&#x3C;form></code>은 <code>form</code>, <code>&#x3C;main></code>은 <code>main</code> 같은 랜드마크 역할에 대응합니다.<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup> 다만 <code>&#x3C;form></code>은 접근 가능한 이름이 있을 때만 <code>form</code> 랜드마크로 노출됩니다.<sup class="cite"><a href="#source-7" aria-label="출처 7">[7]</a></sup></p>
<h4>자주 하는 실수: 기본 역할을 다시 적기</h4>
<pre data-lang="html"><code class="hljs language-html"><span class="hljs-comment">&#x3C;!-- 불필요: button은 이미 button 역할 --></span>
<span class="hljs-tag">&#x3C;<span class="hljs-name">button</span> <span class="hljs-attr">role</span>=<span class="hljs-string">"button"</span>></span>저장<span class="hljs-tag">&#x3C;/<span class="hljs-name">button</span>></span>

<span class="hljs-comment">&#x3C;!-- 충돌: button에 heading 역할을 줄 수 없음 --></span>
<span class="hljs-tag">&#x3C;<span class="hljs-name">button</span> <span class="hljs-attr">role</span>=<span class="hljs-string">"heading"</span>></span>제목<span class="hljs-tag">&#x3C;/<span class="hljs-name">button</span>></span>
</code></pre>
<p>ARIA in HTML 명세는 기본 역할과 같은 값을 <code>role</code>에 다시 넣는 것을 권장하지 않고, 기본 의미와 충돌하는 <code>role</code> 사용을 금지합니다.<sup class="cite"><a href="#source-8" aria-label="출처 8">[8]</a></sup> Testing Library 문서도 같은 이유로 <code>button</code>에 <code>heading</code> 역할을 줄 수 없다고 예를 듭니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup></p>
<p><code>role="button"</code>을 <code>div</code>에 붙이는 것도 해결책이 아닙니다. 스크린 리더에 버튼이라고 알려 줄 뿐, 클릭 이벤트나 키보드 처리 같은 버튼 기능은 생기지 않습니다.<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup> 진짜 <code>&#x3C;button></code>을 쓰는 편이 간단합니다.</p>
<h3 id="접근-가능한-이름-이-요소를-무엇이라-부르는가">접근 가능한 이름: 이 요소를 무엇이라 부르는가</h3>
<p>접근 가능한 이름(accessible name)은 보조 기술 사용자에게 요소를 소개하는 텍스트입니다.<sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup> 같은 역할의 버튼이 여러 개일 때 <code>name</code> 옵션으로 원하는 요소를 정확히 고를 수 있는 것도 이 이름 덕분입니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup> 이름이 어디서 오는지는 요소마다 다릅니다.<sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup></p>
<pre data-lang="html"><code class="hljs language-html"><span class="hljs-tag">&#x3C;<span class="hljs-name">button</span>></span>저장<span class="hljs-tag">&#x3C;/<span class="hljs-name">button</span>></span>

<h4>자주 하는 실수: 역할로 찾을 수 없는 요소</h4>
<pre data-lang="tsx"><code class="hljs language-tsx"><span class="hljs-comment">// &#x3C;input type="password" />는 기본 역할이 없음</span>

<p>명세상 <code>&#x3C;input type="password"></code>에는 기본 역할이 없어서 <code>getByLabelText</code> 같은 쿼리로 찾아야 합니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup> 또 <code>getByRole</code>은 접근성 트리에서 빠진 요소를 기본으로 제외하므로, <code>aria-hidden="true"</code> 안의 요소는 <code>hidden: true</code> 옵션을 줘야 찾을 수 있습니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup> 역할 이름은 문자열로 정확히 비교하기 때문에 <code>checkbox</code>로 찾으면 <code>switch</code> 역할 요소는 나오지 않습니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup></p>
<h2 id="사용자의-동작을-쿼리로-옮기기">사용자의 동작을 쿼리로 옮기기</h2>
<p>원문 필자는 직접 클릭하며 하는 일을 말로 풀어 본 뒤, 그 문장을 그대로 셀렉터로 옮긴다고 합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> "사이드바의 Dashboards 링크를 누른다"는 "내비게이션 안의, 이름이 Dashboards인 링크"가 됩니다.</p>
<h3 id="within으로-범위-좁히기">within으로 범위 좁히기</h3>
<p><code>within</code>은 특정 요소를 받아 그 안에서만 쿼리하도록 묶어 줍니다.<sup class="cite"><a href="#source-9" aria-label="출처 9">[9]</a></sup> 랜드마크나 대화 상자를 먼저 찾고, 그 안에서 컨트롤을 찾으면 같은 이름의 버튼이 여러 곳에 있어도 헷갈리지 않습니다.</p>
<pre data-lang="tsx"><code class="hljs language-tsx"><span class="hljs-comment">// 사이드바의 Dashboards 링크를 누른다</span>

<h3 id="쿼리-우선순위">쿼리 우선순위</h3>
<p>Testing Library는 테스트가 사용자가 코드를 쓰는 방식과 최대한 닮아야 한다는 원칙에 따라 쿼리 우선순위를 정해 둡니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></p>
<ol>
<li><code>getByRole</code>: 거의 모든 경우의 첫 번째 선택이고, 이것으로 찾을 수 없다면 UI가 접근성을 갖추지 못했을 수 있다고 봅니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></li>
<li><code>getByLabelText</code>: 폼 필드에 가장 좋습니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></li>
<li><code>getByPlaceholderText</code>, <code>getByText</code>, <code>getByDisplayValue</code><sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></li>
<li><code>getByAltText</code>, <code>getByTitle</code><sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></li>
<li><code>getByTestId</code>: 사용자가 보거나 들을 수 없으므로, 역할이나 텍스트로 찾을 수 없거나 텍스트가 동적일 때만 권합니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></li>
</ol>
<p>Playwright의 <code>page.getByRole()</code>도 같은 개념입니다. Playwright 문서는 역할 로케이터가 사용자와 보조 기술이 페이지를 인식하는 방식에 가장 가깝다며 우선 쓰라고 권합니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup> 한편 테스트 ID가 텍스트나 역할이 바뀌어도 통과하는 가장 견고한 방식이라고도 적고 있습니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup> 앞의 <code>div</code> 예제에서 문제가 된 것이 바로 이 성질입니다.</p>
<pre data-lang="ts"><code class="hljs language-ts"><span class="hljs-keyword">await</span> page.<span class="hljs-title function_">getByRole</span>(<span class="hljs-string">'button'</span>, { <span class="hljs-attr">name</span>: <span class="hljs-string">'Sign in'</span> }).<span class="hljs-title function_">click</span>()
<span class="hljs-keyword">await</span> <span class="hljs-title function_">expect</span>(page.<span class="hljs-title function_">getByRole</span>(<span class="hljs-string">'heading'</span>, { <span class="hljs-attr">name</span>: <span class="hljs-string">'Sign up'</span> })).<span class="hljs-title function_">toBeVisible</span>()
</code></pre>
<h2 id="역할로-찾을-수-없을-때-고칠-곳">역할로 찾을 수 없을 때 고칠 곳</h2>
<p>역할 기반 셀렉터가 동작하지 않으면 원문 필자는 테스트 대신 앱을 고칩니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 그때 확인할 목록은 다음과 같습니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>
<ul>
<li><strong>시맨틱 HTML을 씁니다.</strong> 기본 ARIA 역할이 따라오므로 <code>role</code>을 직접 붙일 일이 드뭅니다.</li>
<li><strong>상호작용 요소에 이름을 줍니다.</strong> 보이는 텍스트나 label이 있어야 하고, 상호작용하지 않는 것에는 상호작용 요소를 쓰지 않습니다.</li>
<li><strong>키보드로 앱을 다녀 봅니다.</strong> 키보드로 쓸 수 없는 것이 있다면 고칠 대상입니다.</li>
<li><strong>제목, 랜드마크, 그룹 영역으로 구조를 만듭니다.</strong> 테스트에서 <code>within</code>으로 범위를 좁히기도 쉬워집니다.</li>
<li><strong>폼 컨트롤은 항상 label과 연결합니다.</strong> 보이는 label이 싫다면 화면에서만 숨기는 컴포넌트나 <code>sr-only</code> 클래스를 씁니다.</li>
<li><strong>도구로 확인합니다.</strong> Testing Playground로 가장 좋은 셀렉터를 찾거나, 개발자 도구에서 DOM 트리 대신 접근성 트리 보기로 전환해 봅니다.</li>
</ul>
<pre data-lang="tsx"><code class="hljs language-tsx"><span class="hljs-comment">// 보이는 label 없이도 이름을 주는 예</span>
&#x3C;label htmlFor=<span class="hljs-string">"search"</span> className=<span class="hljs-string">"sr-only"</span>>검색어&#x3C;/label>

</code></pre>
<h4>자주 하는 실수: 역할 테스트를 접근성 검사로 착각하기</h4>
<p>역할 기반 셀렉터는 접근성 없는 마크업을 실수로 만들기 어렵게 할 뿐, axe 같은 도구로 하는 전용 접근성 테스트를 대신하지 않습니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> Playwright 문서도 역할 로케이터가 접근성 감사와 적합성 테스트를 대체하지 않고, ARIA 지침에 대한 이른 피드백을 줄 뿐이라고 설명합니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup> 원문 필자는 유럽 접근성법(European Accessibility Act)이나 미국 장애인법(Americans with Disabilities Act) 같은 법이 WCAG 2.1 AA 준수를 요구한다고 짚습니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 법적 기준을 맞추려면 별도의 검사가 필요합니다.</p>
