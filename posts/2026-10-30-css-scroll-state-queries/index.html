붙었을 때만 헤더 그림자 — CSS 스크롤 상태 쿼리

헤더가 붙었는지, 카드가 스냅 대상인지, 아래로 더 스크롤할 수 있는지를 CSS에서 묻습니다. 상태를 읽는 요소와 꾸미는 요소를 나눠 헤더·캐러셀·스크롤 힌트를 만드는 방법을 정리합니다.

요약

  • container-type: scroll-state를 상태를 읽을 요소에 선언하고, @container 안에서 그 자손을 꾸밉니다.[1]
  • stuck은 경계에 붙은 상태, snapped는 스냅 대상, scrollable은 해당 방향으로 더 스크롤할 수 있는지를 묻습니다.[1][2]
  • scrolled는 마지막 스크롤 방향을 묻는 조건이며, 스크롤 가능 방향을 묻는 scrollable과 다릅니다.[3]

스크롤 위치 대신 상태를 묻습니다

헤더에 그림자를 넣으려는 이유는 대개 페이지가 얼마나 이동했는지보다, 헤더가 본문 위에 붙어 있다는 사실을 보여 주기 위해서입니다. 캐러셀에서도 필요한 것은 이동 거리보다 어느 카드가 스냅 대상인지일 때가 많습니다. 스크롤 상태 쿼리(scroll-state query)는 이런 브라우저의 상태를 조건으로 자손 요소의 스타일을 바꿉니다.[1][2]

상태를 읽는 요소와 꾸미는 요소

먼저 상태를 읽을 요소에 container-type: scroll-state를 선언합니다. container-name은 선택 사항이지만, 예제에서는 용도를 구별하기 위해 이름을 붙입니다.[1][2] 조건은 @container 이름 scroll-state(상태: 값) 형태로 쓰며, 그 안의 선택자는 해당 컨테이너의 자손을 대상으로 합니다.[2]

.header-shell {
  container-type: scroll-state;
  container-name: page-header;
}

@container page-header scroll-state(stuck: top) {
  .header-face { box-shadow: 0 5px 5px #0003; }
}
/* header-shell이 위쪽에 붙으면 자손 header-face에 그림자 */

여기서 .header-shell과 .header-face를 같은 요소로 합치면 의도한 구조가 아닙니다. 자기 자신의 상태를 조회해서 자기 자신을 꾸미는 방식이 아니라, 바깥 요소가 상태를 제공하고 안쪽 요소가 반응하는 방식입니다.[1] 이름을 생략하면 조건에 맞는 container-type을 가진 가장 가까운 조상 쿼리 컨테이너를 기준으로 삼습니다.[3]

타임라인과는 다른 도구입니다

스크롤 기반 애니메이션(scroll-driven animation)은 스크롤 위치를 애니메이션 진행도에 연결합니다.[4] 반면 상태 쿼리는 붙었는지, 스냅 대상인지 같은 조건에 따라 스타일을 적용합니다.[1] 읽기 진행 막대라면 타임라인, 붙은 헤더의 그림자라면 상태 쿼리부터 검토하면 됩니다.

기존 글에서 다룬 스크롤 타임라인과 스티키 블로커의 구현 원리는 여기서 반복하지 않습니다. 이 글의 관심사는 헤더를 어떻게 가릴지가 아니라, 이미 브라우저가 판단한 상태를 어떤 요소에 전달할지입니다. 아래 예제의 크기와 색상은 동작을 구별하기 위한 임의의 데모 값입니다.

붙었을 때만 헤더에 그림자 넣기

stuck: top은 position: sticky인 컨테이너가 스크롤 컨테이너의 위쪽 경계에 붙었는지를 묻습니다.[1][2] 단순히 스티키 속성을 선언했는지가 아니라 실제로 붙은 상태가 조건입니다. 따라서 먼저 스티키 배치를 만들고, 그 상태에 반응하는 장식을 추가합니다.[1]

스티키 껍데기와 안쪽 표면

다음 HTML과 CSS를 함께 실행합니다. 앞의 소개 영역을 지나도록 상자를 스크롤하면 헤더가 위쪽에 붙고, 안쪽 표면에 그림자가 생기는 예제입니다. 원문의 그림자 예제를 독립된 스크롤 영역으로 구성했습니다.[1]

<div class="header-demo">
  <p class="header-intro">아래로 내려 헤더를 붙여 보세요.</p>
  <header class="header-shell">
    <nav class="header-face">문서 탐색</nav>
  </header>
  <main class="header-content">본문 영역</main>
</div>

.header-demo { height: 18rem; overflow: auto; }
.header-intro { height: 8rem; }
.header-content { height: 40rem; }

.header-shell {
  container-type: scroll-state;
  container-name: page-header;
  position: sticky;
  top: 0;
}
.header-face {
  padding: 1rem;
  background: white;
  color: black;
  box-shadow: none;
}

@supports (container-type: scroll-state) {
  @container page-header scroll-state(stuck: top) {
    .header-face { box-shadow: 0 5px 5px #0003; }
  }
}
/* 붙기 전: 그림자 없음 / 위쪽에 붙은 뒤: 그림자 표시 */

원문은 @supports (container-type: scroll-state)로 상태 기반 스타일을 점진적으로 적용하는 패턴을 제시합니다.[1] 이 예제도 기본 헤더는 조건문 밖에 두었습니다. 쿼리를 사용할 수 없어도 글자와 배경은 남고, 그림자만 추가되지 않는 구성을 의도했습니다.

자주 하는 실수는 상태 쿼리만 쓰면 스티키 배치까지 만들어질 것으로 생각하는 것입니다. 원문에서도 position: sticky와 top을 먼저 선언한 뒤 상태를 조회합니다.[1] 문제가 생기면 우선 그림자 규칙을 빼고 헤더가 실제로 붙는지 확인하세요. 배치 문제와 조건부 장식 문제를 나누면 조사할 범위가 줄어듭니다.

그림자를 부드럽게 바꾸거나 요소를 움직이는 효과는 별도 선택입니다. 원문은 움직임을 추가할 경우 prefers-reduced-motion: no-preference 조건으로 사용자의 동작 줄이기 설정을 존중하라고 권합니다.[1] 상태 확인과 애니메이션을 처음부터 묶기보다, 상태별 모습부터 완성하는 편을 권합니다.

스냅 캐러셀에서 대상 카드 강조하기

snapped는 컨테이너가 조상 스크롤 컨테이너의 어느 축에서 스냅 대상이 되는지 조회합니다.[2] 이때 쿼리 컨테이너는 가로로 움직이는 목록 전체가 아닙니다. scroll-snap-align을 가진 개별 카드에 container-type: scroll-state를 선언해야 합니다.[1]

스크롤 영역 → 스냅 대상 → 카드 내용

원문은 스크롤 영역, 스냅 대상, 상태에 반응하는 자식의 계층을 구분합니다.[1] 아래에서는 .carousel이 스크롤하고, .slide가 스냅되며, .card가 색을 바꿉니다. 같은 이름의 쿼리 컨테이너를 각 슬라이드에 지정해 각 카드가 자신의 조상 슬라이드를 기준으로 반응하도록 구성했습니다.[3]

<div class="carousel" tabindex="0" aria-label="추천 글">
  <article class="slide"><div class="card">상태 쿼리</div></article>
  <article class="slide"><div class="card">스티키 헤더</div></article>
  <article class="slide"><div class="card">스크롤 힌트</div></article>
</div>

.carousel {
  display: flex;
  width: 20rem;
  overflow-x: auto;
  scroll-snap-type: x mandatory;
}
.slide {
  flex: 0 0 100%;
  scroll-snap-align: center;
  container-type: scroll-state;
  container-name: carousel-slide;
}
.card {
  padding: 2rem;
  background: #eee;
  color: black;
}

@container carousel-slide scroll-state(snapped: x) {
  .card { background: #263c7a; color: white; }
}
/* 가로 스냅 대상의 카드 내용만 진한 배경으로 강조 */

기본 상태에서도 모든 카드 내용을 읽을 수 있게 했습니다. 강조가 없어도 목록의 정보가 사라지지 않도록 만드는 설계입니다. 강조 여부를 필수 내용의 노출 조건으로 쓰기 전에, 상태 쿼리를 빼도 캐러셀을 사용할 수 있는지 먼저 확인하세요.

자주 하는 실수는 .carousel에만 쿼리 컨테이너를 지정하거나, 쿼리 안에서 .slide 자체를 꾸미는 것입니다. 스냅 상태를 읽는 대상은 슬라이드이고, 반응하는 대상은 그 자손이어야 합니다.[1] 세 역할을 이름으로 구분하면 어느 요소에 속성을 넣을지 분명해집니다.

또한 snapped를 “스크롤이 완전히 끝났다”는 알림으로 해석하면 안 됩니다. 원문은 이 쿼리의 반응이 scrollsnapchange보다 scrollsnapchanging에 가깝고, 스냅 대상에 이른 시각적 피드백을 제공한다고 설명합니다.[1] 선택 강조에 쓰는 것과 완료 시점을 판단하는 것은 다른 요구입니다.

더 내려갈 수 있는지, 방금 어디로 움직였는지

scrollable은 지정한 방향으로 사용자가 더 스크롤할 수 있는지를 묻습니다.[2][3] scrollable: bottom은 아래쪽에 도달하지 못한 내용이 있는지, scrollable: top은 위쪽으로 돌아갈 여지가 있는지를 구별하는 데 쓸 수 있습니다.[3] 현재 이동 방향을 뜻하지는 않습니다.

남은 내용에 맞춰 안내 보여 주기

이 경우에는 스크롤 영역 자체가 쿼리 컨테이너입니다.[1] 아래 안내문은 스크롤 영역 안에 두고 위쪽에 붙여, 본문을 움직이는 동안에도 상태 변화를 확인할 수 있게 했습니다. 원문의 스크롤 화살표 아이디어를 텍스트 힌트로 바꾼 예제입니다.[1]

<div class="reader" tabindex="0" aria-label="읽기 영역">
  <div class="reader-hints" aria-hidden="true">
    <span class="more-hint">↓ 아래에 내용이 더 있습니다</span>
    <span class="up-hint">↑ 위로 돌아갈 수 있습니다</span>
    <span class="direction-hint">최근 방향: 아래</span>
  </div>
  <div class="reader-content">스크롤하며 안내 변화를 확인하세요.</div>
</div>

.reader {
  height: 16rem;
  overflow: auto;
  container-type: scroll-state;
  container-name: reading-area;
}
.reader-content { height: 50rem; }
.reader-hints {
  position: sticky;
  top: 0;
  padding: 1rem;
  background: white;
  color: black;
}
.more-hint, .up-hint, .direction-hint {
  display: block;
  visibility: hidden;
}

@container reading-area scroll-state(scrollable: bottom) {
  .more-hint { visibility: visible; }
}
@container reading-area scroll-state(scrollable: top) {
  .up-hint { visibility: visible; }
}
/* 맨 위: 아래 안내 / 중간: 위아래 안내 / 맨 아래: 위 안내 */

안내를 숨길 때 공간은 유지하도록 구성했습니다. 이 힌트는 버튼이 아니라 스크롤 가능 방향을 덧붙이는 장식이며, 실제 내용은 힌트의 표시 여부와 관계없이 남아 있습니다. 실무에서는 콘텐츠가 짧아 스크롤 자체가 필요 없는 경우도 함께 확인하세요. 어느 방향으로도 스크롤할 수 없다면 방향별 조건이 참이 되지 않는다는 정의가 기준입니다.[3]

마지막 이동 방향은 별도 조건입니다

MDN의 scrolled는 컨테이너가 가장 최근에 어느 방향으로 스크롤됐는지를 조회합니다.[2][3] 앞 예제에 다음 규칙을 추가하면 .direction-hint가 최근 아래쪽으로 스크롤한 상태를 표시합니다. 이 예제는 해당 조건을 지원하는 환경에서 확인해야 합니다.

@container reading-area scroll-state(scrolled: bottom) {
  .direction-hint { visibility: visible; }
}
/* 최근 스크롤이 아래 방향이면 방향 안내 표시 */

중간 위치에서 위로 스크롤하더라도 아래쪽에는 여전히 내용이 남아 있을 수 있습니다. 이 경우 “아래로 더 갈 수 있는가”와 “최근 아래로 움직였는가”의 답은 다릅니다. scrollable과 scrolled를 서로 바꿔 쓰지 않아야 하는 이유입니다.[3]

지원 범위도 조건별로 구분합니다

Chrome 원문은 Chrome 133에서 stuck, snapped, scrollable을 사용할 수 있다고 소개합니다.[1] MDN에 설명된 scrolled까지 같은 도입 버전으로 묶을 근거는 이 자료에 없습니다. 다른 브라우저의 지원 버전도 여기서는 단정하지 않습니다.

또한 @container 문서의 일반적인 지원 배지가 모든 하위 기능의 지원을 뜻하지는 않습니다. MDN도 일부 기능은 지원 수준이 다를 수 있다고 명시합니다.[3] 기본 콘텐츠를 먼저 제공하고 상태 쿼리는 장식에 적용하세요. 도입 전에는 사용하려는 조건 각각이 목표 브라우저에서 실제로 반응하는지 확인해야 합니다.

정리

같은 scroll-state() 문법을 쓰더라도 무엇을 쿼리 컨테이너로 삼는지가 다릅니다.[1] 아래 표처럼 상태의 주체와 시각적 반응을 먼저 적어 보면, 별도의 스크롤 감지 코드가 필요한지 판단하기 쉬워집니다.

만들려는 효과 조회할 조건 상태를 읽는 요소 스타일을 바꿀 요소
붙은 헤더에 그림자 stuck: top 스티키 헤더 껍데기 안쪽 탐색 영역
스냅 대상 카드 강조 snapped: x 개별 스냅 대상 카드의 자손 내용
남은 내용 안내 scrollable: bottom 스크롤 영역 안쪽 안내문
최근 아래 이동 표시 scrolled: bottom 스크롤 영역 안쪽 방향 표시

앞의 헤더·스냅·안내 패턴은 원문의 상태별 사용법을 적용했고, 마지막 방향 표시는 MDN의 정의를 따릅니다.[1][3] 핵심은 쿼리가 모든 스크롤 처리를 대체한다는 주장이 아닙니다. 필요한 것이 거리나 진행도가 아니라 상태라면, 그 상태를 읽는 요소와 반응하는 자손을 나누는 것부터 시작하면 됩니다.

프론트엔드 팀이 해 볼 것

  1. 기존 헤더에서 스티키 배치를 맡는 요소와 그림자를 받을 자손 요소를 나누고, 붙기 전후를 비교합니다.
  2. 스냅 캐러셀의 개별 대상에 쿼리 컨테이너를 지정하고, 목록 전체에 지정했을 때와 반응을 비교합니다.
  3. 읽기 영역의 맨 위·중간·맨 아래와 내용이 짧은 경우를 확인하고, 목표 브라우저에서 각 상태 조건을 따로 검증합니다.
