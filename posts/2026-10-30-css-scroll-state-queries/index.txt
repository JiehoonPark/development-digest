17:T618c,<h2 id="스크롤-위치-대신-상태를-묻습니다">스크롤 위치 대신 상태를 묻습니다</h2>
<p>헤더에 그림자를 넣으려는 이유는 대개 페이지가 얼마나 이동했는지보다, 헤더가 본문 위에 붙어 있다는 사실을 보여 주기 위해서입니다. 캐러셀에서도 필요한 것은 이동 거리보다 어느 카드가 스냅 대상인지일 때가 많습니다. 스크롤 상태 쿼리(scroll-state query)는 이런 브라우저의 상태를 조건으로 자손 요소의 스타일을 바꿉니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup><sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup></p>
<h3 id="상태를-읽는-요소와-꾸미는-요소">상태를 읽는 요소와 꾸미는 요소</h3>
<p>먼저 상태를 읽을 요소에 <code>container-type: scroll-state</code>를 선언합니다. <code>container-name</code>은 선택 사항이지만, 예제에서는 용도를 구별하기 위해 이름을 붙입니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup><sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup> 조건은 <code>@container 이름 scroll-state(상태: 값)</code> 형태로 쓰며, 그 안의 선택자는 해당 컨테이너의 자손을 대상으로 합니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup></p>
<pre data-lang="css"><code class="hljs language-css"><span class="hljs-selector-class">.header-shell</span> {
  <span class="hljs-attribute">container-type</span>: scroll-state;
  <span class="hljs-attribute">container-name</span>: page-header;
}

<span class="hljs-keyword">@container</span> page-header scroll-state(<span class="hljs-attribute">stuck</span>: top) {
  <span class="hljs-selector-class">.header-face</span> { <span class="hljs-attribute">box-shadow</span>: <span class="hljs-number">0</span> <span class="hljs-number">5px</span> <span class="hljs-number">5px</span> <span class="hljs-number">#0003</span>; }
}
<span class="hljs-comment">/* header-shell이 위쪽에 붙으면 자손 header-face에 그림자 */</span>
</code></pre>
<p>여기서 <code>.header-shell</code>과 <code>.header-face</code>를 같은 요소로 합치면 의도한 구조가 아닙니다. 자기 자신의 상태를 조회해서 자기 자신을 꾸미는 방식이 아니라, 바깥 요소가 상태를 제공하고 안쪽 요소가 반응하는 방식입니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 이름을 생략하면 조건에 맞는 <code>container-type</code>을 가진 가장 가까운 조상 쿼리 컨테이너를 기준으로 삼습니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></p>
<h3 id="타임라인과는-다른-도구입니다">타임라인과는 다른 도구입니다</h3>
<p>스크롤 기반 애니메이션(scroll-driven animation)은 스크롤 위치를 애니메이션 진행도에 연결합니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup> 반면 상태 쿼리는 붙었는지, 스냅 대상인지 같은 조건에 따라 스타일을 적용합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 읽기 진행 막대라면 타임라인, 붙은 헤더의 그림자라면 상태 쿼리부터 검토하면 됩니다.</p>
<p>기존 글에서 다룬 스크롤 타임라인과 스티키 블로커의 구현 원리는 여기서 반복하지 않습니다. 이 글의 관심사는 헤더를 어떻게 가릴지가 아니라, 이미 브라우저가 판단한 상태를 어떤 요소에 전달할지입니다. 아래 예제의 크기와 색상은 동작을 구별하기 위한 임의의 데모 값입니다.</p>
<h2 id="붙었을-때만-헤더에-그림자-넣기">붙었을 때만 헤더에 그림자 넣기</h2>
<p><code>stuck: top</code>은 <code>position: sticky</code>인 컨테이너가 스크롤 컨테이너의 위쪽 경계에 붙었는지를 묻습니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup><sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup> 단순히 스티키 속성을 선언했는지가 아니라 실제로 붙은 상태가 조건입니다. 따라서 먼저 스티키 배치를 만들고, 그 상태에 반응하는 장식을 추가합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>
<h3 id="스티키-껍데기와-안쪽-표면">스티키 껍데기와 안쪽 표면</h3>
<p>다음 HTML과 CSS를 함께 실행합니다. 앞의 소개 영역을 지나도록 상자를 스크롤하면 헤더가 위쪽에 붙고, 안쪽 표면에 그림자가 생기는 예제입니다. 원문의 그림자 예제를 독립된 스크롤 영역으로 구성했습니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>

<p>원문은 <code>@supports (container-type: scroll-state)</code>로 상태 기반 스타일을 점진적으로 적용하는 패턴을 제시합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 이 예제도 기본 헤더는 조건문 밖에 두었습니다. 쿼리를 사용할 수 없어도 글자와 배경은 남고, 그림자만 추가되지 않는 구성을 의도했습니다.</p>
<p>자주 하는 실수는 상태 쿼리만 쓰면 스티키 배치까지 만들어질 것으로 생각하는 것입니다. 원문에서도 <code>position: sticky</code>와 <code>top</code>을 먼저 선언한 뒤 상태를 조회합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 문제가 생기면 우선 그림자 규칙을 빼고 헤더가 실제로 붙는지 확인하세요. 배치 문제와 조건부 장식 문제를 나누면 조사할 범위가 줄어듭니다.</p>
<p>그림자를 부드럽게 바꾸거나 요소를 움직이는 효과는 별도 선택입니다. 원문은 움직임을 추가할 경우 <code>prefers-reduced-motion: no-preference</code> 조건으로 사용자의 동작 줄이기 설정을 존중하라고 권합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 상태 확인과 애니메이션을 처음부터 묶기보다, 상태별 모습부터 완성하는 편을 권합니다.</p>
<h2 id="스냅-캐러셀에서-대상-카드-강조하기">스냅 캐러셀에서 대상 카드 강조하기</h2>
<p><code>snapped</code>는 컨테이너가 조상 스크롤 컨테이너의 어느 축에서 스냅 대상이 되는지 조회합니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup> 이때 쿼리 컨테이너는 가로로 움직이는 목록 전체가 아닙니다. <code>scroll-snap-align</code>을 가진 개별 카드에 <code>container-type: scroll-state</code>를 선언해야 합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>
<h3 id="스크롤-영역-스냅-대상-카드-내용">스크롤 영역 → 스냅 대상 → 카드 내용</h3>
<p>원문은 스크롤 영역, 스냅 대상, 상태에 반응하는 자식의 계층을 구분합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 아래에서는 <code>.carousel</code>이 스크롤하고, <code>.slide</code>가 스냅되며, <code>.card</code>가 색을 바꿉니다. 같은 이름의 쿼리 컨테이너를 각 슬라이드에 지정해 각 카드가 자신의 조상 슬라이드를 기준으로 반응하도록 구성했습니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></p>

<p>자주 하는 실수는 <code>.carousel</code>에만 쿼리 컨테이너를 지정하거나, 쿼리 안에서 <code>.slide</code> 자체를 꾸미는 것입니다. 스냅 상태를 읽는 대상은 슬라이드이고, 반응하는 대상은 그 자손이어야 합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 세 역할을 이름으로 구분하면 어느 요소에 속성을 넣을지 분명해집니다.</p>
<p>또한 <code>snapped</code>를 “스크롤이 완전히 끝났다”는 알림으로 해석하면 안 됩니다. 원문은 이 쿼리의 반응이 <code>scrollsnapchange</code>보다 <code>scrollsnapchanging</code>에 가깝고, 스냅 대상에 이른 시각적 피드백을 제공한다고 설명합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 선택 강조에 쓰는 것과 완료 시점을 판단하는 것은 다른 요구입니다.</p>
<h2 id="더-내려갈-수-있는지-방금-어디로-움직였는지">더 내려갈 수 있는지, 방금 어디로 움직였는지</h2>
<p><code>scrollable</code>은 지정한 방향으로 사용자가 더 스크롤할 수 있는지를 묻습니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup><sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup> <code>scrollable: bottom</code>은 아래쪽에 도달하지 못한 내용이 있는지, <code>scrollable: top</code>은 위쪽으로 돌아갈 여지가 있는지를 구별하는 데 쓸 수 있습니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup> 현재 이동 방향을 뜻하지는 않습니다.</p>
<h3 id="남은-내용에-맞춰-안내-보여-주기">남은 내용에 맞춰 안내 보여 주기</h3>
<p>이 경우에는 스크롤 영역 자체가 쿼리 컨테이너입니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 아래 안내문은 스크롤 영역 안에 두고 위쪽에 붙여, 본문을 움직이는 동안에도 상태 변화를 확인할 수 있게 했습니다. 원문의 스크롤 화살표 아이디어를 텍스트 힌트로 바꾼 예제입니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>

<h3 id="마지막-이동-방향은-별도-조건입니다">마지막 이동 방향은 별도 조건입니다</h3>
<p>MDN의 <code>scrolled</code>는 컨테이너가 가장 최근에 어느 방향으로 스크롤됐는지를 조회합니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup><sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup> 앞 예제에 다음 규칙을 추가하면 <code>.direction-hint</code>가 최근 아래쪽으로 스크롤한 상태를 표시합니다. 이 예제는 해당 조건을 지원하는 환경에서 확인해야 합니다.</p>

<h3 id="지원-범위도-조건별로-구분합니다">지원 범위도 조건별로 구분합니다</h3>
<p>Chrome 원문은 Chrome 133에서 <code>stuck</code>, <code>snapped</code>, <code>scrollable</code>을 사용할 수 있다고 소개합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> MDN에 설명된 <code>scrolled</code>까지 같은 도입 버전으로 묶을 근거는 이 자료에 없습니다. 다른 브라우저의 지원 버전도 여기서는 단정하지 않습니다.</p>
<p>또한 <code>@container</code> 문서의 일반적인 지원 배지가 모든 하위 기능의 지원을 뜻하지는 않습니다. MDN도 일부 기능은 지원 수준이 다를 수 있다고 명시합니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup> 기본 콘텐츠를 먼저 제공하고 상태 쿼리는 장식에 적용하세요. 도입 전에는 사용하려는 조건 각각이 목표 브라우저에서 실제로 반응하는지 확인해야 합니다.</p>
