17:T4eb5,<h2 id="interop-후보라는-말의-의미">Interop 후보라는 말의 의미</h2>
<p>Interop은 Google, Apple, Microsoft, Mozilla가 Igalia, Bocoup과 함께 해마다 집중할 웹 기술을 정해 브라우저 간 지원을 맞추는 프로젝트입니다<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup>. 어느 해의 집중 영역(focus area)으로 뽑히면 1년 안에 주요 브라우저 지원이 100% 가까이 올라가는 경우가 많습니다<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup>. 서브그리드(subgrid)가 좋은 예입니다. 2019년 Firefox에 먼저 들어갔지만 다른 브라우저는 몇 년간 움직이지 않다가, Interop 2023에 포함된 해 말에 모든 최신 브라우저에서 쓸 수 있게 됐습니다<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup>.</p>
<p>아무 기능이나 후보가 되지는 않습니다. 표준 기구에서 충분히 성숙한 명세가 있어야 하고, WPT(web-platform-tests)나 Test262에 품질 좋은 자동 테스트가 있어야 합니다<sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup>. 그래서 Interop 후보는 명세와 테스트라는 조건을 이미 갖춘 기능이고, 남은 과제는 주로 브라우저 간 구현을 맞추는 일입니다.</p>
<p>2026년 말 현재 Interop 2027 계획이 진행 중이고, Mozilla가 만든 순위 페이지에서 개발자 투표를 받고 있습니다<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup>. 원문 필자 Josh W. Comeau는 자신이 투표한 기능 10개를 소개했습니다<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup>. 이 글은 그중 실무 코드에 바로 영향을 줄 세 가지를 고릅니다. 아직 어느 브라우저에도 없는 <code>inherit()</code> 함수는 필자도 이번에 뽑히기 어렵다고 보고 있어 제외합니다<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup>.</p>
<blockquote>
<p>아래 세 기능은 Interop 2027 <strong>후보</strong>입니다. 최종 포함 여부는 이 글의 자료로 확인되지 않았습니다.</p>
</blockquote>
<h2 id="function-값을-계산해-돌려주는-css-함수">@function — 값을 계산해 돌려주는 CSS 함수</h2>
<p><code>@function</code> 규칙은 CSS 사용자 함수(custom function)를 정의합니다. 이름은 <code>--</code>로 시작하고, 정의한 뒤에는 <code>--my-function(30px, 3)</code>처럼 어떤 속성 값 안에서든 호출할 수 있습니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</p>
<h3 id="기본-형태">기본 형태</h3>
<p>매개변수는 커스텀 속성 이름으로 받고, 돌려줄 값은 <code>result</code> 디스크립터에 씁니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>. 매개변수 뒤에 콜론으로 기본값을 붙일 수 있습니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>. 원문의 그라디언트 예제를 옮기면 다음과 같습니다<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup>.</p>
<pre data-lang="css"><code class="hljs language-css"><span class="hljs-keyword">@function</span> --gradient-to-transparent(--color, <span class="hljs-attribute">--direction</span>: bottom) {
  result: <span class="hljs-built_in">linear-gradient</span>(
    to <span class="hljs-built_in">var</span>(--direction),
    <span class="hljs-built_in">var</span>(--color),
    transparent
  );
}

<span class="hljs-selector-class">.elem</span> {
  <span class="hljs-attribute">background</span>: <span class="hljs-built_in">--gradient-to-transparent</span>(red);
  <span class="hljs-comment">/* → linear-gradient(to bottom, red, transparent) */</span>
}
</code></pre>
<p><code>--direction</code>을 생략했으므로 기본값 <code>bottom</code>이 들어갑니다. 함수 본문 안에서 <code>cos()</code>, <code>sin()</code> 같은 수학 함수도 쓸 수 있어서, 각도와 거리를 받아 이동 값을 만드는 함수도 가능합니다<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup>.</p>
<pre data-lang="css"><code class="hljs language-css"><span class="hljs-keyword">@function</span> --translate-polar(--angle, --distance) {
  result: <span class="hljs-built_in">translate</span>(
    <span class="hljs-built_in">calc</span>(<span class="hljs-built_in">cos</span>(<span class="hljs-built_in">var</span>(--angle)) * <span class="hljs-built_in">var</span>(--distance)),
    <span class="hljs-built_in">calc</span>(<span class="hljs-built_in">sin</span>(<span class="hljs-built_in">var</span>(--angle)) * <span class="hljs-built_in">var</span>(--distance))
  );
}

<span class="hljs-comment">/* 45° 방향으로 100px 이동 */</span>
<span class="hljs-selector-class">.particle</span> {
  <span class="hljs-attribute">transform</span>: <span class="hljs-built_in">--translate-polar</span>(<span class="hljs-number">45deg</span>, <span class="hljs-number">100px</span>);
}
</code></pre>
<h3 id="타입-지정과-지역-변수">타입 지정과 지역 변수</h3>
<p>매개변수 뒤에 <code>&#x3C;color></code>, <code>&#x3C;number></code> 같은 타입을, 괄호 뒤에 <code>returns</code>로 반환 타입을 적을 수 있습니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>. 본문에 선언한 커스텀 속성은 함수 안에서만 쓰는 지역 상수가 됩니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</p>
<pre data-lang="css"><code class="hljs language-css"><span class="hljs-keyword">@function</span> --transparent(--color &#x3C;<span class="hljs-attribute">color</span>>, --alpha &#x3C;number>: <span class="hljs-number">0.8</span>)
  returns &#x3C;<span class="hljs-attribute">color</span>> {
  result: <span class="hljs-built_in">oklch</span>(from <span class="hljs-built_in">var</span>(--color) l c h / <span class="hljs-built_in">var</span>(--alpha));
}

<span class="hljs-selector-tag">section</span> {
  <span class="hljs-attr">--base-color</span>: <span class="hljs-number">#faa6ff</span>;
  <span class="hljs-attribute">background-color</span>: <span class="hljs-built_in">--transparent</span>(<span class="hljs-built_in">var</span>(--base-color));
  <span class="hljs-comment">/* --alpha 생략 → 0.8 */</span>
}
</code></pre>
<p>함수는 호출한 요소에 선언된 커스텀 속성도 읽습니다. 이름이 겹치면 함수 본문의 지역 속성이 가장 우선이고, 그다음이 매개변수, 마지막이 요소의 커스텀 속성입니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</p>
<h3 id="주의점">주의점</h3>
<ul>
<li><strong>타입이 틀리면 값이 사라집니다.</strong> 위 함수의 <code>--alpha</code>를 기본값 없이 <code>&#x3C;number></code>로만 선언하고 <code>50%</code>를 넘기면, 값은 계산값 시점에 무효가 되고 <code>background-color</code>는 <code>transparent</code>가 됩니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>. 퍼센트도 받으려면 <code>type(&#x3C;number> | &#x3C;percentage>)</code>처럼 씁니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</li>
<li><strong>쉼표가 든 값은 중괄호로 감쌉니다.</strong> <code>--max-plus-x({1px, 7px, 2px}, 3px)</code>처럼 감싸지 않으면 쉼표가 인자 구분자로 읽힙니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</li>
<li><strong>같은 이름은 캐스케이드로 정해집니다.</strong> 이름이 같은 함수가 여럿이면 더 강한 <code>@layer</code>의 것이, 같은 레이어면 나중에 정의한 것이 이깁니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</li>
<li><strong>지원 범위가 좁습니다.</strong> web-features 기준 Chrome·Edge 139부터 지원하고 Firefox·Safari는 미지원이며, MDN도 실험적 기능으로 표시합니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup><sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup>. Interop 제안 이슈에는 Safari Technology Preview 249에 들어갔다고 적혀 있습니다<sup class="cite"><a href="#source-7" aria-label="출처 7">[7]</a></sup>. 디자인 토큰 계산처럼 빠지면 화면이 깨지는 곳에는 아직 이릅니다.</li>
</ul>
<h2 id="corner-shape-둥근-모서리-말고-다른-모서리">corner-shape — 둥근 모서리 말고 다른 모서리</h2>
<p><code>corner-shape</code>는 <code>border-radius</code>가 차지하는 영역 안에서 모서리의 모양을 정하는 단축 속성입니다<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup>. 기본값 <code>round</code>는 지금의 둥근 모서리와 같고, <code>scoop</code>, <code>bevel</code>, <code>notch</code>, <code>square</code>, <code>squircle</code>, 그리고 <code>superellipse()</code> 함수를 쓸 수 있습니다<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup>.</p>
<pre data-lang="css"><code class="hljs language-css"><span class="hljs-selector-class">.box</span> {
  <span class="hljs-attribute">border-radius</span>: <span class="hljs-number">16px</span>;

  &#x26;<span class="hljs-selector-class">.squircle</span> { corner-shape: squircle; } <span class="hljs-comment">/* 부드러운 둥근 사각 */</span>
  &#x26;<span class="hljs-selector-class">.bevel</span> { corner-shape: bevel; }       <span class="hljs-comment">/* 모서리를 비스듬히 자름 */</span>
  &#x26;<span class="hljs-selector-class">.notch</span> { corner-shape: notch; }
  &#x26;<span class="hljs-selector-class">.scoop</span> { corner-shape: scoop; }       <span class="hljs-comment">/* 안쪽으로 둥글게 파임 */</span>
}
</code></pre>
<p><code>bevel</code>은 <code>border-radius</code> 양 끝을 직선으로 잇습니다<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup>. 원문 필자는 처음엔 <code>squircle</code>에 끌렸지만 실제로는 게임·SF풍 UI에 <code>bevel</code>을 가장 많이 쓴다고 말합니다<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup>.</p>
<h3 id="clip-path와-다른-점">clip-path와 다른 점</h3>
<p>모서리를 깎는 일은 이전에도 <code>clip-path</code>나 마스크로 할 수 있었습니다. 차이는 <code>corner-shape</code>가 보더 박스 자체의 모양을 바꾼다는 점입니다<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup>. 그래서 <code>border</code>, <code>outline</code>, <code>box-shadow</code>, <code>overflow</code>, <code>backdrop-filter</code>, 배경이 모두 바뀐 모양을 따라갑니다<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup>.</p>
<pre data-lang="css"><code class="hljs language-css"><span class="hljs-selector-class">.card</span> {
  <span class="hljs-attribute">border</span>: <span class="hljs-number">2px</span> solid black;
  <span class="hljs-attribute">border-radius</span>: <span class="hljs-number">20px</span>;
  corner-shape: bevel;
  <span class="hljs-attribute">box-shadow</span>: <span class="hljs-number">4px</span> <span class="hljs-number">4px</span> <span class="hljs-number">0</span> black; <span class="hljs-comment">/* 그림자도 깎인 모서리를 따라감 */</span>
}
</code></pre>
<p>값은 1~4개를 줄 수 있고, 네 개면 왼쪽 위부터 시계 방향으로 적용됩니다<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup>. 키워드 사이는 <code>superellipse()</code> 값으로 보간되어 부드럽게 애니메이션됩니다<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup>.</p>
<h3 id="주의점-1">주의점</h3>
<ul>
<li><strong><code>border-radius</code>가 없으면 아무 일도 없습니다.</strong> 반지름이 0이면 <code>corner-shape</code>는 효과가 없습니다<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup>.</li>
<li><strong>마주 보는 모서리가 겹치면 브라우저가 줄입니다.</strong> 큰 반지름에 <code>scoop</code>처럼 안쪽으로 파는 값을 주면 겹치지 않게 반지름이 조정됩니다<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup>.</li>
<li><strong>클릭 영역은 모양을 따르지 않을 수 있습니다.</strong> MDN 예제는 <code>:hover</code>로 클릭 가능한 영역이 모서리 모양 밖까지 걸친다는 점을 보여 줍니다<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup>.</li>
<li><strong><code>border-shape</code>와 함께 쓰면 무시됩니다.</strong> <code>border-shape</code>가 설정되면 <code>border-radius</code>가 무시되고, 그에 의존하는 <code>corner-shape</code>도 효과가 없습니다<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup>.</li>
</ul>
<p>지원은 Chrome·Edge 139부터이고 Firefox·Safari는 미지원입니다<sup class="cite"><a href="#source-8" aria-label="출처 8">[8]</a></sup><sup class="cite"><a href="#source-9" aria-label="출처 9">[9]</a></sup>. 미지원 브라우저는 속성을 무시하고 <code>border-radius</code>의 둥근 모서리를 그대로 그리므로, 원문 필자는 지금 써도 되는 점진적 향상(progressive enhancement)이라고 봅니다<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup>.</p>

<h2 id="앵커드-컨테이너-쿼리-툴팁이-뒤집혔는지-알기">앵커드 컨테이너 쿼리 — 툴팁이 뒤집혔는지 알기</h2>
<p>앵커 위치 지정(Anchor Positioning)은 툴팁 같은 요소를 다른 요소에 붙여 두는 API로, Interop 2026에서 우선순위를 받아 지금은 널리 사용 가능합니다<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup>. 툴팁이 위쪽 공간이 부족하면 <code>position-try-fallbacks</code>로 아래로 뒤집을 수 있습니다<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup>. 빠져 있던 것은 "지금 뒤집혔는가"를 CSS에서 아는 방법이었습니다. 그래서 앵커를 가리키는 작은 화살표 방향을 바꿀 수 없었습니다<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup>.</p>
<h3 id="두-가지-조각">두 가지 조각</h3>
<p>앵커드 컨테이너 쿼리(anchored container query)는 두 기능으로 이뤄집니다. 위치 지정 요소에 <code>container-type: anchored</code>를 주고, <code>@container anchored(fallback: …)</code>로 어떤 대체 위치가 적용됐는지 검사합니다<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup>. <code>fallback</code>에는 <code>position-try-fallbacks</code>에 쓴 값을 그대로 씁니다<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup>.</p>
<pre data-lang="css"><code class="hljs language-css"><span class="hljs-selector-class">.anchor</span> {
  <span class="hljs-attribute">anchor-name</span>: --my-anchor;
}

<span class="hljs-selector-class">.infobox</span> {
  <span class="hljs-attribute">position</span>: fixed;
  <span class="hljs-attribute">position-anchor</span>: --my-anchor;
  <span class="hljs-attribute">position</span>-area: top;            <span class="hljs-comment">/* 기본: 앵커 위 */</span>
  <span class="hljs-attribute">position</span>-try-fallbacks: bottom; <span class="hljs-comment">/* 위가 넘치면 아래로 */</span>
  <span class="hljs-attribute">container-type</span>: anchored;
}

<span class="hljs-selector-class">.infobox</span><span class="hljs-selector-pseudo">::before</span> {
  <span class="hljs-attribute">content</span>: <span class="hljs-string">"▼"</span>;   <span class="hljs-comment">/* 기본: 아래를 가리키는 화살표 */</span>
  <span class="hljs-attribute">position</span>: absolute;
  <span class="hljs-attribute">top</span>: <span class="hljs-number">105%</span>;
}

<span class="hljs-keyword">@container</span> anchored(<span class="hljs-attribute">fallback</span>: bottom) {
  <span class="hljs-selector-class">.infobox</span><span class="hljs-selector-pseudo">::before</span> {
    <span class="hljs-attribute">content</span>: <span class="hljs-string">"▲"</span>; <span class="hljs-comment">/* 아래로 옮겨지면 위를 가리킴 */</span>
    <span class="hljs-attribute">bottom</span>: <span class="hljs-number">100%</span>;
    <span class="hljs-attribute">top</span>: auto;
  }
}
</code></pre>
<p>스크롤을 올려 정보 상자가 화면 위로 넘치기 시작하면 앵커 아래로 옮겨지고, 그때만 쿼리 안의 스타일이 적용됩니다<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup><sup class="cite"><a href="#source-10" aria-label="출처 10">[10]</a></sup>.</p>
<h3 id="주의점-2">주의점</h3>
<ul>
<li><strong>컨테이너 자신은 바꿀 수 없습니다.</strong> 모든 컨테이너 쿼리처럼 스타일은 자손에게만 적용됩니다<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup>. 위 예제가 <code>.infobox</code>가 아니라 <code>::before</code>를 바꾸는 이유입니다. 배경이나 모서리 반지름처럼 상자 자체를 바꾸려면 안쪽에 감싸는 요소를 하나 두고 그 요소를 꾸밉니다<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup>.</li>
<li><strong>미지원 브라우저 처리를 따로 둡니다.</strong> MDN 예제는 <code>@supports not (container-type: anchored)</code>로 지원 여부를 나눕니다<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup>. 미지원 브라우저에서는 툴팁이 뒤집혀도 화살표가 아래를 가리키므로, 이 블록 안에서 화살표를 숨기는 편이 안전합니다.</li>
<li><strong>지원 범위.</strong> Chrome·Edge 143부터 지원하고 Firefox·Safari는 미지원입니다<sup class="cite"><a href="#source-11" aria-label="출처 11">[11]</a></sup>. 명세는 CSS 앵커 위치 지정 모듈 레벨 2에 있습니다<sup class="cite"><a href="#source-11" aria-label="출처 11">[11]</a></sup>.</li>
</ul>
