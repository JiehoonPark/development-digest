18:T5c22,<h2 id="브라우저가-화면-전환을-그리는-방식">브라우저가 화면 전환을 그리는 방식</h2>
<p>View Transition API(뷰 전환 API)는 SPA의 DOM 상태 사이, 또는 MPA의 문서 사이를 애니메이션으로 잇는 브라우저 기능입니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup> React의 <code>&#x3C;ViewTransition></code>이 이 API 위에서 동작하므로<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>, 브라우저 쪽 동작을 먼저 알아야 합니다.</p>
<h3 id="스냅숏-두-장과-교차-페이드">스냅숏 두 장과 교차 페이드</h3>
<p>뷰 전환은 "바뀌기 전 화면"과 "바뀐 뒤 화면"을 각각 스냅숏으로 찍고, 둘 사이를 애니메이션으로 잇는 방식입니다. 순서는 다음과 같습니다.<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup></p>
<ol>
<li>이전 화면에서 <code>view-transition-name</code>이 지정된 요소의 정적 이미지 스냅숏을 찍습니다.</li>
<li>콜백을 실행해 DOM을 바꿉니다.</li>
<li>새 화면의 "라이브" 스냅숏을 잡습니다. 이 영역은 바로 상호작용할 수 있습니다.</li>
<li>기본값으로 이전 스냅숏은 불투명도 1→0, 새 스냅숏은 0→1로 움직여 교차 페이드(cross-fade)가 됩니다.</li>
</ol>
<p>같은 문서 안에서의 전환은 <code>document.startViewTransition()</code>으로 시작합니다.<sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup></p>
<pre data-lang="js"><code class="hljs language-js"><span class="hljs-keyword">const</span> <span class="hljs-title function_">changeColor</span> = (<span class="hljs-params"></span>) => {
  <span class="hljs-comment">// 지원하지 않는 브라우저: 애니메이션 없이 바로 변경</span>
  <span class="hljs-keyword">if</span> (!<span class="hljs-variable language_">document</span>.<span class="hljs-property">startViewTransition</span>) {
    <span class="hljs-title function_">updateColor</span>();
    <span class="hljs-keyword">return</span>;
  }
  <span class="hljs-comment">// 지원하는 브라우저: 스냅숏 → updateColor() → 교차 페이드</span>
  <span class="hljs-variable language_">document</span>.<span class="hljs-title function_">startViewTransition</span>(<span class="hljs-function">() =></span> {
    <span class="hljs-title function_">updateColor</span>();
  });
};
</code></pre>
<p><code>startViewTransition()</code>은 MDN 기준 2025년 10월부터 Baseline 신규(Newly available) 단계입니다.<sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup></p>
<h3 id="의사-요소로-애니메이션-고르기">의사 요소로 애니메이션 고르기</h3>
<p>전환이 진행되는 동안 브라우저는 <code>::view-transition</code>을 뿌리로 하는 의사 요소(pseudo-element) 트리를 페이지 위에 덮습니다. 이름마다 <code>::view-transition-group()</code>이 생기고, 그 안에 <code>::view-transition-old()</code>(이전 화면)와 <code>::view-transition-new()</code>(새 화면)가 들어갑니다.<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup> 애니메이션을 바꾸려면 이 두 의사 요소에 CSS <code>animation</code>을 지정합니다.</p>
<pre data-lang="css"><code class="hljs language-css">::<span class="hljs-built_in">view-transition-old</span>(*) {
  <span class="hljs-attribute">animation</span>: <span class="hljs-number">300ms</span> ease-out fade-out; <span class="hljs-comment">/* 모든 이전 화면 */</span>
}
::<span class="hljs-built_in">view-transition-new</span>(*) {
  <span class="hljs-attribute">animation</span>: <span class="hljs-number">300ms</span> ease-in fade-in;   <span class="hljs-comment">/* 모든 새 화면 */</span>
}
</code></pre>
<p><code>*</code>는 모든 전환의 기본 애니메이션을 한 번에 바꿉니다.<sup class="cite"><a href="#source-7" aria-label="출처 7">[7]</a></sup> 순수 DOM으로 직접 하려면 어떤 요소에 언제 이름을 붙이고 뗄지를 모두 관리해야 합니다.</p>
<h2 id="viewtransition-무엇을-언제-어떻게"><code>&#x3C;ViewTransition></code>: 무엇을, 언제, 어떻게</h2>
<p><code>&#x3C;ViewTransition></code>은 애니메이션할 부분을 감싸는 컴포넌트입니다. 감싼 트리가 추가·제거되거나 모양이 바뀌면 React가 브라우저 뷰 전환으로 애니메이션합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>
<h3 id="언제-transition-업데이트만-움직인다">언제: Transition 업데이트만 움직인다</h3>

<h4>자주 하는 실수: 직접 <code>startViewTransition</code> 부르기</h4>
<p>내부에서 React는 감싼 트리의 가장 가까운 DOM 노드에 인라인 스타일로 <code>view-transition-name</code>을 붙이고, <code>startViewTransition</code>도 직접 호출합니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup> 그래서 앱 코드에서 따로 부르면 안 되고, 다른 코드가 뷰 전환을 실행 중이면 React가 그것을 중단합니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup></p>
<p>중간에 <code>flushSync</code>가 끼어들면 React는 그 전환을 건너뜁니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup> 애니메이션이 안 보이면 Transition 여부와 <code>flushSync</code>부터 확인합니다.</p>

</code></pre>
<p>React는 이 타입을 브라우저 뷰 전환 타입으로도 넘기므로, CSS의 <code>:active-view-transition-type()</code>으로도 범위를 나눌 수 있습니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup><sup class="cite"><a href="#source-8" aria-label="출처 8">[8]</a></sup> 타입 하나라도 값이 <code>"none"</code>이면 그 경계는 애니메이션하지 않습니다.<sup class="cite"><a href="#source-8" aria-label="출처 8">[8]</a></sup> 타입은 커밋마다 초기화되므로, <code>&#x3C;Suspense></code> 폴백에는 붙지만 이후 내용 공개에는 붙지 않습니다.<sup class="cite"><a href="#source-8" aria-label="출처 8">[8]</a></sup></p>
<h3 id="공유-요소와-name">공유 요소와 <code>name</code></h3>
<p>목록의 썸네일이 상세 페이지의 큰 이미지로 이어지는 효과는 양쪽 <code>&#x3C;ViewTransition></code>에 같은 <code>name</code>을 주면 됩니다.<sup class="cite"><a href="#source-7" aria-label="출처 7">[7]</a></sup></p>
<pre data-lang="jsx"><code class="hljs language-jsx">&#x3C;<span class="hljs-title class_">ViewTransition</span> name={<span class="hljs-string">`video-<span class="hljs-subst">${video.id}</span>`</span>}>
  <span class="xml"><span class="hljs-tag">&#x3C;<span class="hljs-name">Thumbnail</span> <span class="hljs-attr">video</span>=<span class="hljs-string">{video}</span> /></span></span>
&#x3C;/<span class="hljs-title class_">ViewTransition</span>>
</code></pre>
<p><code>name</code>은 공유 요소 전환에만 씁니다. 나머지는 React가 고유한 이름을 자동으로 만듭니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup> 같은 이름이 동시에 두 개 마운트되면 오류가 납니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup></p>
<h3 id="suspense와-함께-쓸-때">Suspense와 함께 쓸 때</h3>
<p><code>&#x3C;Suspense></code>를 감싸면 폴백에서 실제 내용으로 바뀌는 순간을 애니메이션합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 다만 그대로 두면 이미 불러온 내용도 다시 열 때마다 움직입니다. 원문은 폴백은 즉시 보이고, 폴백→내용 전환만 애니메이션하도록 <code>update</code>만 남기는 방법을 권합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>
<pre data-lang="jsx"><code class="hljs language-jsx">&#x3C;<span class="hljs-title class_">ViewTransition</span> update=<span class="hljs-string">"auto"</span> <span class="hljs-keyword">default</span>=<span class="hljs-string">"none"</span>>
  <span class="xml"><span class="hljs-tag">&#x3C;<span class="hljs-name">Suspense</span> <span class="hljs-attr">fallback</span>=<span class="hljs-string">{</span>&#x3C;<span class="hljs-attr">Fallback</span> /></span>}>
    <span class="hljs-tag">&#x3C;<span class="hljs-name">Component</span> /></span>
  <span class="hljs-tag">&#x3C;/<span class="hljs-name">Suspense</span>></span></span>
&#x3C;/<span class="hljs-title class_">ViewTransition</span>>
<span class="hljs-comment">// 폴백: 애니메이션 없이 즉시 표시</span>
<span class="hljs-comment">// 폴백 → 내용: update 애니메이션</span>
</code></pre>
<p><code>&#x3C;ViewTransition></code> 안의 이미지와 폰트는 불러오는 동안 Suspense를 일으키므로, 늦게 깜빡이며 나타나는 대신 모두 준비된 뒤 한 번에 보여 줄 수 있습니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>
<h4>주의점: 움직임 줄이기 설정</h4>
<p>React는 <code>prefers-reduced-motion</code> 사용자를 위해 애니메이션을 자동으로 끄지 않습니다. 문서는 미디어 쿼리로 직접 끄거나 줄이라고 권합니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup></p>
<pre data-lang="css"><code class="hljs language-css"><span class="hljs-keyword">@media</span> (<span class="hljs-attribute">prefers-reduced-motion</span>: reduce) {
  ::<span class="hljs-built_in">view-transition-old</span>(*),
  ::<span class="hljs-built_in">view-transition-new</span>(*) {
    <span class="hljs-attribute">animation</span>: none;
  }
}
</code></pre>
<p>현재 <code>&#x3C;ViewTransition></code>은 DOM에서만 동작합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 또 뷰 전환은 화면 전환·펼치기·순서 변경 같은 UI 전환용이고, 좋아요 버튼처럼 특정 요소 하나를 움직이는 효과는 CSS 애니메이션이 더 맞습니다.<sup class="cite"><a href="#source-7" aria-label="출처 7">[7]</a></sup></p>
<aside class="poster" aria-label="애니메이션이 안 보이면 startTransition부터 확인"><span class="poster-line" aria-hidden="true">애니메이션이 안 보이면</span><span class="poster-line poster-accent" aria-hidden="true">startTransition부터 확인</span></aside>
<h2 id="fragment-ref-래퍼-없이-dom-다루기">Fragment ref: 래퍼 없이 DOM 다루기</h2>
<p>형제 요소 여러 개를 부모 없이 렌더링하거나 <code>ref</code>를 넘겨주지 않는 컴포넌트에는 <code>ref</code>를 걸 곳이 없습니다. 래퍼 <code>&#x3C;div></code>를 넣으면 스타일과 레이아웃이 깨질 수 있습니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 19.3부터는 <code>&#x3C;Fragment></code>에 <code>ref</code>를 직접 넘길 수 있고, React는 <code>FragmentInstance</code>를 줍니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup><sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></p>
<h3 id="fragmentinstance가-하는-일"><code>FragmentInstance</code>가 하는 일</h3>
<p><code>FragmentInstance</code>는 DOM 구조를 바꾸지 않고 Fragment의 자식들을 한 묶음으로 다룹니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 메서드마다 대상 범위가 다르다는 점이 핵심입니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></p>

<p><code>IntersectionObserver</code>를 붙여 자식이 화면에 들어왔는지 알리는 컴포넌트는 이렇게 만듭니다.</p>

<p>포커스는 범위가 다릅니다. <code>fragmentRef.current.focus()</code>는 자식을 깊이 우선으로 훑어 처음 만나는 포커스 가능한 요소에, <code>focusLast()</code>는 마지막 요소에 포커스를 줍니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></p>
<h3 id="자주-하는-실수">자주 하는 실수</h3>
<ul>
<li><strong>단축 문법에 <code>ref</code> 넘기기</strong>: <code>&#x3C;>...&#x3C;/></code>에는 <code>ref</code>를 줄 수 없습니다. <code>Fragment</code>를 import해 <code>&#x3C;Fragment ref={...}></code>로 씁니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></li>
<li><strong>손자 요소까지 이벤트가 붙는다고 생각하기</strong>: 이벤트·옵저버 메서드는 첫 단계 DOM 자식만 대상으로 합니다. 다른 DOM 요소 안에 중첩된 요소는 직접 대상이 아닙니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></li>
<li><strong><code>scrollIntoView</code>에 옵션 객체 넘기기</strong>: <code>Element.scrollIntoView()</code>와 달리 옵션 객체를 받지 않고, 넘기면 오류가 납니다. <code>true</code>/<code>false</code>만 씁니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></li>
<li><strong>텍스트만 감싸기</strong>: <code>observeUsing</code>은 텍스트 노드에서 동작하지 않습니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></li>
</ul>
