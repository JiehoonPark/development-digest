React ViewTransition과 Fragment ref — 브라우저 API부터 실전까지

React 19.3에서 정식이 된 <ViewTransition>과 Fragment ref를 실제 코드에 넣는 방법을 다룹니다. 브라우저 View Transition API가 화면을 어떻게 바꾸는지부터 시작해, React가 그 위에서 무엇을 대신해 주는지 짚습니다.

요약

  • React 19.3에서 <ViewTransition>과 Fragment ref가 실험 단계를 벗어나 안정(stable) API가 됐습니다.[1]
  • <ViewTransition>은 startTransition, useDeferredValue, <Suspense> 공개처럼 Transition으로 표시된 업데이트에서만 애니메이션을 실행하고, 일반 setState로는 움직이지 않습니다.[1][2]
  • React가 view-transition-name 지정과 startViewTransition 호출을 직접 하므로, 앱 코드에서 document.startViewTransition을 따로 부르면 안 됩니다.[2]
  • <Fragment ref>가 주는 FragmentInstance로 래퍼 <div> 없이 자식 DOM에 이벤트·포커스·옵저버를 붙일 수 있습니다.[3]

브라우저가 화면 전환을 그리는 방식

View Transition API(뷰 전환 API)는 SPA의 DOM 상태 사이, 또는 MPA의 문서 사이를 애니메이션으로 잇는 브라우저 기능입니다.[4] React의 <ViewTransition>이 이 API 위에서 동작하므로[1], 브라우저 쪽 동작을 먼저 알아야 합니다.

스냅숏 두 장과 교차 페이드

뷰 전환은 "바뀌기 전 화면"과 "바뀐 뒤 화면"을 각각 스냅숏으로 찍고, 둘 사이를 애니메이션으로 잇는 방식입니다. 순서는 다음과 같습니다.[5]

  1. 이전 화면에서 view-transition-name이 지정된 요소의 정적 이미지 스냅숏을 찍습니다.
  2. 콜백을 실행해 DOM을 바꿉니다.
  3. 새 화면의 "라이브" 스냅숏을 잡습니다. 이 영역은 바로 상호작용할 수 있습니다.
  4. 기본값으로 이전 스냅숏은 불투명도 1→0, 새 스냅숏은 0→1로 움직여 교차 페이드(cross-fade)가 됩니다.

같은 문서 안에서의 전환은 document.startViewTransition()으로 시작합니다.[6]

const changeColor = () => {
  // 지원하지 않는 브라우저: 애니메이션 없이 바로 변경
  if (!document.startViewTransition) {
    updateColor();
    return;
  }
  // 지원하는 브라우저: 스냅숏 → updateColor() → 교차 페이드
  document.startViewTransition(() => {
    updateColor();
  });
};

startViewTransition()은 MDN 기준 2025년 10월부터 Baseline 신규(Newly available) 단계입니다.[6]

의사 요소로 애니메이션 고르기

전환이 진행되는 동안 브라우저는 ::view-transition을 뿌리로 하는 의사 요소(pseudo-element) 트리를 페이지 위에 덮습니다. 이름마다 ::view-transition-group()이 생기고, 그 안에 ::view-transition-old()(이전 화면)와 ::view-transition-new()(새 화면)가 들어갑니다.[5] 애니메이션을 바꾸려면 이 두 의사 요소에 CSS animation을 지정합니다.

::view-transition-old(*) {
  animation: 300ms ease-out fade-out; /* 모든 이전 화면 */
}
::view-transition-new(*) {
  animation: 300ms ease-in fade-in;   /* 모든 새 화면 */
}

*는 모든 전환의 기본 애니메이션을 한 번에 바꿉니다.[7] 순수 DOM으로 직접 하려면 어떤 요소에 언제 이름을 붙이고 뗄지를 모두 관리해야 합니다.

<ViewTransition>: 무엇을, 언제, 어떻게

<ViewTransition>은 애니메이션할 부분을 감싸는 컴포넌트입니다. 감싼 트리가 추가·제거되거나 모양이 바뀌면 React가 브라우저 뷰 전환으로 애니메이션합니다.[1]

언제: Transition 업데이트만 움직인다

startTransition 안의 상태 업데이트, <Suspense>의 내용 공개, useDeferredValue의 업데이트만 애니메이션을 일으킵니다.[1] 일반 setState는 급한 업데이트로 보고 즉시 반영합니다.[2]

import { ViewTransition, useState, startTransition } from 'react';

function Toggle() {
  const [showItem, setShowItem] = useState(false);
  return (
    <>
      <button onClick={() => {
        startTransition(() => setShowItem((prev) => !prev));
      }}>토글</button>
      {showItem && (
        <ViewTransition>
          <Video />
        </ViewTransition>
      )}
    </>
  );
}
// 버튼 클릭 → <ViewTransition> 추가(enter) 또는 제거(exit)
// 결과: 브라우저 기본 교차 페이드로 나타나고 사라짐

React는 트리가 바뀐 모양을 보고 네 가지 중 하나를 고릅니다.[1][2]

종류 언제
enter <ViewTransition>이 새로 추가됨
exit <ViewTransition>이 제거됨
update 안쪽 DOM이 바뀌거나 경계 자체의 크기·위치가 바뀜
share 같은 name이 한 곳에서 빠지고 다른 곳에 추가됨

자주 하는 실수: 직접 startViewTransition 부르기

내부에서 React는 감싼 트리의 가장 가까운 DOM 노드에 인라인 스타일로 view-transition-name을 붙이고, startViewTransition도 직접 호출합니다.[2] 그래서 앱 코드에서 따로 부르면 안 되고, 다른 코드가 뷰 전환을 실행 중이면 React가 그것을 중단합니다.[2]

중간에 flushSync가 끼어들면 React는 그 전환을 건너뜁니다.[2] 애니메이션이 안 보이면 Transition 여부와 flushSync부터 확인합니다.

어떻게: View Transition Class와 CSS

enter, exit, update, share, default 속성에 클래스 이름을 넘기면, 그 클래스를 의사 요소 선택자에 쓸 수 있습니다. 값은 "auto"(브라우저 기본), "none"(끔), 클래스 이름, 또는 객체입니다.[2]

<ViewTransition default="slow-fade">
  <Home />
</ViewTransition>

::view-transition-old(.slow-fade) {
  animation-duration: 500ms;
}
::view-transition-new(.slow-fade) {
  animation-duration: 500ms;
}
/* 결과: 기본 교차 페이드가 500ms로 느려짐 */

default="none"을 주면 따로 적은 종류를 빼고는 모두 꺼집니다.[2]

원인에 따라 다르게: addTransitionType

캐러셀의 "다음"과 "이전"은 방향이 반대여야 합니다. 이럴 때 startTransition 안에서 addTransitionType으로 원인을 적습니다.[1] 타입은 아무 문자열이나 쓸 수 있습니다.[8]

function nextSlide() {
  startTransition(() => {
    addTransitionType('next');
    setCurrentSlide(c => c + 1);
  });
}

<ViewTransition
  enter={{ 'next': 'from-right', 'previous': 'from-left' }}
  exit={{ 'next': 'to-left', 'previous': 'to-right' }}
>
  <Page />
</ViewTransition>
// 'next' 타입 → 새 슬라이드는 from-right, 이전 슬라이드는 to-left

React는 이 타입을 브라우저 뷰 전환 타입으로도 넘기므로, CSS의 :active-view-transition-type()으로도 범위를 나눌 수 있습니다.[1][8] 타입 하나라도 값이 "none"이면 그 경계는 애니메이션하지 않습니다.[8] 타입은 커밋마다 초기화되므로, <Suspense> 폴백에는 붙지만 이후 내용 공개에는 붙지 않습니다.[8]

공유 요소와 name

목록의 썸네일이 상세 페이지의 큰 이미지로 이어지는 효과는 양쪽 <ViewTransition>에 같은 name을 주면 됩니다.[7]

<ViewTransition name={`video-${video.id}`}>
  <Thumbnail video={video} />
</ViewTransition>

name은 공유 요소 전환에만 씁니다. 나머지는 React가 고유한 이름을 자동으로 만듭니다.[2] 같은 이름이 동시에 두 개 마운트되면 오류가 납니다.[2]

Suspense와 함께 쓸 때

<Suspense>를 감싸면 폴백에서 실제 내용으로 바뀌는 순간을 애니메이션합니다.[1] 다만 그대로 두면 이미 불러온 내용도 다시 열 때마다 움직입니다. 원문은 폴백은 즉시 보이고, 폴백→내용 전환만 애니메이션하도록 update만 남기는 방법을 권합니다.[1]

<ViewTransition update="auto" default="none">
  <Suspense fallback={<Fallback />}>
    <Component />
  </Suspense>
</ViewTransition>
// 폴백: 애니메이션 없이 즉시 표시
// 폴백 → 내용: update 애니메이션

<ViewTransition> 안의 이미지와 폰트는 불러오는 동안 Suspense를 일으키므로, 늦게 깜빡이며 나타나는 대신 모두 준비된 뒤 한 번에 보여 줄 수 있습니다.[1]

주의점: 움직임 줄이기 설정

React는 prefers-reduced-motion 사용자를 위해 애니메이션을 자동으로 끄지 않습니다. 문서는 미디어 쿼리로 직접 끄거나 줄이라고 권합니다.[2]

@media (prefers-reduced-motion: reduce) {
  ::view-transition-old(*),
  ::view-transition-new(*) {
    animation: none;
  }
}

현재 <ViewTransition>은 DOM에서만 동작합니다.[1] 또 뷰 전환은 화면 전환·펼치기·순서 변경 같은 UI 전환용이고, 좋아요 버튼처럼 특정 요소 하나를 움직이는 효과는 CSS 애니메이션이 더 맞습니다.[7]

애니메이션이 안 보이면startTransition부터 확인

Fragment ref: 래퍼 없이 DOM 다루기

형제 요소 여러 개를 부모 없이 렌더링하거나 ref를 넘겨주지 않는 컴포넌트에는 ref를 걸 곳이 없습니다. 래퍼 <div>를 넣으면 스타일과 레이아웃이 깨질 수 있습니다.[1] 19.3부터는 <Fragment>에 ref를 직접 넘길 수 있고, React는 FragmentInstance를 줍니다.[1][3]

FragmentInstance가 하는 일

FragmentInstance는 DOM 구조를 바꾸지 않고 Fragment의 자식들을 한 묶음으로 다룹니다.[1] 메서드마다 대상 범위가 다르다는 점이 핵심입니다.[3]

메서드 대상
addEventListener, removeEventListener 첫 단계 DOM 자식 전부
observeUsing, unobserveUsing 첫 단계 DOM 자식 전부
getClientRects 첫 단계 DOM 자식의 사각형 배열
focus, focusLast, blur 중첩된 자식까지 깊이 우선 탐색
scrollIntoView 첫 자식(또는 마지막 자식)으로 스크롤

IntersectionObserver를 붙여 자식이 화면에 들어왔는지 알리는 컴포넌트는 이렇게 만듭니다.

import { Fragment, useRef, useEffect } from 'react';

function InView({ onChange, children }) {
  const fragmentRef = useRef(null);
  useEffect(() => {
    const fragment = fragmentRef.current;
    const observer = new IntersectionObserver((entries) => {
      onChange(entries.some((entry) => entry.isIntersecting));
    });
    fragment.observeUsing(observer);
    return () => {
      fragment.unobserveUsing(observer);
      observer.disconnect();
    };
  }, [onChange]);
  return <Fragment ref={fragmentRef}>{children}</Fragment>;
}
// 자식 중 하나라도 화면에 보이면 onChange(true)
// DOM에는 래퍼 요소가 추가되지 않음

포커스는 범위가 다릅니다. fragmentRef.current.focus()는 자식을 깊이 우선으로 훑어 처음 만나는 포커스 가능한 요소에, focusLast()는 마지막 요소에 포커스를 줍니다.[3]

자주 하는 실수

  • 단축 문법에 ref 넘기기: <>...</>에는 ref를 줄 수 없습니다. Fragment를 import해 <Fragment ref={...}>로 씁니다.[3]
  • 손자 요소까지 이벤트가 붙는다고 생각하기: 이벤트·옵저버 메서드는 첫 단계 DOM 자식만 대상으로 합니다. 다른 DOM 요소 안에 중첩된 요소는 직접 대상이 아닙니다.[3]
  • scrollIntoView에 옵션 객체 넘기기: Element.scrollIntoView()와 달리 옵션 객체를 받지 않고, 넘기면 오류가 납니다. true/false만 씁니다.[3]
  • 텍스트만 감싸기: observeUsing은 텍스트 노드에서 동작하지 않습니다.[3]

정리

하고 싶은 것 쓸 것
나타남·사라짐 애니메이션 <ViewTransition> + startTransition
애니메이션 바꾸기 enter·exit·update·default 클래스 + ::view-transition-new(.클래스)
방향·원인별 애니메이션 addTransitionType + 객체 값
목록→상세 이어지는 요소 양쪽에 같은 name
Suspense 폴백→내용만 update="auto" default="none"
래퍼 없이 이벤트·옵저버·포커스 <Fragment ref> → FragmentInstance

<ViewTransition>은 이름 지정과 전환 시작을 React에 맡기고, Fragment ref는 DOM 구조를 바꾸지 않고 자식에 동작을 붙입니다.

래퍼 div 대신Fragment ref

프론트엔드 팀이 해 볼 것

  1. 프로젝트에서 startTransition으로 감싼 라우팅이나 토글 하나를 골라 <ViewTransition>으로 감싸고, 기본 교차 페이드가 나오는지 확인하기
  2. 전역 CSS에 prefers-reduced-motion 규칙을 추가해 ::view-transition-old(*), ::view-transition-new(*) 애니메이션 끄기
  3. ref만을 위해 넣어 둔 래퍼 <div>를 검색해 <Fragment ref>로 바꿀 수 있는지 검토하기
