767.98px은 이제 그만 — 미디어 쿼리 범위 문법 정리

Bootstrap 소스에 남아 있는 767.98px은 경계가 겹치는 문제를 피하려던 우회책입니다. 왜 그런 숫자가 필요했는지부터, 범위 문법으로 바꾸는 방법, 컨테이너 쿼리와 Tailwind v4에서의 쓰임, 실제로 바꿀 때 확인할 것까지 정리했습니다.

요약

  • min-width와 max-width는 둘 다 경계값을 포함해서, 같은 숫자를 쓰면 경계에서 두 규칙이 겹친다
  • Bootstrap의 767.98px은 겹침을 피하려고 0.02px를 뺀 값이고, 소수점 너비에서는 여전히 빈틈이 남는다[2]
  • width < 768px과 width >= 768px로 쓰면 빈틈도 겹침도 없다 — 2025년 9월부터 Baseline 널리 사용 가능[4]

경계가 왜 문제인가

반응형 레이아웃은 화면 너비를 몇 개의 구간으로 나누고, 구간마다 다른 스타일을 적용합니다. 구간을 나누려면 경계값이 필요하고, 경계값에서는 "이 너비는 어느 구간인가"라는 질문에 정확히 하나의 답이 나와야 합니다.

경계가 겹치는 경우

가장 먼저 떠오르는 방법은 같은 숫자를 양쪽에 쓰는 것입니다.

@media (max-width: 768px) {
  .nav { display: none; } /* 모바일: 메뉴 숨김 */
}

@media (min-width: 768px) {
  .nav { display: flex; } /* 데스크톱: 메뉴 표시 */
}

min-width와 max-width는 모두 경계값을 포함합니다. 그래서 화면 너비가 정확히 768px이면 두 조건이 동시에 참이 됩니다.

/* 화면 너비 768px */
(max-width: 768px) /* true */
(min-width: 768px) /* true */
/* → 두 규칙이 모두 적용되고, 나중에 선언된 display: flex가 이김 */

지금은 우연히 나중 규칙이 원하는 값이라 괜찮아 보이지만, 선언 순서가 바뀌거나 한쪽 규칙에만 다른 속성이 있으면 768px에서만 레이아웃이 어긋나는 버그가 됩니다. 재현하려면 창 너비를 정확히 768px로 맞춰야 해서 찾기도 어렵습니다.

0.02px를 빼는 이유

겹침을 피하려면 한쪽 경계를 조금 줄여야 합니다. Bootstrap은 아래쪽 구간의 최대값에서 0.02px를 뺍니다. Bootstrap 소스의 breakpoint-max 함수가 이 계산을 하고, md 구간(768px)의 결과가 바로 767.98px입니다.[2]

// Bootstrap 5.3 scss/mixins/_breakpoints.scss
@function breakpoint-max($name, $breakpoints: $grid-breakpoints) {
  $max: map-get($breakpoints, $name);
  @return if($max and $max > 0, $max - .02, null);
}
// breakpoint-max(md) → 767.98px

그럼 1px을 빼서 767px로 쓰면 되지 않을까요? 소스 주석에 그 답이 있습니다. 화면 너비는 항상 정수가 아니며(fractional widths), min-/max- 접두사로는 이 경우를 처리하는 데 한계가 있다고 적혀 있습니다.[2] 브라우저 확대·축소나 고해상도 화면에서는 너비가 767.5px처럼 계산될 수 있고, 이 값은 max-width: 767px에도 min-width: 768px에도 해당하지 않습니다.

0.01px가 아니라 0.02px인 이유도 주석에 있습니다. Safari의 반올림 버그를 피하기 위해서입니다.[2] 결국 767.98px은 겹침과 빈틈 사이에서 최대한 빈틈을 줄인 값이지, 빈틈을 없앤 값은 아닙니다.

경계값을 -1px, -0.02px처럼 직접 계산해야 한다는 것 자체가 문법이 의도를 표현하지 못한다는 신호입니다. "768px 미만"이라고 쓸 수 있으면 계산할 필요가 없습니다.

767.98px 대신768px 미만width < 768px

범위 문법

미디어 쿼리 레벨 4에 들어간 범위 문법(Range Syntax)은 min-/max- 접두사 대신 수학 비교 연산자를 씁니다.[3][4]

비교 연산자로 쓰기

연산자는 네 가지이고, 경계값 포함 여부가 연산자에 그대로 드러납니다.

연산자 의미 경계값 768px
width >= 768px 768px 이상 포함
width > 768px 768px 초과 제외
width <= 768px 768px 이하 포함
width < 768px 768px 미만 제외

기존 문법과 대응시키면 다음과 같습니다. min-width와 max-width는 경계값을 포함하므로 >=, <=와 같습니다.[3]

@media (min-width: 768px) { }  /* 이전 */
@media (width >= 768px) { }    /* 같은 뜻 */

@media (max-width: 767.98px) { } /* 이전: 빈틈이 남는 우회 */
@media (width < 768px) { }       /* 768px 미만, 우회 필요 없음 */

앞의 메뉴 예제를 범위 문법으로 바꾸면 경계값을 그대로 씁니다.

@media (width < 768px) {
  .nav { display: none; }
}

@media (width >= 768px) {
  .nav { display: flex; }
}

/* 화면 너비 768px    → 두 번째만 true */
/* 화면 너비 767.99px → 첫 번째만 true */

<와 >=는 서로 정확히 반대이므로 768px은 한쪽에만 속하고, 767.99px 같은 소수점 너비도 빠짐없이 한쪽에 속합니다.

구간 지정

두 경계 사이의 구간은 비교식을 이어서 씁니다. MDN은 아래 세 쿼리가 모두 같은 뜻이라고 설명합니다.[3]

@media (min-width: 30em) and (max-width: 50em) { }
@media (30em <= width <= 50em) { }
@media (50em >= width >= 30em) { }

이어 쓰는 방식이 읽기 어렵다면 and로 나눠 써도 결과는 같습니다. 영상에서 Kevin Powell은 이 방식을 더 선호한다고 말합니다.[1]

@media (768px <= width < 1024px) { }          /* 이어 쓰기 */
@media (width >= 768px) and (width < 1024px) { } /* and로 나누기 */

자주 하는 실수: 양쪽 다 포함하기

구간을 여러 개 이어 붙일 때 양쪽을 모두 <=로 쓰면, 범위 문법에서도 경계가 겹칩니다.

/* 잘못된 예: 1024px에서 두 구간이 모두 true */
@media (768px <= width <= 1024px) { }
@media (1024px <= width <= 1280px) { }

/* 올바른 예: 아래쪽은 포함(<=), 위쪽은 제외(<) */
@media (768px <= width < 1024px) { }
@media (1024px <= width < 1280px) { }

규칙을 하나로 정해 두면 실수가 줄어듭니다. 아래 경계는 포함, 위 경계는 제외로 통일하는 것을 권합니다. 이렇게 쓰면 구간을 몇 개로 나눠도 빈틈과 겹침이 생기지 않습니다.

width 말고도

범위 문법은 값의 크기를 비교하는 미디어 특성이면 똑같이 쓸 수 있습니다. 높이, 화면비, 해상도 같은 특성이 여기에 해당합니다.

@media (height < 600px) { }          /* 낮은 화면: 고정 헤더 줄이기 */
@media (aspect-ratio > 1) { }        /* 가로가 더 긴 화면 */
@media (resolution >= 2dppx) { }     /* 고해상도 화면 */

컨테이너 쿼리에서도 같은 문법

컨테이너 쿼리(Container Query)는 화면 대신 부모 요소의 크기를 기준으로 스타일을 바꿉니다. 조건을 쓰는 방식은 범위 문법과 같습니다. MDN의 컨테이너 쿼리 문서도 범위 문법으로 예제를 씁니다.[5]

.sidebar {
  container-type: inline-size; /* 이 요소의 너비를 기준으로 삼음 */
}

@container (width > 700px) {
  .card { display: grid; grid-template-columns: 2fr 1fr; }
}

미디어 쿼리와 컨테이너 쿼리를 같은 문법으로 쓰면, 컴포넌트를 화면 기준에서 컨테이너 기준으로 옮길 때 @media를 @container로 바꾸는 것만으로 조건을 그대로 가져갈 수 있습니다.

지금 써도 될까

브라우저 지원

범위 문법은 Chrome·Edge 104, Firefox 102, Safari 16.4부터 지원합니다. 마지막으로 지원한 Safari 16.4가 나온 2023년 3월 27일에 Baseline 신규(Newly available)가 됐고, 30개월 뒤인 2025년 9월 27일에 Baseline 널리 사용 가능(Widely available)이 됐습니다.[4]

지원하지 않는 브라우저는 범위 문법이 들어간 쿼리 전체를 이해하지 못해 그 안의 스타일을 적용하지 않습니다. Safari 16.3 이하 사용자를 반드시 지원해야 한다면 해당 사이트의 실제 방문자 통계를 먼저 확인하세요.

이미 쓰고 있을 수도 있습니다

Tailwind CSS v4는 반응형 변형(variant)을 범위 문법으로 출력합니다. md:는 @media (width >= 48rem), max-md:는 @media (width < 48rem)가 됩니다.[6] Tailwind v4를 쓰고 있다면 빌드 결과물에 이미 범위 문법이 들어 있습니다.

Tailwind v4 변형 출력되는 미디어 쿼리
md: @media (width >= 48rem)
max-md: @media (width < 48rem)
md:max-lg: 48rem 이상이면서 64rem 미만

기존 코드 바꾸기

한 번에 바꾸기보다 경계 하나씩 바꾸고 확인하는 편이 안전합니다.

  1. .98px, .99px로 끝나는 값과 max-width를 검색합니다.
  2. max-width: 767.98px처럼 우회한 값은 width < 768px로, min-width: 768px는 width >= 768px로 바꿉니다.
  3. 개발자 도구에서 창 너비를 경계값(768px)과 경계값 바로 아래(767px)로 맞춰 두 상태를 모두 확인합니다.
  4. Sass 같은 전처리기를 거친다면 빌드된 CSS를 열어 범위 문법이 그대로 출력됐는지 확인합니다.

정리

하고 싶은 것 이전 범위 문법
768px 이상 min-width: 768px width >= 768px
768px 미만 max-width: 767.98px width < 768px
768px 이상 1024px 미만 (min-width: 768px) and (max-width: 1023.98px) 768px <= width < 1024px
컨테이너 너비 700px 초과 — @container (width > 700px)

767.98px은 잘못된 코드가 아니라 문법이 표현하지 못하던 "미만"을 숫자로 흉내 낸 결과였습니다. 이제는 연산자로 그대로 쓸 수 있습니다.

경계 규칙 하나만 기억하기아래는 포함위는 제외

프론트엔드 팀이 해 볼 것

  1. 프로젝트에서 .98px, .99px로 끝나는 미디어 쿼리를 검색해 개수를 확인한다
  2. 구간 경계 규칙을 "아래는 포함(<=), 위는 제외(<)"로 팀 컨벤션에 적는다
  3. 방문자 통계에서 Safari 16.3 이하 비율을 확인하고 전환 시점을 정한다
