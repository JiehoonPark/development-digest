16:T4712,<h2 id="경계가-왜-문제인가">경계가 왜 문제인가</h2>
<p>반응형 레이아웃은 화면 너비를 몇 개의 구간으로 나누고, 구간마다 다른 스타일을 적용합니다. 구간을 나누려면 경계값이 필요하고, 경계값에서는 "이 너비는 어느 구간인가"라는 질문에 정확히 하나의 답이 나와야 합니다.</p>
<h3 id="경계가-겹치는-경우">경계가 겹치는 경우</h3>
<p>가장 먼저 떠오르는 방법은 같은 숫자를 양쪽에 쓰는 것입니다.</p>
<pre data-lang="css"><code class="hljs language-css"><span class="hljs-keyword">@media</span> (<span class="hljs-attribute">max-width</span>: <span class="hljs-number">768px</span>) {
  <span class="hljs-selector-class">.nav</span> { <span class="hljs-attribute">display</span>: none; } <span class="hljs-comment">/* 모바일: 메뉴 숨김 */</span>
}

<span class="hljs-keyword">@media</span> (<span class="hljs-attribute">min-width</span>: <span class="hljs-number">768px</span>) {
  <span class="hljs-selector-class">.nav</span> { <span class="hljs-attribute">display</span>: flex; } <span class="hljs-comment">/* 데스크톱: 메뉴 표시 */</span>
}
</code></pre>
<p><code>min-width</code>와 <code>max-width</code>는 모두 경계값을 <strong>포함</strong>합니다. 그래서 화면 너비가 정확히 <code>768px</code>이면 두 조건이 동시에 참이 됩니다.</p>
<pre data-lang="css"><code class="hljs language-css"><span class="hljs-comment">/* 화면 너비 768px */</span>
(<span class="hljs-attribute">max-width</span>: <span class="hljs-number">768px</span>) <span class="hljs-comment">/* true */</span>
(min-width: <span class="hljs-number">768px</span>) <span class="hljs-comment">/* true */</span>
<span class="hljs-comment">/* → 두 규칙이 모두 적용되고, 나중에 선언된 display: flex가 이김 */</span>
</code></pre>
<p>지금은 우연히 나중 규칙이 원하는 값이라 괜찮아 보이지만, 선언 순서가 바뀌거나 한쪽 규칙에만 다른 속성이 있으면 768px에서만 레이아웃이 어긋나는 버그가 됩니다. 재현하려면 창 너비를 정확히 768px로 맞춰야 해서 찾기도 어렵습니다.</p>
<h3 id="002px를-빼는-이유">0.02px를 빼는 이유</h3>
<p>겹침을 피하려면 한쪽 경계를 조금 줄여야 합니다. Bootstrap은 아래쪽 구간의 최대값에서 <code>0.02px</code>를 뺍니다. Bootstrap 소스의 <code>breakpoint-max</code> 함수가 이 계산을 하고, <code>md</code> 구간(768px)의 결과가 바로 <code>767.98px</code>입니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup></p>
<pre data-lang="scss"><code class="hljs language-scss"><span class="hljs-comment">// Bootstrap 5.3 scss/mixins/_breakpoints.scss</span>
<span class="hljs-keyword">@function</span> breakpoint-max(<span class="hljs-variable">$name</span>, <span class="hljs-variable">$breakpoints</span>: <span class="hljs-variable">$grid-breakpoints</span>) {
  <span class="hljs-variable">$max</span>: <span class="hljs-built_in">map-get</span>(<span class="hljs-variable">$breakpoints</span>, <span class="hljs-variable">$name</span>);
  <span class="hljs-keyword">@return</span> if(<span class="hljs-variable">$max</span> <span class="hljs-keyword">and</span> <span class="hljs-variable">$max</span> > <span class="hljs-number">0</span>, <span class="hljs-variable">$max</span> - .<span class="hljs-number">02</span>, null);
}
<span class="hljs-comment">// breakpoint-max(md) → 767.98px</span>
</code></pre>
<p>그럼 <code>1px</code>을 빼서 <code>767px</code>로 쓰면 되지 않을까요? 소스 주석에 그 답이 있습니다. 화면 너비는 항상 정수가 아니며(fractional widths), <code>min-</code>/<code>max-</code> 접두사로는 이 경우를 처리하는 데 한계가 있다고 적혀 있습니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup> 브라우저 확대·축소나 고해상도 화면에서는 너비가 <code>767.5px</code>처럼 계산될 수 있고, 이 값은 <code>max-width: 767px</code>에도 <code>min-width: 768px</code>에도 해당하지 않습니다.</p>
<figure><img src="/development-digest/figures/mq-gap.svg" alt="min/max 방식에서 생기는 빈틈" loading="lazy"><figcaption>그림 1 · 0.02px를 빼면 겹침은 사라지지만 아주 좁은 빈틈이 남습니다</figcaption></figure>
<p><code>0.01px</code>가 아니라 <code>0.02px</code>인 이유도 주석에 있습니다. Safari의 반올림 버그를 피하기 위해서입니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup> 결국 <code>767.98px</code>은 겹침과 빈틈 사이에서 최대한 빈틈을 줄인 값이지, 빈틈을 없앤 값은 아닙니다.</p>
<blockquote>
<p>경계값을 <code>-1px</code>, <code>-0.02px</code>처럼 직접 계산해야 한다는 것 자체가 문법이 의도를 표현하지 못한다는 신호입니다. "768px 미만"이라고 쓸 수 있으면 계산할 필요가 없습니다.</p>
</blockquote>
<aside class="poster" aria-label="767.98px 대신 768px 미만 width < 768px"><span class="poster-line" aria-hidden="true">767.98px 대신</span><span class="poster-line" aria-hidden="true">768px 미만</span><span class="poster-line poster-accent" aria-hidden="true">width &#x3C; 768px</span></aside>
<h2 id="범위-문법">범위 문법</h2>
<p>미디어 쿼리 레벨 4에 들어간 범위 문법(Range Syntax)은 <code>min-</code>/<code>max-</code> 접두사 대신 수학 비교 연산자를 씁니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup><sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup></p>
<h3 id="비교-연산자로-쓰기">비교 연산자로 쓰기</h3>
<p>연산자는 네 가지이고, 경계값 포함 여부가 연산자에 그대로 드러납니다.</p>
<table>

<tr>

<p>기존 문법과 대응시키면 다음과 같습니다. <code>min-width</code>와 <code>max-width</code>는 경계값을 포함하므로 <code>>=</code>, <code>&#x3C;=</code>와 같습니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></p>
<pre data-lang="css"><code class="hljs language-css"><span class="hljs-keyword">@media</span> (<span class="hljs-attribute">min-width</span>: <span class="hljs-number">768px</span>) { }  <span class="hljs-comment">/* 이전 */</span>
<span class="hljs-keyword">@media</span> (<span class="hljs-attribute">width</span> >= <span class="hljs-number">768px</span>) { }    <span class="hljs-comment">/* 같은 뜻 */</span>

<span class="hljs-keyword">@media</span> (<span class="hljs-attribute">max-width</span>: <span class="hljs-number">767.98px</span>) { } <span class="hljs-comment">/* 이전: 빈틈이 남는 우회 */</span>
<span class="hljs-keyword">@media</span> (<span class="hljs-attribute">width</span> &#x3C; <span class="hljs-number">768px</span>) { }       <span class="hljs-comment">/* 768px 미만, 우회 필요 없음 */</span>
</code></pre>
<p>앞의 메뉴 예제를 범위 문법으로 바꾸면 경계값을 그대로 씁니다.</p>
<pre data-lang="css"><code class="hljs language-css"><span class="hljs-keyword">@media</span> (<span class="hljs-attribute">width</span> &#x3C; <span class="hljs-number">768px</span>) {
  <span class="hljs-selector-class">.nav</span> { <span class="hljs-attribute">display</span>: none; }
}

<span class="hljs-keyword">@media</span> (<span class="hljs-attribute">width</span> >= <span class="hljs-number">768px</span>) {
  <span class="hljs-selector-class">.nav</span> { <span class="hljs-attribute">display</span>: flex; }
}

<span class="hljs-comment">/* 화면 너비 768px    → 두 번째만 true */</span>
<span class="hljs-comment">/* 화면 너비 767.99px → 첫 번째만 true */</span>
</code></pre>
<p><code>&#x3C;</code>와 <code>>=</code>는 서로 정확히 반대이므로 768px은 한쪽에만 속하고, 767.99px 같은 소수점 너비도 빠짐없이 한쪽에 속합니다.</p>
<figure><img src="/development-digest/figures/mq-range.svg" alt="범위 문법의 경계" loading="lazy"><figcaption>그림 2 · 한쪽은 포함, 한쪽은 제외로 나누면 빈틈과 겹침이 동시에 사라집니다</figcaption></figure>
<h3 id="구간-지정">구간 지정</h3>
<p>두 경계 사이의 구간은 비교식을 이어서 씁니다. MDN은 아래 세 쿼리가 모두 같은 뜻이라고 설명합니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></p>
<pre data-lang="css"><code class="hljs language-css"><span class="hljs-keyword">@media</span> (<span class="hljs-attribute">min-width</span>: <span class="hljs-number">30em</span>) <span class="hljs-keyword">and</span> (<span class="hljs-attribute">max-width</span>: <span class="hljs-number">50em</span>) { }
<span class="hljs-keyword">@media</span> (<span class="hljs-number">30em</span> &#x3C;= <span class="hljs-attribute">width</span> &#x3C;= <span class="hljs-number">50em</span>) { }
<span class="hljs-keyword">@media</span> (<span class="hljs-number">50em</span> >= <span class="hljs-attribute">width</span> >= <span class="hljs-number">30em</span>) { }
</code></pre>
<p>이어 쓰는 방식이 읽기 어렵다면 <code>and</code>로 나눠 써도 결과는 같습니다. 영상에서 Kevin Powell은 이 방식을 더 선호한다고 말합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>
<pre data-lang="css"><code class="hljs language-css"><span class="hljs-keyword">@media</span> (<span class="hljs-number">768px</span> &#x3C;= <span class="hljs-attribute">width</span> &#x3C; <span class="hljs-number">1024px</span>) { }          <span class="hljs-comment">/* 이어 쓰기 */</span>
<span class="hljs-keyword">@media</span> (<span class="hljs-attribute">width</span> >= <span class="hljs-number">768px</span>) <span class="hljs-keyword">and</span> (<span class="hljs-attribute">width</span> &#x3C; <span class="hljs-number">1024px</span>) { } <span class="hljs-comment">/* and로 나누기 */</span>
</code></pre>
<h4>자주 하는 실수: 양쪽 다 포함하기</h4>
<p>구간을 여러 개 이어 붙일 때 양쪽을 모두 <code>&#x3C;=</code>로 쓰면, 범위 문법에서도 경계가 겹칩니다.</p>
<pre data-lang="css"><code class="hljs language-css"><span class="hljs-comment">/* 잘못된 예: 1024px에서 두 구간이 모두 true */</span>
<span class="hljs-keyword">@media</span> (<span class="hljs-number">768px</span> &#x3C;= <span class="hljs-attribute">width</span> &#x3C;= <span class="hljs-number">1024px</span>) { }
<span class="hljs-keyword">@media</span> (<span class="hljs-number">1024px</span> &#x3C;= <span class="hljs-attribute">width</span> &#x3C;= <span class="hljs-number">1280px</span>) { }

<span class="hljs-comment">/* 올바른 예: 아래쪽은 포함(&#x3C;=), 위쪽은 제외(&#x3C;) */</span>
<span class="hljs-keyword">@media</span> (<span class="hljs-number">768px</span> &#x3C;= <span class="hljs-attribute">width</span> &#x3C; <span class="hljs-number">1024px</span>) { }
<span class="hljs-keyword">@media</span> (<span class="hljs-number">1024px</span> &#x3C;= <span class="hljs-attribute">width</span> &#x3C; <span class="hljs-number">1280px</span>) { }
</code></pre>
<p>규칙을 하나로 정해 두면 실수가 줄어듭니다. <em>아래 경계는 포함, 위 경계는 제외</em>로 통일하는 것을 권합니다. 이렇게 쓰면 구간을 몇 개로 나눠도 빈틈과 겹침이 생기지 않습니다.</p>
<h3 id="width-말고도">width 말고도</h3>
<p>범위 문법은 값의 크기를 비교하는 미디어 특성이면 똑같이 쓸 수 있습니다. 높이, 화면비, 해상도 같은 특성이 여기에 해당합니다.</p>
<pre data-lang="css"><code class="hljs language-css"><span class="hljs-keyword">@media</span> (<span class="hljs-attribute">height</span> &#x3C; <span class="hljs-number">600px</span>) { }          <span class="hljs-comment">/* 낮은 화면: 고정 헤더 줄이기 */</span>
<span class="hljs-keyword">@media</span> (<span class="hljs-attribute">aspect-ratio</span> > <span class="hljs-number">1</span>) { }        <span class="hljs-comment">/* 가로가 더 긴 화면 */</span>
<span class="hljs-keyword">@media</span> (<span class="hljs-attribute">resolution</span> >= <span class="hljs-number">2dppx</span>) { }     <span class="hljs-comment">/* 고해상도 화면 */</span>
</code></pre>
<h2 id="컨테이너-쿼리에서도-같은-문법">컨테이너 쿼리에서도 같은 문법</h2>
<p>컨테이너 쿼리(Container Query)는 화면 대신 부모 요소의 크기를 기준으로 스타일을 바꿉니다. 조건을 쓰는 방식은 범위 문법과 같습니다. MDN의 컨테이너 쿼리 문서도 범위 문법으로 예제를 씁니다.<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup></p>
<pre data-lang="css"><code class="hljs language-css"><span class="hljs-selector-class">.sidebar</span> {
  <span class="hljs-attribute">container-type</span>: inline-size; <span class="hljs-comment">/* 이 요소의 너비를 기준으로 삼음 */</span>
}

<span class="hljs-keyword">@container</span> (<span class="hljs-attribute">width</span> > <span class="hljs-number">700px</span>) {
  <span class="hljs-selector-class">.card</span> { <span class="hljs-attribute">display</span>: grid; <span class="hljs-attribute">grid-template-columns</span>: <span class="hljs-number">2</span>fr <span class="hljs-number">1</span>fr; }
}
</code></pre>
<p>미디어 쿼리와 컨테이너 쿼리를 같은 문법으로 쓰면, 컴포넌트를 화면 기준에서 컨테이너 기준으로 옮길 때 <code>@media</code>를 <code>@container</code>로 바꾸는 것만으로 조건을 그대로 가져갈 수 있습니다.</p>
<h2 id="지금-써도-될까">지금 써도 될까</h2>
<h3 id="브라우저-지원">브라우저 지원</h3>
<p>범위 문법은 Chrome·Edge 104, Firefox 102, Safari 16.4부터 지원합니다. 마지막으로 지원한 Safari 16.4가 나온 2023년 3월 27일에 Baseline 신규(Newly available)가 됐고, 30개월 뒤인 2025년 9월 27일에 Baseline 널리 사용 가능(Widely available)이 됐습니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup></p>
<figure><img src="/development-digest/figures/mq-support.svg" alt="범위 문법 지원 버전" loading="lazy"><figcaption>그림 3 · 2025년 9월부터 Baseline 널리 사용 가능 단계입니다</figcaption></figure>
<p>지원하지 않는 브라우저는 범위 문법이 들어간 쿼리 전체를 이해하지 못해 그 안의 스타일을 적용하지 않습니다. Safari 16.3 이하 사용자를 반드시 지원해야 한다면 해당 사이트의 실제 방문자 통계를 먼저 확인하세요.</p>
<h3 id="이미-쓰고-있을-수도-있습니다">이미 쓰고 있을 수도 있습니다</h3>
<p>Tailwind CSS v4는 반응형 변형(variant)을 범위 문법으로 출력합니다. <code>md:</code>는 <code>@media (width >= 48rem)</code>, <code>max-md:</code>는 <code>@media (width &#x3C; 48rem)</code>가 됩니다.<sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup> Tailwind v4를 쓰고 있다면 빌드 결과물에 이미 범위 문법이 들어 있습니다.</p>

<h3 id="기존-코드-바꾸기">기존 코드 바꾸기</h3>
<p>한 번에 바꾸기보다 경계 하나씩 바꾸고 확인하는 편이 안전합니다.</p>
<ol>
<li><code>.98px</code>, <code>.99px</code>로 끝나는 값과 <code>max-width</code>를 검색합니다.</li>
<li><code>max-width: 767.98px</code>처럼 우회한 값은 <code>width &#x3C; 768px</code>로, <code>min-width: 768px</code>는 <code>width >= 768px</code>로 바꿉니다.</li>
<li>개발자 도구에서 창 너비를 경계값(768px)과 경계값 바로 아래(767px)로 맞춰 두 상태를 모두 확인합니다.</li>
<li>Sass 같은 전처리기를 거친다면 빌드된 CSS를 열어 범위 문법이 그대로 출력됐는지 확인합니다.</li>
</ol>
