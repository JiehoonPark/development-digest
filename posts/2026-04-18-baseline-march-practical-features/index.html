반복자는 잇고 들여쓰기는 나누고 — 3월 Baseline 실전

데이터를 배열로 합치지 않고 순회하는 방법과 줄바꿈 종류에 따라 들여쓰기를 다르게 주는 방법을 정리합니다. 새 기능을 쓰기 전에 확인할 지원 범위와 자주 혼동하는 동작도 함께 짚습니다.

새로 쓸 수 있다는 말의 범위

브라우저가 지원한다는 소식을 읽고도 기존 코드를 어디서 바꿀지 떠오르지 않을 때가 있습니다. 기능 이름보다 먼저 볼 것은 데이터가 어떤 형태로 들어오고, 화면에서 어떤 줄을 구분해야 하는지입니다. 이 글은 여러 데이터 묶음을 순회하는 코드와 본문 들여쓰기라는 작은 문제에서 출발합니다.

web.dev의 월간 다이제스트는 Iterator.concat(), text-indent: each-line, text-indent: hanging을 2026년 3월 Baseline Newly available 기능으로 소개했습니다.[1] 여기서는 이 기능들을 각각 데이터 연결, 강제 줄바꿈 뒤의 들여쓰기, 첫 줄을 제외한 들여쓰기로 나눠 적용합니다. 지원 예정 기능이나 표준화 후보 목록이 아니라, 원문이 해당 월에 상호운용성을 확보했다고 분류한 기능입니다.[1]

Newly와 Widely는 같은 뜻이 아닙니다

Baseline의 신규 사용 가능(Newly available)은 평가 대상 브라우저 각각의 최신 안정 버전에서 기능이 동작한다는 뜻입니다.[4] 널리 사용 가능(Widely available)은 그 지원이 최소 2.5년 동안 이어진 상태입니다.[4] 이번 월간 다이제스트는 이를 상호운용성 확보 후 30개월이 지난 단계로 설명합니다.[1]

따라서 신규라는 표시를 모든 방문자에게 바로 배포해도 된다는 허가로 읽으면 안 됩니다. Baseline은 구형 기기·브라우저, 운영체제 웹뷰, 보조 기술에서의 동작까지 보장하지 않으며 접근성·성능·보안 테스트를 대신하지도 않습니다.[4] 실제 도입에서는 프로젝트의 지원 대상과 예제가 실행되는 환경을 별도로 확인해야 합니다.

Iterator.concat() — 배열 대신 순회 순서를 잇기

Iterator.concat()은 여러 이터러블(iterable)을 받아, 각 입력의 값을 차례대로 내보내는 반복자(iterator)를 만드는 정적 메서드입니다.[2] 반환값이 배열이 아니므로 입력을 지연 순회할 수 있고, 연결만을 위한 중간 배열을 만들지 않아도 됩니다.[2]

서로 다른 자료형을 같은 순서로 읽기

고정 항목은 배열에, 선택 항목은 집합에 들어 있다고 가정해 보겠습니다. 필요한 것은 원본 자료형을 통일하는 작업이 아니라 고정 항목 다음에 선택 항목을 읽는 순서입니다. MDN은 배열과 Set, 제너레이터를 함께 연결하는 예제를 제공합니다.[2]

const pinned = ["공지", "시작 안내"];
const selected = new Set(["CSS", "JavaScript"]);
const items = Iterator.concat(pinned, selected);

for (const item of items) {
  console.log(item);
}
// 공지 → 시작 안내 → CSS → JavaScript 순서로 출력

이 예제의 문자열은 화면 항목을 가정한 샘플이며, 연결 동작은 MDN의 혼합 이터러블 예제를 줄인 것입니다.[2] 루프 안에 항목을 처리할 코드를 두면 됩니다. 소비자가 순차 처리만 요구하는데 연결 결과를 먼저 배열로 만드는 단계를 둘 필요는 없습니다.

반대로 결과를 배열로 받아야 하는 코드라면 펼침 문법으로 소비할 수 있습니다. MDN도 연결 결과를 [...it]로 확인하지만, 이때는 결과 배열을 실제로 만들게 됩니다.[2] 지연 연결과 배열 변환은 서로 다른 선택입니다.

실수: 연결을 병합이나 중복 제거로 생각하기

이 메서드는 입력의 값을 순서대로 내보낼 뿐, 같은 값이나 키를 정리하는 정책을 맡지 않습니다.[2] 최종 결과를 어떤 자료형으로 소비하느냐를 따로 보아야 합니다. 다음은 MDN의 맵 연결 예제를 설정값 병합 상황에 맞춰 줄인 코드입니다.[2]

const defaults = new Map([["theme", "light"]]);
const overrides = new Map([["theme", "dark"]]);
const settings = new Map(
  Iterator.concat(defaults, overrides),
);
console.log(settings);
// Map(1) { "theme" => "dark" }

같은 키의 마지막 값이 남는 것은 Iterator.concat()의 중복 제거 때문이 아니라 Map 생성자의 동작입니다.[2] 따라서 기본값 뒤에 사용자 설정을 두는 순서가 중요합니다. 데이터를 연결하는 단계와 최종 자료구조가 충돌을 처리하는 단계를 구분하면 코드의 책임도 분명해집니다.

또 다른 실수는 next()만 있는 객체를 곧바로 넘기는 것입니다. 입력은 이터러블이어야 하므로, 순회 프로토콜만 구현한 객체는 먼저 Iterator.from()으로 감싸야 합니다.[2]

const nextOnly = {
  next() {
    return { done: true };
  },
};

// Iterator.concat(nextOnly); // TypeError
const empty = Iterator.concat(Iterator.from(nextOnly));
console.log([...empty]); // []

무한 이터러블을 연결할 수도 있지만, 앞의 무한 입력을 다 읽을 수 없으므로 그 뒤의 입력에는 도달하지 않습니다.[2] 여러 소스에서 번갈아 하나씩 가져오는 병렬 소비 도구로 해석하지 않아야 합니다. 이 기능이 표현하는 것은 어디까지나 앞 입력 다음에 뒤 입력을 읽는 순서입니다.

each-line — 강제로 나눈 줄에 들여쓰기

text-indent는 블록 안의 텍스트 줄 앞에 들여쓰기 공간을 설정합니다.[3] 여기에 each-line을 붙이면 블록의 첫 줄뿐 아니라 강제 줄바꿈 뒤의 줄에도 들여쓰기를 적용하고, 폭이 부족해 자동으로 꺾인 줄에는 적용하지 않습니다.[3]

강제 줄바꿈과 자동 줄바꿈 구분하기

같은 블록 안에 안내 문장을 나누어 놓되, 각 문장의 시작을 들여쓰고 싶다고 가정하겠습니다. 다음 예제는 MDN의 <br> 예제와 each-line 정의를 이용한 최소 문서입니다.[3] HTML 파일에 넣고 창을 좁히면 강제로 시작한 줄과 자동으로 이어진 줄의 차이를 볼 수 있습니다.

<style>
  .notice {
    text-indent: 3em each-line;
  }
</style>

<p class="notice">
  이 안내 문장은 창이 좁으면 여러 줄로 이어집니다.
  자동으로 이어진 부분의 시작 위치를 확인하세요.<br>
  여기는 강제로 줄을 나눈 뒤 시작하는 안내입니다.
  이 문장도 창을 좁혀 자동으로 줄바꿈해 보세요.
</p>
<!-- 첫 줄과 br 바로 뒤의 줄: 3em 들여쓰기 -->
<!-- 폭이 부족해 자동으로 이어진 줄: 들여쓰기 없음 -->

핵심은 화면에 보이는 모든 줄이 아니라 작성자가 강제로 나눈 줄이라는 구분입니다. 창 너비가 바뀌어 문장이 더 많은 줄로 보이더라도, 자동 줄바꿈이 새로운 들여쓰기 시작점을 만들지는 않습니다.[3] 문장 시작과 이어지는 줄에 다른 정렬 규칙을 주고 싶을 때 검토할 만합니다.

실수: 이름을 보고 모든 줄이 들어간다고 생각하기

each-line이라는 이름만 읽으면 모든 시각적 줄이 같은 폭만큼 들어갈 것 같습니다. 그러나 MDN은 자동 줄바꿈 뒤에는 영향을 주지 않는다고 명시합니다.[3] 텍스트 덩어리 전체를 안쪽으로 옮기는 요구와, 특정 줄의 시작만 안쪽으로 옮기는 요구를 구분해야 합니다.

또한 원문에서 새로 사용 가능해졌다고 소개한 대상은 오래된 text-indent 속성 전체가 아니라 해당 키워드입니다.[1] MDN 페이지 상단의 속성 전체 지원 배지만 보고 하위 문법까지 같은 시점에 지원됐다고 판단하면 안 됩니다. 실제로 해당 문서는 일부 세부 기능의 지원 수준이 다를 수 있다고 경고합니다.[3]

이 기능을 시험할 때는 자동 줄바꿈이 생기도록 창을 좁힌 상태와 <br> 다음 줄을 나란히 확인하는 편이 좋습니다. 넓은 화면에서 각 문장이 한 줄로만 보이면 가장 중요한 차이를 놓치기 쉽습니다. 디자인 검수에서도 단순히 들여쓰기 유무가 아니라 어떤 종류의 줄바꿈 뒤인지 기록해 두세요.

hanging — 첫 줄을 남기고 나머지를 들여쓰기

hanging은 들여쓰기를 적용할 줄의 선택을 뒤집는 키워드입니다.[3] 단독으로 사용하면 첫 줄은 그대로 두고 이후 줄을 들여쓰는 내어쓰기(hanging indent) 모양을 만듭니다.[3] 원문은 참고문헌과 편집 디자인을 대표적인 사용처로 들고 있습니다.[1]

참고문헌의 이어지는 줄 정렬하기

아래 예제는 MDN의 3em hanging 값을 사용합니다.[3] 첫 줄은 블록의 시작 위치에 두고, 길어진 설명이 다음 줄로 넘어가면 그 줄부터 안쪽으로 들어가도록 합니다. 예제의 제목과 설명은 실제 서지 정보가 아닌 표시용 문구입니다.

<style>
  .reference {
    text-indent: 3em hanging;
  }
</style>

<p class="reference">
  편집팀. 웹 인터페이스 문서 작성 안내.
  참고문헌의 설명이 길어질 때 이어지는 줄이 어디서
  시작하는지 확인하기 위한 예제 문장입니다.
</p>
<!-- 첫 줄: 들여쓰기 없음 -->
<!-- 창을 좁혀 생긴 다음 줄들: 3em 들여쓰기 -->

검수할 때 첫 줄이 상자 밖으로 밀려나는지부터 볼 필요는 없습니다. 양수 값과 hanging을 함께 쓰면 첫 줄을 밖으로 보내는 것이 아니라 나머지 줄을 안으로 이동시키기 때문입니다.[3] 문장 길이가 짧아 줄바꿈이 생기지 않으면 이 차이도 드러나지 않습니다.

실수: 음수 들여쓰기와 같은 것으로 보기

음수 text-indent는 첫 줄을 내용 영역의 시작 바깥으로 밀어낼 수 있습니다.[3] 반면 양수 값에 hanging을 붙이면 첫 줄을 밀어내지 않고 다른 줄을 안쪽으로 들여씁니다.[3] 같은 내어쓰기 모양처럼 보여도, 어느 줄의 위치를 움직이는지가 다릅니다.

.outdent {
  text-indent: -3em;
  /* 첫 줄을 내용 영역 시작보다 바깥으로 이동 */
}

.hanging {
  text-indent: 3em hanging;
  /* 첫 줄은 그대로, 나머지 줄을 안쪽으로 이동 */
}

이 비교는 MDN이 음수 값과 양수 hanging을 구분한 설명을 옮긴 것입니다.[3] 기존의 음수 들여쓰기 코드를 새 키워드로 교체할 때도 값만 바꾸고 끝내지 말고, 첫 줄과 이어지는 줄의 시작 위치를 각각 비교해야 합니다.

each-line과 함께 쓰면 무엇이 뒤집힐까

MDN은 hanging과 each-line을 함께 쓰는 문법도 제공합니다.[3] each-line이 고른 첫 줄·강제 줄바꿈 뒤의 줄을 hanging이 뒤집는 것으로 읽으면, 두 키워드의 역할을 분리할 수 있습니다.[3]

.notice {
  text-indent: 3em hanging each-line;
  /* 첫 줄과 강제 줄바꿈 직후: 들여쓰기 없음 */
  /* 자동으로 이어지는 줄: 3em 들여쓰기 */
}

앞의 안내문 예제에서 스타일만 이 규칙으로 교체해 비교해 보세요. 단독 hanging과 조합 문법을 같은 것으로 취급하지 않는 것이 중요합니다. 먼저 어떤 줄을 선택할지 정하고, 그 선택을 뒤집을지 정하면 선언을 읽기가 쉬워집니다.

프론트엔드 팀이 해 볼 것

  1. 배열을 먼저 합친 뒤 순회하는 코드를 찾아, 지원 대상 환경에서 Iterator.concat()으로 연결했을 때 소비 방식이 맞는지 확인합니다.
  2. 본문의 안내문 예제를 HTML 파일에 넣고 창을 좁혀 each-line과 hanging each-line의 차이를 비교합니다.
  3. 참고문헌 스타일에 음수 text-indent가 있다면 hanging 예제와 첫 줄·이어지는 줄의 시작 위치를 각각 대조합니다.
