헤더 배경은 투명하게, 가림막은 구역마다 — 스티키 블로커 기법

고정 헤더 아래로 본문이 비치는 문제를 JavaScript 없이 푸는 방법을 정리했습니다. position: sticky가 컨테이너 끝에서 멈추는 성질과 쌓임 순서만으로 구역마다 다른 배경색을 헤더 뒤에 깔 수 있습니다.

요약

  • 헤더 배경은 투명하게 두고, 각 구역 안에 헤더 높이만 한 position: sticky 가림막을 넣어 배경색을 맞춘다[1]
  • 스티키 요소는 자기 컨테이닝 블록의 반대쪽 끝을 만나면 더 따라오지 않아서, 구역이 바뀔 때 가림막이 자연스럽게 교대한다[2]
  • 쌓는 순서는 헤더 > 가림막 > 본문이고, 위치 지정 요소가 일반 요소보다 위에 그려지는 기본 규칙과 헤더의 z-index: 1로 만든다[1][3]
  • 가림막이 쉴 빈 공간이 헤더 높이만큼 필요해서, 그 자리가 없는 디자인에서는 원문 필자도 JavaScript로 헤더 배경을 바꾼다[1]

고정 헤더 아래로 무엇이 비치는가

고정 헤더(fixed header)는 스크롤해도 화면 위쪽에 계속 붙어 있는 헤더입니다. 헤더는 본문 위에 겹쳐 그려지기 때문에, 배경이 투명하면 아래로 지나가는 본문 글자가 헤더 메뉴 글자와 겹쳐 보입니다.

header {
  position: fixed;
  top: 0;
  height: 4rem;
  /* background 없음 → 스크롤하면 본문 글자가 메뉴 뒤로 비쳐 보임 */
}

가장 흔한 처방은 헤더에 배경색을 칠하는 것입니다. 페이지 전체가 한 가지 배경색이면 이것으로 끝납니다. 문제는 구역마다 배경색이 다를 때입니다.

header {
  background: white;
  /* 흰 본문 위에서는 자연스러움 */
  /* 파란 상단 영역(hero) 위에서는 흰 띠가 떠 보임 */
}

그래서 보통은 JavaScript로 스크롤 위치를 보고 헤더 배경색을 바꿉니다. Josh W. Comeau의 블로그도 홈페이지에서는 이 방식을 씁니다. 하지만 글 페이지에서는 헤더 배경이 한 번도 바뀌지 않는데도, 상단 영역에서는 파랗게, 본문에서는 하얗게 보입니다. JavaScript는 전혀 쓰지 않고 CSS만으로 만든 효과입니다.[1]

비결은 관점을 뒤집는 데 있습니다. 헤더가 배경을 들고 다니는 대신, 각 구역이 자기 배경색과 같은 가림막을 헤더 바로 뒤에 깔아 둡니다. 원문은 이 가림막을 블로커(blocker)라고 부릅니다.[1] 이 기법을 이해하려면 개념 두 가지가 필요합니다. 스티키 요소가 어디까지 따라오는가, 그리고 겹친 요소가 어떤 순서로 그려지는가입니다.

position: sticky는 컨테이너 밖으로 나가지 않는다

position: sticky는 평소에는 일반 흐름대로 놓여 있다가, 스크롤 중 지정한 기준선(top 등)에 닿으면 그 자리에 붙는 배치 방식입니다. MDN은 스티키 요소를 기준선에 닿기 전까지는 상대 위치(relative)처럼 다루고, 닿은 뒤에는 컨테이닝 블록(containing block)의 반대쪽 끝을 만날 때까지 "붙은(stuck)" 상태로 다룬다고 설명합니다.[2]

여기서 뒷부분이 자주 잊힙니다. 스티키 요소는 화면 끝까지 따라오지 않고, 부모 컨테이너가 끝나면 함께 밀려 올라갑니다.[1][2]

<style>
  .container {
    height: 300px;
  }
  .sticky {
    position: sticky;
    top: 2px;
    height: 40px;
    background: tomato;
  }
</style>

<div class="container">
  <div class="sticky"></div>
</div>
<div class="container">
  <div class="sticky"></div>
</div>

<!-- 스크롤하면 첫 번째 블록이 위쪽에 붙어 따라오다가 -->
<!-- 첫 번째 .container 의 끝에서 함께 밀려 사라짐 -->
<!-- 이어서 두 번째 블록이 붙어 따라옴 -->

블로커 기법은 이 "교대"를 그대로 이용합니다. 상단 영역의 가림막이 상단 영역과 함께 밀려나는 순간, 본문의 가림막이 그 자리를 이어받습니다.[1]

자주 하는 실수: 붙지 않는 스티키

  • top을 안 씀: 붙을 축의 인셋 속성(top, inset-block-start 등)을 최소 하나는 auto가 아닌 값으로 정해야 합니다. 둘 다 auto면 그 축에서는 relative처럼 동작합니다.[2]
  • 조상에 overflow가 있음: 스티키 요소는 스크롤 메커니즘이 있는 가장 가까운 조상에 붙습니다. overflow가 hidden, scroll, auto, overlay인 조상이 있으면, 그 조상이 실제로 스크롤되지 않더라도 거기에 붙습니다.[2] 페이지 스크롤에 맞춰 붙기를 기대했다면 중간 래퍼의 overflow부터 확인하세요.
  • 컨테이너 높이가 스티키 요소와 같음: 컨테이너에 따라 움직일 여유가 없으면 붙는 구간도 없습니다. 바로 위 예제에서 .container의 height를 지우면 블록이 거의 붙지 않습니다.

블로커: 배경색을 구역이 들고 있게 한다

블로커는 헤더와 높이가 같은 스티키 요소입니다. 구역의 맨 앞에 두고, 그 구역의 배경색으로 칠합니다. 헤더 자체는 투명한 채로 position: fixed로 맨 앞에 떠 있을 뿐, 특별한 일을 하지 않습니다.[1] 원문이 보여 주는 최소 구현은 다음과 같습니다.[1]

<style>
  html {
    --blue: hsl(210deg 80% 85%);
    --header-height: 4rem;
  }
  header {
    position: fixed;
    z-index: 1;
    top: 0;
    height: var(--header-height);
  }
  .blocker {
    position: sticky;
    top: 0;
    height: var(--header-height);
  }
  .hero .blocker {
    background: var(--blue);
  }
  .main-content .blocker {
    background: white;
  }
</style>

<header>Sticky Header</header>
<div class="hero">
  <div class="blocker"></div>
  <h1>Article Title</h1>
</div>
<main class="main-content">
  <div class="blocker"></div>
  <p>본문 문단…</p>
</main>

<!-- 상단 영역을 지나는 동안: 파란 블로커가 헤더 뒤에 붙어 제목을 가림 -->
<!-- 본문에 들어서면: 파란 블로커는 .hero 와 함께 밀려나고 흰 블로커가 이어받음 -->

헤더 높이를 --header-height 하나로 공유하는 점이 중요합니다. 헤더와 블로커의 높이가 어긋나면, 그 차이만큼 본문이 비치거나 블로커 아랫단이 헤더 밑으로 삐져나옵니다.

헤더는 투명하게가림막은 구역마다

대가: 블로커가 쉴 자리

스티키 요소는 일반 흐름 안에 있으므로, 붙기 전에도 자기 높이만큼 공간을 차지합니다. 그래서 페이지 맨 위로 스크롤했을 때 블로커가 머물 빈 공간이 헤더 높이만큼 본문 위에 있어야 합니다. 원문 블로그는 헤더 높이가 5rem(보통 80px)이라 본문 위에 최소 5rem의 빈 공간을 둡니다.[1] 원문 필자는 이 제약 때문에 상단 영역의 구름 곡선을 원하는 만큼 깊게 만들지 못했다고 말합니다.[1]

곡선이 훨씬 과감한 홈페이지에는 블로커를 숨길 자리가 없습니다. 블로커를 어색한 곳에 두고 JavaScript로 opacity를 켜고 끄는 방법도 있지만, 원문 필자는 갑자기 나타나면 거슬리고, 짧은 전환을 주면 빠르게 스크롤하는 사람을 따라가지 못한다고 봅니다. 그래서 홈페이지에서는 헤더 자체에 배경색을 주고, 스크롤 위치에 따라 JavaScript로 파란색에서 흰색으로 바꿉니다.[1]

쌓임 순서: 헤더 > 블로커 > 본문

블로커 기법이 동작하려면 세 층이 정확한 순서로 겹쳐야 합니다. 맨 앞에 헤더, 그 뒤에 블로커, 맨 뒤에 본문입니다.[1] 이 순서는 쌓임 맥락(stacking context) 규칙으로 정해집니다.

z-index 없이도 정해지는 순서

쌓임 맥락은 화면을 바라보는 사용자 쪽으로 뻗은 가상의 z축을 따라 요소를 겹치는 단위입니다.[4] z-index를 아무 데도 쓰지 않으면, 요소는 아래에서 위로 다음 순서로 그려집니다.[3]

  1. 루트 요소의 배경과 테두리
  2. 위치 지정이 없는 자손 요소, HTML에 나온 순서대로
  3. 위치 지정 자손 요소, HTML에 나온 순서대로

위치 지정 요소는 position의 계산값이 static이 아닌 요소입니다.[2] 블로커는 sticky라 3번에, 제목과 본문 문단은 2번에 속합니다. 그래서 블로커가 HTML에서 <h1>보다 앞에 있어도 제목 위에 그려집니다.

<div class="hero">
  <div class="blocker"></div> <!-- sticky: 위치 지정 요소 -->
  <h1>Article Title</h1>      <!-- static: 블로커 아래에 그려짐 -->
</div>

헤더도 fixed라 3번에 속하는데, HTML에서 블로커보다 먼저 나옵니다. 규칙대로라면 나중에 나온 블로커가 헤더를 덮습니다. 최소 구현의 헤더에 z-index: 1이 붙은 이유입니다. z-index: auto인 상자의 쌓임 수준은 0이고, 값이 큰 요소가 작은 요소를 덮으므로 헤더가 블로커 위로 올라갑니다.[3][5]

앞에 둘 장식은 블로커 뒤에 쓴다

원문 블로그의 상단 영역에는 구름 장식도 있습니다. 뒤에서 앞으로 본문 텍스트, 블로커, 어두운 배경 구름, 흰 전경 구름 순서로 겹치고, 블로커는 텍스트를 가리되 절대 위치(absolute) 구름 SVG의 뒤로 미끄러져 들어갑니다.[1] 같은 3번 그룹 안에서는 HTML 순서가 그리는 순서이므로, 구름을 블로커보다 뒤에 쓰면 됩니다.[3]

<div class="hero">
  <div class="blocker"></div>
  <h1>Article Title</h1>
  <svg class="cloud back">…</svg>  <!-- 블로커 위 -->
  <svg class="cloud front">…</svg> <!-- 가장 앞(헤더 제외) -->
</div>

<style>
  .hero { position: relative; }  /* 구름의 기준. z-index 없음 */
  .cloud { position: absolute; bottom: 0; }
</style>

자주 하는 실수: 구역에 z-index를 주기

.hero에 position: relative만 주면 쌓임 맥락이 생기지 않습니다. relative와 absolute는 z-index가 auto가 아닐 때만 새 쌓임 맥락을 만듭니다.[2][4] 그런데 "구름이 안 보여서" .hero에 z-index를 주면 문제가 생깁니다.

.hero {
  position: relative;
  z-index: 2;
  /* .hero 전체가 쌓임 수준 2인 한 덩어리가 됨 */
  /* 헤더(z-index: 1)보다 위 → 상단 영역에서 헤더 메뉴가 가려짐 */
}

쌓임 맥락은 부모 맥락 안에서 하나의 단위로 취급되고, 자식의 z-index는 그 맥락 안에서만 의미가 있습니다.[4] 블로커와 구름이 .hero 안에 갇힌 채 .hero가 통째로 헤더 위로 올라가는 것입니다. opacity가 1 미만이거나 transform, filter가 none이 아니어도 쌓임 맥락이 생기니[4], 블로커가 엉뚱하게 그려지면 개발자 도구에서 조상 요소들의 이런 속성부터 확인하세요.

정리

층 요소 핵심 선언 이유
맨 앞 헤더 position: fixed; z-index: 1; 배경은 투명. HTML에서 먼저 나와도 블로커 위에 그려지게 함
가운데 블로커 position: sticky; top: 0; 구역 배경색으로 칠함. 구역이 끝나면 함께 밀려남
가운데 위 장식(구름 등) position: absolute; 블로커보다 뒤에 써서 블로커 위에 그려짐
맨 뒤 제목·본문 위치 지정 없음 위치 지정 요소보다 항상 아래
  • 블로커 높이와 헤더 높이는 변수 하나로 묶습니다.
  • 구역 위쪽에 헤더 높이만큼 빈 공간이 있어야 합니다. 없으면 JavaScript로 헤더 배경을 바꾸는 쪽이 현실적입니다.[1]
  • 블로커가 헤더를 덮으면, 구역 조상에 쌓임 맥락을 만드는 속성이 있는지 먼저 봅니다.[4]

프론트엔드 팀이 해 볼 것

  1. 지금 프로젝트의 고정 헤더가 JavaScript로 배경색을 바꾸고 있다면, 구역마다 .blocker를 넣는 방식으로 바꿀 수 있는지 상단 여백부터 확인한다
  2. 헤더 높이를 --header-height 같은 CSS 변수 하나로 모으고, 헤더 높이를 쓰는 곳이 모두 그 변수를 참조하는지 점검한다
  3. 붙지 않는 스티키 요소가 있으면 개발자 도구에서 조상 요소의 overflow 값을 차례로 확인한다
