17:T5dcf,<h2 id="rsc는-데이터와-함께-코드를-보낸다">RSC는 데이터와 함께 코드를 보낸다</h2>
<p>React Server Components(RSC)는 서버에서 렌더링한 React 트리를 직렬화해 클라이언트로 보내고, 클라이언트가 이를 다시 React 트리로 되살리는 구조입니다. React 저장소에서는 직렬화기가 <code>packages/react-server</code>, 역직렬화기가 <code>packages/react-client</code>에 있습니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>. <code>react-server</code> README는 RSC를 본질적으로 Suspense·Lazy 같은 React 기본 요소를 지원하는 범용 직렬화·역직렬화 기능이라고 설명합니다<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup>.</p>
<h3 id="직렬화하기-쉬운-것-태그와-props">직렬화하기 쉬운 것: 태그와 props</h3>
<p>일반 HTML 태그로 된 트리는 평범한 객체로 바꾸면 됩니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</p>
<pre data-lang="js"><code class="hljs language-js"><span class="hljs-comment">// &#x3C;p>Hello, world&#x3C;/p> 를 직렬화하면</span>
{
  <span class="hljs-attr">type</span>: <span class="hljs-string">'p'</span>,
  <span class="hljs-attr">props</span>: {
    <span class="hljs-attr">children</span>: <span class="hljs-string">'Hello, world'</span>
  }
}
<span class="hljs-comment">// → JSON 문자열로 보내고, 받는 쪽에서 그대로 &#x3C;p>를 만든다</span>
</code></pre>
<p><code>react-server</code>가 렌더링할 수 있는 값은 <code>structuredClone()</code>이 다루는 타입의 상위 집합입니다. 복제 가능한 타입에 더해 Symbol, Promise, Iterator·Iterable, async Iterator·Iterable도 보낼 수 있습니다<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup>.</p>
<h3 id="직렬화하기-어려운-것-컴포넌트-함수">직렬화하기 어려운 것: 컴포넌트 함수</h3>
<p>문제는 상태와 이벤트를 가진 컴포넌트입니다. 아래 <code>Counter</code>는 서버에서 렌더 결과만 찍어 보내서는 안 됩니다. 클라이언트에서 실제로 동작해야 하므로 코드 자체가 건너가야 합니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</p>
<pre data-lang="js"><code class="hljs language-js"><span class="hljs-comment">// client.js</span>
<span class="hljs-string">'use client'</span>;
<span class="hljs-keyword">import</span> { useState, useEffect } <span class="hljs-keyword">from</span> <span class="hljs-string">'react'</span>;

<span class="hljs-keyword">export</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">Counter</span>(<span class="hljs-params">{ initialCount }</span>) {
  <span class="hljs-keyword">const</span> [count, setCount] = <span class="hljs-title function_">useState</span>(initialCount);
  <span class="hljs-comment">// ...</span>
}
</code></pre>
<pre data-lang="js"><code class="hljs language-js"><span class="hljs-comment">// 서버 컴포넌트에서</span>
<span class="hljs-keyword">import</span> { <span class="hljs-title class_">Counter</span> } <span class="hljs-keyword">from</span> <span class="hljs-string">'./client'</span>;

<span class="xml"><span class="hljs-tag">&#x3C;<span class="hljs-name">Counter</span> <span class="hljs-attr">initialCount</span>=<span class="hljs-string">{10}</span> /></span></span>
<span class="hljs-comment">// → type 자리에 들어갈 것이 문자열 'p'가 아니라 함수다</span>
</code></pre>
<p>가장 단순한 방법은 함수 소스를 문자열로 JSON에 넣는 것입니다. 원문 필자는 이 방법이 나쁘다고 봅니다. 클라이언트에서 문자열을 <code>eval</code>해야 하고, 같은 컴포넌트가 여러 번 나오면 같은 코드를 여러 번 보내게 되기 때문입니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</p>
<h3 id="코드-대신-주소를-보낸다">코드 대신 주소를 보낸다</h3>
<p>그래서 RSC는 코드를 정적 JS 파일로 따로 제공한다고 가정하고, 직렬화 결과에는 그 파일을 가리키는 참조만 넣습니다. <code>&#x3C;script></code> 태그가 <code>src</code>로 파일을 가리키는 것과 비슷합니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</p>
<pre data-lang="js"><code class="hljs language-js">{
  <span class="hljs-attr">type</span>: <span class="hljs-string">'/src/client.js#Counter'</span>, <span class="hljs-comment">// client.js를 불러와 Counter를 꺼낸다</span>
  <span class="hljs-attr">props</span>: {
    <span class="hljs-attr">initialCount</span>: <span class="hljs-number">10</span>
  }
}
<span class="hljs-comment">// → props(데이터)는 값으로, Counter(코드)는 주소로 보낸다</span>
</code></pre>
<aside class="poster" aria-label="코드가 아니라 모듈 주소를 보낸다"><span class="poster-line" aria-hidden="true">코드가 아니라</span><span class="poster-line poster-accent" aria-hidden="true">모듈 주소를 보낸다</span></aside>
<h2 id="use-client는-모듈-그래프에-긋는-경계">'use client'는 모듈 그래프에 긋는 경계</h2>
<p>어떤 모듈을 "주소로 보낼 코드"로 취급할지 정하는 표시가 <code>'use client'</code>입니다. 파일 맨 위에 쓰면 그 모듈과 그 모듈이 의존하는 모든 모듈(전이 의존성)이 클라이언트 코드가 됩니다. 서버 컴포넌트가 이런 파일을 import하면, 호환 번들러는 그 import를 서버 실행 코드와 클라이언트 실행 코드의 경계로 처리합니다<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup>.</p>
<h3 id="렌더-트리가-아니라-모듈-트리">렌더 트리가 아니라 모듈 트리</h3>
<p>react.dev의 예제를 줄이면 다음과 같습니다. <code>InspirationGenerator.js</code>에만 <code>'use client'</code>가 있습니다<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup>.</p>
<pre data-lang="jsx"><code class="hljs language-jsx"><span class="hljs-comment">// App.js — 지시어 없음</span>
<span class="hljs-keyword">import</span> <span class="hljs-title class_">FancyText</span> <span class="hljs-keyword">from</span> <span class="hljs-string">'./FancyText'</span>;
<span class="hljs-keyword">import</span> <span class="hljs-title class_">InspirationGenerator</span> <span class="hljs-keyword">from</span> <span class="hljs-string">'./InspirationGenerator'</span>;
<span class="hljs-keyword">import</span> <span class="hljs-title class_">Copyright</span> <span class="hljs-keyword">from</span> <span class="hljs-string">'./Copyright'</span>;

<span class="hljs-keyword">export</span> <span class="hljs-keyword">default</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">App</span>(<span class="hljs-params"></span>) {
  <span class="hljs-keyword">return</span> (
    <span class="xml"><span class="hljs-tag">&#x3C;></span>
      <span class="hljs-tag">&#x3C;<span class="hljs-name">FancyText</span> <span class="hljs-attr">title</span> <span class="hljs-attr">text</span>=<span class="hljs-string">"Get Inspired App"</span> /></span>
      <span class="hljs-tag">&#x3C;<span class="hljs-name">InspirationGenerator</span>></span>
        <span class="hljs-tag">&#x3C;<span class="hljs-name">Copyright</span> <span class="hljs-attr">year</span>=<span class="hljs-string">{2004}</span> /></span>
      <span class="hljs-tag">&#x3C;/<span class="hljs-name">InspirationGenerator</span>></span>
    <span class="hljs-tag">&#x3C;/></span></span>
  );
}
<span class="hljs-comment">// App            → 서버 컴포넌트</span>
<span class="hljs-comment">// FancyText      → 서버 컴포넌트 (App이 직접 렌더링)</span>
<span class="hljs-comment">// Copyright      → 서버 컴포넌트 (클라이언트 컴포넌트의 children인데도)</span>
<span class="hljs-comment">// InspirationGenerator → 클라이언트 컴포넌트</span>
</code></pre>
<p><code>Copyright</code>는 클라이언트 컴포넌트 안에 그려지지만 서버 컴포넌트입니다. <code>Copyright</code>를 import하고 호출하는 쪽은 <code>App</code>이고, <code>InspirationGenerator</code>는 이미 렌더링된 결과를 <code>children</code>으로 받을 뿐이기 때문입니다<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup>. 예제에서는 <code>InspirationGenerator</code>도 <code>FancyText</code>를 import해 씁니다. 이 사용처는 클라이언트 컴포넌트이므로, <code>FancyText</code> 정의는 서버에서도 실행되고 클라이언트에도 내려갑니다<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup>.</p>
<h3 id="자주-하는-실수">자주 하는 실수</h3>
<ul>
<li>지시어는 import보다 위, 파일 맨 처음에 둡니다. 주석은 위에 와도 되지만, 작은따옴표나 큰따옴표로만 쓰고 백틱은 안 됩니다<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup>.</li>
<li>이미 클라이언트 모듈인 파일에서 import한 모듈에 <code>'use client'</code>를 또 붙여도 아무 효과가 없습니다<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup>.</li>
<li>서버 모듈이 <code>'use client'</code> 모듈에서 가져온 값은 React 컴포넌트이거나 클라이언트 컴포넌트에 넘길 수 있는 직렬화 가능한 props여야 합니다. 그 밖의 용도로 쓰면 예외가 납니다<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup>.</li>
<li>서버 컴포넌트를 표시하는 지시어는 없습니다. <code>"use server"</code>는 서버 컴포넌트가 아니라 서버 함수용입니다<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup>.</li>
</ul>
<h2 id="클라이언트-참조와-서버-참조">클라이언트 참조와 서버 참조</h2>
<p>번들러가 경계를 찾으면 그다음은 React가 그 모듈을 "참조"로 다룰 수 있게 해야 합니다. <code>react-server</code>에는 렌더링할 수 있는 참조가 두 종류 있습니다<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup>.</p>
<h3 id="클라이언트-참조client-reference">클라이언트 참조(client reference)</h3>
<p>RSC 프레임워크가 번들링 중 <code>"use client"</code>를 만나면, 그 모듈에서 export한 값들을 <code>registerClientReference</code>로 등록해야 합니다. 그러면 Flight(RSC 렌더러의 코드명)는 그 값을 서버 모듈 그래프의 직접 의존성이 아니라 클라이언트에서 불러올 참조로 해석하고, 출력에 코드를 불러오는 방법을 기록합니다<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup>. 참조는 컴포넌트가 아니어도 됩니다<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup>.</p>
<pre data-lang="jsx"><code class="hljs language-jsx"><span class="hljs-comment">// 'use client' 모듈 두 개에서 가져온 값</span>
<span class="hljs-keyword">import</span> { alert } <span class="hljs-keyword">from</span> <span class="hljs-string">'...'</span>;      <span class="hljs-comment">// 함수</span>
<span class="hljs-keyword">import</span> { <span class="hljs-title class_">ClientComp</span> } <span class="hljs-keyword">from</span> <span class="hljs-string">'...'</span>; <span class="hljs-comment">// 컴포넌트</span>

<span class="hljs-title function_">createResponse</span>(
  <span class="xml"><span class="hljs-tag">&#x3C;<span class="hljs-name">App</span>></span>
    <span class="hljs-tag">&#x3C;<span class="hljs-name">ClientComp</span> <span class="hljs-attr">onClick</span>=<span class="hljs-string">{alert}</span> <span class="hljs-attr">message</span>=<span class="hljs-string">{</span>"<span class="hljs-attr">hello</span> <span class="hljs-attr">world</span>"} /></span>
  <span class="hljs-tag">&#x3C;/<span class="hljs-name">App</span>></span></span>,
  ...)
<span class="hljs-comment">// → ClientComp도, onClick에 넘긴 alert 함수도 참조로 직렬화된다</span>
</code></pre>
<p>일반 함수는 직렬화 대상이 아닙니다. 서버 함수 인자로도 서버 함수가 아닌 함수는 지원하지 않습니다<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup>. 여기서 <code>alert</code>는 클라이언트 모듈의 export라서 함수 본문 대신 주소로 보낼 수 있습니다.</p>
<h3 id="서버-참조server-reference">서버 참조(server reference)</h3>
<p>방향이 반대인 참조도 있습니다. <code>"use server"</code>가 붙은 함수는 클라이언트에서 호출할 수 있는 서버 진입점이 되고, <code>registerServerReference()</code>로 등록해 Flight가 서버 참조로 인식하게 합니다<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup>. 클라이언트에서 서버 함수를 부르면 인자를 직렬화한 네트워크 요청이 서버로 가고, 반환값도 직렬화되어 돌아옵니다<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup>.</p>
<pre data-lang="js"><code class="hljs language-js"><span class="hljs-comment">// actions.js</span>
<span class="hljs-string">'use server'</span>;

<span class="hljs-keyword">export</span> <span class="hljs-keyword">async</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">likeComment</span>(<span class="hljs-params">id</span>) {
  <span class="hljs-keyword">let</span> newLikeCount = <span class="hljs-keyword">await</span> db.<span class="hljs-title function_">incrementLikeCount</span>(id);
  <span class="hljs-keyword">return</span> newLikeCount;
}
<span class="hljs-comment">// → 클라이언트에는 함수 본문이 아니라 호출용 참조만 전달된다</span>
</code></pre>
<p>Parcel에서는 서버 함수마다 Parcel이 만든 id가 있고, 클라이언트는 이 id와 호출 인자를 HTTP 요청으로 서버에 보냅니다<sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup>. 네트워크 호출은 항상 비동기이므로 <code>'use server'</code>는 async 함수에만 쓸 수 있습니다. 인자는 클라이언트가 마음대로 정할 수 있으니 신뢰할 수 없는 입력으로 보고 검증·권한 확인을 해야 합니다<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup>.</p>
<h2 id="번들러-바인딩이-하는-세-가지-일">번들러 바인딩이 하는 세 가지 일</h2>
<p>참조를 문자열 하나로 만드는 것까지는 번들러 없이도 됩니다. React 저장소에는 번들러 없이 ESM으로 RSC를 돌리는 개념 증명 예제(<code>fixtures/flight-esm</code>)도 있습니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup><sup class="cite"><a href="#source-7" aria-label="출처 7">[7]</a></sup>. 원문 필자는 이 예제가 기록용에 가깝다고 봅니다. 추가 최적화 없이 단순하게 하면 너무 비효율적이라는 이유입니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</p>
<h3 id="모듈을-하나씩-받으면-생기는-폭포">모듈을 하나씩 받으면 생기는 폭포</h3>
<p>브라우저가 <code>/src/client.js</code>를 받아 실행해 보기 전에는 그 파일이 무엇을 import하는지 모릅니다. 의존성을 발견할 때마다 새 요청을 보내야 하니 요청이 줄줄이 이어지는 폭포(waterfall)가 생깁니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</p>
<pre data-lang="js"><code class="hljs language-js"><span class="hljs-comment">// client.js 를 받아 파싱한 뒤에야 다음 요청이 시작된다</span>
<span class="hljs-keyword">import</span> { useState } <span class="hljs-keyword">from</span> <span class="hljs-string">'react'</span>;          <span class="hljs-comment">// 요청 2</span>
<span class="hljs-keyword">import</span> { formatDate } <span class="hljs-keyword">from</span> <span class="hljs-string">'./formatters'</span>; <span class="hljs-comment">// 요청 3</span>
<span class="hljs-comment">// formatters.js 가 또 무언가를 import하면 → 요청 4 ...</span>
</code></pre>
<p>원문 필자는 이 문제의 답이 클라이언트 앱에서 오래 써 온 번들링이라고 봅니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>. 그래서 실제로 쓰는 RSC 통합은 번들러마다 따로 있고, Parcel·Webpack용 바인딩이 React 저장소에 있습니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</p>
<h3 id="빌드서버클라이언트">빌드·서버·클라이언트</h3>
<p>바인딩이 하는 일은 세 단계로 나뉩니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</p>
<ol>
<li><strong>빌드</strong>: <code>'use client'</code> 파일을 찾아 그 파일들을 진입점으로 번들 청크를 만듭니다.</li>
<li><strong>서버</strong>: 모듈을 클라이언트로 보내는 표기법을 React에 알려 줍니다. 예를 들어 <code>'chunk123.js#Counter'</code>처럼 청크 이름으로 가리킵니다.</li>
<li><strong>클라이언트</strong>: 그 참조를 받으면 번들러 런타임에 모듈 로드를 요청하는 방법을 React에 알려 줍니다.</li>
</ol>
<pre data-lang="js"><code class="hljs language-js"><span class="hljs-comment">// 번들러 바인딩을 거친 뒤 (원문의 예시 표기)</span>
{
  <span class="hljs-attr">type</span>: <span class="hljs-string">'chunk123.js#Counter'</span>,
  <span class="hljs-attr">props</span>: { <span class="hljs-attr">initialCount</span>: <span class="hljs-number">10</span> }
}
</code></pre>
<p><code>react-server</code> README의 render 함수 예시도 직렬화할 트리(<code>model</code>)와 함께 <code>clientManifest: ClientManifest</code>를 인자로 받습니다<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup>. 직렬화기가 클라이언트 모듈 정보를 바깥에서 받는다는 점이 API 모양에도 드러납니다.</p>
<h3 id="실제-api-parcel">실제 API: Parcel</h3>
<p>원문은 <code>serialize</code>/<code>deserialize</code>라는 이름을 예시로 들고, 실제 이름은 바인딩마다 다르다고 밝힙니다. <code>@parcel/rsc</code>는 <code>react-server-dom-parcel</code> 위의 얇은 래퍼로, 직렬화를 <code>renderRSC</code>, 역직렬화를 <code>fetchRSC</code>로 제공합니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>. Parcel은 v2.14.0부터 RSC를 기본 지원하며 아직 베타이고, <code>react</code>·<code>react-dom</code> v19.1.0 이상이 필요합니다<sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup>.</p>
<pre data-lang="js"><code class="hljs language-js"><span class="hljs-comment">// server/server.js</span>
<span class="hljs-keyword">import</span> { renderRSC } <span class="hljs-keyword">from</span> <span class="hljs-string">"@parcel/rsc/node"</span>;

app.<span class="hljs-title function_">get</span>(<span class="hljs-string">"/comments"</span>, <span class="hljs-function">(<span class="hljs-params">req, res</span>) =></span> {
  <span class="hljs-keyword">let</span> stream = <span class="hljs-title function_">renderRSC</span>(<span class="xml"><span class="hljs-tag">&#x3C;<span class="hljs-name">Comments</span> /></span></span>);
  res.<span class="hljs-title function_">set</span>(<span class="hljs-string">"Content-Type"</span>, <span class="hljs-string">"text/x-component"</span>);
  stream.<span class="hljs-title function_">pipe</span>(res);
});
<span class="hljs-comment">// → 컴포넌트 트리를 직렬화한 RSC 페이로드를 스트림으로 응답</span>
</code></pre>
<pre data-lang="js"><code class="hljs language-js"><span class="hljs-comment">// src/App.js</span>
<span class="hljs-keyword">import</span> {fetchRSC} <span class="hljs-keyword">from</span> <span class="hljs-string">'@parcel/rsc/client'</span>;

<span class="hljs-keyword">let</span> request = <span class="hljs-literal">null</span>;
<span class="hljs-keyword">function</span> <span class="hljs-title function_">Comments</span>(<span class="hljs-params"></span>) {
  request ??= <span class="hljs-title function_">fetchRSC</span>(<span class="hljs-string">'http://localhost:3000/comments'</span>);
  <span class="hljs-keyword">return</span> request;
}
<span class="hljs-comment">// → Suspense 안에서 렌더링하면 페이로드 속 참조를 따라 청크를 불러온다</span>
</code></pre>
<p>역직렬화한 결과는 클라이언트에서 직접 쓴 JSX와 같아서 렌더링하거나 상태에 넣거나 HTML로 바꿀 수 있습니다<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>. Parcel 문서는 서버가 응답 렌더링에 필요한 클라이언트 컴포넌트와 CSS를 클라이언트에 알려 주므로, 리소스가 데이터와 병렬로 로드된다고 설명합니다<sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup>.</p>
<h4>자주 하는 실수: 하위 API를 직접 고정하지 않기</h4>
<p>React 19의 RSC 자체는 마이너 버전 사이에 깨지지 않지만, 번들러·프레임워크가 RSC를 구현할 때 쓰는 하위 API는 semver를 따르지 않습니다. React는 특정 버전에 고정하거나 Canary 릴리스를 쓰라고 권합니다<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup>. <code>react-server-dom-parcel</code>도 README에서 실험적 바인딩이라고 밝힙니다<sup class="cite"><a href="#source-8" aria-label="출처 8">[8]</a></sup>. 또 Parcel은 현재 <code>"use server"</code>를 파일 맨 위에만 지원하고 함수 안 인라인 지시어는 지원하지 않습니다<sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup>.</p>
