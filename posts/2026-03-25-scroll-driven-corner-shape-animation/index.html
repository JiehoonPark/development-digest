스크롤하면 모서리가 휘어진다 — corner-shape를 스크롤 타임라인에 묶기

corner-shape의 키워드는 모두 superellipse() 값이라 숫자처럼 보간됩니다. 이 값을 시간 대신 스크롤 위치에 묶으면 JavaScript 없이 페이지를 내릴수록 모양이 바뀌는 효과를 만들 수 있습니다. scroll()과 view() 타임라인의 동작, 끝값을 고르는 요령, 자주 틀리는 선언 순서까지 정리했습니다.

요약

  • animation-timeline: scroll()을 주면 애니메이션 진행률이 시간 대신 스크롤 위치를 따르므로 animation-duration을 따로 줄 필요가 없다[1][2]
  • corner-shape의 키워드는 superellipse() 값으로 계산되어 보간되므로, notch에서 square까지 스크롤에 맞춰 부드럽게 바뀐다[1][3]
  • superellipse(±infinity) 대신 ±6 같은 유한값을 끝값으로 쓰면 양 끝의 급격한 꺾임이 줄어든다[1]
  • animation 단축 속성은 animation-timeline을 auto로 되돌리므로, animation-timeline은 반드시 그 뒤에 선언한다[2]

시간 대신 스크롤을 타임라인으로

CSS 애니메이션은 기본적으로 문서가 열린 뒤 흐른 시간, 즉 DocumentTimeline을 따라 진행합니다.[2] animation-timeline 속성은 이 타임라인을 바꿉니다. 스크롤 진행 타임라인(scroll progress timeline)으로 바꾸면 스크롤 컨테이너를 위아래나 좌우로 움직일 때 애니메이션이 진행합니다.[2][4]

50% 스크롤했으면 애니메이션도 50% 지점에 있습니다.[1]

@keyframes grow {
  from { scale: 0.5; }
  to { scale: 1; }
}

.badge {
  animation: grow linear;
  animation-timeline: scroll();
}
/* 페이지 맨 위: scale 0.5 → 절반 스크롤: 0.75 → 맨 아래: 1 */

scroll()의 두 인자

scroll()은 이름 없는 스크롤 진행 타임라인을 만드는 함수이고, 어떤 스크롤러를 볼지(nearest, root, self)와 어느 축을 볼지(block, inline, x, y)를 인자로 받습니다.[5] 기본값은 nearest와 block이라서 scroll(), scroll(block), scroll(nearest block)은 모두 같은 뜻입니다.[5]

.a { animation-timeline: scroll(); }             /* 가장 가까운 스크롤 조상, 블록 축 */
.b { animation-timeline: scroll(root); }         /* 문서 루트 요소 */
.c { animation-timeline: scroll(inline self); }  /* 자기 자신의 인라인 축 */

자주 하는 실수

  • animation 단축 속성 뒤에 animation-timeline을 쓰지 않음. animation은 animation-timeline을 auto로 초기화하는 reset-only 값을 포함합니다. 그래서 animation-timeline을 먼저 쓰고 animation을 나중에 쓰면 다시 시간 기반으로 돌아갑니다.[2]
  • 스크롤바가 없는 축을 지정함. 지정한 축에 스크롤바가 없으면 타임라인이 비활성 상태가 되어 아무 일도 일어나지 않습니다.[5]
  • Firefox에서 길이를 생략함. MDN의 scroll() 예제는 Firefox가 애니메이션을 적용하려면 animation-duration: 1ms가 필요하다고 주석을 달아 둡니다.[5]

corner-shape는 숫자라서 보간된다

corner-shape는 border-radius가 차지하는 영역 안에서 모서리의 모양을 정하는 속성입니다.[3] 키워드별 생김새와 clip-path와의 차이는 이전 글 "Chromium에만 있는 CSS 세 가지"에서 다뤘으니, 여기서는 애니메이션에 필요한 성질 하나만 짚습니다. 모든 키워드는 superellipse() 함수의 특정 값과 같습니다.[1][3]

키워드 superellipse() 값
square superellipse(infinity)
squircle superellipse(2)
round superellipse(1)
bevel superellipse(0)
scoop superellipse(-1)
notch superellipse(-infinity)

계산된 값도 superellipse()이고, 애니메이션 유형은 superellipse 보간입니다.[3] 그래서 scoop에서 squircle로 가는 애니메이션은 사실 -1에서 2로 숫자가 바뀌는 애니메이션입니다.[3] 원문 필자도 corner-shape가 수학적으로 정의되어 있어서 쉽게 애니메이션된다고 설명합니다.[1]

키워드도 결국 숫자notch는 -∞, square는 +∞

border-radius가 좌표를 정한다

corner-shape는 border-radius가 없거나 0이면 효과가 없습니다.[3] 원문 필자는 이 관계를 이렇게 설명합니다. border-radius는 모서리 곡선이 시작될 x축·y축 좌표를 정하고, 그 사이를 실제로 둥글게 그리는 것은 기본값인 corner-shape: round라는 것입니다.[1]

/* 문법: x축 좌표, y축 좌표 */
border-bottom-left-radius: 50% 50%;
/* 두 값이 같으면 하나로 줄여 씀 */
border-bottom-left-radius: 50%;

이 점을 이용하면 한 모서리에만 모양을 줄 수 있습니다. border-bottom-left-radius만 지정하면 나머지 세 모서리는 반지름이 0이라 corner-shape를 무시합니다.[3]

화면 전체를 스크롤로 구부리기

원문의 대표 데모는 화면 전체를 덮는 흰 도형의 왼쪽 아래 모서리가 스크롤에 따라 안쪽으로 파였다가 바깥으로 부풀어 오르는 효과입니다.[1] 전체 코드는 다음과 같습니다.

@keyframes bend-it-like-beckham {
  from { corner-shape: notch; }  /* = superellipse(-infinity) */
  to { corner-shape: square; }   /* = superellipse(infinity) */
}

body::before {
  /* 뷰포트 채우기 */
  content: "";
  position: fixed;
  inset: 0;
  /* 아래 콘텐츠를 클릭할 수 있게 */
  pointer-events: none;
  /* 아래 레이어 색 반전 */
  mix-blend-mode: difference;
  background: white;
  /* 이게 없으면 corner-shape가 동작하지 않음 */
  border-bottom-left-radius: 100%;
  animation: bend-it-like-beckham;
  animation-timeline: scroll();
}

/* 반전에서 뺄 카드에 붙임 */
.no-filter {
  isolation: isolate;
}

핵심 선언은 네 가지입니다.

  • border-bottom-left-radius: 100%는 곡선의 시작 좌표를 각 축의 반대쪽 끝까지 밀어, 왼쪽 아래 모서리 하나가 화면 전체 크기의 곡선이 되게 합니다.[1]
  • 키프레임이 기본값 round를 덮어써서 notch(안쪽으로 꺾인 사각)에서 square(바깥으로 꺾인 사각)로 바뀝니다.[1]
  • 스크롤 기반 애니메이션이므로 길이를 지정하지 않았습니다.[1]
  • 원문은 키프레임에 superellipse(notch)라고도 적었지만, MDN의 형식 문법에서 superellipse()가 받는 값은 숫자와 infinity, -infinity뿐입니다.[1][3] 키워드를 쓸 때는 함수로 감싸지 말고 notch처럼 그대로 씁니다.
  • 도형이 콘텐츠 위에 있으므로 pointer-events: none으로 클릭을 통과시킵니다.[1]

색 반전과 쌓임 맥락

mix-blend-mode는 같은 쌓임 맥락(stacking context) 안에서 뒤에 그려진 내용과 요소를 섞습니다.[6] 흰 배경에 difference를 주면 아래 색이 반전되고, 반전에서 뺄 카드에는 새 쌓임 맥락을 만드는 isolation: isolate를 붙입니다.[1][7]

끝값을 ±infinity로 두지 않는다

이 데모는 처음과 끝에서 곡선이 날카롭고 도형이 모서리로 빨려 들어가 보이며, 뷰포트 가장자리에 붙어 답답합니다.[1] 원문 필자는 두 가지를 고칩니다.[1]

body::before {
  inset: -1rem; /* 도형을 뷰포트 밖으로 1rem 넓힘 */
}

@keyframes bend-it-like-beckham {
  from { corner-shape: superellipse(-6); }
  to { corner-shape: superellipse(6); }
}

도형을 넓히면 애니메이션이 늦게 시작해 일찍 끝나 보이는데, 끝값을 ±6으로 줄이면 상쇄됩니다.[1] 대신 도형 일부가 항상 남으므로 그 부분이 뷰포트 밖에 머물도록 값을 조정합니다.[1]

모양을 바꾸는 다른 패턴

border-radius를 움직이는 마스크

모양은 고정하고 border-radius를 움직여도 됩니다. 원문의 두 번째 예제는 뷰포트 안쪽에 테두리를 그리고, 그 위를 배경색과 같은 notch 도형으로 덮은 뒤 스크롤에 따라 네 모서리를 드러냅니다.[1]

@keyframes tech-corners {
  from { border-radius: 0; }
  to { border-radius: 20vw / 20vh; }
}

body::before { /* 테두리 */
  content: "";
  position: fixed;
  inset: 1rem;
  border: 1rem solid black;
}

body::after { /* 테두리를 가리는 notch 도형 */
  content: "";
  position: fixed;
  inset: -3rem;
  background: inherit;
  rotate: 5deg;
  corner-shape: notch;
  animation: tech-corners;
  animation-timeline: scroll();
}

main { /* 콘텐츠를 도형 위로 */
  position: relative;
  z-index: 1;
}

20vw / 20vh는 각 모서리의 x축 20vw, y축 20vh입니다.[1] 시작할 때는 반지름이 0이라 notch가 효과가 없고 도형이 테두리를 모두 가립니다.[3] 반지름이 커질수록 네 모서리가 파이며 테두리가 드러납니다.[1] 고정 가상 요소가 콘텐츠를 덮으므로 main의 z-index를 올리는 것도 잊지 않습니다.[1]

여러 요소에 같은 타임라인

원문의 세 번째 예제는 div를 여러 겹 중첩하고, 모두에 corner-shape: bevel과 border-radius: 100%를 주어 마름모를 만듭니다.[1] 키프레임은 padding만 7rem에서 14rem으로 키웁니다.[1]

@keyframes diamonds-are-forever {
  from { padding: 7rem; }
  to { padding: 14rem; }
}

#diamonds {
  position: fixed;
  inset: 50% auto auto 50%;
  translate: -50% -50%;

  &, div {
    corner-shape: bevel;
    border-radius: 100%;
    animation: diamonds-are-forever;
    animation-timeline: scroll();
    border: 0.0625rem solid #00000030;
  }
}

bevel은 border-radius의 양 끝을 직선으로 잇는 값입니다.[3] 각 요소의 padding이 바깥 요소 안에 쌓이므로, 스크롤할수록 마름모들이 동시에 커지며 퍼집니다.

원문 필자는 스크롤 스냅(scroll-snap-type: y)이나 scrollIntoView() 같은 다른 스크롤 기능과도 이 애니메이션이 그대로 함께 동작한다고 봅니다.[1]

보이는 동안만 바꾸기: view()

scroll()은 스크롤러 전체 진행률을 봅니다. 카드 하나가 화면에 들어오는 동안만 모양을 바꾸고 싶다면 보기 진행 타임라인(view progress timeline)을 만드는 view()를 씁니다.[8] 기본적으로 요소가 스크롤러 한쪽 끝에서 처음 보일 때 0%, 반대쪽 끝을 완전히 빠져나갈 때 100%입니다.[2][8]

animation-range는 타임라인의 어느 구간에 애니메이션을 붙일지 정하고, 퍼센트는 전체 타임라인 기준입니다.[9]

@keyframes card-corner {
  from { corner-shape: scoop; }
  to { corner-shape: squircle; }
}

.card {
  border-radius: 2rem;
  animation: card-corner linear both;
  animation-timeline: view();
  animation-range: 0% 50%;
}
/* 카드가 아래에서 들어오기 시작: scoop(-1)
   타임라인 절반 지점: squircle(2), 이후 유지 */

자주 하는 실수: 구간 밖에서 원래 모양으로 돌아감

키프레임 스타일은 기본적으로 애니메이션 구간 안에서만 적용됩니다.[9] 위 예제에서 both를 빼면 타임라인 50%를 지나는 순간 카드가 round로 돌아갑니다. 구간 밖에서도 첫 키프레임이나 마지막 키프레임을 유지하려면 animation-fill-mode를 backwards, forwards, both 중 하나로 줍니다.[9]

하고 싶은 일 쓰는 것 주의점

모서리 모양을 연속으로 바꾸기 corner-shape 키프레임 border-radius가 0이면 효과 없음[3]

지원 범위

원문 필자는 corner-shape가 아직 Chrome에서만 동작하고, 데모를 온전히 보려면 Chrome 139 이상이 필요하다고 적습니다.[1] 스크롤 기반 애니메이션은 Interop 2026에 포함돼 있어, Firefox가 플래그 없이 지원하면 Baseline이 될 것으로 봅니다.[1] MDN은 현재 corner-shape와 animation-timeline을 모두 Baseline이 아닌 제한적 지원으로 표시합니다.[3][2] 그러니 장식으로만 쓰고, 미지원 브라우저는 MDN 예제처럼 @supports not (animation-timeline: scroll())로 따로 처리합니다.[5]

프론트엔드 팀이 해 볼 것

  1. Chrome 139 이상에서 빈 페이지에 원문의 body::before 코드를 붙여 넣고, 키프레임 끝값을 ±infinity와 ±6으로 바꿔 가며 양 끝의 차이를 비교한다
  2. 기존 프로젝트에서 animation 단축 속성과 animation-timeline을 함께 쓰는 곳을 찾아 선언 순서가 animation 다음인지 확인한다
  3. 카드 목록에 animation-timeline: view()와 animation-range: 0% 50%를 적용해 보고, both를 넣고 뺄 때 구간 밖 모양이 어떻게 달라지는지 확인한다
