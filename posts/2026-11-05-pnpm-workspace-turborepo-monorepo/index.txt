18:T6c24,<h2 id="저장소-뼈대-잡기">저장소 뼈대 잡기</h2>
<p>모노레포(monorepo)는 여러 프로젝트를 저장소 하나에 두는 방식이고, pnpm은 이를 워크스페이스(workspace)로 기본 지원합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> Turborepo는 패키지 매니저의 워크스페이스 위에서 태스크를 실행합니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup></p>
<h3 id="패키지-위치-선언">패키지 위치 선언</h3>
<p>워크스페이스 루트에는 <code>pnpm-workspace.yaml</code>이 있어야 하고, <code>packages</code> 필드에 프로젝트 디렉터리를 적습니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> Turborepo 문서는 애플리케이션은 <code>apps/</code>, 라이브러리와 도구는 <code>packages/</code>로 나누는 것부터 시작하라고 권합니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup> 이 글의 예제 저장소는 다음과 같습니다.</p>
<pre data-lang="yaml"><code class="hljs language-yaml"><span class="hljs-comment"># pnpm-workspace.yaml</span>
<span class="hljs-attr">packages:</span>
  <span class="hljs-bullet">-</span> <span class="hljs-string">"apps/*"</span>
  <span class="hljs-bullet">-</span> <span class="hljs-string">"packages/*"</span>

<span class="hljs-comment"># 결과 구조</span>
<span class="hljs-comment"># apps/web/package.json          → web (Next.js 앱)</span>
<span class="hljs-comment"># packages/ui/package.json       → @repo/ui</span>
<span class="hljs-comment"># packages/config/package.json   → @repo/config (tsconfig 공유)</span>
</code></pre>
<p><code>apps</code>나 <code>packages</code> 아래 <code>package.json</code>이 있는 디렉터리는 모두 패키지가 됩니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup> 다만 Turborepo는 <code>apps/**</code>처럼 중첩된 패키지를 지원하지 않아서, <code>apps/a</code>와 <code>apps/a/b</code>에 각각 패키지를 두면 오류가 납니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup> 이름에 <code>@repo/</code> 같은 네임스페이스 접두사를 붙이면 npm 레지스트리 패키지와의 충돌을 피할 수 있습니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup></p>
<h3 id="루트-packagejson에는-도구만">루트 package.json에는 도구만</h3>
<p>루트 <code>package.json</code>은 워크스페이스의 바탕입니다. 공식 예시는 <code>turbo run</code> 스크립트와 <code>turbo</code> 개발 의존성만 둡니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup></p>
<pre data-lang="json"><code class="hljs language-json"><span class="hljs-punctuation">{</span>
  <span class="hljs-attr">"private"</span><span class="hljs-punctuation">:</span> <span class="hljs-literal"><span class="hljs-keyword">true</span></span><span class="hljs-punctuation">,</span>
  <span class="hljs-attr">"scripts"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">{</span>
    <span class="hljs-attr">"build"</span><span class="hljs-punctuation">:</span> <span class="hljs-string">"turbo run build"</span><span class="hljs-punctuation">,</span>
    <span class="hljs-attr">"dev"</span><span class="hljs-punctuation">:</span> <span class="hljs-string">"turbo run dev"</span><span class="hljs-punctuation">,</span>
    <span class="hljs-attr">"lint"</span><span class="hljs-punctuation">:</span> <span class="hljs-string">"turbo run lint"</span>
  <span class="hljs-punctuation">}</span><span class="hljs-punctuation">,</span>
  <span class="hljs-attr">"devDependencies"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">{</span>
    <span class="hljs-attr">"turbo"</span><span class="hljs-punctuation">:</span> <span class="hljs-string">"latest"</span>
  <span class="hljs-punctuation">}</span>
<span class="hljs-punctuation">}</span>
</code></pre>
<p><code>turbo</code> 명령은 루트 <code>package.json</code>에만 씁니다. 패키지의 스크립트에 넣으면 <code>turbo</code>가 재귀로 호출될 수 있습니다.<sup class="cite"><a href="#source-7" aria-label="출처 7">[7]</a></sup> 락파일도 꼭 커밋합니다. Turborepo는 락파일로 내부 패키지 사이의 의존 관계를 파악하고, 락파일이 없으면 예측할 수 없게 동작할 수 있습니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup></p>
<h4>자주 하는 실수: 루트에 앱 의존성 몰기</h4>
<p><code>react</code>나 <code>next</code>를 루트에 한 번만 설치하면 편해 보이지만, Turborepo 문서는 의존성을 실제로 쓰는 패키지에 설치하라고 권하고, 루트에 둘 것은 <code>turbo</code>, <code>husky</code>, <code>lint-staged</code> 같은 저장소 관리 도구뿐이라고 설명합니다.<sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup> 루트 <code>package.json</code>의 의존성을 바꾸면 모든 태스크가 캐시를 놓치기 때문입니다.<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup><sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup> 여러 패키지에 한 번에 설치할 때는 필터를 씁니다.<sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup></p>
<pre data-lang="bash"><code class="hljs language-bash">pnpm add jest --save-dev --recursive --filter=web --filter=@repo/ui
</code></pre>
<h2 id="내부-패키지-연결과-버전-통일">내부 패키지 연결과 버전 통일</h2>
<h3 id="workspace-프로토콜">workspace: 프로토콜</h3>
<p>내부 패키지(Internal Package)는 소스 코드가 워크스페이스 안에 있는 라이브러리입니다. 버전 대신 패키지 매니저의 워크스페이스 문법으로 설치합니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></p>
<pre data-lang="json"><code class="hljs language-json"><span class="hljs-punctuation">{</span>
  <span class="hljs-attr">"name"</span><span class="hljs-punctuation">:</span> <span class="hljs-string">"web"</span><span class="hljs-punctuation">,</span>
  <span class="hljs-attr">"dependencies"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">{</span>
    <span class="hljs-attr">"next"</span><span class="hljs-punctuation">:</span> <span class="hljs-string">"latest"</span><span class="hljs-punctuation">,</span>
    <span class="hljs-attr">"@repo/ui"</span><span class="hljs-punctuation">:</span> <span class="hljs-string">"workspace:*"</span>
  <span class="hljs-punctuation">}</span><span class="hljs-punctuation">,</span>
  <span class="hljs-attr">"devDependencies"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">{</span>
    <span class="hljs-attr">"@repo/config"</span><span class="hljs-punctuation">:</span> <span class="hljs-string">"workspace:*"</span>
  <span class="hljs-punctuation">}</span>
<span class="hljs-punctuation">}</span>
</code></pre>
<p><code>workspace:</code> 프로토콜을 쓰면 pnpm은 로컬 워크스페이스 패키지가 아닌 것으로는 해석하지 않습니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 패키지를 <code>pnpm pack</code>이나 <code>pnpm publish</code>로 묶을 때는 <code>workspace:*</code>가 실제 버전으로 바뀝니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>
<pre data-lang="json"><code class="hljs language-json"><span class="hljs-comment">// 워크스페이스의 foo가 1.5.0일 때 발행 전 변환</span>
<span class="hljs-attr">"foo"</span><span class="hljs-punctuation">:</span> <span class="hljs-string">"workspace:*"</span>   <span class="hljs-comment">// → "1.5.0"</span>
<span class="hljs-attr">"qar"</span><span class="hljs-punctuation">:</span> <span class="hljs-string">"workspace:^"</span>   <span class="hljs-comment">// → "^1.5.0"</span>
</code></pre>
<h4>자주 하는 실수: 버전 범위로 적기</h4>
<p><code>"@repo/ui": "^1.0.0"</code>처럼 일반 범위를 쓰면 결과가 설정에 따라 달라집니다. <code>linkWorkspacePackages</code>의 기본값은 <code>false</code>이고, 이때 로컬 패키지는 <code>workspace:</code>를 쓸 때만 링크됩니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> <code>true</code>로 켜도 선언한 범위를 만족하는 로컬 버전이 없으면 레지스트리에서 설치하며, pnpm 문서도 이 동작이 불확실성을 낳는다고 설명합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> <code>saveWorkspaceProtocol</code> 기본값은 <code>rolling</code>이라, <code>pnpm add</code>로 추가하면 <code>savePrefix</code>에 따라 <code>workspace:*</code>나 <code>workspace:^</code> 같은 형태로 저장됩니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>
<h3 id="catalog-로-외부-버전-맞추기">catalog: 로 외부 버전 맞추기</h3>
<p>카탈로그(catalog)는 의존성 버전 범위를 재사용 가능한 상수로 정의하는 기능입니다.<sup class="cite"><a href="#source-8" aria-label="출처 8">[8]</a></sup> Turborepo 문서는 pnpm v9.5 이상에서 쓸 수 있다고 안내합니다.<sup class="cite"><a href="#source-6" aria-label="출처 6">[6]</a></sup></p>
<pre data-lang="yaml"><code class="hljs language-yaml"><span class="hljs-comment"># pnpm-workspace.yaml</span>
<span class="hljs-attr">packages:</span>
  <span class="hljs-bullet">-</span> <span class="hljs-string">"apps/*"</span>
  <span class="hljs-bullet">-</span> <span class="hljs-string">"packages/*"</span>
<span class="hljs-attr">catalog:</span>
  <span class="hljs-attr">react:</span> <span class="hljs-string">^18.3.1</span>
</code></pre>
<pre data-lang="json"><code class="hljs language-json"><span class="hljs-comment">// apps/web/package.json, packages/ui/package.json 모두</span>
<span class="hljs-attr">"react"</span><span class="hljs-punctuation">:</span> <span class="hljs-string">"catalog:"</span>
<span class="hljs-comment">// → "^18.3.1"을 직접 쓴 것과 같음</span>
</code></pre>
<p>업그레이드는 <code>pnpm-workspace.yaml</code> 한 줄만 고치면 되고, 버전을 하나로 유지하기 쉬워져 중복으로 인한 런타임 충돌과 번들 크기 증가를 피할 수 있습니다.<sup class="cite"><a href="#source-8" aria-label="출처 8">[8]</a></sup> 발행할 때 <code>catalog:</code>는 실제 범위로 바뀝니다.<sup class="cite"><a href="#source-8" aria-label="출처 8">[8]</a></sup></p>
<h2 id="내부-패키지의-진입점">내부 패키지의 진입점</h2>
<p>다른 패키지가 내부 패키지를 쓰는 통로는 <code>exports</code> 필드입니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup> <code>type</code>과 조건부 내보내기 규칙은 「사내 패키지는 ESM 하나로 — exports 설정과 토스뱅크의 세 가지 기준」에서 다뤘으니 모노레포에서의 선택만 봅니다. Turborepo 문서는 하위 경로(subpath)마다 진입점을 두는 방식이 배럴 파일을 피하게 해 준다고 설명합니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup> 배럴 파일이 실행 의존성을 넓히는 문제는 「파일만 나누면 끝일까 — JavaScript 모듈 경계 설계」를 참고하세요.</p>
<h3 id="just-in-time-패키지">Just-in-Time 패키지</h3>
<p>Just-in-Time 패키지는 사용하는 앱의 번들러가 컴파일합니다. TypeScript 파일을 그대로 내보내므로 빌드 스크립트가 없습니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></p>
<pre data-lang="json"><code class="hljs language-json"><span class="hljs-punctuation">{</span>
  <span class="hljs-attr">"name"</span><span class="hljs-punctuation">:</span> <span class="hljs-string">"@repo/ui"</span><span class="hljs-punctuation">,</span>
  <span class="hljs-attr">"exports"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">{</span>
    <span class="hljs-attr">"./button"</span><span class="hljs-punctuation">:</span> <span class="hljs-string">"./src/button.tsx"</span>
  <span class="hljs-punctuation">}</span><span class="hljs-punctuation">,</span>
  <span class="hljs-attr">"scripts"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">{</span>
    <span class="hljs-attr">"check-types"</span><span class="hljs-punctuation">:</span> <span class="hljs-string">"tsc --noEmit"</span>
  <span class="hljs-punctuation">}</span>
<span class="hljs-punctuation">}</span>
</code></pre>
<pre data-lang="tsx"><code class="hljs language-tsx"><span class="hljs-comment">// packages/ui/src/button.tsx</span>
<span class="hljs-keyword">import</span> <span class="hljs-keyword">type</span> { <span class="hljs-title class_">ReactNode</span> } <span class="hljs-keyword">from</span> <span class="hljs-string">"react"</span>;

<span class="hljs-keyword">export</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">Button</span>(<span class="hljs-params">{ children }: { children: ReactNode }</span>) {
  <span class="hljs-keyword">return</span> <span class="xml"><span class="hljs-tag">&#x3C;<span class="hljs-name">button</span>></span>{children}<span class="hljs-tag">&#x3C;/<span class="hljs-name">button</span>></span></span>;
}

<span class="hljs-comment">// apps/web/app/page.tsx</span>
<span class="hljs-keyword">import</span> { <span class="hljs-title class_">Button</span> } <span class="hljs-keyword">from</span> <span class="hljs-string">"@repo/ui/button"</span>;

<span class="hljs-keyword">export</span> <span class="hljs-keyword">default</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">Page</span>(<span class="hljs-params"></span>) {
  <span class="hljs-keyword">return</span> <span class="xml"><span class="hljs-tag">&#x3C;<span class="hljs-name">Button</span>></span>Submit<span class="hljs-tag">&#x3C;/<span class="hljs-name">Button</span>></span></span>;
}
</code></pre>
<p>설정은 가장 적지만 소비하는 쪽이 TypeScript를 변환할 수 있어야 하고, 자체 빌드가 없어 Turborepo가 캐시할 수 없습니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup> 이 패키지에서는 <code>compilerOptions.paths</code>도 쓸 수 없어서, TypeScript 5.4 이상이면 Node.js 하위 경로 가져오기(<code>imports</code>)를 대신 쓰라고 권합니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup><sup class="cite"><a href="#source-9" aria-label="출처 9">[9]</a></sup></p>
<h3 id="compiled-패키지">Compiled 패키지</h3>
<p>Compiled 패키지는 <code>tsc</code> 같은 도구로 스스로 컴파일합니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup> 같은 <code>@repo/ui</code>를 이 방식으로 바꾸면 타입은 소스를, 실행은 <code>dist</code>를 가리킵니다.</p>
<pre data-lang="json"><code class="hljs language-json"><span class="hljs-punctuation">{</span>
  <span class="hljs-attr">"name"</span><span class="hljs-punctuation">:</span> <span class="hljs-string">"@repo/ui"</span><span class="hljs-punctuation">,</span>
  <span class="hljs-attr">"exports"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">{</span>
    <span class="hljs-attr">"./button"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">{</span>
      <span class="hljs-attr">"types"</span><span class="hljs-punctuation">:</span> <span class="hljs-string">"./src/button.tsx"</span><span class="hljs-punctuation">,</span>
      <span class="hljs-attr">"default"</span><span class="hljs-punctuation">:</span> <span class="hljs-string">"./dist/button.js"</span>
    <span class="hljs-punctuation">}</span>
  <span class="hljs-punctuation">}</span><span class="hljs-punctuation">,</span>
  <span class="hljs-attr">"scripts"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">{</span>
    <span class="hljs-attr">"build"</span><span class="hljs-punctuation">:</span> <span class="hljs-string">"tsc"</span>
  <span class="hljs-punctuation">}</span>
<span class="hljs-punctuation">}</span>
</code></pre>
<p>빌드 결과는 태스크의 <code>outputs</code>에 넣어야 Turborepo가 캐시합니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup> 편집기에서 정의로 이동이 원본 소스로 가려면 <code>declaration</code>과 <code>declarationMap</code>을 켭니다.<sup class="cite"><a href="#source-9" aria-label="출처 9">[9]</a></sup><sup class="cite"><a href="#source-10" aria-label="출처 10">[10]</a></sup> 발행할 패키지라면 <code>types</code>가 소스를 가리킬 수 없으니 선언 파일을 따로 만들어야 합니다.<sup class="cite"><a href="#source-9" aria-label="출처 9">[9]</a></sup></p>
<h3 id="설정-공유-패키지">설정 공유 패키지</h3>
<p>tsconfig도 패키지로 공유합니다. 공식 예시는 <code>base.json</code>을 두고 각 패키지의 <code>tsconfig.json</code>이 <code>extends</code>로 이어받게 합니다.<sup class="cite"><a href="#source-9" aria-label="출처 9">[9]</a></sup></p>
<pre data-lang="json"><code class="hljs language-json"><span class="hljs-comment">// apps/web/tsconfig.json</span>
<span class="hljs-punctuation">{</span>
  <span class="hljs-attr">"extends"</span><span class="hljs-punctuation">:</span> <span class="hljs-string">"@repo/config/base.json"</span><span class="hljs-punctuation">,</span>
  <span class="hljs-attr">"include"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">[</span><span class="hljs-string">"src"</span><span class="hljs-punctuation">]</span>
<span class="hljs-punctuation">}</span>
</code></pre>
<p>루트에는 <code>tsconfig.json</code>을 두지 않는 편이 좋습니다. 패키지마다 자기 설정을 가져야 타입 검사 캐시가 쉬워지고, 루트 변경은 모든 태스크의 캐시를 깨기 때문입니다.<sup class="cite"><a href="#source-9" aria-label="출처 9">[9]</a></sup></p>
<h2 id="turbojson-순서-캐시-필터">turbo.json: 순서, 캐시, 필터</h2>
<h3 id="dependson으로-순서-정하기">dependsOn으로 순서 정하기</h3>
<p><code>tasks</code>의 각 키는 <code>turbo run</code>으로 실행할 태스크이고, 같은 이름의 패키지 스크립트를 찾아 실행합니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup> <code>"build": {}</code>만 두면 모든 <code>build</code>가 병렬로 돌고 파일 출력도 캐시하지 않아서, 공식 문서도 잘못된 설정이라고 표시합니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup></p>
<pre data-lang="json"><code class="hljs language-json"><span class="hljs-punctuation">{</span>
  <span class="hljs-attr">"tasks"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">{</span>
    <span class="hljs-attr">"build"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">{</span>
      <span class="hljs-attr">"dependsOn"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">[</span><span class="hljs-string">"^build"</span><span class="hljs-punctuation">]</span><span class="hljs-punctuation">,</span>
      <span class="hljs-attr">"outputs"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">[</span>
        <span class="hljs-string">".next/**"</span><span class="hljs-punctuation">,</span>
        <span class="hljs-string">"!.next/cache/**"</span><span class="hljs-punctuation">,</span>
        <span class="hljs-string">"!.next/dev/**"</span><span class="hljs-punctuation">,</span>
        <span class="hljs-string">"dist/**"</span>
      <span class="hljs-punctuation">]</span>
    <span class="hljs-punctuation">}</span><span class="hljs-punctuation">,</span>
    <span class="hljs-attr">"topo"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">{</span> <span class="hljs-attr">"dependsOn"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">[</span><span class="hljs-string">"^topo"</span><span class="hljs-punctuation">]</span> <span class="hljs-punctuation">}</span><span class="hljs-punctuation">,</span>
    <span class="hljs-attr">"check-types"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">{</span> <span class="hljs-attr">"dependsOn"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">[</span><span class="hljs-string">"topo"</span><span class="hljs-punctuation">]</span> <span class="hljs-punctuation">}</span>
  <span class="hljs-punctuation">}</span>
<span class="hljs-punctuation">}</span>
<span class="hljs-comment">// turbo run build → @repo/ui의 build 완료 후 web의 build</span>
</code></pre>
<p><code>^</code>는 직접 의존하는 패키지의 태스크를 먼저 실행하라는 뜻입니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup> <code>^</code> 없이 쓰면 같은 패키지 안의 태스크를 가리킵니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup> <code>check-types</code>에는 공식 가이드의 전달 노드(Transit Node) <code>topo</code>를 썼습니다. 태스크는 병렬로 돌리면서 다른 패키지의 소스 변경은 해시에 반영하는 방법입니다.<sup class="cite"><a href="#source-9" aria-label="출처 9">[9]</a></sup></p>
<h3 id="outputs와-캐시-입력">outputs와 캐시 입력</h3>
<p><code>outputs</code>는 태스크가 성공했을 때 캐시할 파일입니다. 이 키가 없으면 파일을 캐시하지 않고, 다음 실행에서 캐시가 맞아도 파일은 복원되지 않습니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup> 글롭은 패키지 기준 상대 경로입니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup></p>
<aside class="callout-pitfall" aria-label="증상과 확인할 곳"><p class="callout-head"><span class="callout-tag">증상</span><strong>캐시가 맞았는데 <code>dist</code>가 없다</strong></p><p><code>turbo.json</code>의 <code>outputs</code>에 빌드 결과 경로가 있는지 확인합니다. 없으면 캐시가 맞아도 파일은 복원되지 않습니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup></p></aside>
<p>캐시가 맞으려면 무엇이 해시에 들어가는지 알아야 합니다. 전역 해시에는 해석된 <code>turbo.json</code>, 루트에 영향을 주는 락파일 변경, <code>globalDependencies</code> 파일, <code>globalEnv</code> 변수 값 등이 들어갑니다.<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup> 패키지 해시에는 패키지의 <code>package.json</code>, 그 패키지에 영향을 주는 락파일 변경, 그리고 기본으로 패키지 디렉터리의 Git 추적 파일 전체가 들어갑니다.<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup> 둘 중 하나라도 바뀌면 캐시를 놓칩니다.<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup></p>
<pre data-lang="json"><code class="hljs language-json"><span class="hljs-attr">"build"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">{</span>
  <span class="hljs-attr">"inputs"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">[</span><span class="hljs-string">"$TURBO_DEFAULT$"</span><span class="hljs-punctuation">,</span> <span class="hljs-string">"!README.md"</span><span class="hljs-punctuation">]</span>
<span class="hljs-punctuation">}</span>
<span class="hljs-comment">// README.md만 바꾸면 build는 캐시 히트</span>
</code></pre>
<p><code>inputs</code>를 직접 적으면 기본 동작 전체를 대체해 <code>.gitignore</code>도 무시되므로, 기본값을 유지하려면 <code>$TURBO_DEFAULT$</code>를 함께 씁니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup> 예상과 달리 캐시를 놓친다면 <code>--summarize</code>로 두 실행의 입력을 비교하고, <code>--dry</code>로 실행 없이 태스크와 해시를 확인합니다.<sup class="cite"><a href="#source-5" aria-label="출처 5">[5]</a></sup><sup class="cite"><a href="#source-11" aria-label="출처 11">[11]</a></sup></p>
<h3 id="--filter로-일부만-실행">--filter로 일부만 실행</h3>
<p>패키지 이름, 의존 관계, Git 변경으로 실행 범위를 좁힐 수 있습니다.<sup class="cite"><a href="#source-7" aria-label="출처 7">[7]</a></sup></p>
<pre data-lang="bash"><code class="hljs language-bash">turbo build --filter=@repo/ui     <span class="hljs-comment"># ui만</span>
turbo build --filter=...@repo/ui  <span class="hljs-comment"># ui와 ui에 의존하는 패키지</span>
turbo dev --filter=web...         <span class="hljs-comment"># web과 web이 의존하는 패키지</span>
turbo build --filter=[HEAD^1]     <span class="hljs-comment"># 직전 커밋 이후 바뀐 패키지</span>
turbo run build --affected        <span class="hljs-comment"># --filter=...[main...HEAD]와 같음</span>
</code></pre>
<p><code>--filter</code>를 여러 개 쓰면 합집합이지만, <code>--affected</code>와 <code>--filter</code>를 함께 쓰면 둘 다 만족하는 패키지만 고릅니다.<sup class="cite"><a href="#source-7" aria-label="출처 7">[7]</a></sup><sup class="cite"><a href="#source-11" aria-label="출처 11">[11]</a></sup> CI에서 <code>--affected</code>를 쓸 때는 체크아웃 이력이 충분해야 합니다. 너무 얕으면 모든 패키지를 바뀐 것으로 봅니다.<sup class="cite"><a href="#source-11" aria-label="출처 11">[11]</a></sup> pnpm도 <code>pnpm --filter "...[origin/master]" test</code>처럼 바뀐 패키지와 그 의존자를 고를 수 있습니다.<sup class="cite"><a href="#source-12" aria-label="출처 12">[12]</a></sup></p>
