border-bottom 밑줄은 이제 그만 — text-decoration으로 두께·간격 다루기

링크 밑줄의 색이나 두께를 바꾸려고 border-bottom이나 box-shadow로 가짜 밑줄을 그리던 습관이 아직 남아 있다면 바꿀 때입니다. 밑줄을 이루는 text-decoration 속성들을 하나씩 나누고, 링크 hover와 한글 글꼴에서 확인할 점까지 정리했습니다.

요약

  • 예전에는 밑줄 색을 글자 색과 따로 정할 수 없었고 두께도 브라우저마다 달라서, border-bottom으로 가짜 밑줄을 그리는 우회가 오래 쓰였다[1]
  • 지금은 text-decoration-color, text-decoration-thickness, text-underline-offset으로 색·두께·간격을 직접 정하고, 모두 Baseline 널리 사용 가능 단계다[2][3][4]
  • text-decoration 축약형은 두께까지 초기화하지만 text-underline-offset, text-underline-position, text-decoration-skip-ink는 건드리지 않는다[5]
  • 한중일(CJK) 글꼴에서는 기본값 auto가 밑줄을 끊지 않을 수 있어, 필요하면 text-decoration-skip-ink: all을 시험한다[6]

가짜 밑줄이 생긴 이유

밑줄은 원래 글자에 딸린 장식이라 손댈 곳이 거의 없었습니다. 밑줄 색은 글자 색을 그대로 물려받을 수밖에 없었고, 명세가 밑줄 두께를 정하지 않아 두께는 브라우저가 알아서 정했습니다. 그 결과 큰 글자에서 특히 브라우저마다 밑줄 굵기가 달랐습니다.[1]

그래서 오랫동안 쓰인 우회책이 밑줄을 끄고 테두리로 선을 긋는 방법입니다.[1]

/* 오래된 우회책: 테두리를 밑줄처럼 쓰기 */
a {
  border-bottom: 1px solid;
  text-decoration: none;
}
/* 결과: 색·두께는 마음대로 바뀌지만, 선은 글자가 아니라 상자 아래쪽에 붙는다 */

box-shadow로 상자 아래에 그림자 선을 넣는 방법도 같은 계열입니다. 둘 다 글자가 아니라 요소의 상자를 꾸미는 속성이라, 선이 글자 모양과 상관없이 상자 맨 아래에 그려집니다.

원문 필자는 이 방식이 우아하지 않고 보기에도 좋지 않다고 봅니다. 밑줄은 g, y처럼 아래로 내려오는 획(디센더, descender)이 있는 글자와 만나야 하는데 테두리는 그러지 못하기 때문입니다.[1] 반대로 진짜 밑줄은 글자를 기준으로 그려지므로, 디센더 근처에서 선을 끊을지 말지를 브라우저가 판단할 수 있습니다.[6]

가짜 밑줄은 상자를 꾸미고, 진짜 밑줄은 글자를 꾸밉니다. 디센더 근처를 어떻게 그릴지처럼 글자에 맞춰야 하는 판단은 진짜 밑줄에서만 할 수 있습니다.

밑줄을 이루는 네 가지 속성

text-decoration은 네 개의 개별 속성을 묶은 축약형(shorthand)입니다. 선의 종류 text-decoration-line, 색 text-decoration-color, 모양 text-decoration-style, 두께 text-decoration-thickness입니다.[5]

종류·모양·색

text-decoration-line은 어떤 선을 그을지 정합니다. underline, overline, line-through를 띄어 써서 여러 개를 함께 줄 수 있습니다.[7] text-decoration-style은 선 모양으로 solid, double, dotted, dashed, wavy 중 하나를 고릅니다.[8] text-decoration-color는 선 색이고, 초기값은 currentcolor라서 따로 정하지 않으면 글자 색을 따라갑니다.[4][5]

원문이 소개한 코드는 네 속성을 하나씩 다 적은 형태입니다.[1]

a {
  text-decoration-line: underline;
  text-decoration-color: teal;
  text-decoration-style: solid;
  text-decoration-thickness: 1px;
}
/* 결과: 글자 색과 상관없이 청록색 1px 실선 밑줄 */

두께: text-decoration-thickness

text-decoration-thickness는 밑줄·윗줄·취소선의 굵기를 정합니다.[2] 값은 네 가지입니다.[2]

  • auto: 브라우저가 적당한 두께를 고릅니다.
  • from-font: 글꼴 파일에 권장 두께가 있으면 그 값을 쓰고, 없으면 auto처럼 동작합니다.
  • 길이(3px, 0.1em): 글꼴의 권장값과 브라우저 기본값을 무시하고 이 값을 씁니다.
  • 퍼센트(10%): 현재 글꼴 1em에 대한 비율이고, 최소 1 장치 픽셀(device pixel)은 보장됩니다.
.thin  { text-decoration: underline red 1px; } /* 1px 빨간 밑줄 */
.thick { text-decoration: underline red 5px; } /* 5px 빨간 밑줄 */
.scale { text-decoration: underline 10%; }     /* 글자 크기에 비례 */

이 속성은 한때 text-decoration-width라는 이름이었고 2019년에 지금 이름으로 바뀌었습니다.[2] 예전 글이나 코드에서 옛 이름을 보면 같은 기능으로 읽으면 됩니다.

자주 하는 실수: 자식의 글자 크기를 따라갈 거라 기대하기

퍼센트 두께는 속성을 적용한 상자 전체에서 일정하게 유지됩니다. 안에 글자 크기가 다른 자식 요소가 있어도 두께는 바뀌지 않습니다.[2] 또 text-decoration-thickness는 상속되지 않는 속성입니다.[2] 링크 안에 큰 글씨 span을 넣었다고 그 부분만 밑줄이 굵어지지는 않습니다.

축약형이 초기화하는 것

축약형은 편하지만, 적지 않은 값을 초기값으로 되돌립니다. 두께도 축약형에 포함되므로 text-decoration: underline처럼 두께를 빼고 쓰면 앞서 정한 두께가 초기값 auto로 돌아갑니다.[2][5]

a {
  text-decoration-thickness: 3px;
  text-decoration: underline; /* 두께가 초기값 auto로 돌아감 */
}

a {
  text-decoration: underline 3px; /* 축약형 안에 두께까지 적기 */
}

반대로 text-decoration-skip-ink, text-underline-offset, text-underline-position은 밑줄에 영향을 주지만 축약형에는 들어 있지 않습니다.[5] 축약형을 다시 써도 이 셋은 유지됩니다.

자주 하는 실수: 자식에서 밑줄 지우기

장식선은 자손 텍스트 위로 이어서 그려집니다. 그래서 부모에 밑줄이 있으면 자식에서 text-decoration: none을 줘도 밑줄이 사라지지 않습니다.[5] 링크 안의 아이콘이나 배지에만 밑줄을 빼고 싶다면, 밑줄을 링크 전체가 아니라 글자를 감싼 요소에만 거는 식으로 구조를 바꿔야 합니다.

p  { text-decoration: underline; }
em { text-decoration: none; }     /* 효과 없음: em도 여전히 밑줄 */
em { text-decoration: overline; } /* em에만 윗줄이 하나 더 생김 */

위치와 간격, 그리고 한글

간격: text-underline-offset

text-underline-offset은 밑줄을 원래 위치에서 얼마나 떨어뜨릴지 정합니다. 밑줄에만 적용되고 윗줄이나 취소선에는 영향이 없습니다.[3] 값은 auto, 길이, 퍼센트이고, MDN은 글자 크기에 맞춰 함께 커지도록 em 단위를 권합니다.[3]

a {
  text-decoration: underline;
  text-underline-offset: 0.2em; /* 글자 크기에 비례해 아래로 */
}

이 속성은 상속되고, 퍼센트 값은 상대값 그대로 상속되어 글꼴이 바뀌면 함께 달라집니다.[3] 그래서 문서 전체 기준을 한 번 정해 두기 좋습니다.

:root {
  text-underline-offset: 20%; /* 모든 밑줄이 글자 크기의 20%만큼 내려감 */
}

border-bottom 우회에서 padding-bottom으로 하던 일을 이 속성 하나가 맡는다고 보면 됩니다.

위치: text-underline-position

text-underline-position은 밑줄을 어느 기준에 둘지 정합니다. under는 밑줄을 알파벳 기준선(baseline) 아래, 디센더와 겹치지 않는 위치로 내립니다. 아래 첨자가 많은 화학식이나 수식에서 읽기 좋게 하려는 값입니다.[9] 세로쓰기(vertical writing mode)에서는 left, right로 밑줄을 글자의 왼쪽이나 오른쪽에 둡니다.[9]

이 속성도 상속되고 축약형이 초기화하지 않으므로, MDN은 수식이 많은 문서라면 전역에 설정하는 방법을 소개합니다.[9]

:root {
  text-underline-position: under;
}
/* 결과: 모든 밑줄이 디센더와 겹치지 않는 기준선 아래에 놓임 */

잉크 건너뛰기: text-decoration-skip-ink

text-decoration-skip-ink는 밑줄과 윗줄이 글자의 위·아래로 튀어나온 획을 지날 때 선을 끊을지 정합니다.[6] 이 속성도 축약형에 들어 있지 않습니다.[6]

  • auto(기본값): 브라우저가 글자에 닿거나 가까워지는 곳에서 선을 끊을 수 있습니다.
  • none: 끊지 않고 텍스트 전체 길이에 선을 긋습니다.
  • all: 글자에 닿거나 가까워지는 곳에서 반드시 끊습니다.
p        { text-decoration: underline blue; }  /* auto가 기본 */
.no-skip { text-decoration-skip-ink: none; }   /* g, y 아래로 선이 지나감 */
.cjk     { text-decoration-skip-ink: all; }    /* 글자 근처는 항상 끊김 */

한글 글꼴에서 확인할 점

MDN은 일부 한중일(CJK) 글꼴에서 auto가 선을 끊지 않을 수 있고, 이때 all이 도움이 된다고 설명합니다.[6] 한글 본문에서 밑줄이 글자 아래쪽 획에 붙어 보인다면 먼저 all을 켜 보고 결과를 비교하세요.

all로도 답답하다면 선 자체를 내리는 방법이 있습니다. text-underline-offset을 em이나 퍼센트로 주거나 text-underline-position: under를 쓰면 됩니다.[3][9] 어느 쪽이 나은지는 글꼴마다 다르니, 실제 서비스에서 쓰는 한글 웹폰트로 받침이 많은 단어를 넣어 확인하는 것이 확실합니다.

링크 hover 밑줄

두께와 간격을 전환하기

text-decoration-thickness와 text-underline-offset의 애니메이션 유형은 "계산값 유형에 따름(by computed value type)"이고, text-decoration-color는 색으로 보간됩니다.[2][3][4] 반면 text-decoration-line과 text-decoration-style은 중간값 없이 바뀌는 이산(discrete) 유형입니다.[7][8] 그래서 hover 효과는 굵기·간격·색으로 만드는 편이 자연스럽습니다. 두 상태 사이의 변화는 transition으로 정하고, 상태는 :hover 같은 의사 클래스로 나눕니다.[10]

a {
  text-decoration: underline 1px;
  text-underline-offset: 0.2em;
  transition:
    text-decoration-thickness 0.2s,
    text-underline-offset 0.2s;
}
a:hover {
  text-decoration-thickness: 3px;
}
/* 결과: hover 하면 밑줄이 0.2초 동안 1px → 3px로 굵어짐 */

border-bottom 방식이라면 같은 효과를 위해 테두리 두께와 padding-bottom을 함께 조정해야 했지만, 여기서는 밑줄 속성만 바꿉니다.

자주 하는 실수: 색만 바꾸기

MDN은 글자 색과 text-decoration-color만 바꾸는 것으로는 링크에 포커스가 있다는 사실을 알리기에 부족하다고 설명합니다. 색만으로 의미를 전달하지 말라는 것입니다.[4] 굵기나 간격 변화처럼 색이 아닌 단서를 함께 주고, 같은 규칙을 :focus-visible에도 적용하세요. :focus-visible은 요소에 포커스가 있고 브라우저가 포커스를 눈에 보이게 표시해야 한다고 판단할 때 적용되는 의사 클래스입니다.[11]

a:hover,
a:focus-visible {
  text-decoration-thickness: 3px;
  text-decoration-color: currentcolor;
}

밑줄을 아예 없애는 것도 조심해야 합니다. MDN은 사용자가 링크를 알아보는 데 밑줄에 의존하는 경우가 많으니, 링크의 밑줄을 지울 때 주의하라고 적고 있습니다.[5] 밑줄 색을 흐리게 하거나 대비를 낮출 때도 글자·배경·밑줄 색의 대비가 충분한지 확인해야 합니다.[4]

text-underline-offset, text-underline-position, text-decoration-skip-ink, text-decoration, text-decoration-line에는 일부 기능의 지원 수준이 다를 수 있다는 표시가 붙어 있습니다.[3][5][6][9][7] 특정 값(예: from-font)에 기대는 경우에는 MDN 호환성 표를 따로 확인하세요.

기억할 규칙은 두 가지입니다. 축약형은 두께까지 초기화하고, 간격·위치·잉크 건너뛰기는 축약형 밖에 있습니다.[5]

프론트엔드 팀이 해 볼 것

  1. 프로젝트에서 border-bottom과 text-decoration: none이 함께 쓰인 링크 스타일을 검색해 text-decoration + text-underline-offset으로 바꿀 수 있는지 확인한다
  2. 서비스에서 쓰는 한글 웹폰트로 밑줄 링크를 띄워 text-decoration-skip-ink를 auto와 all로 번갈아 비교한다
  3. 링크 hover·focus 스타일이 색만 바꾸는지 점검하고, text-decoration-thickness 변화를 :focus-visible에도 함께 건다
