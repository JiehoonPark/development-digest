17:T6327,<h2 id="모달이-지키는-것과-막는-것">모달이 지키는 것과 막는 것</h2>
<p>화면 위에 무언가를 띄우는 UI는 이름이 비슷해도 성격이 다릅니다. 원문은 다음처럼 구분합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>
<table>
<thead>
<tr>
<th>용어</th>
<th>뜻</th>
</tr>
</thead>
<tbody>
<tr>
<td>다이얼로그(dialog)</td>
<td>사용자와 시스템의 대화를 가리키는 넓은 말</td>
</tr>
<tr>
<td>오버레이(overlay)</td>
<td>페이지 위에 뜨는 작은 콘텐츠 패널</td>
</tr>
<tr>
<td>모달(modal)</td>
<td>오버레이와만 상호작용 가능, 배경은 막힘</td>
</tr>
<tr>
<td>논모달(nonmodal)</td>
<td>오버레이가 떠 있어도 배경을 쓸 수 있음</td>
</tr>
<tr>
<td>라이트박스(lightbox)</td>
<td>배경을 어둡게 해 시선을 모으는 방식</td>
</tr>
</tbody>
</table>
<p>모달의 가장 큰 장점은 현재 화면의 맥락을 지킨다는 점입니다. 입력하던 값, 스크롤 위치, 펼친 아코디언, 고른 필터와 정렬이 그대로 남습니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 반대로 배경을 막기 때문에 다른 데이터와 비교하거나 값을 복사해 붙여 넣기 어렵습니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>
<p>HTML의 <code>&#x3C;dialog></code>는 두 방식을 모두 지원합니다. <code>show()</code>는 논모달로, <code>showModal()</code>은 모달로 엽니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup></p>
<pre data-lang="js"><code class="hljs language-js"><span class="hljs-keyword">const</span> panel = <span class="hljs-variable language_">document</span>.<span class="hljs-title function_">getElementById</span>(<span class="hljs-string">"panel"</span>);

panel.<span class="hljs-title function_">show</span>();      <span class="hljs-comment">// 논모달: 페이지의 나머지를 그대로 쓸 수 있음</span>
panel.<span class="hljs-title function_">close</span>();
panel.<span class="hljs-title function_">showModal</span>(); <span class="hljs-comment">// 모달: 바깥 요소가 inert가 되고 ::backdrop이 깔림</span>
</code></pre>
<p><code>showModal()</code>로 연 dialog는 최상위 레이어(top layer)에 그려지고, dialog와 그 자손을 뺀 같은 문서의 요소가 <code>inert</code> 속성을 준 것처럼 막힙니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup> 이미 <code>show()</code>로 열린 dialog에 <code>showModal()</code>을 호출하면 <code>InvalidStateError</code>가 발생합니다.<sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup> 그래서 위 예제는 중간에 <code>close()</code>를 넣었습니다.</p>
<h2 id="네-가지-질문으로-고르기">네 가지 질문으로 고르기</h2>
<p>원문은 Ryan Neufeld가 만든 결정 트리를 소개합니다. 페이지를 기본값으로 두고, 모달은 흐름을 끊고 집중시켜야 할 때만 씁니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 질문은 네 단계입니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>
<ol>
<li>아래 화면의 맥락을 유지해야 하는가</li>
<li>작업이 짧고 단순한가, 길고 복잡한가</li>
<li>작업 중에 배경 데이터를 자주 참고해야 하는가</li>
<li>오버레이로 간다면 모달인가 논모달인가(논모달 쪽으로 기운다)</li>
</ol>

<h3 id="모달을-피할-자리">모달을 피할 자리</h3>
<p>원문은 다음 경우에 모달을 쓰지 말라고 합니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>
<ul>
<li>오류 메시지, 새 기능 알림, 온보딩</li>
<li>길고 여러 단계로 된 작업. 모달 안의 마법사나 탭은 잘 동작하지 않고, 사이드 패널이나 드로어가 낫습니다</li>
<li>모달 위에 모달을 겹치는 구조. 이전/다음 이동으로 바꿉니다</li>
<li>사용자가 누르지 않았는데 저절로 뜨는 모달</li>
</ul>
<p>같은 작업을 반복하는 업무용 화면이라면 모달과 페이지 이동 모두 흐름을 끊습니다. 이때는 펼치는 영역이나 제자리 편집이 작업을 현재 화면에 붙잡아 둡니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup> 사용자가 같은 페이지를 탭 여러 개로 다시 열어 비교하고 있다면 모달이 비교를 막고 있다는 신호입니다.<sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup></p>

<h3 id="처음-포커스와-닫는-방법">처음 포커스와 닫는 방법</h3>
<p><code>showModal()</code>로 열면 포커스는 안쪽의 첫 번째 포커스 가능한 요소로 갑니다. <code>autofocus</code>로 위치를 명시하는 편이 안전합니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup> 되돌리기 어려운 동작을 확인하는 dialog라면 가장 덜 파괴적인 버튼에 포커스를 두는 것이 좋습니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup> 위 예제가 "삭제"가 아니라 "취소"에 <code>autofocus</code>를 둔 이유입니다.</p>
<p>닫는 방법은 <code>closedby</code> 속성으로 정합니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup></p>
<ul>
<li><code>any</code>: 바깥 클릭(라이트 디스미스), Esc, 개발자가 만든 버튼 모두 허용</li>
<li><code>closerequest</code>: Esc나 모바일의 뒤로 가기 제스처 같은 플랫폼 동작과 버튼만 허용</li>
<li><code>none</code>: 개발자가 만든 버튼으로만 닫힘</li>
</ul>
<p>값을 주지 않으면 <code>showModal()</code>로 연 dialog는 <code>closerequest</code>처럼 동작합니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup> 입력 폼이 든 모달에 <code>any</code>를 주면 실수로 바깥을 눌러 입력이 날아갈 수 있으니 용도에 맞춰 고릅니다. 어떤 경우든 눈에 보이는 닫기 버튼을 넣습니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></p>
<h4>자주 하는 실수</h4>
<ul>
<li><code>open</code> 속성으로 열기. 이렇게 열면 논모달이 됩니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup></li>
<li><code>&#x3C;dialog></code>에 <code>tabindex</code> 주기. dialog 자체는 포커스를 받는 요소가 아니므로 쓰지 않습니다.<sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup></li>
<li>모달이 아닌데 <code>aria-modal="true"</code> 주기. 일부 보조 기술 사용자는 바깥 콘텐츠를 아예 인식하지 못하게 됩니다.<sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup></li>
</ul>

<h2 id="url과-뒤로-가기">URL과 뒤로 가기</h2>
