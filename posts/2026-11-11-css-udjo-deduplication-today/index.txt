17:T391d,<h2 id="udjo-선언을-한-번만-쓰기">UDJO: 선언을 한 번만 쓰기</h2>
<p>UDJO(using declarations just once)는 같은 선언이 스타일시트에 두 번 이상 나타나면 셀렉터를 묶어 선언을 한 번만 남기는 기법입니다 <sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>. DRY(don't repeat yourself) 원칙에서 출발했고, 최소 18년 된 방식입니다 <sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</p>
<pre data-lang="css"><code class="hljs language-css"><span class="hljs-comment">/* before */</span>
<span class="hljs-selector-class">.example</span> {
  <span class="hljs-attribute">display</span>: flex;
}
<span class="hljs-selector-class">.sample</span> {
  <span class="hljs-attribute">display</span>: flex;
}

<span class="hljs-comment">/* after — 선언은 1개, 셀렉터는 2개 */</span>
<span class="hljs-selector-class">.example</span>,
<span class="hljs-selector-class">.sample</span> {
  <span class="hljs-attribute">display</span>: flex;
}
</code></pre>
<p>효과는 두 가지에 달려 있습니다 <sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>. 하나는 중복 제거가 얼마나 영리하게 되었는지, 즉 묶인 셀렉터 전체에 대해 그 선언을 정말 같이 바꿀 수 있는지입니다 <sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>. 다른 하나는 셀렉터 길이입니다. 셀렉터가 길면 묶느라 늘어난 셀렉터 문자열이 줄어든 선언보다 커질 수 있습니다 <sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</p>
<p>자주 하는 실수는 "같은 값이니까 같은 의도"라고 가정하는 것입니다. <code>.modal</code>과 <code>.toast</code>가 우연히 둘 다 <code>display: flex</code>일 뿐이라면, 묶는 순간 한쪽만 바꾸려 할 때마다 다시 분리해야 합니다. 유지보수 이득이 없는 중복 제거는 그냥 파일만 건드린 것입니다 <sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</p>
<h2 id="중복을-줄이면-파일은-커질-수도-있다">중복을 줄이면 파일은 커질 수도 있다</h2>
<p>원문 저자는 CSS Dedup이라는 도구를 만들어 임의로 고른 20개 사이트의 외부 스타일시트를 측정했습니다 <sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>. 결과는 직관과 어긋납니다.</p>
<ul>
<li>20개 사이트 전부에서 선언 중복을 줄일 수 있었습니다 <sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</li>
<li>그중 18개 사이트는 중복을 줄였더니 파일 크기가 <strong>늘었습니다</strong>. 셀렉터가 반복되고, 그 셀렉터가 절약된 선언보다 길었기 때문입니다 <sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</li>
<li>다만 모든 사이트에서, 크기가 줄어드는 스타일시트에만 선택적으로 적용하는 방식으로 하면 크기를 줄일 수 있었습니다 <sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</li>
</ul>
<p>증가 폭은 작지 않습니다. eff.org는 단순 중복 제거 시 +120.8 KB(+27.7%)였지만, 절감되는 경우만 공격적으로 적용하면 -8.5 KB(-2.0%)였습니다 <sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>. die-linke.de도 +104.0 KB(+20.5%) 대 -21.2 KB(-4.2%)였습니다 <sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</p>
<p>웹 개발자 개인 사이트 10곳은 양상이 달랐습니다. 파일이 커진 경우가 5곳으로, 조직 사이트의 90%에 비해 50%였습니다 <sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>. sarasoueidan.com은 단순 적용만으로도 -2.9 KB(-7.3%), 선택 적용 시 -4.5 KB(-11.1%)였습니다 <sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>. 개발자들이 더 짧은 셀렉터를 쓰기 때문에 UDJO의 이득을 더 볼 수 있다는 해석이 가능합니다 <sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</p>
<aside class="poster" aria-label="중복은 모두 줄일 수 있지만 줄인다고 작아지지 않는다"><span class="poster-line" aria-hidden="true">중복은 모두 줄일 수 있지만</span><span class="poster-line poster-accent" aria-hidden="true">줄인다고 작아지지 않는다</span></aside>
<p>이 수치들은 CSS 품질 지표가 아닙니다. 셀렉터 길이에 좌우되고, 해당 사례에서 중복 제거가 실제로 유지보수에 도움이 되는지 따로 확인해야 합니다 <sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>. 또한 압축(gzip/Brotli) 이후의 변화는 이 실험에 포함되지 않았습니다 <sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>. 실무에서는 압축 후 전송 크기까지 재보고 판단해야 합니다.</p>
<h2 id="묶기-전에-캐스케이드를-확인한다">묶기 전에 캐스케이드를 확인한다</h2>
<p>중복 제거는 선언의 위치를 바꿉니다. 그리고 위치는 캐스케이드가 승자를 정하는 방식의 일부입니다 <sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>. 브라우저는 관련성 → 중요도 → 출처 → 캐스케이드 레이어 → 명시도 → 스코프 근접성 → 등장 순서 순으로 값을 결정합니다 <sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup>.</p>
<h3 id="등장-순서">등장 순서</h3>
<p>명시도와 스코프 근접성까지 같다면, 마지막에 선언된 쪽이 이깁니다 <sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup>. 병합은 선언을 다른 위치로 옮기는 일이므로, 경쟁하는 규칙을 건너뛰는 순간 승자가 바뀝니다.</p>
<pre data-lang="html"><code class="hljs language-html"><span class="hljs-tag">&#x3C;<span class="hljs-name">p</span> <span class="hljs-attr">class</span>=<span class="hljs-string">"card alert"</span>></span>두 클래스를 함께 가진 요소<span class="hljs-tag">&#x3C;/<span class="hljs-name">p</span>></span>
</code></pre>
<pre data-lang="css"><code class="hljs language-css"><span class="hljs-comment">/* before: .card alert 요소는 blue
   — .alert 가 뒤에 오고 명시도가 같다 */</span>
<span class="hljs-selector-class">.card</span>  { <span class="hljs-attribute">color</span>: red; }
<span class="hljs-selector-class">.alert</span> { <span class="hljs-attribute">color</span>: blue; }
<span class="hljs-selector-class">.badge</span> { <span class="hljs-attribute">color</span>: red; }

<span class="hljs-comment">/* after: color: red 를 뒤쪽 위치로 모으면 */</span>
<span class="hljs-selector-class">.alert</span> { <span class="hljs-attribute">color</span>: blue; }
<span class="hljs-selector-class">.card</span>,
<span class="hljs-selector-class">.badge</span> { <span class="hljs-attribute">color</span>: red; }   <span class="hljs-comment">/* ← 같은 요소가 red 로 바뀐다 */</span>
</code></pre>
<p><code>color: red</code>는 <code>.card</code>와 <code>.badge</code> 두 곳에 중복이지만, 둘 사이에 같은 속성을 건드리는 <code>.alert</code>가 끼어 있습니다. 병합 위치가 <code>.alert</code> 뒤로 내려가면 등장 순서가 뒤집히고 결과가 달라집니다 <sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup>. 반대로 앞쪽 위치로 모으면 이 예제에서는 결과가 유지됩니다. 어느 쪽이든 중간에 같은 속성을 경쟁시키는 규칙이 하나라도 있으면 자동 병합은 안전하지 않습니다.</p>
<h3 id="단축-속성">단축 속성</h3>
<p>단축 속성(shorthand)은 명시하지 않은 하위 속성까지 포함해 모든 하위 속성을 설정합니다. 생략된 값은 초기값으로 들어갑니다 <sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup>.</p>
<pre data-lang="css"><code class="hljs language-css"><span class="hljs-selector-class">.a</span> { <span class="hljs-attribute">background</span>: green; }        <span class="hljs-comment">/* background-image 등도 초기화된다 */</span>
<span class="hljs-selector-class">.b</span> { <span class="hljs-attribute">background-color</span>: green; }  <span class="hljs-comment">/* 색만 바꾼다 */</span>
</code></pre>
<p>값이 같아 보여도 이 둘은 같은 선언이 아닙니다 <sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup>. 묶으면 <code>.b</code>에 다른 곳에서 상속·적용되던 배경 이미지가 사라질 수 있습니다.</p>
<h3 id="레이어와-출처">레이어와 출처</h3>
<p>캐스케이드 레이어가 다르면 선언의 우선순위 자체가 다릅니다. 일반 선언의 레이어 순서는 먼저 만들어진 레이어부터이고, 레이어에 속하지 않은 일반 스타일이 가장 마지막(가장 높은 우선순위)입니다 <sup class="cite"><a href="#source-3" aria-label="출처 3">[3]</a></sup>. <code>@import ... layer(framework.component)</code> 같은 구문으로 들어온 스타일시트도 그 레이어에 속합니다 <sup class="cite"><a href="#source-2" aria-label="출처 2">[2]</a></sup>. 레이어가 다른 두 규칙은 값이 같아도 묶으면 안 됩니다.</p>
<p>도구는 선언의 용도를 구분하지 못합니다. 그래서 무디고(blunt), 성능 이득만 취하도록 설정해서 쓰는 접근이 필요합니다 <sup class="cite"><a href="#source-1" aria-label="출처 1">[1]</a></sup>.</p>
<h2 id="값의-중복은-셀렉터가-아니라-커스텀-속성으로">값의 중복은 셀렉터가 아니라 커스텀 속성으로</h2>
<p>UDJO는 셀렉터를 묶어 선언의 반복을 줄입니다. 반면 커스텀 속성(custom properties)은 값을 한 곳에 정의하고 여러 곳에서 참조해 값의 반복을 줄입니다 <sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup>. 큰 사이트에서 같은 색이 수백 군데 중복되는 문제를 다루는 방식입니다 <sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup>.</p>
<pre data-lang="css"><code class="hljs language-css"><span class="hljs-selector-pseudo">:root</span> {
  <span class="hljs-attr">--main-bg-color</span>: teal;
}

<span class="hljs-selector-class">.one</span>,
<span class="hljs-selector-class">.three</span>,
<span class="hljs-selector-class">.four</span>,
<span class="hljs-selector-class">.five</span> {
  <span class="hljs-attribute">background-color</span>: <span class="hljs-built_in">var</span>(--main-bg-color);
}

<span class="hljs-selector-class">.two</span> {
  <span class="hljs-attribute">color</span>: black;
  <span class="hljs-attribute">background-color</span>: pink;
}
</code></pre>
<p>이 코드는 두 기법을 함께 쓴 형태입니다. 값은 <code>--main-bg-color</code> 한 곳에서 관리되고, 같은 선언을 쓰는 셀렉터는 하나로 묶였습니다 <sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup>.</p>
<p>주의할 점 세 가지입니다.</p>
<ul>
<li><code>var()</code>는 속성 값 자리에만 쓸 수 있습니다. 속성 이름, 셀렉터, 미디어 쿼리나 컨테이너 쿼리 조건에는 쓸 수 없습니다 <sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup>.</li>
<li>두 대시로 정의한 커스텀 속성은 항상 부모 값을 상속합니다 <sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup>. 값은 저장되는 게 아니라 필요한 지점에서 계산되므로, 형제의 자손 규칙에서 꺼내 쓸 수 없습니다 <sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup>.</li>
<li>상속을 끄거나 타입·초기값을 지정하려면 <code>@property</code>를 씁니다 <sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup>.</li>
</ul>
<pre data-lang="css"><code class="hljs language-css"><span class="hljs-keyword">@property</span> --box-color {
  syntax: <span class="hljs-string">"&#x3C;color>"</span>;
  inherits: false;
  initial-value: teal;
}
<span class="hljs-comment">/* 자식은 부모의 --box-color 를 물려받지 않는다 */</span>
</code></pre>
<p>커스텀 속성 이름은 대소문자를 구분합니다. <code>--my-color</code>와 <code>--My-color</code>는 별개입니다 <sup class="cite"><a href="#source-4" aria-label="출처 4">[4]</a></sup>.</p>
