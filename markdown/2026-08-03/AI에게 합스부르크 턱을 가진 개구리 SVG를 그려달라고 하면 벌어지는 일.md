## 아티클

# AI에게 "합스부르크 턱을 가진 개구리 SVG"를 그려달라고 하면 벌어지는 일

[frogs.vaguespac.es](https://frogs.vaguespac.es/)는 다소 엉뚱하지만 예리한 개인 AI 벤치마크 사이트입니다. 프롬프트는 단 하나, "Generate an SVG of a frog with a Habsburg jaw(합스부르크 턱을 가진 개구리를 SVG로 그려줘)"뿐입니다. 합스부르크 왕가는 근친혼으로 인해 아래턱이 심하게 돌출되는 유전적 특징(하악전돌증)으로 유명한데, 이걸 개구리라는 전혀 다른 대상에 이식하라는 요구는 언어 모델이 (1) "합스부르크 턱"이라는 문화적·해부학적 개념을 정확히 이해하고, (2) 그 특징을 SVG 좌표와 path로 실제로 표현할 수 있는지를 동시에 테스트하는 재미있는 척도가 됩니다. 이 사이트는 Anthropic의 Claude Opus, Claude Sonnet 등 여러 모델에게 같은 프롬프트를 3회씩 반복 실행시켜, 생성 시간·파일 크기·SVG 소스·그리고 코드에 남긴 주석의 성격까지 비교해서 보여줍니다.

## 벤치마크의 구조

각 실행 결과는 다음 정보를 함께 제공합니다.

- **모델명과 제공사** (예: `anthropic/claude-opus-5`, `anthropic/claude-sonnet-5`)
- **실행 회차와 날짜, 소요 시간, 결과물 바이트 크기** (예: Run 1 of 3 · Aug 2 2026 · 64.0s · 3,900 B)
- **SVG 코드 내 주석에 대한 짧은 해설** — 모델이 단순히 구조를 설명하는 라벨만 달았는지, 아니면 해부학적 해석이나 감정·분위기까지 덧붙였는지를 분석
- **실제 SVG 소스 코드** 전문

즉 이 벤치마크는 단순히 "그림이 예쁜가"를 넘어서, 모델이 결과물에 대해 스스로 어떤 언어로 설명하는지—즉 메타인지적 표현 방식—까지 관찰 대상으로 삼고 있는 셈입니다.

## Claude Opus의 세 번의 시도

Claude Opus는 세 번의 실행에서 각각 64.0초/3,900바이트, 42.0초/3,465바이트, 59.6초/3,909바이트의 결과를 냈습니다. 세 SVG 모두 공통적으로 다음과 같은 구조를 취합니다.

- `linearGradient` 또는 `radialGradient`로 피부색에 입체감을 부여 (밝은 연두색 → 어두운 초록색)
- 몸통은 `ellipse`로, 머리는 `path` 돔 형태로 표현
- 눈은 볼록 튀어나온 원(eye bulge)과 그 위에 다시 눈동자·홍채·하이라이트를 겹쳐 그리는 다층 구조
- 콧구멍은 작은 `ellipse` 두 개
- 몸 곳곳에 반투명 원으로 사마귀(warts)나 반점 표현
- 앞다리는 곡선 `path`로 마무리

핵심은 역시 턱 부분입니다. 세 실행 모두 주석에 명시적으로 `<!-- HABSBURG JAW: massive protruding mandible -->` 같은 표시를 달아두었는데, 실제로 아래턱을 몸통 아래쪽까지 거대하게 부풀린 `path`로 그리고, 위턱(입술)을 턱 뒤로 밀어 넣듯("recessed, tucked behind the jaw") 표현했습니다. 특히 아랫니가 윗입술 위로 튀어나온 형태(protruding lower teeth over the upper lip)를 작은 삼각형이나 둥근 사각형 여러 개로 표현해 부정교합(underbite)을 시각화한 점이 눈에 띕니다.

이 사이트의 해설에 따르면, Opus가 남긴 주석들은 단순한 구조 라벨을 넘어 "거대하게 돌출된 아래턱(massive protruding mandible)"이나 "왕족다운 눈꺼풀(droopy regal eyelids)" 같은 표현으로 해부학적 해석이나 분위기까지 편집자적으로 덧붙이는 경향이 있었습니다. 두 번째 실행에서는 특히 "규모감(HUGE)"과 "왕족의 위엄(regal)"이라는 수식어까지 등장해, 단순히 기하학적 형태를 묘사하는 데 그치지 않고 캐릭터에 서사를 부여하려는 모습을 보였습니다. 반면 세 번째 실행은 상대적으로 감정이나 왕족성에 대한 언급 없이 "거대하고 길쭉하게 돌출된 하악골(massive elongated protruding mandible)"처럼 해부학적 과장에만 집중한 주석을 남겼습니다.

세 실행의 코드 구조를 비교해보면 세부 구현 방식이 상당히 다릅니다.

- Run 1: 몸통과 머리를 별도의 `ellipse`/`path`로 분리하고, 턱은 하나의 복잡한 곡선 `path`로 처리
- Run 2: `radialGradient`를 3종류(g1, g2, g3) 사용해 머리·눈·턱에 각각 다른 하이라이트를 부여했고, 발을 `ellipse` 4개의 조합으로 좀 더 입체적으로 표현
- Run 3: `stroke`를 적극적으로 사용해 테두리선을 강조하는 카툰풍 스타일을 택했고, 위 눈꺼풀을 별도의 반원 `path`로 그려 넣어 눈매 표현에 신경 쓴 흔적이 보임

이처럼 같은 모델이 같은 프롬프트를 세 번 받았음에도 불구하고 색상 팔레트, 그래디언트 개수, 눈·이빨의 표현 방식이 매번 달라진다는 점은, SVG 생성이 결정론적이지 않고 매 실행마다 상당한 창작적 변주가 발생함을 보여줍니다.

## Claude Sonnet의 결과

Claude Sonnet의 첫 번째 실행은 7.1초 만에 1,237바이트짜리 SVG를 생성했습니다. Opus의 결과물(3,400~3,900바이트대)과 비교하면 크기가 3분의 1 이하로, 소요 시간 역시 6~9배가량 빠릅니다. 다만 이 실행의 SVG 소스는 `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 400 40`에서 잘려 있어 전체 코드를 확인할 수 없었고, 주석 역시 "No comments in the SVG"로 기록되어 Opus와 달리 별도의 해설 없이 순수 코드만 생성한 것으로 보입니다.

## 정리

이 벤치마크가 말해주는 핵심은 세 가지로 요약할 수 있습니다.

- **모델 규모와 응답 속도·크기의 트레이드오프**: Claude Opus는 40~64초에 걸쳐 3,400~3,900바이트의 상세한 SVG를 만든 반면, Claude Sonnet은 7초 만에 1,200바이트대의 훨씬 간결한 결과물을 냈습니다. 이는 "더 큰/느린 모델일수록 더 정교한 그래픽 디테일(그래디언트, 다층 눈, 이빨 개별 표현 등)을 만들어낸다"는 일반적인 직관과 일치합니다.
- **같은 모델도 실행마다 다른 결과**: Opus의 세 번의 시도는 색상 팔레트, 그래디언트 구성, 눈꺼풀 표현 방식이 모두 달라, SVG 코드 생성에도 상당한 확률적 변동성이 존재함을 보여줍니다.
- **모델이 남기는 주석의 성격 차이**: 어떤 모델(혹은 실행)은 구조를 설명하는 데 그치지 않고 "거대한(HUGE)", "왕족다운(regal)" 같은 편집자적 표현을 코드 주석에 남기는 반면, 다른 실행은 순수하게 해부학적 과장만 서술하거나 아예 주석을 남기지 않기도 합니다. 이는 같은 모델이라도 결과물에 대한 "자기 설명" 스타일이 일관되지 않을 수 있음을 시사합니다.

프론트엔드 개발자 입장에서 이 벤치마크가 흥미로운 이유는, LLM이 생성한 SVG가 실무에서 아이콘·일러스트 프로토타이핑에 쓰일 가능성이 커지는 상황에서, "그럴듯한 형태를 만드는 능력"과 "코드에 스스로 설명을 남기는 방식"이 모델마다, 그리고 같은 모델의 실행마다도 얼마나 편차가 큰지를 구체적인 예시로 보여주기 때문입니다. 결과물의 일관성이나 코드 가독성이 중요한 프로덕션 워크플로에 AI 생성 SVG를 도입하려 한다면, 이런 변동성을 감안한 검증 절차가 필요하다는 점을 시사합니다.
