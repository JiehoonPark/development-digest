## 핵심 개념

> [!abstract]
> Cursor, Claude Max, GPT Pro, Gemini Ultra 등을 합치면 월 320달러가 넘는 AI 구독 비용을 오픈소스 도구로 대체한 사례를 다룹니다. Ollama로 로컬 모델을 돌리고, Nine Router로 여러 모델 공급자를 폴백 티어 구조로 연결하며, Headroom으로 불필요한 토큰 낭비를 압축합니다. 이후 Dify의 비주얼 워크플로우 빌더와 SWE-bench 상위권 자율 코딩 에이전트인 Open Hands까지 연동해 자체 VPS 위에서 완결된 AI 개발 스택을 구축합니다.

## 아티클

AI 툴 구독료를 계산해본 적 있으신가요? Cursor에 20달러, Claude Max에 100달러, GPT Pro에 또 100달러, Gemini Ultra에 100달러... 여기에 11 Labs, DeepSeek, 그리고 2년 전 가입하고 잊어버린 API 키들까지 더하면 한 달에 320달러가 훌쩍 넘어갑니다. Fireship 채널에서는 이 비정상적인 지출 구조를 깨닫고 모든 구독을 해지한 뒤, 더 저렴하면서도 생산성은 오히려 높은 셀프 호스팅 AI 스택으로 갈아탄 이야기를 다룹니다. 이번 글에서는 그 과정에서 소개된 5가지 오픈소스 도구를 정리해봅니다.

## AI 구독료가 술값보다 무서운 이유

미국의 주류 판매량이 역대 최저치를 기록하고 있다는 통계가 있는데요, 아이러니하게도 그 원인 중 하나로 빅 AI 기업들의 구독 모델이 지목됩니다. Cursor, Claude Max, GPT Pro, Gemini Ultra를 동시에 결제하고 있다면 한 달 AI 지출이 웬만한 월세 수준에 도달하는 건 시간문제입니다. 이 글에서 소개하는 스택의 핵심 아이디어는 간단합니다. 인프라는 직접 서버에서 무료로 돌리되, 필요할 때만 Claude나 GPT 같은 대형 모델의 지능을 빌려 쓰는 하이브리드 구조를 만드는 것입니다.

## 1. Ollama - 모델을 내 손 안에

모든 AI 스택은 결국 모델이 있어야 시작됩니다. 대부분의 개발자는 자신의 프로퍼라이어터리 코드를 조 단위 시가총액의 기업에 전송하고 그들이 안전하게 지켜주길 믿는 방식을 택하는데요, Ollama를 쓰면 이 모든 걸 로컬에서 처리할 수 있습니다.

Ollama는 흔히 "LLM을 위한 Docker"라고 불립니다. 커맨드라인 인터페이스와 API를 통해 모델을 다운로드하고 자신의 머신에서 실행할 수 있게 해주는데요, 최신 중국산 오픈웨이트 모델이나 다른 공개 모델을 테스트해보기에도 안성맞춤입니다. 모든 프롬프트가 로컬에만 머물러 프라이버시가 보장되고, 추론 비용도 0원입니다. 신용카드 결제가 거절돼도 모델은 계속 작동한다는 뜻이죠.

문제는 대부분의 개인이 프론티어급 모델을 돌릴 만한 하드웨어를 갖고 있지 않다는 점입니다. 작은 모델은 어디서든 돌아가지만, 최상위급 모델을 로컬에서 구동하려면 작은 데이터센터 수준의 장비가 필요합니다. "바이브 엔지니어"가 최상급 슬롭 코드를 뽑아내려면 이 한계가 꽤 치명적입니다.

## 2. Nine Router - 여러 모델 공급자를 하나의 창구로

이 하드웨어 한계를 우회할 수 있는 셀프 호스팅 솔루션이 Nine Router입니다. 이 도구는 여러분의 AI 툴과 수십 개의 모델 공급자 사이에 위치하며, 로컬 엔드포인트 하나로 모든 걸 연결해줍니다. 아홉 개의 API 키를 저글링하는 대신, OpenAI 호환 프록시를 통해 localhost 하나로 모든 요청을 몰아넣을 수 있는 구조입니다.

Nine Router의 진짜 매력은 **폴백 티어(fallback tier)** 기능입니다.

- 티어 1: 이미 결제 중인 Claude Max 같은 구독 모델
- 티어 2: 저렴한 종량제(pay-per-token) 백업 모델 (예: OpenAI)
- 티어 3: Chinese 모델, Vertex 트라이얼 크레딧 등 완전 무료 공급자들

Claude Max 사용량을 다 소진하면 별다른 조작 없이 자동으로 다음 티어로 넘어가는 구조입니다. 여기에 더해 사용량을 추적하고, 툴 출력값을 압축해 토큰 소비를 줄여주는 기능도 있어서 결과적으로 비용을 상당히 절감할 수 있습니다.

## 3. Headroom - 컨텍스트 압축으로 토큰 낭비 막기

그래도 하루에 수십억 토큰을 태우고 있다면 Headroom을 알아둘 필요가 있습니다. 이 도구는 AI 에이전트를 위한 컨텍스트 압축 레이어인데요, div 하나를 가운데 정렬해달라고 요청했을 뿐인데 AI가 5만 줄짜리 package.json 파일을 통째로 읽고, 결국 Tailwind CSS 설치가 필요하다는 결론에 도달하기 위해 올림픽 규격 수영장 하나 분량의 물을 증발시키는(연산 리소스를 낭비하는) 비효율을 해결하기 위한 도구입니다.

Headroom은 애플리케이션과 모델 공급자 사이에 위치해서 툴 출력값, 로그 파일 등 과금 대상이 되는 불필요한 청크들을 모델에 전달하기 전에 미리 압축합니다. 흥미로운 설계 포인트는 이 압축이 **가역적(reversible)**이라는 점입니다. 모델에 전송되는 압축된 콘텐츠는 로컬 머신에 캐싱되기 때문에, 모델이 나중에 원본 데이터가 필요하다고 판단하면 언제든 다시 불러올 수 있습니다.

## 셀프 호스팅 인프라: Hostinger

여기까지 소개한 도구들을 어디에 배포할지가 관건인데요, 영상에서는 스폰서인 Hostinger의 VPS(가상 사설 서버)를 활용하는 방법을 제시합니다. Hostinger 패널에는 Docker 카탈로그가 내장돼 있어서, 지금까지 소개한 오픈소스 프로젝트들을 클릭 한 번으로 설치할 수 있고, 이 모든 도구를 같은 VPS 위에서 동시에 구동하고 서로 연동시키는 것도 가능합니다.

## 4. Dify - 드래그 앤 드롭으로 만드는 AI 워크플로우

인프라를 갖췄다면 이제 실제로 돈이 되는 앱을 만들 차례입니다. 모든 로직을 프롬프트로 짜내려 애쓰는 대신, Dify는 캔버스 위에서 노드를 드래그해 워크플로우를 구성하는 비주얼 빌더입니다.

영상에서는 예시로 "Horse Tinder"라는 말(馬) 매칭 앱을 듭니다. 앱이 각 말의 프로필 정보를 Dify로 전송하면, 비주얼 워크플로우가 데이터베이스에서 궁합이 맞는 말들을 조회하고, LLM을 활용해 각 매칭 결과를 설명해줍니다. 예컨대 "Thunder와 Butternuts는 둘 다 트레일 라이드를 좋아하고 아이들을 무는 걸 즐긴다는 공통점 때문에 94% 매칭"이라는 식이죠. 이렇게 완성된 워크플로우는 API로 노출되므로, 프런트엔드 애플리케이션은 사용자가 말 프로필을 오른쪽으로 스와이프할 때마다 이 API를 호출하기만 하면 됩니다.

## 5. Open Hands - 스스로 일하는 코딩 에이전트

Dify로 앱을 만드는 것조차 구식이 될 정도로, Open Hands는 개발자를 자동화하는 오픈소스 자율 코딩 에이전트입니다. 이 도구는 실제 GitHub 이슈를 해결하는 벤치마크인 SWE-bench Verified에서 상위권 성능을 기록한 자율 코딩 에이전트입니다.

직접 코드를 고치려 하지 말고, GitHub 이슈만 열어두면 Open Hands가 알아서 작업을 처리하는 방식입니다. 본질적으로 이 도구는 항상 켜져 있고 백그라운드에서 작동하는 AI 에이전트 군단을 지휘할 수 있는 커맨드 센터를 제공합니다. 자신의 VPS 위에서 돌아가기 때문에 OpenAI나 Anthropic 모델을 붙일 수도 있고, 앞서 Ollama로 설치해둔 로컬 LLM을 그대로 활용할 수도 있습니다.

## 정리

- **비용 구조 재설계**: Cursor, Claude Max, GPT Pro, Gemini Ultra 등을 동시에 구독하면 월 320달러가 넘는 지출이 발생합니다. 이를 오픈소스 셀프 호스팅 스택으로 대체하면 비용은 줄이고 유연성은 늘릴 수 있습니다.
- **Ollama**로 로컬에서 오픈웨이트 모델을 무료로 돌리되, 하드웨어 한계가 있다는 점을 인지해야 합니다.
- **Nine Router**의 폴백 티어 구조를 활용하면 기존 구독 → 저가 종량제 → 완전 무료 공급자 순으로 자동 전환되어 비용을 절감할 수 있습니다.
- **Headroom**은 불필요한 토큰 낭비(과도한 파일 읽기, 로그 등)를 압축해 줄이면서도, 필요시 원본 데이터를 복원할 수 있는 가역적 구조를 가지고 있습니다.
- **Dify**로 코드를 최소화한 비주얼 워크플로우를 구성하고, **Open Hands**로 GitHub 이슈 해결 자체를 자동화하는 것까지가 이 스택의 최종 목표입니다.
- 이 모든 도구는 Hostinger 같은 VPS의 Docker 카탈로그를 통해 한 서버 위에서 통합 운영할 수 있습니다.

프런트엔드 개발자 입장에서는 매달 수백 달러씩 나가는 AI 구독료를 무작정 늘리기보다, 로컬 모델과 라우팅/압축 레이어를 조합해 비용 대비 생산성을 최적화하는 전략을 고민해볼 시점입니다. 특히 팀 단위로 여러 AI 툴을 굴리고 있다면 Nine Router나 Headroom 같은 중간 계층 하나만 도입해도 토큰 비용을 눈에 띄게 줄일 수 있습니다.
