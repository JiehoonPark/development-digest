## 핵심 개념

> [!abstract]
> Next.js가 v16.3.8(Active LTS)과 v15.5.27(Maintenance LTS)을 통해 이미지 최적화 SSRF, SSG/ISR 캐시 포이즈닝, 메타데이터 이미지 라우트 정보 노출, use cache/Draft Mode 캐시 누출, 개발 서버 MCP 엔드포인트 노출 등 총 7건의 보안 취약점을 수정했습니다. 셀프 호스팅 환경과 Cache Components, Draft Mode를 사용하는 프로젝트가 특히 영향을 받을 수 있습니다. Vercel 배포 환경은 일부 취약점(캐시 포이즈닝)의 영향을 받지 않습니다.

## 아티클

지난주 Next.js 팀은 예정된 보안 패치를 발표하면서, 치명적(critical) 취약점 1건과 심각도 높은(high) 취약점 1건에 대한 수정은 업스트림 의존성 지연으로 인해 늦춰진다고 공지한 바 있습니다. 이번 포스트는 그 후속 조치로, 해당 취약점들을 포함한 총 7건의 보안 이슈를 수정한 v16.3.8(Active LTS)과 v15.5.27(Maintenance LTS) 릴리스를 안내합니다. Next.js를 사용 중이라면 아래 내용을 확인하고 가능한 한 빨리 패치하는 것을 권장합니다.

## 패치 방법

```bash
npm install next@15.5.27 # for 15.5
npm install next@16.3.8 # for 16.3
```

## 수정된 취약점 상세

### 이미지 최적화 과정의 SSRF (심각도: 높음)
**CVE-2026-94483 / GHSA-cjq9-62q9-8jv4**

공격자가 제어할 수 있는, allow-list에 등록된 원격 URL을 통해 이미지 최적화 과정에서 서버 측 요청 위조(SSRF)가 발생할 수 있습니다. 예를 들어 사설 IP 대역으로의 요청을 유도하는 식입니다. 다만 `images.remotePatterns`를 설정하지 않은 애플리케이션이라면 이 문제의 영향을 받지 않습니다.

### 셀프 호스팅 환경의 SSG/ISR 페이지 캐시 포이즈닝 (심각도: 중간)
**CVE-2026-94543 / GHSA-4jqv-mc3x-m676**

Pages Router 기반으로 SSG나 ISR을 사용하는 셀프 호스팅 Next.js 애플리케이션에서, 특정 페이지의 캐시 엔트리가 전혀 다른 라우트의 콘텐츠로 뒤바뀔 수 있습니다. 이 경우 캐시가 재검증(revalidate)되기 전까지 모든 방문자에게 잘못된 콘텐츠가 노출됩니다. Vercel에 배포된 애플리케이션은 이 문제의 영향을 받지 않습니다.

### Root-level catch-all 라우트를 통한 SSG/ISR 캐시 포이즈닝 (심각도: 중간)
**CVE-2026-94484 / GHSA-mcj8-r9mp-w47p**

루트 레벨 catch-all 페이지와 SSG 또는 ISR 라우트를 함께 사용하는 Next.js 애플리케이션은, 인증되지 않은 사용자가 보낸 단 하나의 조작된 요청만으로 공유 응답 캐시가 오염될 수 있습니다. 이는 사용자 간 콘텐츠가 뒤섞이는 문제뿐 아니라 지속적인 서비스 거부(DoS)로 이어질 수 있습니다.

### App Router 메타데이터 이미지 라우트의 dynamicParams 우회로 인한 정보 노출 (심각도: 중간)
**CVE-2026-94485 / GHSA-f87g-xv8r-7p7x**

webpack으로 빌드된 App Router 애플리케이션에서 `opengraph-image`, `twitter-image` 같은 메타데이터 이미지 라우트가 `dynamicParams` 라우트 세그먼트 옵션을 무시하는 문제입니다. 공격자는 `generateStaticParams()`에서 의도적으로 제외된 동적 세그먼트에 대해서도 메타데이터 이미지 URL을 요청할 수 있습니다. Turbopack으로 빌드한 애플리케이션은 영향을 받지 않습니다.

### 중첩된 'use cache' 함수에서 root param 값이 다른 사용자 간 누출 (심각도: 중간)
**GHSA-h694-7cp9-m8p3**

Cache Components가 활성화된 환경에서, root param을 읽는 다른 `'use cache'` 함수를 호출하는 `'use cache'` 함수의 캐시 키 계산에 오류가 있습니다. 감싸고 있는(enclosing) 함수의 캐시 키가 해당 root param을 누락하기 때문에, 한 root param 값에 대해 생성된 콘텐츠가 다른 값의 요청에 서빙될 수 있습니다. 이는 페이지가 프리렌더링되든 동적으로 렌더링되든 동일하게 발생합니다. 다만 어떤 값이 누출되는지는 공격자가 제어할 수 없습니다.

### Draft Mode 콘텐츠가 use cache의 대기 중인 채움(pending fill)을 통해 일반 응답에 누출 (심각도: 중간)
**CVE-2026-94544 / GHSA-3w37-wq28-93x7**

동일한 캐시 키에 대한 대기 중인 `use cache` 채움(fill)이, Draft Mode 요청인지 일반 요청인지 구분 없이 여러 요청 간에 공유되는 문제입니다. 편집자의 Draft Mode 요청과 시점이 겹치는 일반 요청은 아무런 인증 없이 미공개(unpublished) 콘텐츠를 받게 됩니다. 만약 이 요청이 페이지를 프리렌더링하는 상황이라면, 미공개 콘텐츠가 생성된 페이지에 영구적으로 박제되어 페이지가 재검증될 때까지 모든 후속 방문자에게 서빙될 수 있습니다. Cache Components(또는 experimental.useCache)를 활성화하고, 캐시된 함수가 draft 여부에 따라 다른 콘텐츠를 반환하는 Draft Mode 프리뷰를 제공하는 사이트가 영향을 받습니다.

### 개발 서버의 MCP(Model Context Protocol) 엔드포인트를 통한 정보 노출 (심각도: 낮음)
**CVE-2026-94486 / GHSA-39w2-rjm5-chcv**

`next dev`로 구동되는 개발 서버가 노출하는 MCP 엔드포인트가 요청의 출처 사이트를 검증하지 않는 문제입니다. 개발자가 방문한 악성 웹사이트가 이 엔드포인트를 통해 프로젝트의 디스크 상 경로, 에러 리포트에 포함된 소스 코드 조각, 라우트 목록, 개발 로그 등 민감한 개발 정보를 읽어갈 수 있습니다. `next dev`로 실행 중인 애플리케이션만 영향을 받으며, 프로덕션 배포본은 이 엔드포인트를 서빙하지 않으므로 영향이 없습니다.

## Next.js의 보안 프로그램

Next.js 팀은 Vercel의 Open Source Bug Bounty 프로그램을 통해 다수의 보안 연구자들과 협력하여 Next.js를 비롯한 오픈소스 프레임워크들의 보안을 강화하고 있습니다. 해당 프로그램에 기여하고 싶다면 참여를 권장하며, 보안 프로그램이나 취약점 관리와 관련된 문의사항은 security@vercel.com으로 보낼 수 있습니다.

## 정리

이번 릴리스는 이미지 최적화의 SSRF부터 SSG/ISR 캐시 포이즈닝, 메타데이터 이미지 라우트의 정보 노출, `use cache`와 Draft Mode 관련 캐시 누출, 개발 서버의 MCP 엔드포인트 노출까지 총 7건의 취약점을 다룹니다.

- 셀프 호스팅 중이고 Pages Router의 SSG/ISR을 사용한다면 캐시 포이즈닝 이슈(CVE-2026-94543)를 특히 주의해야 합니다. Vercel 배포는 영향을 받지 않습니다.
- `images.remotePatterns`를 설정한 프로젝트는 SSRF 취약점(CVE-2026-94483) 대상이므로 즉시 패치가 필요합니다.
- Cache Components나 `experimental.useCache`를 쓰면서 Draft Mode 프리뷰를 운영한다면, 미공개 콘텐츠가 프리렌더링된 페이지에 영구적으로 박히는 CVE-2026-94544를 꼭 확인하세요.
- webpack 빌드 환경에서 `opengraph-image`/`twitter-image` 같은 메타데이터 라우트를 쓴다면 CVE-2026-94485 대상이며, Turbopack으로 전환하거나 패치하면 됩니다.
- 영향 범위와 관계없이 `npm install next@15.5.27` 또는 `npm install next@16.3.8`로 업그레이드하는 것이 가장 확실한 대응입니다.
