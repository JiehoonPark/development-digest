## 핵심 개념

> [!abstract]
> Cursor가 Bugbot, Security Reviewer, Rollouts 같은 자사 에이전트를 구축할 때 사용한 프레임워크인 Agent SDK를 정식 공개했습니다. 에이전트를 TypeScript와 Markdown으로 정의해 일반 소프트웨어 프로젝트처럼 버전 관리하고, agent-sdk deploy 명령 한 번으로 Cursor 인프라나 자체 인프라에 배포할 수 있습니다. PR 리뷰, 컴플라이언스 체크, 인시던트 대응 등 팀별 워크플로우에 맞춘 커스텀 에이전트를 빠르게 구축할 수 있으며, evals와 이벤트 리플레이를 기본 지원해 신뢰성 있는 반복 개발이 가능합니다.

## 아티클

개발팀은 코드 리뷰, 컴플라이언스 워크플로우 실행, 인시던트 조사처럼 반복적으로 발생하는 업무를 자동화하기 위해 에이전트를 활용합니다. 문제는 팀마다 일하는 방식이 제각각이라 가장 쓸모 있는 에이전트는 결국 그 팀의 워크플로우에 맞춰 커스터마이징된 것이라는 점입니다. 지금까지는 이런 에이전트를 만들려면 다른 누군가의 워크플로우에 맞춰 설계된 기성 제품을 억지로 끼워 맞추거나, 아예 처음부터 직접 만들어야 했는데요. Cursor가 이 문제를 해결하기 위해 Bugbot, Security Reviewer, Rollouts 같은 자사 매니지드 에이전트를 만들 때 실제로 사용한 프레임워크인 **Agent SDK**를 공개했습니다.

## 코드로 정의하고, 소프트웨어처럼 관리한다

Agent SDK의 핵심은 에이전트를 코드로 정의하고 일반적인 소프트웨어 프로젝트처럼 다룰 수 있다는 점입니다. 템플릿에서 시작하거나, 코딩 에이전트에게 Agent SDK 문서를 참조하게 해서 함께 만들어갈 수도 있습니다. 에이전트가 준비되면 `agent-sdk deploy` 명령어 하나로 Cursor 인프라에 배포됩니다.

## 팀의 워크플로우에 맞춰 구축하기

Agent SDK로 만든 에이전트는 팀이 이미 다루고 있는 이벤트에 반응하고, 팀이 직접 검토하고 수정할 수 있는 정책을 따르도록 설계됩니다.

대표적인 예가 코드 리뷰입니다. 팀마다 무엇을 중점적으로 검토해야 하는지, 누가 리뷰해야 하는지에 대한 기준이 다른데요. Agent SDK를 사용하면 GitHub, GitLab, Bitbucket에서 발생하는 풀 리퀘스트 이벤트에 반응하는 에이전트를 만들 수 있습니다. 이 에이전트는 변경 사항의 위험도를 평가하고, 적절한 팀에 라우팅하며, 정책에 부합하는 변경은 자동으로 승인할 수 있습니다.

실제 사례로, Cursor 내부의 한 팀은 빠르게 성장하는 대규모 지식 베이스(과거에 얻은 교훈들을 정리한 문서)를 운영하면서 모든 풀 리퀘스트가 이 지식 베이스와 충돌하지 않는지 검증하고 싶어 했습니다. 코드베이스가 계속 바뀌더라도 팀이 과거에 내린 결정들이 계속 지켜지도록 하기 위해서였는데요. 이 팀은 Agent SDK로 `kb-reviewer`라는 에이전트를 단 하루 만에 구축했습니다. 이 에이전트는 현재 메인 코드베이스의 모든 PR에서 동작하며, 기록된 교훈과 모순되는 변경 사항을 찾아내고, 각 발견 사항마다 근거가 된 노트를 인용하며, 엔지니어들이 발견된 불일치를 해소하도록 유도합니다.

더 복잡한 작업의 경우 에이전트는 자체 도구와 세션을 가진 다른 전문 에이전트에게 작업을 위임할 수 있고, 하나의 작업을 여러 서브에이전트에게 나눠 병렬로 처리하게 할 수도 있습니다.

Agent SDK는 평가(evals)와 이벤트 리플레이 기능을 기본으로 지원해서, 핵심 워크플로우가 예상대로 동작하는지 확인하면서도 빠르게 개발을 진행할 수 있습니다. PGA Tour는 Agent SDK로 자체 소프트웨어 개발 공정을 운영하고 있는데, 이때 evals 덕분에 빠른 속도를 유지할 수 있다고 합니다.

> "Agent SDK 덕분에 PGA는 소프트웨어 팩토리의 모든 구성 요소를 Cursor 인프라 위에서 구축할 수 있었습니다. 개발 프로세스를 이끄는 에이전트를 만드는 데 필요한 유연성을 제공해주었고, 기본 제공되는 evals 지원 덕분에 새로운 아이디어를 빠르게 반복 검증하고 기존 기능을 안정적으로 최적화할 수 있었습니다." — Michael Gyarmathy, Principal Engineer, PGA America

## 모든 것을 코드로 정의한다

Agent SDK로 만든 에이전트는 작은 소프트웨어 프로젝트처럼 구성됩니다. 에이전트의 행동을 안내하는 지시문(instructions)은 도구 코드, 외부 서비스 연동, 테스트용 evals 코드와 나란히 하나의 프로젝트 안에 존재합니다.

각 파일은 에이전트가 알고 있는 지식이나 수행할 수 있는 작업 하나하나를 나타냅니다. 프롬프트는 Markdown으로 작성하고, 도구는 TypeScript 함수로 정의합니다. 모든 것이 코드이기 때문에 나머지 소프트웨어와 동일한 버전 관리 및 리뷰 프로세스를 그대로 적용할 수 있습니다.

## 어디서든 배포 가능

에이전트를 실제로 사용할 준비가 되면, 프로젝트 디렉터리에서 `agent-sdk deploy`를 실행해 Cursor에 배포할 수 있습니다. 이 명령어는 에이전트를 빌드하고, URL을 부여하고, Cursor 인프라에서 실행을 시작합니다. 시크릿과 외부 연동은 대시보드에서 관리하면서도, 로컬에서 쓰던 것과 동일한 로그, evals, 플레이그라운드를 계속 사용할 수 있습니다.

물론 자체 인프라에서 실행하는 것도 가능합니다. 각 에이전트는 하나의 Node 프로세스로 실행되므로 컨테이너로 패키징할 수 있습니다.

## 시작하기

Agent SDK를 시작하는 과정은 다른 소프트웨어 프로젝트를 시작하는 것과 크게 다르지 않습니다. 프로젝트 디렉터리를 만들고 로컬 플레이그라운드를 실행하면 됩니다.

```ts
import { homedir } from "node:os";
import { join } from "node:path";
import { defineAgent } from "@cursor/agent-sdk";

export default defineAgent({
  name: "Robo",
  model: {
    id: "composer-2.5",
    params: [
      { id: "effort", value: "high" },
      { id: "fast", value: "true" },
    ],
  },
  local: {
    cwd: join(homedir(), ".cache", "factory", "robo"),
  },
})
```

이렇게 로컬에서 반복 작업을 하며 evals를 돌려본 뒤, 준비가 되면 `agent-sdk deploy`로 배포하면 됩니다.

Agent SDK에는 코딩 에이전트가 개발 과정을 안내받을 수 있도록 하는 skills도 함께 제공됩니다. 에이전트에게 문서를 참조하게 하면, 봇을 함께 만들어나가는 작업을 도와줄 수도 있습니다.

Agent SDK는 오늘부로 정식 출시(GA)되었으며, 공식 문서에서 바로 시작해볼 수 있습니다.

## 정리

- Agent SDK는 Cursor가 Bugbot, Security Reviewer, Rollouts 같은 자체 매니지드 에이전트를 만들 때 사용한 프레임워크로, 이제 외부에도 공개되어 누구나 자신의 팀 워크플로우에 맞는 에이전트를 코드로 정의할 수 있습니다.
- 에이전트는 GitHub/GitLab/Bitbucket의 PR 이벤트 같은 팀이 이미 다루는 이벤트에 반응하도록 설계되며, 필요하면 다른 전문 에이전트나 병렬 서브에이전트에게 작업을 위임할 수 있습니다.
- 프롬프트는 Markdown, 도구는 TypeScript 함수로 정의되어 일반 소프트웨어 프로젝트와 동일하게 버전 관리·코드 리뷰 프로세스를 적용할 수 있습니다.
- evals와 이벤트 리플레이를 기본 지원해 빠른 반복 개발과 신뢰성 검증을 동시에 챙길 수 있으며, `agent-sdk deploy` 명령 하나로 Cursor 인프라 또는 자체 인프라(Node 프로세스/컨테이너)에 배포할 수 있습니다.
- 실제 사례로 Cursor 내부 팀은 지식 베이스 기반 PR 리뷰 봇(`kb-reviewer`)을 하루 만에 구축했고, PGA Tour는 Agent SDK로 소프트웨어 개발 공정 전체를 구축해 운영 중입니다.

프론트엔드 개발자 입장에서는 TypeScript로 도구를 정의하고 Markdown으로 프롬프트를 작성하는 친숙한 개발 경험으로 사내 자동화 봇(코드 리뷰, CI 정책 체크 등)을 직접 만들고 배포할 수 있다는 점이 특히 매력적입니다.
