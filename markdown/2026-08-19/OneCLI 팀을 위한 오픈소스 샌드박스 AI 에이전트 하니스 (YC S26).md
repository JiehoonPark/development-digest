## 핵심 개념

> [!abstract]
> OneCLI는 팀원마다 격리된 샌드박스 AI 에이전트를 부여하고, Rust 게이트웨이를 통해 자격 증명 주입과 정책 강제를 중앙화하는 오픈소스 플랫폼입니다. 원래 Rust로 만든 자격 증명 볼트에서 출발했으나, 개인용 자율 에이전트를 팀 단위로 확장하려는 수요를 반영해 IdP 연동, 휴먼인더루프 승인, 전용 Slack 앱 등을 갖춘 v2로 발전했습니다. 웹 대시보드, API 서버, Rust 게이트웨이, 러너, 샌드박스 슈퍼바이저로 구성되며, 코어는 Apache-2.0, 일부 엔터프라이즈 기능은 별도 라이선스로 배포됩니다.

## 아티클

AI 에이전트를 개인이 아니라 '팀' 단위로 굴리려고 하면 순식간에 복잡해집니다. 에이전트마다 시크릿을 따로 관리하고, 권한을 일일이 정해줘야 하고, 누가 어떤 에이전트를 갖고 있는지도 추적해야 하죠. YC S26 배치의 OneCLI는 바로 이 지점을 파고든 오픈소스 프로젝트입니다. Hacker News에 올라온 Launch HN 글을 바탕으로, OneCLI가 어떤 문제의식에서 출발했고 어떤 아키텍처로 이를 풀어내는지 정리해보겠습니다.

## OneCLI는 무엇인가

OneCLI는 팀이 AI 에이전트를 함께 운영할 수 있도록 만든 오픈소스 플랫폼입니다. 핵심 아이디어는 단순합니다. 사람마다 에이전트를 하나씩 만들고, 각 에이전트에 필요한 접근 권한만 부여한 뒤, 그 에이전트를 샌드박스 안에서 실행시킵니다. 그리고 이 모든 요청은 게이트웨이를 거치는데, 이 게이트웨이가 자격 증명(credential)을 주입하고 정책을 강제합니다.

즉 "개인용 에이전트를 회사 차원에서 안전하게 여러 명에게 나눠주는" 구조라고 보면 됩니다.

## 왜 만들었나

OneCLI는 원래 Rust로 만든 AI 에이전트용 자격 증명 볼트(credential vault)로 시작했습니다. 그런데 실제 수요를 들여다보니, Hermes, OpenClaw, NanoClaw 같은 자율 에이전트를 돌리는 개인과 팀에서 요청이 몰려들었다고 합니다. 사람들은 자신을 대신해 실제 업무를 처리해주는 에이전트를 원했지만, 여기엔 두 가지가 빠져 있었습니다.

- 시크릿과 권한 관리
- 팀 단위의 멀티플레이어 관리 기능

시중의 자율 에이전트들은 대부분 '한 사람'을 위해 만들어져 있습니다. 개인 사용자 입장에서는 훌륭하지만, 이걸 팀 전체로 복제하려는 순간 문제가 생깁니다. 에이전트를 하나하나 띄우고, 각각 무엇을 할 수 있고 없는지 정하고, 호스팅하고, 누구 것이 누구 것인지 계속 추적해야 하니까요. 이 문제를 풀기 위해 나온 것이 OneCLI v2입니다.

## 팀을 위해 설계된 기능들

- **IdP 연동**: 회사의 아이덴티티 프로바이더(IdP)와 바로 연결해서, 각 직원의 신원을 기반으로 에이전트를 프로비저닝할 수 있습니다.
- **1인 1에이전트**: 워크스페이스에 속한 모든 사람이 각자의 샌드박스 에이전트를 갖게 되고, 대시보드나 Slack에서 바로 접근할 수 있습니다.
- **정책의 일원화**: 팀 정책을 한 곳에서 관리하면, 워크스페이스 내 모든 에이전트에 동일하게 적용됩니다.
- **결정론적 휴먼인더루프 승인**: 메일 발송, Linear 티켓 삭제, S3 버킷 비우기처럼 100% 사람의 통제가 필요한 작업은 채팅 안에서 승인 절차를 거치도록 합니다.
- **글로벌 커넥션**: LLM API 키나 서비스 계정 같은 자원을 팀 레벨에서 공유하되, 실제 값은 에이전트에 절대 넘겨주지 않고 에이전트별로 권한만 부여합니다.

## 에이전트의 구조

OneCLI가 말하는 "에이전트"는 단발성 프롬프트가 아니라 지속적으로 존재하는 개체입니다. 구성 요소는 다음과 같습니다.

- **컴퓨터**: 자체 파일시스템과 셸을 가진 격리된 샌드박스. 외부로 나가는 유일한 통로는 게이트웨이뿐이라, 부여받은 것 외에는 아무것도 접근할 수 없습니다.
- **대화**: 대시보드 혹은 Slack에 자신만의 페이지를 가지며, 이미지와 파일도 포함됩니다. 에이전트가 작업 중일 때 새 메시지를 보내면 큐에 밀려 대기하는 대신 즉시 리다이렉트되어 처리됩니다.
- **메모리**: 에이전트가 학습한 내용은 플랫폼이 보관하므로 유실되지 않으며, 언제든 읽고 수정할 수 있습니다.
- **스킬**: 한 번 작성해두면 에이전트가 항상 활용할 수 있는 지시문과 헬퍼 함수입니다.
- **일정(schedule)**: 에이전트가 향후 작업을 계획해두면, 플랫폼이 적절한 시점에 깨워 실행합니다.
- **결코 노출되지 않는 자격 증명**: 각 에이전트는 부여받은 접근 권한만 가지며, 게이트웨이가 모든 요청에서 이를 강제합니다. Bitwarden이나 1Password를 연결해 필요할 때만 주입하는 방식도 지원하며, 이 경우 서버에는 아무것도 저장되지 않습니다.
- **자체 Slack 앱**: 한 번 연결하면 에이전트가 자신의 이름과 아바타로 채널과 DM에서 파일·이미지와 함께 응답합니다. 에이전트를 삭제하면 해당 Slack 앱도 함께 사라집니다.

에이전트는 사용자 자신의 인프라에서 실행됩니다. 러너(runner)는 아웃바운드 전용으로 동작하며 인바운드 포트를 열지 않기 때문에, 노트북이든 홈랩이든 NAT 뒤에 있는 VPC든 별도의 인그레스나 터널 없이 그대로 사용할 수 있습니다.

## 아키텍처

OneCLI는 다음과 같은 컴포넌트로 구성됩니다.

- **웹 대시보드**: Next.js 앱으로, 에이전트 생성, 대화, 메모리·스킬 수정, 커넥션/시크릿/권한 관리를 담당합니다.
- **API 서버**: 컨트롤 플레인 역할을 하며 데이터베이스, 대화 플레인, 그리고 러너가 폴링하는 작업 큐를 소유합니다.
- **Rust 게이트웨이**: MITM 방식을 포함해 아웃바운드 요청(HTTPS 포함)을 가로채 자격 증명을 주입합니다. 에이전트는 Proxy-Authorization 헤더를 통한 액세스 토큰으로 인증됩니다.
- **러너**: 에이전트 샌드박스를 시작, 대기(park), 회수(reap)합니다. 아웃바운드 전용이며 데이터베이스에는 직접 접근하지 않습니다.
- **샌드박스 슈퍼바이저**: 각 샌드박스 내부에서 실행되며, 벤더 중립적인 하니스 인터페이스를 사용해 에이전트 런타임을 자유롭게 교체할 수 있게 합니다.
- **채널 어댑터**: Slack 데몬으로, 에이전트당 하나의 앱을 운영합니다.
- **시크릿 스토어**: AES-256-GCM으로 저장 시 암호화되고, 요청 시점에만 복호화됩니다. 호스트와 경로 패턴으로 매칭되어 헤더나 쿼리 파라미터로 주입됩니다.

## 로컬 개발 환경 설정

로컬에서 직접 실행해보려면 다음 순서를 따르면 됩니다.

```
git clone https://github.com/onecli/onecli.git && cd onecli
mise install
pnpm install
pnpm dev
```

이게 전부입니다. `pnpm dev` 한 줄이 필요한 모든 시크릿이 담긴 `.env`를 생성하고, PostgreSQL을 실행하고, 마이그레이션을 적용한 뒤 전체 스택을 띄워줍니다. 사전 요구사항, 명령어 레퍼런스, 프로젝트 구조, 상세 설정은 `docs/development.md`에 정리되어 있습니다.

클라우드 호스팅 버전은 onecli.sh에서 바로 사용할 수 있고, 셀프 호스팅을 원한다면 다음처럼 실행합니다.

```
git clone https://github.com/onecli/onecli.git && cd onecli
pnpm install
pnpm run setup
```

이후 `http://localhost:10254`로 접속하면 됩니다.

## 라이선스 구조

OneCLI는 기본적으로 Apache-2.0 라이선스로 배포되며, 상용 라이선스 없이 프로덕션에서 셀프 호스팅할 수 있습니다. 예외는 `ee/` 디렉터리로, 여기에 담긴 엔터프라이즈 기능들은 OneCLI Enterprise License를 따릅니다. 이 라이선스는 각 파일에 별도 고지가 붙어 있으며, 개발·테스트·평가 목적으로는 무료이지만 프로덕션에서 사용하려면 구독이 필요합니다. 어떤 경로가 엔터프라이즈 라이선스 대상인지는 `LICENSE-ENTERPRISE` 파일에 정리되어 있습니다.

컨트리뷰션은 Contributing Guide와 Code of Conduct를 먼저 확인해야 하며, 모든 기여는 Contributor License Agreement 조건 하에 수용됩니다. 보안 취약점은 공개 이슈가 아니라 별도의 Security Policy 절차를 통해 신고해야 합니다.

## 정리

OneCLI는 "개인용 자율 에이전트"와 "팀에서 안전하게 관리 가능한 에이전트" 사이의 간극을 메우는 프로젝트입니다. 핵심은 세 가지로 요약됩니다.

- **1인 1에이전트 + 중앙 정책**: 팀원마다 격리된 샌드박스 에이전트를 두되, 시크릿 관리와 정책 강제는 게이트웨이 한 곳에서 처리해 관리 부담을 줄입니다.
- **에이전트를 지속 가능한 개체로 취급**: 단발성 프롬프트가 아니라 메모리, 스킬, 스케줄, 전용 Slack 앱을 가진 지속적인 존재로 설계했습니다.
- **인프라 친화적 배포**: 러너가 아웃바운드 전용으로 동작해 인그레스나 터널 설정 없이 노트북, 홈랩, NAT 뒤 VPC 어디서든 돌릴 수 있습니다.

사내에서 여러 명이 동시에 자율 에이전트를 도입하려는 프론트엔드·플랫폼 팀이라면, 자격 증명 관리와 권한 통제를 어떻게 설계할지 고민하는 데 있어 OneCLI의 게이트웨이·러너·샌드박스 구조는 참고할 만한 레퍼런스가 될 수 있습니다. 특히 MITM 기반 요청 가로채기와 시크릿 주입 방식, Apache-2.0 코어 + 엔터프라이즈 기능 분리라는 라이선스 모델은 오픈소스로 이런 인프라를 설계할 때의 실용적인 패턴을 보여줍니다.
