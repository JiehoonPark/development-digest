## 핵심 개념

> [!abstract]
> CSS의 px 단위는 실제 물리적 픽셀과 일치하지 않는 지각적 근사값에 불과합니다. 저자는 텍스트 중심 블로그에서 본문 너비와 여백을 px 대신 문자 폭 기준의 ch, 소문자 높이 기준의 ex 단위로 설정해본 경험을 공유합니다. 댓글에서는 lh, vh 단위 활용법과 웹폰트 사용 시 ch 단위의 레이아웃 시프트 주의점도 함께 논의됩니다.

## 아티클

# 픽셀은 거짓말이다: px 대신 ch를 쓰는 이유

웹 개발자라면 누구나 px 단위로 픽셀 완벽한(pixel perfect) 레이아웃을 만들었다고 믿은 적이 있을 겁니다. 하지만 이 글은 그 믿음 자체가 애초에 착각이라고 지적합니다. CSS에서 텍스트 중심 콘텐츠의 너비와 여백을 다룰 때, px 대신 `ch`와 `ex` 같은 상대 단위를 쓰면 어떤 이점이 있는지 실제 적용 사례를 통해 살펴봅니다.

## 픽셀은 애초에 거짓말이다

모니터에 "완벽한 픽셀"로 무언가를 그린다고 생각해도, 사실 모니터는 우리를 속이고 있습니다. 플라톤적으로 완벽한 정사각형들의 격자 같은 건 존재하지 않기 때문입니다.

CSS에서 픽셀은 이중으로 거짓말을 합니다. 먼저 CSS의 1px이 실제 물리적 디바이스 픽셀 1개와 반드시 일치하지 않는다는 점입니다. 고해상도(HD) 디스플레이에서는 CSS 1px이 여러 개의 물리적 픽셀에 걸쳐 표현될 수 있습니다. 이는 CSS의 1cm가 SI 단위계의 정확한 100분의 1미터와 일치하지 않는 것과 비슷합니다. 대형 TV 화면에서는 CSS의 1cm가 실제로는 그보다 더 긴 경우가 많습니다.

결국 CSS의 길이 단위는 지각적(perceptual) 개념에 가깝습니다. 즉 16px은 휴대폰, 노트북, TV 화면 각각에서 일반적인 시청 거리를 기준으로 봤을 때 대략 비슷하게 보이도록 설계된 값이라는 것입니다. 절대적인 물리량이 아니라, 사람 눈에 비슷하게 느껴지도록 맞춘 상대적인 값인 셈입니다.

## 텍스트 너비는 문자 폭 기준으로

이 블로그는 기본적으로 텍스트 중심 콘텐츠입니다. 저자는 평균적인 사람이 읽기 편안한 텍스트 너비를 원했습니다. 그래서 본문 너비를 화면 비율(퍼센트)로 설정하는 대신, 문자 너비를 기준으로 하는 `ch` 단위를 사용했습니다. `ch`가 정확히 하나의 문자 폭과 일치하는 것은 아니지만, 이 목적에는 충분히 쓸 만하다고 설명합니다.

```css
:root {
  --width-content: min(75ch, 100%);
}

main {
  max-width: var(--width-content);
}
```

이렇게 하면 본문 너비가 최대 75자 정도의 폭을 넘지 않으면서도, 화면이 좁을 때는 100%로 줄어들도록 유연하게 대응합니다.

## 패딩과 마진도 텍스트 비율에 맞춰서

너비뿐 아니라 패딩과 마진에도 같은 논리가 적용됩니다. 어떤 요소 주변에 여백을 두고 싶다면, 그 여백은 안에 들어있는 텍스트 크기에 비례하는 것이 자연스럽습니다.

가로 방향 여백(너비 관련)에는 `ch` 단위를 재사용하는 것이 합리적입니다. 텍스트의 가로 폭에 비례한 여백을 만들 수 있기 때문입니다.

다만 세로 방향(높이) 여백까지 문자의 가로 폭 기준인 `ch`로 표현하는 게 맞는지는 의문이 남습니다. 이런 경우에는 `ex` 단위를 활용할 수 있습니다. `ex`는 일반적인 소문자 하나의 높이 크기를 기준으로 합니다.

## 과유불급, 그리고 한계

저자는 이전에 HTML에서 CSS 클래스를 없애보려 시도했던 것과 마찬가지로, 이런 시도도 지나치면 문제가 될 수 있다고 인정합니다. 실제로 모든 px 참조를 ch로 바꾼 것은 아니며, 이게 잘 작동하는지 실험해보는 단계라고 밝힙니다.

px이나 다른 단위를 쓰는 것 자체가 잘못되었거나 나쁜 것은 아닙니다. 단지 `ch`와 `ex`가 저자 개인의 취향과 작업 방식에 잘 맞았을 뿐이라고 강조합니다.

## 댓글에서 나온 추가 논의

이 글에 달린 댓글들도 실무에 참고할 만한 내용을 담고 있습니다.

- Jeff Sonstein은 경험상 px 같은 절대 단위보다 상대 단위가 거의 항상 더 유용하다고 동의했습니다.
- Shiv J.M.은 `en` 단위(`padding: 0.75en`)를 쓰다가 아무 효과가 없어서 헷갈렸던 경험을 유머러스하게 공유했는데, 이는 `en`이 실제 CSS 표준 단위가 아니기 때문일 가능성이 있습니다.
- Tyler Sticka는 `ch` 단위를 좋아하지만, 웹폰트와 함께 사용할 때 발생할 수 있는 레이아웃 시프트(layout shift) 부작용을 주의해야 한다며 Cloud Four 블로그의 관련 글(Watch Out for Layout Shifts with 'ch' Units)을 링크했습니다. 단, 시스템 폰트를 사용한다면 이 문제는 발생하지 않는다고 덧붙였습니다.
- Adam은 `line-height`의 계산된 값과 같은 `lh` 단위가 패딩과 마진에 매우 유용하다며, `ch`와 `lh`를 함께 쓰는 것이 레이아웃을 "제대로" 보이게 만드는 자신만의 방법이라고 소개했습니다.
- mahadevank는 최근 px 대신 `vh` 단위를 사용해 화면 크기에 따라 웹페이지와 폰트가 함께 스케일되도록 작업하고 있다고 공유했습니다.

## 정리

이 글의 핵심은 CSS 픽셀 단위가 절대적인 물리량이 아니라 지각적으로 비슷하게 보이도록 조정된 상대적 값이라는 사실에서 출발합니다. 텍스트 중심 콘텐츠에서는 화면 비율(%)이나 절대 px보다, 문자 폭 기준의 `ch`와 소문자 높이 기준의 `ex` 단위를 사용하는 것이 읽기 편한 레이아웃을 만드는 데 더 적합할 수 있습니다.

실무에 적용할 때 참고할 포인트는 다음과 같습니다.

- 본문 최대 너비는 `max-width: min(75ch, 100%)`처럼 설정하면 좁은 화면에서도 유연하게 대응하면서 넓은 화면에서는 가독성 좋은 줄 길이를 유지할 수 있습니다.
- 텍스트를 감싸는 요소의 가로 여백은 `ch`, 세로 여백은 `ex`나 `lh`(line-height 기반) 단위로 텍스트 크기에 비례하게 설정하면 폰트 크기가 바뀌어도 비율이 깨지지 않습니다.
- 단, 웹폰트를 사용하는 경우 `ch` 단위가 폰트 로딩 시점에 따라 레이아웃 시프트를 유발할 수 있으니 주의가 필요하며, 시스템 폰트를 쓴다면 이런 문제에서 자유롭습니다.
- 모든 px을 상대 단위로 바꿔야 한다는 절대적 규칙은 없습니다. px 자체가 나쁜 것은 아니며, 프로젝트와 콘텐츠 성격에 맞게 선택적으로 적용하는 것이 현실적입니다.
