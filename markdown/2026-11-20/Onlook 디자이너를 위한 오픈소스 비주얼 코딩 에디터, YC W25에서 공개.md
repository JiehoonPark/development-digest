## 아티클

# Onlook: 디자이너를 위한 오픈소스 개발자 도구

디자이너가 직접 코드로 작업할 수 있게 해주는 로컬 우선(local-first) 비주얼 에디터, Onlook이 YC W25 배치로 Hacker News에 출시 소식을 알렸습니다. Figma, V0, Replit Agent, Base44, Webflow 같은 도구들의 오픈소스 대안을 표방하며, "실제로 돌아가는 앱을 캔버스 위에서 보면서 디자인하고, 그 결과물이 바로 실제 코드가 되는" 워크플로우를 제안합니다.

## Onlook이 풀려는 문제

기존 디자인 툴에서 만든 결과물은 대부분 개발자가 다시 코드로 옮겨야 하는 "목업"입니다. Onlook은 이 간극을 없애겠다는 목표로 만들어졌습니다. 캔버스에서 보고 수정하는 대상이 곧 실제로 동작하는 애플리케이션이기 때문에, 디자인이 끝난 뒤 별도로 구현할 필요가 없습니다.

핵심 아이디어는 세 가지로 요약됩니다.

- **디자인 중심 설계**: 터미널이 아니라 캔버스 위에서 실제 앱이 라이브로 렌더링되는 걸 보면서 작업합니다. 로컬 폰트와 에셋을 그대로 사용해 앱, 웹사이트, 포스터, 그래픽 등을 디자인할 수 있습니다.
- **에이전트는 직접 가져오기(BYO Agent)**: Onlook은 자체 AI 모델을 제공하지 않습니다. 대신 이미 사용 중인 Claude Code나 ChatGPT/Codex 계정을 연결하면, 그 에이전트가 프로젝트 내부에서 실제 작업을 수행합니다. MCP 커넥터를 통해 추가 도구를 연결할 수도 있고, 여러 저장소·페이지에 걸쳐 동시에 여러 디자인 작업을 진행할 수 있습니다.
- **실제 레포지토리 위에서 동작**: 로컬 머신의 Git 저장소를 그대로 열고, 사용자의 개발 서버를 직접 실행합니다. 즉 디자인 결과물이 곧 실제 제품이지, 나중에 누군가 다시 만들어야 하는 목업이 아닙니다.

## 로컬 우선 데스크톱 앱

Onlook은 데스크톱 앱으로 동작하며, 코드는 사용자의 컴퓨터에만 남습니다. 소스 빌드 시 Onlook 계정, 클라우드 키, `.env` 파일이 전혀 필요 없습니다. 완성된 결과물은 자체 포함(self-contained) HTML, PNG, JPEG, PDF로 내보내 동료에게 공유하거나 리뷰, 게시에 활용할 수 있습니다.

라이선스는 Apache 2.0으로, 코드를 읽고 포크해서 자유롭게 커스터마이징할 수 있습니다. 다만 아이콘(Central Icons by Iconists), 브랜드 마크, DMG 아트, 사운드 등은 Onlook 제품에만 한정된 별도 라이선스이며 포크에는 적용되지 않는다는 점은 유의해야 합니다.

## 실제로 할 수 있는 것들

Onlook의 기능은 크게 네 묶음으로 나뉩니다.

**실제 코드베이스 위에서 디자인하기**
- 무한 캔버스에 라이브 앱을 띄우고, 모바일·태블릿·데스크톱 프레임을 나란히 배치해 비교
- 작업 폴더를 건드리지 않는 안전한 워크트리 복사본 사용
- 탭 형태로 여러 프로젝트를 병렬 진행

**자신의 에이전트로 디자인하기**
- 기존에 사용 중인 Claude Code 또는 ChatGPT/Codex 플랜 연결
- 캔버스 위 임의의 요소에 대해 질문
- 에이전트가 알아서 캔버스를 정리(변형, 상태, 플로우 등)
- 캔버스에 참고 이미지 첨부 가능

**스케치하고 공유하기**
- 저장소 밖에서 빠르게 HTML 스케치를 만드는 Artifacts 기능
- HTML, PDF, PNG, JPEG로 내보내기

**실제 배포까지**
- GitHub 저장소 임포트
- 완전히 새로운 코드베이스를 처음부터 시작
- 체크부터 머지까지 원클릭 Pull Request

## 동작 원리

Onlook의 작업 흐름은 다음과 같습니다.

1. **프로젝트 열기**: 컴퓨터 안의 아무 Git 저장소를 지정하거나 새로 임포트합니다. 코드는 원래 위치에 그대로 남습니다.
2. **앱 실행**: 터미널에서 하듯 사용자의 개발 서버를 로컬에서 직접 구동합니다.
3. **캔버스에서 라이브로 확인**: 실행 중인 앱이 캔버스 위 프레임들로 표시되어, 여러 페이지·크기·아이디어를 나란히 비교할 수 있습니다.
4. **에이전트와 함께 디자인**: 채팅으로 원하는 바를 설명하면, 연결해둔 Claude Code나 ChatGPT/Codex 에이전트가 요청을 받아 저장소의 실제 파일을 직접 수정합니다.
5. **실시간 반영 확인**: 개발 서버가 리로드되면서 변경 사항이 캔버스에 바로 반영되고, Git이 모든 변경 이력을 추적합니다.
6. **결과 공유**: 자체 포함 HTML, PNG, JPEG, PDF로 내보냅니다.

Onlook은 사용자의 프로젝트를 그 프로젝트 고유의 툴체인으로 실행하기 때문에, 개발 서버가 지원하는 모든 웹 프레임워크나 언어와 호환됩니다.

### 예시 워크플로우

실제 사용 흐름은 다음과 같이 진행됩니다. 프로젝트 페이지 좌측 상단의 "New Draft" 버튼으로 빈 프로젝트를 시작하고, 화면 우측 하단 입력창에 원하는 디자인을 설명합니다. 에이전트가 되묻는 질문에 답하며 빌드를 기다린 뒤, 개별 프레임을 클릭해 후속 프롬프트의 컨텍스트로 삼거나 특정 요소를 더블클릭해 인라인 채팅으로 그 요소만 수정할 수 있습니다. 공유할 준비가 되면 해당 프레임을 선택해 Artifact로 변환해달라고 요청하고, 프레임 우측 상단의 내보내기 버튼으로 HTML/CSS나 PNG로 추출한 뒤 Slack이나 이메일 등에 붙여넣으면 됩니다.

## 기술 스택

| 레이어 | 구성 |
|---|---|
| 데스크톱 | Electron · React 19 · Astryx(디자인 시스템) · React Flow · Zustand · CodeMirror |
| 프로젝트 연동 | Git(저장소 직접 작업) · node-pty(개발 서버/셸 실행) |
| 툴링 | Bun · Turborepo · 사용량 분석 |
| 내보내기 | HTML · PNG/JPEG(Electron capturePage) · PDF(Electron printToPDF, pdf-lib) |

## 설치 및 데이터 관련 참고 사항

macOS(Apple Silicon·Intel x64)용 데스크톱 앱이 제공되며, Windows는 출시 예정으로 대기자 명단을 운영 중입니다. Linux는 아직 수요를 파악하는 단계라 별도 빌드가 제공되지 않으며, 역시 대기자 명단이 있습니다. 소스 빌드는 Mac 기준으로 `SOURCE_BUILD.md`에 안내되어 있고, 계정이나 클라우드 키 없이 진행할 수 있습니다.

공식 배포판은 기본적으로 제품 사용량 분석(텔레메트리)이 켜져 있고, 소스 빌드는 먼저 동의를 묻습니다. 설정에서 끄거나 `STUDIO_TELEMETRY=0` 환경변수로 비활성화한 채 실행·빌드할 수 있습니다.

참고로 Onlook v1(브라우저 기반 버전)은 이 저장소의 `v1` 브랜치에, 최초의 Electron 데스크톱 버전은 `onlook-dev/desktop` 저장소에 별도로 남아 있습니다.

## 정리

- Onlook은 디자이너가 실제 코드베이스 위에서, 실제로 동작하는 앱을 캔버스로 보며 직접 디자인할 수 있게 하는 오픈소스 로컬 데스크톱 도구입니다.
- 자체 AI 모델 대신 이미 보유한 Claude Code나 ChatGPT/Codex 계정을 연결해 쓰는 "Bring Your Own Agent" 방식을 택해, 모델 종속성 없이 에이전트가 레포지토리의 실제 파일을 직접 편집하게 합니다.
- 코드와 작업물은 로컬에만 저장되며, 소스 빌드 시 Onlook 계정이나 클라우드 키가 필요 없다는 점에서 프라이버시와 자체 호스팅을 중시하는 팀에 적합합니다.
- HTML/PNG/JPEG/PDF 내보내기와 원클릭 PR 생성을 지원해 디자인 결과물을 바로 공유하거나 실제 배포 파이프라인으로 연결할 수 있습니다.
- 현재 macOS만 공식 지원되며 Windows·Linux는 대기 명단 단계이므로, 다른 플랫폼에서는 아직 바로 도입하기 어렵다는 점을 감안해야 합니다.
