## 핵심 개념

> [!abstract]
> SecretSpec 팀은 dotenvy가 bcrypt 해시처럼 달러 기호(`$`)가 포함된 시크릿 값을 변수 치환 문법으로 오인해 조용히 변조하는 버그를 발견했습니다. 문제는 파싱 단계가 아니라 인증 실패로 뒤늦게 드러났고, 관련 업스트림 요청은 2024년부터 방치되어 있었습니다. 게다가 '잘 관리되는 포크'라던 dotenvy 자체도 2023년 3월 이후 3년 넘게 릴리스가 없었기에, 팀은 결국 dotenvy 0.15.7을 베이스로 dotenv-ng 1.0을 새로 만들어 치환 기본값 변경, 구조화된 에러, 100% 커버리지의 파서/렌더러 등을 도입했습니다.

## 아티클

# dotenvy를 포크해서 dotenv-ng를 만든 이유

SecretSpec 팀이 `.env` 파일을 읽고 렌더링하는 Rust 라이브러리 dotenv-ng 1.0을 공개했습니다. 이 라이브러리는 원래 dotenvy의 포크로 시작했는데, 계기가 흥미롭습니다. dotenvy의 파서가 파일을 읽는 과정에서 시크릿 값을 조용히 변조하는 버그를 발견했기 때문입니다.

언뜻 보면 모순처럼 들릴 수 있습니다. SecretSpec은 애초에 환경변수를 시크릿 저장 수단으로 쓰는 관행 자체를 없애는 것을 목표로 하는 프로젝트이고, `.env`가 왜 시크릿의 최종 저장소가 되어서는 안 되는지도 별도로 다룬 바 있습니다. 하지만 `.env`에서 벗어나려면 일단 그 파일을 "정확하게" 읽는 것부터 시작해야 한다는 게 이 프로젝트의 입장입니다.

## dotenvy를 포크한 이유

직접적인 계기는 SecretSpec 이슈 #73이었습니다. 어떤 dotenv 파일에 bcrypt 해시 조각이 포함된 값이 들어 있었습니다.

```
TEST="foo:$2a$10$TWoviNHS27HJMw1PKe4tBeIMlms6tWdYS9hKoHANKCQhluDlEt/gu"
```

파일 자체는 멀쩡했습니다. 그런데 dotenv 프로바이더를 통해 이 값을 읽으면 전혀 다른 값이 반환됐습니다. dotenvy가 달러 기호(`$`)로 시작하는 부분을 변수 치환(variable substitution) 구문으로 해석해버렸기 때문입니다. 더 골치 아픈 점은 이 문제가 파싱 에러가 아니라 한참 뒤 인증 에러로 나타났다는 겁니다. 즉, 값이 조용히 바뀌어서 나중에야 문제가 드러나는 구조였습니다.

이 치환 동작을 설정 가능하게 만들어달라는 요청은 이미 2024년부터 업스트림에 올라와 있었습니다. 2026년에 관련 풀 리퀘스트가 올라오긴 했지만, 아직 릴리스되지 않은 API를 대상으로 작성되어 있었습니다. 마이그레이션 도구 입장에서는 사용자가 자기 시크릿 값 안에서 파서 전용 문법을 알아보고 이스케이프 처리까지 해야 한다는 전제 자체가 성립할 수 없습니다.

## 유지보수 공백 문제

원래 Rust의 `dotenv` 크레이트는 2020년에 릴리스가 끊겼고, 결국 RustSec에 의해 "관리되지 않음(unmaintained)"으로 표시되면서 대안으로 dotenvy가 제시됐습니다.

문제는 dotenvy 역시 스스로를 "잘 관리되는 포크(a well-maintained fork)"라고 소개하고 있지만, 최신 배포 버전인 0.15.7은 2023년 3월 22일에 릴리스된 이후 갱신이 없었다는 점입니다. 2025년에 있었던 한 Rust 포럼 토론에서 이미 2년의 릴리스 공백이 지적된 바 있고, bcrypt 버그가 SecretSpec을 가로막았을 무렵에는 그 공백이 3년을 넘어선 상태였습니다.

업스트림의 문제를 해결하겠다고 나선 포크가 결국 업스트림과 똑같은 릴리스 정체 문제를 반복하고 있다는 건 아이러니한 지점입니다. 물론 dotenvy 메인테이너들이 SecretSpec에 릴리스를 빚진 것은 아닙니다. 다만 SecretSpec 입장에서는 깨지는 버그(breaking bug)에 대한 수정이 자신들이 통제할 수 있는 일정에 맞춰 나와야 했습니다.

## dotenv-ng는 무엇을 개선했나

처음에는 작은 패치로 해결할 생각이었습니다. 하지만 파서를 감사(audit)하는 과정에서 JSON 처리, Windows 경로, 유니코드 이름, 우선순위(precedence), 환경변수의 부분적 변경(partial environment mutation) 등 여러 문제가 추가로 드러났습니다.

이런 이유로 dotenv-ng는 dotenvy 0.15.7을 베이스로 하되, 올바른 동작을 위해 필요한 곳에서는 의도적으로 호환성을 깨는 방식을 택했습니다. 1.0 버전에서 추가된 사항은 다음과 같습니다.

- 소스 위치를 인식하는 파서와 구조화된 에러 메시지
- 기본값으로는 달러 기호를 문자 그대로 처리하며, 치환 기능은 호출자가 명시적으로 활성화했을 때만 동작
- 대시, 앞자리 숫자, 앞자리 점, 유니코드까지 지원하는 더 넓은 범위의 키 문법
- 값을 다시 파싱했을 때 원래 값과 동일하게 복원되도록, 필요한 최소한의 따옴표 처리와 이스케이프만 추가하는 렌더러
- 프로세스 환경변수를 변경하기 전에 수행되는 검증 단계
- 해당 변경 동작 주변에 명시적으로 표시된 unsafe 경계

프로퍼티 테스트(property test)를 통해 임의의 유니코드와 복잡한 문법이 섞인 값들을 검증하고, 따옴표 처리가 꼭 필요한 경우에만 적용되는지 확인하며, 문서 전체를 라운드트립(round-trip)으로 검증합니다. 이번 재작성의 핵심인 파서와 렌더러는 모두 100% 라인 커버리지를 달성했습니다. 전체 호환성 변경 사항과 API 변경 내역은 dotenv-ng 1.0 체인지로그에 기록되어 있습니다.

## dotenv-ng 1.0 사용해보기

dotenv-ng 패키지는 crates.io에서 받을 수 있습니다. 기존 애플리케이션은 의존성 별칭(alias)을 사용해 익숙한 `dotenv`라는 크레이트 이름을 그대로 유지할 수 있습니다.

```
[dependencies]
dotenv = { package = "dotenv-ng", version = "1" }
```

SecretSpec 0.20부터는 SecretSpec 전반의 dotenv 파싱과 렌더링을 dotenv-ng가 담당하게 됩니다. (참고: SecretSpec 0.19에서는 프로바이더 간 시크릿 이동 및 임포트 기능이 다뤄진 바 있습니다.)

## 정리

이 사례는 의존성으로 가져다 쓰는 라이브러리의 "암묵적인 파싱 규칙"이 실제로는 데이터 무결성 문제로 이어질 수 있다는 점을 잘 보여줍니다. dotenvy는 `$`로 시작하는 값을 변수 치환 문법으로 해석하는데, 이 동작이 기본으로 켜져 있다 보니 bcrypt 해시처럼 우연히 `$` 패턴을 포함한 시크릿 값이 조용히 손상되고, 그 여파가 파싱 단계가 아니라 훨씬 나중인 인증 단계에서 에러로 나타났습니다. 게다가 이 문제를 고쳐줄 업스트림 라이브러리조차 몇 년째 릴리스가 멈춰 있었다는 점이 SecretSpec 팀으로 하여금 결국 포크를 결정하게 만들었습니다.

실무적으로 참고할 만한 포인트는, `.env` 파일이나 유사한 설정 파일을 다루는 도구를 선택할 때는 "잘 관리되는 포크"라는 설명만 믿지 말고 실제 릴리스 주기와 이슈 대응 속도를 확인해야 한다는 것, 그리고 시크릿처럼 임의의 바이너리/해시 데이터가 들어갈 수 있는 값에 대해서는 파서가 어떤 이스케이프·치환 규칙을 기본으로 적용하는지 반드시 점검해야 한다는 점입니다. dotenv-ng는 이런 문제의식을 바탕으로 기본 동작에서 치환 기능을 끄고, 명시적 opt-in으로만 활성화하도록 설계를 바꿨다는 점이 핵심입니다.
