## 아티클

# Meta, 터미널 코딩 에이전트 'Muse Code'와 신규 모델 'Muse Spark 1.2' 공개

Meta AI 리서치팀이 터미널 기반 코딩 에이전트 Muse Code(베타)와 이를 구동하는 최신 모델 Muse Spark 1.2를 공개했습니다. 이번 발표는 Meta가 프론티어 모델 경쟁에 본격적으로 뛰어들기 위한 다음 단계로, 앞으로 더 크고 강력한 모델들이 이어질 예정임을 시사합니다. 이 글에서는 Muse Code의 아키텍처적 특징과 Muse Spark 1.2의 학습 방식, 그리고 GPU 커널 최적화 사례를 통해 실제로 얼마나 강력한 코딩 능력을 보여주는지 살펴보겠습니다.

## Muse Code: 지속형 서브에이전트를 활용하는 터미널 코딩 에이전트

Muse Code는 macOS와 Linux에서 아래 명령어로 바로 설치할 수 있습니다.

```
curl -fsSL https://dev.meta.ai/install.sh | bash
```

Muse Code는 대규모 저장소를 대상으로 복잡한 소프트웨어 엔지니어링 작업을 수행합니다. 변경 사항을 계획하고, 코드를 작성하고, 결과를 검증하는 전 과정을 처리하는데요, 특히 하나의 작업에 대해 여러 개의 지속형(persistent) 서브에이전트를 동시에 조율할 수 있다는 점이 특징입니다. 이를 통해 어려운 문제를 더 빠르고 정확하게, 사람의 개입을 줄이면서 해결합니다.

### 비동기 백그라운드 에이전트

Muse Code는 단순한 에이전트 루프에 더해, 메인 에이전트의 능력을 보강하는 일련의 비동기 백그라운드 에이전트를 함께 운용합니다. 이 특화된 백그라운드 에이전트들은 개별 작업마다 새로 생성되는 것이 아니라 세션 내내 활성 상태를 유지하는데요, 덕분에 중복된 정보 수집을 피할 수 있습니다. 이들은 스스로 다음 단계를 진행하고, 메인 에이전트에게 언제 결과를 보고할지도 자체적으로 판단합니다. 이러한 지속성 덕분에 여러 단계를 거치는 어려운 작업에서 지연 시간이 줄고, 사람이 일일이 방향을 잡아줄 필요도 줄어듭니다.

### 런타임 설계: 재실행 가능한 이벤트 로그

Muse Code는 로컬 이벤트 로그를 활용합니다. 모델 호출, 도구 실행, 승인, 편집 등 모든 이벤트가 이 로그에 순서대로 기록되는데요, 이 로그 하나가 시스템 전체의 단일 진실 공급원(single source of truth) 역할을 하기 때문에 런타임을 정확히 재생(replay-exact)할 수 있고, 크래시가 발생해도 안전하게 재시작(restart-safe)할 수 있습니다. 즉 오류로 세션이 중단되더라도 에이전트가 멈춘 지점에서 정확히 이어서 작업을 재개할 수 있다는 뜻입니다. 이 능력 덕분에 Muse Code는 장시간 실행되는 작업도 중간 실패에 흔들리지 않고 끝까지 수행할 수 있습니다.

### 기본 제공 스킬

Muse Code는 몇 가지 기본 스킬을 함께 제공합니다.

- `/plan`: 작업을 승인 게이트가 걸린 계획으로 변환
- `/grill`: 그 계획이 실제로 잘 작동하는지 스트레스 테스트
- `/goal`: 지정된 목표를 향해 작업을 완수

예시로, 사용자가 어떤 주택을 촬영한 fly-through 영상을 mp4 파일로 터미널에 입력하면, Muse Code가 이 영상을 해석해 시각적으로 풍부한 휴가용 주택 마케팅 및 예약 페이지를 생성해내는 데모가 소개되었습니다.

## Muse Spark 1.2: 코딩에 특화된 모델 업데이트

Muse Spark 1.2는 이전 버전인 Muse Spark 1.1을 코딩 중심으로 개선한 모델입니다. 코드 생성, 복잡한 디버깅, 코드베이스 이해, 엔드투엔드 개발자 워크플로우 전반에서 성능이 향상되었습니다. 이번 업데이트에서는 코딩 태스크에 투입되는 학습 연산량을 크게 늘리는 동시에 학습 환경의 다양성도 확장했습니다. 그러면서도 일반 에이전트(general agents) 영역에서의 기존 강점은 그대로 유지하고 있습니다. 자세한 평가 결과는 Meta의 공식 리포트에서 확인할 수 있습니다.

### Muse Code와의 공동 학습

Meta는 Muse Spark 1.2를 Muse Code와 함께 학습시켜, 두 시스템을 함께 사용할 때 최상의 성능과 사용성을 발휘하도록 만들었습니다. 학습 과정에는 거부 샘플링(rejection sampled) 방식의 하네스 트래젝토리, 목표(goal)·컨텍스트 압축(compaction)·서브에이전트 관련 레시피 최적화, 그리고 Muse Code 툴셋과의 하네스 호환성을 극대화하기 위한 통합 작업이 포함되었습니다.

### 장기 과제(Long-Horizon) 대응

Muse Spark 1.2는 저장소 전체 생성, 대규모 엔드투엔드 프로젝트, 자동 연구(auto-research)를 포함한 장기 코딩 작업에 대해 광범위하게 학습되었습니다. 계획(planning)을 통해 작업 순서를 정하고, 목표 조건화(goal conditioning)로 방향성을 유지하며, 컨텍스트 압축(context compaction)으로 작업을 지속하는 데 필요한 지식을 계속 보존합니다.

### 자기개선(Self-Improvement) 루프

Meta는 Muse Spark 1.1을 활용해 난이도 높은 코딩 환경과 지시 이행(instruction-following) 템플릿을 직접 생성했습니다. 그런 다음 이 모델이 후보 솔루션들이 요구 사항을 얼마나 잘 만족하는지 채점하도록 해, 확장 가능한 학습 데이터셋을 만들어냈습니다. 이런 자기개선 루프 덕분에 Muse Spark 1.2는 이전 모델보다 복잡한 지시 사항을 더 정밀하게 따르게 되었습니다.

## 케이스 스터디: GPU 커널 최적화

Meta는 Muse Spark 1.2가 1,000회 이상의 도구 호출(최대 24시간 소요)에 걸쳐 GPU 커널을 반복적으로 최적화하는 능력을 테스트했습니다. Muse Code의 에이전틱 코딩 환경을 활용해 모델이 직접 커널을 작성하고, 컴파일하고, 프로파일링하며, 주어진 베이스라인 대비 성능을 점진적으로 개선해나가는 방식입니다. 벤치마크는 NVIDIA Hopper GPU용 KDA와 MLA 커널을 대상으로 진행되었고, 에이전트는 제공된 베이스라인 구현 대비 상당한 성능 개선을 지속적으로 달성했습니다.

**KDA 벤치마크**: 베이스라인은 KDA의 FLA Triton 구현이었습니다. 모델은 FLA 같은 서드파티 커널 라이브러리를 직접 임포트하는 것이 금지되었고, 대신 특화된 커널 최적화 지식을 적용해 Triton으로 알고리즘 자체를 구현해야 했습니다(기존 구현을 단순히 감싸는 방식은 불허). Muse Spark 1.2는 chunk-parallel 방식의 준비(preparation) 커널과 순차적인 청크 간(inter-chunk) 스캔을 결합했으며, 표준적인 퓨전·타일링 기법에 더해 청크 중간점에서 gated cumulative decay를 재중심화하는 등 KDA에 특화된 최적화를 적용했습니다.

**MLA 벤치마크**: PyTorch 참조 구현을 기준으로, 배치 사이즈 1, 헤드 수 64, 시퀀스 길이 8192, 잠재 차원(latent dimension) 512 조건에서 성능을 비교했습니다. Muse Spark 1.2는 이 워크로드에 맞춰 2개의 커널로 구성된 Triton 파이프라인을 설계했고, 커널 퓨전과 타일링에 더해 공유 KV 잠재값(latent)을 K와 V 양쪽으로 재사용하는 MLA 특화 최적화를 적용했습니다.

## 출시 현황

Muse Spark 1.2는 오늘부터 Muse Code와 Meta Model API를 통해 사용할 수 있으며, 글로벌 접근성도 확대되었습니다. Meta는 새로운 하네스 기능과 더 강력한 모델을 포함해 추가 로드맵을 예고했습니다.

## 정리

- **Muse Code**는 단일 메인 에이전트 루프에 지속형 비동기 백그라운드 서브에이전트를 결합한 구조로, 세션 내내 상태를 유지하며 중복 작업 없이 복잡한 엔지니어링 태스크를 처리합니다.
- 로컬 **이벤트 로그 기반 런타임**을 채택해 재생 정확성(replay-exact)과 재시작 안전성(restart-safe)을 확보했으며, 이는 장시간 실행되는 작업에서 크래시 복구를 가능하게 하는 핵심 설계입니다.
- **Muse Spark 1.2**는 Muse Code와 공동 학습(co-training)되어 하네스 호환성을 극대화했고, 장기 과제 수행을 위해 계획·목표 조건화·컨텍스트 압축 기법을 폭넓게 학습했습니다.
- 이전 모델(Muse Spark 1.1)을 활용해 난이도 높은 학습 환경과 채점 기준을 스스로 만들어내는 **자기개선 루프**를 통해 복잡한 지시 이행 능력을 끌어올렸습니다.
- KDA·MLA GPU 커널 최적화 실험에서 1,000회 이상의 반복적 도구 호출로 서드파티 라이브러리 없이 직접 Triton 커널을 설계·개선하며 베이스라인 대비 유의미한 성능 향상을 보였다는 점은, 실제 프로덕션 수준의 저수준 최적화 작업에도 에이전트를 투입할 수 있는 가능성을 보여줍니다.

Muse Code와 Muse Spark 1.2는 단순한 코드 자동완성을 넘어, 장시간·다단계 소프트웨어 엔지니어링 작업을 사람의 개입을 최소화하며 수행하는 방향으로 설계되었습니다. 프론트엔드 개발자 입장에서도 대규모 리팩터링이나 마이그레이션처럼 오랜 시간과 여러 단계를 요구하는 작업에 이런 지속형 에이전트 구조가 실질적인 생산성 향상을 가져다줄지 지켜볼 만합니다.
