## 핵심 개념

> [!abstract]
> LINE 프리미엄콜은 통화 중 소리와 영상을 기록해 Keep Memo에 저장하는 기능으로, 음성 통화가 영상 통화로 전환되어도 하나의 파일에 기록을 이어가고 자체 온디바이스 모델로 STT를 제공합니다. 이를 위해 오디오/비디오 트랙을 처음부터 함께 준비하고, 통화 상태 전환과 실제 영상 도착 시점을 구분해 처리했으며, 녹화용 화면을 통화 UI와 분리해 렌더링했습니다. STT는 서버 없이 기기 내에서 처리하되 고음질/최적화 스트림을 나누고 음성 수신과 인식을 비동기로 분리해 통화 중 기기 성능 부담을 줄였습니다.

## 아티클

LINE 앱에는 통화 중 소리와 영상을 기록해 Keep Memo에 저장하는 '프리미엄콜'이라는 기능이 있습니다. 녹화 버튼 하나만 누르면 끝나는 것처럼 보이지만, 실제로는 음성 통화가 영상 통화로 바뀌는 순간을 하나의 파일에 이어 담고, 온디바이스 STT 모델로 기기 성능을 해치지 않으면서 음성을 인식하는 등 까다로운 문제들이 숨어 있습니다. LINE Android VoIP 개발자가 이 기능을 만들며 겪은 설계 고민과 해결 과정을 정리했습니다.

## 프리미엄콜이란 어떤 기능인가

프리미엄콜은 LINE Labs로 출시된 기능으로, 현재 일본·대만·태국에서 녹음/녹화를 지원하며 국가마다 제공 범위가 다릅니다. LINE의 1:1 음성/영상 통화 중 원하는 구간을 기록하면, 나와 상대방의 목소리(영상 통화라면 모습까지)가 함께 남고, 통화 종료 후 Keep Memo에서 다시 확인할 수 있습니다.

예를 들어 전화로 물건 사용법을 설명받다가 이해가 안 되는 부분이 있어 카메라를 켜고 직접 보여 달라고 하는 상황을 생각해보면, 이 통화를 기록해두면 음성으로 들은 설명과 영상으로 본 동작을 나중에 함께 확인할 수 있어 모든 내용을 외우거나 메모할 필요가 없어집니다.

재생 화면에는 상대방 프로필, 이름, 통화 시작 시각이 함께 표시되어 어떤 통화인지 바로 알아볼 수 있고, 통화 상대에게도 녹음/녹화 중임을 안내합니다. 또한 음성 통화에서는 설정에 따라 STT(음성의 텍스트 변환, 현재 일본어 지원)를 함께 사용할 수 있는데, 이 음성 인식은 서버가 아닌 기기 내 자체 모델로 처리됩니다. 프리미엄콜의 핵심은 어디까지나 다시 보고 들을 수 있는 통화 기록이고, STT는 그 기록을 더 편하게 활용하도록 돕는 보조 기능입니다.

## 음성 통화가 영상 통화로 바뀌어도 기록은 끊기지 않아야 한다

통화 중 카메라를 켜는 순간, 사용자 입장에서는 음성 통화에서 영상 통화로 전환되는 시점입니다. 이때 카메라를 켰다는 이유로 기록이 멈추거나 녹화 버튼을 다시 눌러야 한다면, 사용자는 대화보다 녹화 상태를 신경 쓰게 됩니다. 그래서 개발팀은 카메라를 켜도 진행 중인 기록이 끊기지 않고 이어지도록 설계했습니다.

음성 구간과 영상 구간을 따로 저장하는 방법도 고려할 수 있지만, 이 경우 결과 파일이 나뉘고 전환 구간의 데이터를 따로 다뤄야 하며, 통화 종료 후 파일을 이어 붙이려면 임시 파일과 후처리까지 관리해야 합니다. 대신 LINE은 한 번 시작한 기록이 통화 방식이 바뀌어도 같은 파일에 이어지도록, 처음부터 음성과 영상을 함께 담을 수 있는 구조를 준비하고 통화 상태에 따라 그 안에 넣을 화면만 바꾸는 방식을 택했습니다.

## 음성 통화에도 화면을 담은 이유

음성 통화라면 목소리만 저장해도 되는데 왜 화면까지 함께 담았을까요? 두 가지 이유가 있습니다.

첫째, 기록된 파일을 열었을 때 누구와 나눈 통화인지 쉽게 알아볼 수 있도록 상대방 프로필, 이름, 통화 시작 시각을 보여주기 위해서입니다. 목소리를 한참 듣지 않아도 어떤 통화의 기록인지 바로 확인할 수 있습니다.

둘째, 통화 도중 음성에서 영상으로 전환되는 순간을 같은 기록 안에 자연스럽게 담기 위해서입니다. 음성 통화 중에는 프로필 화면을 보여주다가, 영상 통화로 전환되면 같은 파일 안에서 상대방의 실제 영상으로 이어집니다. 재생할 때도 다른 파일을 열 필요 없이 프로필 화면에서 통화 영상으로 자연스럽게 이어지는 대화를 볼 수 있습니다.

이를 구현하기 위해 음성 통화를 기록할 때부터 오디오 트랙과 비디오 트랙(하나의 파일 안에서 음성과 화면을 각각 담는 경로)을 함께 준비합니다. 오디오에는 양쪽 목소리를, 비디오에는 프로필과 통화 정보로 만든 화면을 담는데, 실제 카메라 영상이 없어도 이미지를 영상의 한 프레임으로 만들어 기록할 수 있습니다.

영상 통화로 전환되면 비디오 트랙에 전달하던 프로필 화면을 실제 통화 영상으로 교체합니다. 오디오는 계속 기록되고, 파일과 트랙도 그대로 유지됩니다. 하나의 녹화를 관리하는 작업 단위를 '녹화 세션'이라고 부르는데, 세션을 새로 시작하지 않고 그 안에서 사용할 화면만 바꾸는 방식입니다.

## 통화 상태 전환과 영상 도착 시점은 다르다

그렇다면 영상 통화로 바뀌었다는 신호를 받는 즉시 프로필 화면을 실제 영상으로 바꾸면 될까요? 여기서 한 가지 더 고려할 점이 있습니다. 통화 상태가 바뀌는 시점과 실제로 그릴 수 있는 영상이 도착하는 시점은 같지 않을 수 있다는 점입니다.

VoIP 엔진은 통화 세션의 미디어 상태가 바뀌었다는 이벤트를 전달하지만, 내 카메라 영상과 상대방에게서 받은 영상은 각각 별도의 입력 경로로 들어옵니다. 내 영상이 먼저 준비될 수도, 상대방 영상이 먼저 도착할 수도 있습니다.

그래서 '영상 통화를 시작했다'는 것과 '기록할 영상이 도착했다'는 것을 구분해서 다룹니다. 영상 통화로 바뀌면 내 영상과 상대방 영상을 각각 확인해, 실제로 프레임이 도착했고 화면에 그릴 수 있는 상태인지 판단합니다. 예를 들어 내 카메라 영상이 먼저 준비됐다면, 내 영상 영역에는 실제 영상을 넣고 아직 도착하지 않은 상대방 영역에는 프로필을 유지한 채로 녹화를 이어가다가, 상대방 영상이 준비되면 그 영역을 실제 영상으로 바꿉니다.

이렇게 양쪽 영상이 동시에 준비될 때까지 녹화 전체를 멈추지 않고, 아직 사용할 수 없는 입력에는 대체 화면을 두고 사용 가능한 입력부터 반영합니다. 이 구분은 카메라를 끄는 등 영상 통화 중 입력 상태가 달라지는 경우에도 동일하게 적용됩니다.

## 표정을 잘 담기 위한 렌더링 분리

프리미엄콜은 상대방 영상과 내 영상을 함께 기록해, 통화 당시의 표정과 반응을 다시 볼 수 있도록 합니다. 이때 녹화 화면은 휴대폰 화면을 그대로 캡처하는 방식이 아니라, VoIP 엔진이 전달하는 내 영상과 상대방 영상으로 녹화 전용 화면을 따로 구성합니다. 이렇게 하면 알림이나 통화와 무관한 UI 요소 없이 통화 영상만으로 녹화 화면을 만들 수 있습니다. 즉 사용자가 보는 통화 UI와 파일에 남길 화면을 분리해서 다루는 것입니다.

문제는 실제 영상이 도착한 뒤에도 입력 조건이 계속 변한다는 점입니다. 내 영상과 상대방 영상의 크기나 비율이 다를 수 있고, 통화 중 해상도가 바뀌기도 합니다. 이 변화를 그대로 녹화 파일의 화면 크기에 반영하면 입력 하나가 바뀔 때마다 이후 기록 경로 전체가 영향을 받게 됩니다.

그래서 영상이 들어오는 쪽과 파일에 저장하는 쪽을 나눠서 처리합니다. 영상 소스나 해상도가 바뀌면 필요한 경우 화면을 그리는 렌더러에 해당 입력을 다시 연결하지만, 파일에 기록하는 최종 프레임의 크기는 유지합니다. 그 안에서 상대방 영상과 내 영상을 화면 영역에 맞춰 렌더링하는 식으로, 입력 조건이 바뀌어도 녹화 세션은 끊기지 않고 유지됩니다.

## STT는 왜 온디바이스로 처리하는가

STT는 소리를 켜고 녹음을 듣기 어려운 상황에서도 텍스트로 대화 내용을 확인할 수 있도록 돕는 기능으로, 현재는 음성 통화 구간에서만 동작합니다. 프리미엄콜의 STT는 자체 온디바이스 음성 인식 모델을 사용하며, 통화 음성을 서버로 보내지 않고 기기 안에서 텍스트로 변환합니다.

개발 과정에서 기술적으로 가장 어려웠던 부분이 바로 이 지점이었습니다. 음성 인식을 서버 없이 처리하므로 그 연산 부담을 통화 중인 디바이스가 그대로 떠안아야 했습니다. 상대방 목소리를 재생하고, 내 음성을 전송하고, 녹음까지 진행 중인 기기에서 음성 인식 모델까지 함께 돌려야 했기에, 인식 정확도뿐 아니라 통화 중 디바이스에 가해지는 퍼포먼스 부담을 해결하는 데 많은 공을 들였습니다.

### 모델에는 다운샘플링한 음성을 전달

먼저 모델에 넣을 음성 데이터 자체를 최적화했습니다. 통화 중 재생되는 음성과 녹음용 음성은 깨끗한 고음질이 필요하지만, STT 모델에까지 같은 형식의 음성을 그대로 넣을 필요는 없었습니다. 실제로 사용 중인 온디바이스 모델은 샘플레이트를 낮춘 다운샘플링 음성만으로도 대화 내용을 충분히 텍스트로 변환할 수 있었습니다. 이를 통해 모델에 전달하는 오디오 데이터 양을 줄이면서도, 통화 중 듣는 음질은 그대로 유지했습니다.

### 엔진 단에서 두 개의 스트림 생성

통화 중 계속 들어오는 음성 데이터 흐름(스트림)을, VoIP 엔진 내부 오디오 처리 과정에서 고음질 스트림과 모델 입력 조건에 맞춘 최적화 스트림 두 가지로 함께 만들도록 했습니다. 내 목소리와 상대방 목소리는 엔진 안에서 각각 필요한 처리를 거치고, 고음질 스트림은 통화 재생에, 최적화 스트림은 앱으로 전달되어 녹음과 STT에 함께 사용됩니다.

음성을 각 용도에 맞게 준비하는 작업 자체를 VoIP 엔진 내부에서 처리하므로, 앱 단에서는 이미 준비된 최적화 스트림을 녹음과 온디바이스 STT에 그대로 사용할 수 있어 별도의 다운샘플링이 필요 없습니다. 녹음 모듈은 파일 생성에, STT 모듈은 모델 실행과 인식 결과 처리에 집중하도록 역할을 분리했습니다.

### 음성 입력과 인식 작업의 비동기 분리

음성을 받는 작업과 실제로 인식하는 연산 작업을 비동기로 연결해, 새 음성을 받는 쪽이 인식 완료를 기다리지 않도록 했습니다. 두 작업은 같은 디바이스 자원을 사용하므로 서로 영향을 줄 수 있고, 인식이 늦어지면 처리 대기 작업이 쌓일 수 있기 때문입니다.

인식할 음성 구간도 선별합니다. STT에서는 나와 상대방의 음성을 구분해 인식 작업에 전달하고, VAD(음성 활동 감지)를 활용해 말소리가 없는 구간의 불필요한 처리를 줄입니다.

다만 이 조건을 녹음에 그대로 적용하면 문제가 생깁니다. 예를 들어 설명을 듣던 사람이 물건을 찾느라 잠시 말을 멈춘 구간이 있을 때, 말소리가 있는 부분만 이어 붙이면 실제로는 잠시 멈췄다가 이어진 대화가 바로 이어진 것처럼 들릴 수 있습니다. 그래서 STT는 말소리 구간만 골라 처리하되, 녹음에는 대화 사이의 침묵도 그대로 남깁니다. 같은 음성이지만 사람이 다시 들을 기록과 모델이 인식할 입력을 목적에 맞게 다르게 다룬 것입니다.

## 통화 종료와 기록 완성은 별개의 시점

통화가 끝났다고 해서 기록이 곧바로 완성되는 것은 아닙니다. 새 데이터를 받는 일이 끝났을 뿐, 이미 받은 데이터가 모두 파일에 반영된 것은 아니기 때문입니다.

녹음/녹화에서는 먼저 새 음성과 영상을 받는 작업을 멈춘 뒤, 남은 미디어 처리를 마치고 나서야 파일을 닫고 자원을 해제합니다. 파일을 먼저 닫아버리면 아직 처리 중인 데이터를 기록하지 못할 수 있기 때문입니다.

음성 통화 구간에서 모델에 전달한 인식 작업 역시 통화 종료 후에도 남아있을 수 있습니다. STT는 녹화 파일과 별도로 텍스트 결과를 만들기 때문에, 남은 작업과 결과를 따로 정리합니다. 자원 해제 시에는 대기 시간에 한도를 두고, 인식이 끝나지 못한 경우도 결과 상태에 반영합니다.

사용자 화면에서는 파일과 STT 결과의 상태를 모아 보여주며, 통화 종료 후 녹음/녹화 파일과 STT 결과를 각각 마무리해 저장합니다. 즉 '통화 종료'와 '기록 완성'을 명확히 구분해서 다루는 것입니다.

## 정리

LINE 프리미엄콜은 '통화를 기록한다'는 단순한 요구사항 안에 생각보다 많은 설계 포인트를 담고 있습니다.

- **단일 파일 지속 기록**: 음성 통화를 녹음할 때부터 오디오/비디오 트랙을 함께 준비해, 영상 통화로 전환되어도 같은 녹화 세션 안에서 화면만 교체하는 방식으로 기록이 끊기지 않게 했습니다.
- **상태 전환과 데이터 도착의 분리**: '영상 통화 시작'이라는 상태 이벤트와 '실제 영상 프레임 도착'을 구분해, 내 영상·상대방 영상이 각각 준비되는 대로 순차 반영하며 전체 녹화를 멈추지 않습니다.
- **녹화용 화면과 통화 UI의 분리**: 화면 캡처 대신 VoIP 엔진의 영상 소스로 별도 녹화 화면을 구성해, 입력 해상도가 바뀌어도 파일의 최종 프레임 크기는 고정 유지합니다.
- **온디바이스 STT 최적화**: 엔진 단에서 고음질(재생용)/최적화(녹음·STT용) 두 스트림을 동시에 생성하고, 음성 수신과 인식 연산을 비동기로 분리하며, VAD로 STT 처리량은 줄이되 녹음에는 침묵 구간까지 그대로 보존합니다.
- **종료 시점의 이원화**: 통화 종료(신규 데이터 수신 중단)와 기록 완성(남은 처리 완료 후 파일 닫기, STT 결과 정리)을 분리해 데이터 유실을 방지합니다.

실시간 미디어와 온디바이스 모델을 함께 다뤄야 하는 서비스를 설계할 때, 이벤트 발생 시점과 실제 데이터 가용 시점을 구분하고, 재생/저장/인식이라는 서로 다른 목적에 맞춰 데이터 파이프라인을 분리하는 접근 방식은 참고할 만한 패턴입니다.
