18:T15d1,<h2>CSS만으로 개발자에게 에러 메시지 보여주기</h2>
<p>CSS를 아무리 꼼꼼하게 작성해도, 그걸 사용하는 다른 개발자가 의도와 다르게 오남용하는 경우는 피하기 어렵습니다. 특히 여러 명이 함께 작업하는 팀 환경이라면 이런 일이 더 자주 생기는데요. Kevin Powell은 이런 상황에서 CSS만으로 &quot;에러 메시지&quot;를 만들어 보여주는 트릭을 소개합니다. 복잡한 린팅 도구 없이도, 컴포넌트가 잘못 사용됐을 때 눈에 띄는 아웃라인과 함께 왜 잘못됐는지 힌트까지 보여줄 수 있는 방법입니다.</p>
<h3>기본 아이디어: 조건에 맞지 않으면 아웃라인 표시</h3>
<p>예를 들어 카드 컴포넌트 안에 H2, H3, H4 같은 제목 요소가 하나도 없다면, 그건 잘못된 사용법일 가능성이 높습니다. 이럴 때 <code>:not()</code> 선택자를 활용해 해당 조건을 만족하지 않는 카드에 눈에 띄는 아웃라인을 걸어줄 수 있습니다. 구현 자체는 아주 단순합니다.</p>
<p>문제는 이렇게 아웃라인만 보여주면, 누군가 요소를 인스펙트해서 &quot;뭐가 문제지?&quot; 하고 들여다봐도 원인을 바로 알아채기 쉽지 않다는 점입니다. 결국 알아내긴 하겠지만, 더 쉽게 찾을 수 있는 방법이 있습니다.</p>
<h3>CSS content로 에러 메시지 직접 보여주기</h3>
<p><code>content</code> 속성을 활용해 &quot;This card needs a heading&quot; 같은 문구를 아예 화면에 띄워버리면, 개발자가 요소를 인스펙트하는 순간 바로 눈에 보이는 에러 메시지로 문제를 파악할 수 있습니다. 더 나아가 AI 코딩 도구를 사용하는 경우라면, AI가 이 스타일과 에러 문구를 그대로 읽어서 &quot;이 스타일이 왜 적용됐는지&quot; 설명해줄 수도 있습니다.</p>
<p>이 트릭은 혼자 코드를 작성할 때보다는, 여러 명 혹은 큰 팀이 함께 작업하는 코드베이스에서 특정 패턴이 반복적으로 잘못 쓰이는 걸 발견했을 때 그 사용 규칙을 강제하는 용도로 특히 유용합니다. 물론 린팅 같은 다른 방식으로도 규칙을 강제할 수 있지만, 스타일링 관련 오용은 테스트 코드로 잡아내기 까다로운 경우가 많습니다. 이런 간단한 CSS 트릭으로 빠르게 더블체크할 수 있다는 점이 장점입니다.</p>
<h3>접근성 체크에 특히 유용</h3>
<p>이 기법이 가장 빛을 발하는 영역은 접근성(accessibility) 관련 체크입니다.</p>
<ul>
<li>이미지에 alt 텍스트가 빠졌을 때</li>
<li>다이얼로그에 <code>aria-labelledby</code>가 없을 때</li>
</ul>
<p>같은 경우에, 본격적인 접근성 테스트 단계에 도달하기 훨씬 전, 즉 개발자가 코드를 작성하는 바로 그 시점에 경고를 띄울 수 있습니다. 접근성 테스트가 파이프라인 한참 뒤쪽에서 돌아가는 걸 기다리지 않고, 작성 단계에서 바로 규칙을 강제할 수 있다는 점이 핵심입니다.</p>
<p>페이지 내 H1이 여러 개 존재하는 경우를 잡아내는 선택자도 시도해봤다고 언급했는데요. 꽤 까다로운 선택자이고 실제로 작동은 하는 것으로 보이지만, 직접 테스트해보고 사용하는 것을 권장합니다.</p>
<h3>구조 강제하기: 자식 요소 개수나 특정 레이아웃 검증</h3>
<p>꼭 &quot;무언가 빠져있다&quot;는 상황뿐 아니라, 특정 레이아웃 구조를 강제하는 데도 활용할 수 있습니다. 예를 들어 페이지 레이아웃이 header, main, footer로 구성되어야 한다면, main 요소의 자식이 4개 이상인 경우를 감지해서 &quot;이 레이아웃은 이렇게 동작하면 안 된다&quot;는 에러를 띄울 수 있습니다.</p>
<p>조금 더 공격적으로 가고 싶다면, 조건에 안 맞을 때 <code>position: fixed</code> 요소를 강제로 끼워 넣는 방식도 가능합니다. 다소 과격한 방법이라 개인적으로는 썩 선호하지 않지만, 팀 내에서 특정 패턴을 강하게 막아야 할 때 고려해볼 수 있는 옵션으로 언급됩니다.</p>
<h3>출처</h3>
<p>이 아이디어는 본인이 처음 생각해낸 것이 아니라, Heydon Pickering의 글에서 소개된 내용을 참고한 것임을 밝히고 있습니다.</p>
<h3>정리</h3>
<ul>
<li>CSS의 <code>:not()</code> 선택자와 <code>content</code> 속성을 조합하면, 컴포넌트가 잘못 사용됐을 때 아웃라인과 에러 메시지를 화면에 직접 띄울 수 있습니다.</li>
<li>이 방법은 특히 여러 명이 함께 작업하는 코드베이스에서, 테스트 코드로 잡아내기 어려운 스타일 오남용 패턴을 빠르게 체크하는 데 유용합니다.</li>
<li>접근성(alt 텍스트 누락, aria-labelledby 누락 등) 체크에 활용하면, 별도의 접근성 테스트 단계를 기다리지 않고 작성 시점에 바로 규칙을 강제할 수 있다는 것이 가장 큰 장점입니다.</li>
<li>특정 레이아웃 구조(자식 요소 개수 제한 등)를 강제하는 용도로도 확장 가능하며, 필요하다면 <code>position: fixed</code> 요소를 강제 삽입하는 더 공격적인 방식도 쓸 수 있지만 신중하게 접근해야 합니다.</li>
<li>AI 코딩 도구를 사용하는 환경에서는, AI가 이 에러 메시지를 읽고 왜 해당 스타일이 적용됐는지 설명해주는 보너스 효과도 기대할 수 있습니다.</li>
