유니코드 특수 문자로 만드는 신기한 도메인 해킹 (2018)

Domain hacks with unusual Unicode characters (2018)

📅 2026-11-02📰 Hacker News (Top)

유니코드의 숨겨진 트릭: 특수 문자로 도메인 꾸미기

유니코드에는 거의 쓰이지 않는 특이한 기호들이 숨어 있습니다. 상표를 뜻하는 ™, 서비스마크 ℠, 처방전 기호 ℞처럼 말이죠. 그런데 "Letterlike Symbols" 블록을 뒤지다 보면 흥미로운 두 기호를 발견할 수 있습니다. 바로 전화 기호(℡)와 번호 기호(№)인데요, 이 두 글자가 각각 단일 문자로 존재한다는 점이 핵심입니다. 그리고 공교롭게도 .tel과 .no는 둘 다 실제로 존재하는 최상위 도메인(TLD)입니다. 이 우연을 이용하면 꽤 재미있는 도메인 "해킹"이 가능해집니다.

℡와 №로 실제 URL 만들기

예를 들어 edent.tel이라는 연락처 사이트는 다음과 같이 쓸 수 있습니다.

https://edent.℡/

노르웨이 도메인 등록 기관인 NORID의 사이트도 마찬가지입니다.

https://www.norid.№/

놀랍게도 이 링크들은 그냥 복사해서 아무 브라우저 주소창에 붙여넣기만 해도 정상적으로 동작합니다.

TLD 자리에만 국한되지 않는다

이 트릭은 TLD 뒤에만 쓸 수 있는 게 아니라, 도메인 이름의 어느 위치에나 적용할 수 있습니다. 유니코드에는 알파벳을 흉내 낸 다양한 "스타일" 문자들이 있는데, 이들을 조합해서 똑같은 도메인을 완전히 다른 모양의 글자로 표현할 수 있습니다. 예를 들면 다음과 같습니다.

  • Script: https://ℰ𝒳𝒜ℳ𝓟ℒℰ.𝒞𝓞ℳ/
  • Math Bold: https://𝐞𝐱𝐚𝐦𝐩𝐥𝐞.𝐜𝐨𝐦/
  • Fraktur: https://𝖊𝖝𝖆𝖒𝖕𝖑𝖊.𝖈𝖔𝖒/
  • Math bold italic: https://𝒆𝒙𝒂𝒎𝒑𝒍𝒆.𝒄𝒐𝒎/
  • Math bold script: https://𝓮𝔁𝓪𝓶𝓹𝓵𝓮.𝓬𝓸𝓶/
  • Double struck: https://𝕖𝕩𝕒𝕞𝕡𝕝𝕖.𝕔𝕠𝕞/
  • Monospace: https://𝚎𝚡𝚊𝚖𝚙𝚕𝚎.𝚌𝚘𝚖/
  • Super script: https://ᵉˣᵃᵐᵖˡᵉ.ᶜᵒᵐ/
  • Sub script: https://ₑₓₐₘₚₗₑ.cₒₘ/ (단, 일부 문자는 서브스크립트 형태가 지원되지 않습니다)
  • Math sans bold: https://𝗲𝘅𝗮𝗺𝗽𝗹𝗲.𝗰𝗼𝗺/
  • Math sans bold italic: https://𝙚𝙭𝙖𝙢𝙥𝙡𝙚.𝙘𝙤𝙢/
  • Math sans italic: https://𝘦𝘹𝘢𝘮𝘱𝘭𝘦.𝘤𝘰𝘮/
  • Math Squared: https://🄴🅇🄰🄼🄿🄻🄴.🄲🄾🄼/ (단, 점(.)은 사각형 문자로 바꾸면 안 됩니다)
  • Circled: https://ⓔⓧⓐⓜⓟⓛⓔ.ⓒⓞⓜ/ (마찬가지로 점은 동그라미 문자로 바꾸면 안 됩니다)

이 외에도 조합 가능한 잡다한 문자들이 더 존재합니다.

어떻게 동작하는 걸까?

겉보기엔 마법 같지만, 실제로는 브라우저가 알아서 변환을 해주는 것입니다. DNS 서버는 .℡ 같은 도메인에 대한 질의에 정상적으로 응답하지 않습니다. 대신 브라우저가 .℡를 발견하면 RFC 5895에 정의된 IDNA2008 정규화 과정을 거쳐 이를 일반 문자로 변환합니다.

이 과정에서 핵심은 각 문자를 유니코드 데이터베이스의 "Simple_Lowercase_Mapping" 속성(UnicodeData.txt의 14번째 컬럼)에 매핑하는 단계입니다. ℡ 문자의 유니코드 데이터 항목을 보면 다음과 같습니다.

2121;TELEPHONE SIGN;So;0;ON;<compat> 0054 0045 004C;;;;N;T E L SYMBOL;;;;

여기서 <compat> 0054 0045 004C가 바로 호환 분해(compatibility decomposition) 값인데, U+0054는 T, U+0045는 E, U+004C는 L입니다. 즉 ℡는 내부적으로 "TEL"로 분해되도록 정의되어 있는 것이죠. 이걸 파이썬으로 직접 테스트해볼 수도 있습니다.

python -c 'import sys;print sys.argv[1].decode("utf-8").encode("idna")' "℡"

실제로 동작하는가?

실제로 동작합니다. 글쓴이가 트위터에서 사람들에게 .℡ 도메인으로 자신의 사이트에 접속할 수 있는지 물어봤는데, 최신 브라우저와 운영체제 대부분에서 정상적으로 동작했다고 합니다. 심지어 wget이나 curl 같은 커맨드라인 도구에서도 문제없이 작동했습니다.

한계점

다만 모든 곳에서 완벽하게 동작하는 건 아닙니다. 크게 두 가지 제약이 있습니다.

첫째, 트위터나 페이스북 같은 서비스는 이런 문자를 포함한 문자열을 유효한 URL로 인식하지 못해서 자동으로 링크를 걸어주지 않습니다.

둘째, dig나 host 같은 일부 커맨드라인 네트워크 도구는 이 변환 과정을 이해하지 못합니다. 실제로 dig로 질의하면 다음과 같은 결과가 나옵니다.

dig edent.℡
; <<>> DiG 9.10.6 <<>> edent.℡
;; global options: +cmd
;; Got answer:
;; ->>HEADER<<- opcode: QUERY, status: NXDOMAIN, id: 55282

즉 브라우저는 알아서 정규화해서 처리하지만, dig는 날것의 문자열을 그대로 DNS에 질의하기 때문에 존재하지 않는 도메인(NXDOMAIN)으로 처리되는 겁니다.

쓸모가 있을까?

글쓴이는 농담 반 진담 반으로 "이번 10년 중 가장 중요한 발견일지도 모른다"고 말하는데, 실용적인 쓸모보다는 멋져 보이는 URL을 만들거나 특정 도메인에서 글자 수를 약간 아낄 수 있다는 정도의 재미 요소에 가깝습니다. 다만 일관되게 동작하지 않는다는 단점은 감수해야 합니다.

조금 더 진지하게 생각해보면 URL 필터를 우회하는 용도로 악용될 가능성도 있습니다. 최신 브라우저는 이런 "장식된" 도메인을 대부분 지원하지만, 대부분의 웹사이트는 이를 자동으로 링크 처리하지 않기 때문에 페이스북 같은 곳에 공유하면 제대로 링크가 걸리지 않습니다.

정리

이 글의 핵심은 유니코드의 호환 분해(compatibility decomposition) 기능과 IDNA2008 정규화 규칙이 맞물려서, 전혀 다른 모양의 특수 문자가 실제 도메인 이름의 일반 문자로 치환될 수 있다는 점입니다.

  • ℡, № 같은 단일 유니코드 문자는 내부적으로 "TEL", "NO" 같은 ASCII 문자열로 분해되도록 정의돼 있고, 이게 우연히 실존하는 TLD(.tel, .no)와 일치합니다.
  • 브라우저는 RFC 5895의 IDNA2008 정규화 과정을 거쳐 이런 문자를 알아서 변환해주기 때문에, Math Bold·Fraktur·Circled·Double struck 등 다양한 유니코드 스타일 문자로 꾸민 URL도 실제 사이트로 정상 연결됩니다.
  • 반면 DNS 자체는 이런 변환을 모르기 때문에 dig, host 같은 저수준 도구는 정규화 없이 질의를 날려 NXDOMAIN을 반환하며, 트위터·페이스북 등은 이런 문자열을 URL로 인식하지 못해 자동 링크가 걸리지 않습니다.
  • 실무적으로는 당장 쓸 일이 많은 기능은 아니지만, 프론트엔드 개발자 입장에서는 사용자 입력이나 링크 미리보기, URL 파싱 로직을 만들 때 "겉보기엔 평범해 보이는 도메인이 실제로는 특수 유니코드 문자로 구성될 수 있다"는 점을 염두에 둘 필요가 있습니다. 이는 피싱이나 URL 필터 우회에 악용될 소지가 있는 지점이기도 합니다.
💡
사용자 입력이나 URL을 다루는 프론트엔드 로직에서 겉보기엔 평범한 도메인이 특수 유니코드 문자로 구성될 수 있다는 점을 알아두면, 피싱이나 URL 필터 우회 같은 보안 이슈를 이해하는 데 도움이 됩니다.
