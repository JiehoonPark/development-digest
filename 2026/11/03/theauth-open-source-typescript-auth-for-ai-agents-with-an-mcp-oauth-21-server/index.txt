19:T2226,<p>AI 에이전트가 사람처럼 API를 호출하고 작업을 수행하는 시대가 되면서, 에이전트에게 공유 API 키 대신 독립적인 신원과 세분화된 권한을 부여해야 한다는 문제의식이 커지고 있습니다. GLINCKER가 공개한 오픈소스 TypeScript 인증 라이브러리 <code>theAuth</code>는 바로 이 문제를 겨냥합니다. 일반 사용자 로그인과 나란히, AI 에이전트 전용 신원·권한 스코프·위임·감사 추적 기능을 제공하는 것이 핵심입니다.</p>
<h3>theAuth란 무엇인가</h3>
<p>theAuth는 AI 에이전트에게 자체 신원(identity)을 부여하는 오픈소스 TypeScript 인증 라이브러리입니다. 사람이 로그인하는 기존 인증 흐름뿐 아니라, 에이전트 전용으로 스코프가 지정된 권한, 권한 위임(delegation), 그리고 모든 결정에 대한 감사 로그(audit trail)를 함께 지원합니다. MCP(Model Context Protocol) OAuth 2.1 서버도 포함되어 있어, MCP 생태계와 바로 연동할 수 있습니다.</p>
<p>웹사이트, 문서, Quickstart, Playground, 예제, Go 라이브러리 등 레퍼런스가 함께 제공됩니다.</p>
<h3>Quickstart로 보는 사용법</h3>
<p>Node 20 이상이 필요하며, 아래 코드는 인메모리 SQLite 데이터베이스로 그대로 실행됩니다.</p>
<p>주의할 점이 하나 있는데, 이 예제 코드는 저장소 안의 2.0.0 버전을 기준으로 작성되었습니다. 2026년 10월 31일 기준 npm에 배포된 최신 버전은 1.2.0이고, 여기에는 <code>auth.user</code>가 없습니다. 작성자가 로컬 빌드로 직접 돌려서 얻은 출력을 주석으로 남겨뒀으니, 2.0.0이 정식 배포되기 전까지는 <code>packages/core</code>를 직접 빌드해서 써야 합니다.</p>
<pre><code>npm install @glinr/theauth</code></pre>
<pre><code class="language-javascript">import { createTheAuth } from &quot;@glinr/theauth&quot;;
const auth = await createTheAuth({
database: { provider: &quot;sqlite&quot;, url: &quot;:memory:&quot; },
agents: { enabled: true },
});
// An agent needs an owner row. Human sign in creates these for you.
const owner = await auth.user.create({ email: &quot;owner@example.com&quot;, name: &quot;Owner&quot; });
const agent = await auth.agent.create({
ownerId: owner.id,
name: &quot;github-reader&quot;,
type: &quot;autonomous&quot;,
permissions: [{ resource: &quot;mcp:github:*&quot;, actions: [&quot;read&quot;] }],
});
const read = await auth.authorize(agent.id, { action: &quot;read&quot;, resource: &quot;mcp:github:repos&quot; });
const write = await auth.authorize(agent.id, { action: &quot;write&quot;, resource: &quot;mcp:github:repos&quot; });
console.log(read.allowed, read.code); // true allowed
console.log(write.allowed, write.code); // false no_permission</code></pre>
<p>여기서 눈여겨볼 부분은 에이전트가 소유자(owner) row에 종속된다는 점입니다. 사람이 로그인하면 이 owner row가 자동으로 생성되고, 에이전트는 그 owner 아래 특정 리소스에 대한 권한(예: <code>mcp:github:*</code>에 대한 <code>read</code>)만 부여받습니다. 위 예제에서 <code>read</code> 액션은 허용(<code>allowed</code>)되지만 <code>write</code> 액션은 <code>no_permission</code> 코드와 함께 거부되는 걸 볼 수 있습니다.</p>
<p>발급되는 <code>agent.token</code>은 <code>ta_</code>로 시작하며 한 번만 보여집니다. 이를 HTTP로 서비스하려면 프레임워크 어댑터를 마운트하면 됩니다.</p>
<h3>왜 이런 설계가 필요한가</h3>
<p>theAuth가 전제하는 모델은 명확합니다. 에이전트는 공유 API 키가 아니라 소유자(owner)가 있는 독립된 주체(principal)로 취급되어야 한다는 것입니다. 이 모델 위에서 부모 에이전트가 자신이 가진 권한의 일부를 자식 에이전트에게 위임(delegation)할 수 있고, 어떤 위임 링크든 철회(revoke)하면 다음 호출부터 바로 반영됩니다. 그리고 모든 인가(authorize) 결정은 기계가 읽을 수 있는 코드(<code>allowed</code>, <code>no_permission</code> 등)를 반환하면서 동시에 감사 로그 row를 하나씩 남깁니다.</p>
<p>런타임 측면에서는 Node, Bun, Deno, Cloudflare Workers에서 모두 동작하며, core 패키지의 런타임 의존성은 <code>drizzle-orm</code>, <code>jose</code>, <code>sql.js</code>, <code>zod</code> 네 개뿐입니다. 별도의 호스팅 서비스가 필요 없다는 점도 강조하고 있습니다.</p>
<h3>안정성 현황</h3>
<p>theAuth의 버전 정책은 <code>STABILITY.md</code>를 따릅니다. 1.0 이상은 stable, 0.2~0.9는 beta, 0.1은 experimental로 구분합니다.</p>

<p>30여 개에 달하는 전체 패키지 목록과 버전, 알려진 모든 제약사항은 &quot;Packages and status&quot; 문서에서 확인할 수 있습니다. 자신의 상황에 맞는지 확신이 서지 않는다면 &quot;When not to use theAuth&quot; 문서를 먼저 읽어보는 것을 권하고 있습니다.</p>
<h3>패키지 구성</h3>
<p>버전과 성숙도가 포함된 전체 패키지 테이블은 &quot;Packages and status&quot; 문서에 정리되어 있고, Core는 <code>packages/core</code> 디렉터리에 있습니다.</p>
<p>관련 프로젝트로는 동일한 모델을 따르는 Go 서버 라이브러리 <code>theauth-go</code>(v2)가 있으며, 이는 <code>sdks/go</code>에 있는 Go REST 클라이언트와는 별개입니다. Python 클라이언트와 Terraform provider도 제공됩니다. 참고로 이 프로젝트는 이전에 <code>kavachOS</code>라는 이름으로 불렸으며, 이름 변경 매핑표도 공개되어 있습니다.</p>
<h3>개발 방식과 테스트</h3>
<p>이 코드베이스의 일부는 AI의 도움을 받아 작성되었다고 밝히고 있습니다. 약 5,000개의 테스트 케이스(텍스트 기준 카운트, &quot;by the numbers&quot; 문서 참고)로 커버되며, CI에서는 CodeQL도 함께 돌아갑니다. 다만 아직 제3자 보안 감사는 받지 않은 상태입니다. 문제를 발견하면 이슈를 열거나 <code>SECURITY.md</code>에 기술된 방식대로 비공개로 제보할 수 있습니다.</p>

<p>질문이 있다면 GitHub Discussions나 GLINR Discord를 이용하면 됩니다. 기여 방법은 <code>CONTRIBUTING.md</code>, 변경 이력은 <code>CHANGELOG.md</code>에서 확인할 수 있습니다. 라이선스는 MIT이며, GLINR STUDIOS 산하의 GLINCKER가 개발했습니다.</p>
<h3>정리</h3>
<p>theAuth는 AI 에이전트를 &quot;공유 API 키&quot;가 아니라 소유자를 가진 독립된 주체로 다루면서, 권한 스코프·위임·즉시 철회·감사 로그를 패키지 수준에서 제공하는 TypeScript 인증 라이브러리입니다. Node·Bun·Deno·Cloudflare Workers 등 다양한 런타임에서 최소 의존성으로 동작하고, MCP OAuth 2.1 서버까지 포함하고 있어 MCP 기반 에이전트 시스템을 구축하는 개발자라면 눈여겨볼 만합니다.</p>
