Deno의 보안 모델을 믿지 않는 이유
via Hacker News (Top)
💡알면 좋은 정보frontend

Deno가 플래그십으로 내세우는 권한 시스템이 실제로는 근본적인 허점을 가지고 있다는 비판 글입니다. 터미널 프롬프트가 공격자가 제어 가능한 stdout/stdin 채널 위에서 동작해 색상 조작 등으로 우회될 수 있고, --allow-run은 PATH 조작과 LD_PRELOAD 환경 변수를 이용해 임의 코드 실행으로 이어질 수 있음을 실제 PoC로 보여줍니다. 저자는 Deno가 표준 라이브러리 호출만 필터링할 뿐 진짜 OS 수준 샌드박스가 아니기 때문에, 신뢰할 수 없는 코드는 bwrap 같은 실제 샌드박스로 격리해야 한다고 결론 내립니다.

💡
런타임이 제공하는 권한 플래그나 프롬프트를 실제 보안 경계로 오해하면, 신뢰할 수 없는 코드를 다루는 도구나 CLI를 만들 때 치명적인 샌드박스 탈출 취약점을 놓칠 수 있다는 점에서 프론트엔드·풀스택 개발자 모두에게 경계가 필요한 내용입니다.
