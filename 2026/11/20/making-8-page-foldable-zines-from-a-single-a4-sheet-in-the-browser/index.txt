18:T1bba,<h2>종이 한 장으로 만드는 8페이지 진(zine), 브라우저에서 레이아웃 해결하기</h2>
<p>A4 용지 한 장을 접고 가운데를 살짝 자르기만 하면 스테이플이나 풀 없이도 8페이지짜리 소책자를 만들 수 있습니다. 이렇게 간단한 작업인데도 막상 컴퓨터로 레이아웃을 짜려고 하면 페이지 순서가 뒤죽박죽이고 일부는 180도 뒤집어야 하는 번거로움이 있었습니다. 이 글은 이 문제를 해결하기 위해 만든 웹 도구 <code>fanzines.app</code>을 최근 어떻게 개선했는지 정리한 개발기입니다.</p>
<h3>A4 한 장으로 진을 만드는 방법</h3>
<p>A4 용지를 세 번 반으로 접었다가 다시 펼친 뒤, 가운데 접힌 선을 따라 가위로 자릅니다. 그다음 종이를 십자 모양으로 접어 닫으면 스테이플이나 풀 없이도 8페이지 소책자가 완성됩니다. 저자는 이 방식으로 사진, 시, 메모 등 원하는 내용을 채워 넣은 진을 만들어 친구, 가족, 직장 동료들에게 나눠주고 있다고 합니다.</p>
<p>문제는 인쇄 전 평면 시트를 레이아웃하는 과정이었습니다. A4 용지가 접히면서 페이지 순서가 이상해지고, 윗줄은 거꾸로 배치해야 하기 때문입니다.</p>
<pre><code>┌─────────┬─────────┬─────────┬─────────┐
│    6    │    5    │    4    │    3    │ ← 180도 뒤집힘
├─────────┼─────────┼─────────┼─────────┤
│  Back   │  Cover  │    1    │    2    │ ← 정방향
└─────────┴─────────┴─────────┴─────────┘</code></pre>
<p>매번 진을 새로 만들 때마다 포토샵에서 사진을 돌리고 열 배치를 다시 확인하는 데 지쳐서, 저자는 이 작업을 자동화하는 <code>fanzines.app</code>을 만들었습니다. 브라우저에서 각 페이지를 정방향으로 보면서 사진과 텍스트를 배치하면, 내보내기 시 앱이 8개 패널을 A4 그리드에 자동 배치하면서 윗줄을 180도 회전시키고 300 DPI PDF를 생성해줍니다. 모든 작업은 브라우저 로컬에서 처리되며 사진이 서버로 업로드되지 않습니다.</p>
<p>최근 며칠간 저자는 진을 만들 때마다 걸리적거렸던 부분들을 중심으로 에디터를 다시 설계했습니다.</p>
<h3>페이지 짝짓기 방식 수정</h3>
<p>첫 번째 버전에서는 사이드바가 8개 페이지를 단순한 2열 그리드로 나열했습니다. 이 구조는 Front Cover와 Page 1, Page 2와 Page 3, Page 4와 Page 5, Page 6과 Back Cover를 한 쌍으로 묶었습니다.</p>
<p>화면상으로는 깔끔해 보였지만 실제 접힌 책자와는 맞지 않는 배열이었습니다. 실제로 접힌 진을 손에 들면 앞표지는 오른쪽에 혼자 있고, 책을 펼치면 Page 1과 Page 2가 접힌 선을 사이에 두고 마주보며, 이어서 3과 4, 5와 6이 마주보고, 뒤표지는 왼쪽에 혼자 남게 됩니다.</p>
<p>이에 맞춰 사이드바는 이제 페이지 썸네일을 실제 펼침면(spread) 단위로, 읽는 순서대로 그룹화하도록 바뀌었습니다.</p>
<p>캔버스에도 Spread 뷰를 추가했습니다. Page 1을 편집하는 중에도 Page 2가 옆에 낮은 투명도로 표시되어, 인쇄하기 전에 두 마주보는 페이지가 어떻게 어우러지는지 확인할 수 있습니다. 흐리게 표시된 페이지를 클릭하면 바로 그 페이지 편집으로 전환됩니다.</p>
<h3>에디터를 덜 번거롭게 만드는 작은 개선들</h3>
<p>사진으로 진을 만들 때는 보통 이미 선별한 8장의 사진이 담긴 폴더로 시작하게 됩니다. 이제는 사진 묶음 전체를 에디터 창에 드래그하면, 사이드바가 각 사진이 읽는 순서대로 어느 페이지에 들어갈지 미리 하이라이트로 보여줍니다. 드롭하기 전에 결과를 미리 확인할 수 있는 셈입니다.</p>
<p>사이드 패널도 손봤습니다. 초기 버전에서는 사진을 클릭하면 X, Y, Width, Height 네 가지 좌표 입력창이 열렸습니다. 하지만 실제로 좌표를 직접 입력할 일은 거의 없었고, 대부분 사진을 페이지에 꽉 채우거나(Fill), 여백 안에 맞추거나(Fit), 가운데 정렬(Center)하고 싶었을 뿐이었습니다. 이제 Fill, Fit, Center 옵션이 인스펙터 상단과 선택 영역 위 작은 툴바에 배치됩니다.</p>
<p>세부 좌표 필드는 여전히 하단의 접을 수 있는 섹션에 남아있지만, 단위가 밀리미터(접힌 패널 기준 74.25 × 105 mm)와 텍스트용 포인트로 바뀌었습니다.</p>
<p>PDF를 다운로드하기 전에는 Review 단계가 추가되어, 접지 않은 전체 A4 시트를 보여주면서 절단선/접는 선 토글과 5mm 안전 여백(safe margin)을 확인할 수 있습니다. 대부분의 가정용 프린터는 A4 용지 가장자리를 몇 밀리미터씩 잘라내기 때문에, 안전 여백 기능은 레이아웃을 약 95% 크기로 축소해 표지가 잘리지 않도록 보호합니다.</p>
<p>그 외에도 에디터가 휴대폰 화면에서 동작하도록 (한 번에 한 페이지씩, 하단에 썸네일 스트립 표시) 개선했고, 사이트가 영어와 스페인어를 모두 지원하게 되었습니다. 언어를 바꿔도 현재 작업 중이던 페이지는 그대로 유지됩니다.</p>
<h3>정리</h3>
<ul>
<li>A4 한 장을 접어 만드는 8페이지 진은 접힌 구조 때문에 페이지 순서가 뒤틀리고 일부가 180도 뒤집히는데, <code>fanzines.app</code>은 이를 정방향 편집 → 자동 재배치 → 300 DPI PDF 출력 방식으로 해결합니다.</li>
<li>이번 업데이트의 핵심은 사이드바의 페이지 그룹화를 &quot;그리드 순서&quot;가 아니라 &quot;실제 접힌 책자에서 마주보는 펼침면&quot; 기준으로 바꾼 것입니다. 데이터 모델이 화면에 보기 좋은 형태가 아니라 실제 사용자의 물리적 경험(접힌 책을 펼쳤을 때 보이는 면)을 반영해야 한다는 점을 보여주는 사례입니다.</li>
<li>좌표 직접 입력 대신 Fill/Fit/Center 같은 의도 기반 조작을 전면에 배치하고, 세부 설정은 접어서 숨기는 방식은 실제 사용 패턴에 맞춰 UI 우선순위를 재조정한 좋은 예입니다.</li>
<li>드래그 앤 드롭 시 어느 사진이 어느 페이지에 들어갈지 미리 보여주는 것, 인쇄 여백을 고려한 5mm 안전 마진, 모바일 대응, 다국어 지원 등은 모두 &quot;실제로 종이에 인쇄해서 쓰는&quot; 워크플로우를 세심하게 배려한 디테일입니다.</li>
<li>모든 처리가 브라우저 로컬에서 끝나고 서버 업로드가 없다는 점은 개인 사진을 다루는 도구에서 신뢰를 얻는 중요한 설계 선택입니다.</li>
