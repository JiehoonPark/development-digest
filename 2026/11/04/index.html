Next.js 2026년 11월 보안 릴리스: 캐시 교차 노출 등 7건 취약점 패치
via Next.js Blog
frontend

Next.js가 v16.4.5(Active LTS)와 v15.5.29(Maintenance LTS)를 통해 7건의 보안 취약점을 패치했습니다. 핵심은 Cache Components와 use cache를 사용하는 애플리케이션에서 발생하는 테넌트/사용자 간 캐시 교차 노출 이슈이며, 그 외 셀프 호스팅 환경의 공유 셸 캐시 오염, Edge 라우트 쿠키 노출, SVG 거부 우회 등이 포함됩니다. 멀티테넌트 서비스를 운영 중이라면 즉시 업그레이드가 필요합니다.

💡
Cache Components나 use cache, 셀프 호스팅 배포를 사용 중인 Next.js 애플리케이션이라면 테넌트/사용자 데이터가 섞여 노출될 수 있는 심각한 문제이므로, 프론트엔드 개발자도 즉시 버전을 확인하고 패치해야 합니다.

Safari 27.3, 밝은 웹사이트를 자동으로 다크 모드로 바꿔주는 Adaptive Dark Mode 공개
via Hacker News (Top)
frontend

Safari 27.3 베타에 추가된 Adaptive Dark Mode는 다크 모드를 지원하지 않는 밝은 웹사이트를 브라우저 엔진 차원에서 자동으로 어둡게 변환해주는 기능이다. 색조는 유지하고 명도만 반전시키는 컬러 매트릭스와 SVG·비트맵 이미지 분석을 통해 가독성과 대비를 유지하며, color-scheme 선언으로 개발자가 동작을 제어할 수 있다. 개인정보 보호를 위해 웹사이트는 이 변환 적용 여부를 감지할 수 없다.

💡

모던 CSS가 오히려 프론트엔드를 더 복잡하게 만드는 이유
via Smashing Magazine
frontend

ResizeObserver를 컨테이너 쿼리로, JavaScript 로직을 :has() 선택자로 대체하면 코드의 diff는 줄어들지만 시스템 전체의 복잡성은 오히려 늘어날 수 있다. 이 글은 CSS와 JavaScript가 하나의 행동을 동시에 제어할 때, container-type이 블록 포매팅 컨텍스트를 의도치 않게 생성할 때, 짧은 선택자가 예상보다 넓게 매치될 때 발생하는 세 가지 실제 버그 시나리오를 다룬다. 핵심 주장은 '지역적 단순함'과 '시스템 복잡성'을 구분해야 한다는 것이다.

💡
컨테이너 쿼리, :has(), 네이티브 중첩 같은 모던 CSS 기능을 실무에 도입하는 프론트엔드 개발자라면, diff가 줄어드는 것만 보고 넘어갔다가 겪을 수 있는 숨겨진 부작용과 디버깅 함정을 미리 알아둘 필요가 있다.

최신 CSS 기능으로 :nth-child() 직접 구현해보기
via CSS-Tricks
frontend

이 글은 CSS의 if(), style(), sibling-index(), mod() 같은 최신 기능을 조합해 :nth-child() 선택자를 처음부터 재구현하는 과정을 다룹니다. 목표는 커스텀 프로퍼티로 선택자 인자를 동적으로 바꿀 수 있게 만드는 것이며, 단일 요소 선택부터 일반형 An+B 패턴까지 단계적으로 구현합니다. A가 음수이거나 0인 특수 케이스를 처리하는 방법도 함께 설명합니다.

💡
CSS의 if()와 style() 조건부 문법, sibling-index() 같은 새로운 함수들이 어떻게 결합되어 동작하는지 실전 예제로 익힐 수 있어, 향후 동적 스타일링이 필요한 상황에서 응용할 수 있는 사고방식을 제공합니다.

via Hacker News (Top)
frontendai

Figma는 범용 프런티어 모델이 Figma 고유 포맷을 이해하지 못하고 토큰 비용이 과도하다는 문제를 겪으면서, 디자인 편집 전용 모델을 SFT로 학습시키고 이후 RL로 전환했습니다. 25만 건 이상의 합성 학습 데이터와 teacher 모델, 결정론적 검증기·비주얼 판정기 기반 self-healing 파이프라인을 통해 Llama 3.3 70B 모델이 당대 최상위 모델과 경쟁할 수준에 도달했고, 이후 Qwen 등 더 강력한 베이스 모델과 RL을 결합했습니다.
