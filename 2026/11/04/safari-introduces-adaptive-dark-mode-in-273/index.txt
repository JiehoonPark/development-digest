18:T2698,<p>WebKit 팀이 Safari 27.3 베타에서 새로운 기능인 Adaptive Dark Mode를 공개했습니다. 사용자가 다크 모드를 켜두면 다크 모드를 지원하지 않는 밝은 웹사이트를 브라우저가 알아서 어둡게 바꿔주는 기능인데요, 웹 전반의 다크 모드 지원률이 생각보다 낮다는 문제의식에서 출발했습니다. 이 글에서는 이 기능이 어떤 원리로 동작하는지, 웹 개발자 입장에서 무엇을 준비해야 하는지를 정리합니다.</p>
<h3>왜 Adaptive Dark Mode가 필요한가</h3>
<p>2019년 봄 Safari 12.1은 웹에서 다크 모드를 지원한 최초의 브라우저였습니다. 이후 많은 사용자가 다크 모드를 애용하게 됐지만, 정작 모든 웹사이트가 다크 버전을 제공하는 것은 아닙니다. WebKit 팀의 집계에 따르면 전체 페이지 로드 중 약 40%가 다크 모드 상태의 사용자에게서 발생하는데, 이 중 다크 모드를 실제로 지원하는 페이지는 단 10%에 불과합니다. 다크 모드를 즐겨 쓰는 사람이라면 유독 눈부시게 밝은 사이트를 만난 경험이 있을 텐데, Adaptive Dark Mode는 바로 이 간극을 메우기 위해 만들어졌습니다.</p>
<p>사용 방법은 간단합니다. 시스템 외형을 다크 모드로 설정한 뒤 밝은 배경의 웹사이트에 접속하면, Safari가 Adaptive Dark Mode 미리보기를 제안합니다. 여기서 'Try'를 누르면 바로 체험할 수 있습니다.</p>
<p>HTML에 <code>&lt;meta name=&quot;color-scheme&quot; content=&quot;light dark&quot;&gt;</code>를 넣었거나 CSS에 <code>color-scheme: light dark</code>를 선언해 다크 모드 지원을 명시한 사이트는 Adaptive Dark Mode의 영향을 전혀 받지 않습니다. 그 외의 사이트에 대해서는 Safari가 페이지의 색상을 빠르게 분석해 전체적으로 밝은지 어두운지를 추정합니다. 이미 어두운 배경에 밝은 텍스트로 구성된 페이지라면 아무것도 바꾸지 않고, 밝은 외형의 페이지만 어둡게 변환합니다.</p>
<h3>동작 원리: 색상 변환의 핵심</h3>
<p>Adaptive Dark Mode의 핵심은 색상 변환입니다. 웹페이지의 색상 중 일부는 단순 장식용이지만 어떤 색상은 의미를 전달하기도 하는데, Adaptive Dark Mode는 이 둘을 구분해서 색을 반전시킬지, 그대로 둘지를 판단합니다.</p>
<p>이를 위해 WebKit 팀은 색상의 색조(hue)는 유지하면서 명도(luminosity)만 반전시키는 컬러 매트릭스를 개발했습니다. 이 매트릭스로 밝은 배경은 어둡게, 어두운 텍스트는 밝게 바꿉니다. 텍스트 색상을 변환할 때는 WCAG 기준인 4.5:1 명도 대비를 충족하도록 조정하며, 밝은 톤의 CSS 그라디언트도 어둡게 변환됩니다.</p>
<p>단순히 색만 뒤집는 게 아니라 변환된 결과물이 실제로 보기 좋고 사용 가능한 상태를 유지하도록 세심하게 처리합니다. 버튼은 배경과 충분한 대비를 유지하고, 이미지 위의 텍스트는 잘 보이도록 하며, 호버 메뉴도 명확하게 표시되도록 신경 씁니다.</p>
<p>이미지 처리에도 같은 원칙이 적용됩니다. 대부분의 이미지는 원본 그대로 유지해 무결성을 지키지만, 아이콘이나 로고는 배경색이 반전되면서 대비를 잃는 경우가 많습니다. 그래서 Adaptive Dark Mode는 SVG 이미지를 검사해 필요한 경우 색을 변환하고, 비트맵 이미지는 픽셀 히스토그램을 분석해 단순한 흑백 로고라면 색을 반전시킵니다.</p>
<p>mask나 mix-blend-mode 같은 효과는 색이 변환된 요소에 적용될 경우 원치 않는 결과를 낼 수 있어서, 경우에 따라 이런 효과 자체를 꺼버리기도 합니다. 또한 <code>&lt;canvas&gt;</code> 콘텐츠는 그 안에 어떤 내용이 담길지 예측하기 어렵기 때문에 변환 대상에서 제외됩니다.</p>
<p>이런 복잡한 판단들이 WebKit 브라우저 엔진 내부 깊숙한 곳에서 처리되기 때문에, 속도와 전력 효율을 유지하면서도 사용자 개인정보를 철저히 보호하는 방식으로 구현할 수 있었다고 팀은 설명합니다.</p>
<h3>내 사이트가 더 잘 동작하게 만들려면</h3>
<p>현대적인 웹 개발 관행을 따르는 사이트라면 대체로 Adaptive Dark Mode와도 잘 어울립니다. 만약 오래된 기법을 여전히 쓰고 있다면 다음과 같은 작은 개선으로 큰 도움을 받을 수 있습니다.</p>
<ul>
<li>로고와 아이콘은 비트맵 대신 SVG로 교체</li>
<li>타일형 배경 이미지 대신 CSS의 단색/그라디언트 색상 사용</li>
<li>이미지 스프라이트 대신 둥근 모서리, 그림자, 버튼 상태 표현을 위한 현대적 CSS 사용</li>
<li>페이지 배경색을 이미지에 미리 구워 넣지 말고, 투명 배경의 콘텐츠 이미지로 제작</li>
<li>컨테이너에 패딩을 추가해 요소가 밀집되지 않도록 함</li>
</ul>
<p>페이지의 특정 영역에만 별도의 다크 모드 경험을 주고 싶다면, 해당 요소에 <code>color-scheme: light dark</code>를 적용하고 자체 다크 스타일을 추가하면 됩니다.</p>
<h3>직접 다크 모드를 구현하기</h3>
<p>사이트의 다크 모드 외형을 완전히 직접 제어하고 싶다면, 지금이 바로 완전한 다크 모드 지원을 추가하기 좋은 시점입니다. 필요한 웹 기술은 이미 널리 지원되고 있습니다.</p>
<ul>
<li><code>&lt;meta name=&quot;color-scheme&quot; content=&quot;light dark&quot;&gt;</code></li>
<li><code>:root { color-scheme: light dark }</code></li>
<li><code>@media (prefers-color-scheme: dark) { }</code></li>
<li><code>&lt;picture&gt;&lt;source media=&quot;(prefers-color-scheme: dark)&quot;&gt;</code></li>
<li><code>light-dark()</code></li>
</ul>
<p>여기에 더해 <code>color-mix()</code>, <code>contrast-color()</code> 같은 최신 CSS 함수와, CSS 변수로 디자인 시스템을 구성하는 기법들을 활용하면 더 다양한 옵션과 유연성을 확보할 수 있습니다.</p>
<p>다크 모드 지원 여부는 반드시 HTML <code>&lt;head&gt;</code>의 color-scheme 메타 태그나 CSS의 <code>:root</code> 혹은 <code>body</code>에 대한 color-scheme 속성으로 선언해야 합니다. 이 정보를 JavaScript로 나중에 주입하는 방식은 피해야 하는데, 이렇게 선언해두면 사이트가 최대한 빠르게 올바른 형태로 렌더링되는 데 도움이 됩니다.</p>
<h3>&quot;light only&quot; 색상 스킴 사용하기</h3>
<p>웹 앱이나 사이트가 Adaptive Dark Mode에 의해 변환되지 않길 원한다면 color-scheme으로 이를 명시할 수 있습니다. HTML <code>&lt;meta name=&quot;color-scheme&quot; content=&quot;light only&quot;&gt;</code> 태그는 브라우저에게 이 페이지가 라이트 모드를 지원하며 라이트 모드로만 표시되어야 한다고 알려줍니다. <code>color-scheme: light only</code> CSS 규칙도 동일한 역할을 하지만, CSS답게 페이지 전체(<code>:root { }</code>)뿐 아니라 특정 요소에만 적용하는 유연성을 제공합니다. 다만 Safari 27.3 베타 1에서는 'only' 키워드가 아직 지원되지 않으며, 베타가 진행되며 Adaptive Dark Mode가 발전함에 따라 지원 여부를 확인해야 한다고 WebKit 팀은 안내하고 있습니다.</p>
<h3>사용자 개인정보 보호</h3>
<p>애플은 사용자 개인정보를 기본적 인권으로 보고 있다고 강조합니다. 만약 웹사이트가 사용자의 Adaptive Dark Mode 활성화 여부를 감지할 수 있다면, 이는 추적자에 대한 핑거프린팅 정보가 늘어나 개인정보 보호를 약화시키는 결과로 이어집니다.</p>
<p>이 때문에 Safari는 웹사이트가 Adaptive Dark Mode의 적용 여부를 감지하지 못하도록 막습니다. CSS 색상을 조회하는 JavaScript 코드는 변환된 색상이 아니라 원래 작성된 색상 값을 그대로 받게 되며, canvas에 그려진 이미지 역시 원본 형태로 렌더링됩니다.</p>
<h3>정리</h3>
<ul>
<li>Safari 27.3 베타에 도입된 Adaptive Dark Mode는 다크 모드를 지원하지 않는 밝은 웹사이트를 브라우저 엔진 차원에서 자동으로 어둡게 변환해주는 기능이다. 전체 페이지 로드의 40%가 다크 모드 사용자에게서 나오는데 실제 다크 모드 지원 페이지는 10%뿐이라는 격차를 메우기 위한 시도다.</li>
<li><code>color-scheme: light dark</code>(혹은 메타 태그)를 선언한 사이트는 변환 대상에서 제외되며, 그렇지 않은 사이트는 색조는 보존하고 명도만 반전시키는 컬러 매트릭스로 텍스트·배경·그라디언트가 변환되고, SVG·비트맵 이미지도 상황에 맞춰 선택적으로 처리된다.</li>
<li>개발자 입장에서는 비트맵 로고를 SVG로, 배경 이미지를 CSS 색상으로, 이미지 스프라이트를 현대적 CSS로 바꾸는 등 모던 웹 개발 관행을 따르는 것만으로도 Adaptive Dark Mode와의 호환성이 크게 개선된다.</li>
<li>다크 모드를 직접 완전히 제어하고 싶다면 <code>color-scheme</code> 메타 태그/CSS 속성, <code>prefers-color-scheme</code> 미디어 쿼리, <code>light-dark()</code> 함수 등 이미 널리 지원되는 기술로 자체 다크 테마를 구축할 수 있고, 반대로 변환을 원치 않으면 <code>light only</code> 값을 사용하면 된다(단, 베타 1에서는 아직 미지원).</li>
<li>Safari는 핑거프린팅 방지를 위해 웹사이트가 JavaScript나 canvas를 통해 Adaptive Dark Mode 적용 여부를 감지하지 못하도록 원본 색상 값을 그대로 노출한다.</li>
