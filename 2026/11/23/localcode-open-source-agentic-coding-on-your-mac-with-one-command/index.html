Localcode: 명령어 한 줄로 맥에서 돌리는 오픈소스 에이전틱 코딩 도구

Localcode, open source agentic coding on your Mac with one command

📅 2026-11-23📰 Hacker News (Top)
frontendai

맥북에서 외부 API 호출 없이 로컬 모델만으로 에이전틱 코딩을 돌릴 수 있다면 어떨까요? Localcode는 바로 이 질문에서 출발한 오픈소스 프로젝트입니다. Apple Silicon 맥에서 명령어 한 줄로 설치하고, 로컬 LLM이 프로젝트 파일을 읽고 수정하고 테스트까지 돌리는 에이전트로 동작하도록 만들었는데요. 이번 글에서는 Localcode의 설치 방법부터 지원 모델, 그리고 로컬 환경에서 성능을 끌어올리기 위해 적용한 최적화 기법들을 살펴보겠습니다.

설치와 실행

설치는 uv를 이용한 pip 설치로 끝납니다.

uv pip install localcode

업그레이드는 uv pip install -U localcode로 처리합니다. 실행은 작업하려는 프로젝트 디렉터리에서 다음과 같이 합니다.

cd your-project
localcode

다른 로컬 애플리케이션에서 실행 중인 모델을 가져다 쓰고 싶다면 /server를 열거나 localcode api 명령으로 OpenAI 호환 엔드포인트를 띄울 수 있습니다.

Localcode가 하는 일

Localcode는 단순한 챗봇이 아니라 프로젝트 안에서 직접 작업을 수행하는 에이전트로 설계되었습니다. 주요 기능은 다음과 같습니다.

  • 프로젝트 내 파일을 읽고 수정
  • 테스트, 빌드, Git, 셸 명령을 프로젝트 안에서는 자율적으로 실행하되, 프로젝트 밖의 작업은 사용자에게 먼저 확인
  • 이름, 내용, 구조 기준으로 코드 검색
  • 앱을 스캐폴딩하고 실행한 뒤 정상적으로 응답하는지 확인
  • 여러 메시지에 걸쳐 작업 맥락을 기억

실행 요구 사항

로컬에서 모델을 돌려야 하는 만큼 하드웨어 조건이 명확합니다.

  • Apple Silicon 탑재 Mac, macOS 13 이상
  • 통합 메모리 16GB 이상
  • Python 3.10 이상
  • Localcode 자체와 선택한 모델을 위한 디스크 공간 (모델별 용량은 아래 표 참고)

지원 모델

코딩, 이미지 입력, 구조화된 결정(typed decision) 용도에 맞춰 총 12개 모델, 169가지 양자화(quant) 옵션 중에서 고를 수 있습니다. 모델은 Hugging Face에서 내려받으며, 다운로드는 병렬로 진행되고 중단되어도 이어받을 수 있습니다. /models 명령으로 모델을 전환할 수 있고, Localcode는 현재 맥의 메모리에 맞는 가장 성능 좋은 모델을 별표로 추천해줍니다.

속도 면에서는 Gemma 4, Qwen 3.6, Muse Glimmer, Qwen 3.8이 벤더 자체 스펙큘레이티브 드래프터(speculative drafter)를 이용해 토큰을 미리 추측하는 방식을 지원하며, 이 드래프터는 모델과 함께 다운로드됩니다. 모델 서버의 GPU 커널은 미리 컴파일된 상태로 배포되기 때문에 설치 후 첫 실행이 더 빠릅니다.

성능을 위한 최적화

Localcode는 기본 모델 서버 위에 여러 최적화 레이어를 얹어서 로컬 환경에서도 실용적인 속도와 품질을 확보하려고 합니다.

속도

  • 드래프팅: 벤더 자체 드래프터가 토큰을 미리 추측하는 방식으로, Gemma 4·Qwen 3.6·Qwen 3.8·Muse Glimmer에서 응답 속도가 약 2배 빨라집니다.
  • 카피 드래프팅: 모델이 이미 읽은 파일을 다시 작성할 때, 생성 대신 복사하는 방식을 써서 재작성 속도가 3.5~4배 빨라집니다.
  • 프롬프트 캐시 재사용: 시스템 프롬프트가 매 턴 동일하게 유지되므로, 모델은 새로 추가된 부분만 읽으면 됩니다.
  • 워밍업: 모델이 로드되는 동안 첫 요청의 프롬프트를 미리 읽어두어 첫 메시지 응답이 더 빨리 시작됩니다.
  • 사전 컴파일된 GPU 커널: 첫 실행 시 발생하던 30초가량의 셰이더 컴파일 과정이 없습니다.
  • 스레드를 맥의 퍼포먼스 코어 수에 맞춰 배치
  • Flash attention이 기본으로 켜져 있음
  • Inkling 2: 원래 CPU에서 조용히 돌고 있던(약 5배 느림) 익스퍼트(expert)들을 GPU에서 실행하도록 수정했고, 밴디드 어텐션(banded attention)과 퓨즈드 액티베이션 연산을 적용해 GPU 메모리 사용량을 절반으로 줄이면서 프롬프트 읽기 속도도 20~30% 빨라졌습니다.
  • 다운로드는 병렬로 진행되며 중단 시 이어받고, 다른 모델을 사용하는 중에도 계속 진행됩니다.

메모리

  • 기본적으로 8비트 KV 캐시를 사용해 풀 정밀도 대비 메모리 사용량을 절반으로 줄여, 더 긴 컨텍스트를 담을 수 있습니다.
  • Inkling 2는 대신 16비트 캐시를 사용하는데, 어텐션이 이를 직접 읽기 때문에 긴 프롬프트를 1.4~1.8배 빠르게 읽고, 128K 컨텍스트 기준으로 메모리를 3.3GB 덜 사용합니다.
  • 컨텍스트 크기는 서버가 보고하는 값에 맞춰 조정되어, 긴 대화가 공간 부족으로 끊기기 전에 미리 압축됩니다.
  • 모델 선택 화면에서는 현재 맥 사양에 맞는 가장 성능 좋은 모델을 추천합니다.

품질

  • 히든 씽킹(hidden thinking)은 기본적으로 꺼져 있어 답변이 바로 나오며, 생각에 막혀버린 모델은 실패 처리되는 대신 복구됩니다.
  • 플랜 패널: 모델이 작업 목록을 유지하고 이를 계속 업데이트하도록 리마인드합니다.
  • 멈춤 감지: 진전이 없거나 같은 검사에서 계속 실패하는 모델은 접근 방식을 바꾸도록 유도되고, 그래도 안 되면 중단되어 지금까지 수행한 내용을 보고합니다.
  • 모든 릴리스는 출시 전에 모든 모델을 대상으로 실제 구동(로드, 응답, 툴 호출, 이미지 처리)까지 라이브 테스트를 거칩니다.

네트워크 경계

Localcode의 추론 자체는 전적으로 로컬에서 이루어집니다. 네트워크를 사용하는 기능은 모델 다운로드, web_search·web_fetch 툴, 그리고 사용자가 추가한 MCP 서버, 이 세 가지뿐입니다. 자세한 내용은 프로젝트의 Network Boundary 문서에서 확인할 수 있습니다.

로컬을 지향하는 이유

프로젝트 측은 "강력하고 개인적인 AI는 누구나, 어떤 기기에서든, 어디서든 쓸 수 있어야 한다"는 철학을 내세웁니다. 그러려면 결국 로컬에서 돌아가야 한다는 것이고, Localcode는 그 첫걸음이라고 설명합니다. 라이선스는 Apache 2.0이며, 스폰서십과 기여는 각각 프로젝트 문의 및 CONTRIBUTING.md를 통해 안내하고 있습니다.

정리

Localcode는 클라우드 API 의존 없이 Apple Silicon 맥 한 대로 에이전틱 코딩 워크플로를 완성하려는 오픈소스 도구입니다. uv pip install localcode 한 줄로 설치해 프로젝트 디렉터리에서 바로 실행할 수 있고, 12개 모델·169개 양자화 옵션 중 맥 메모리에 맞는 모델을 추천받아 쓸 수 있습니다. 드래프팅, 카피 드래프팅, 프롬프트 캐시 재사용, 8비트 KV 캐시 같은 최적화로 응답 속도와 메모리 효율을 동시에 개선했고, 플랜 패널과 멈춤 감지로 에이전트가 작업 중 길을 잃지 않도록 설계했습니다. 네트워크는 모델 다운로드와 웹 검색/페치 툴, MCP 서버 연동에만 사용되고 추론 자체는 완전히 로컬에서 처리된다는 점이 핵심 차별점입니다. 로컬 LLM 기반 개발 도구에 관심 있는 프론트엔드·풀스택 개발자라면 사내 코드 유출 걱정 없이 에이전틱 코딩을 실험해볼 수 있는 선택지로 살펴볼 만합니다.

💡
클라우드 API 비용이나 코드 유출 우려 없이 로컬 환경에서 에이전틱 코딩을 실험할 수 있는 선택지를 제공해, 프론트엔드 개발자가 개인 정보나 사내 코드를 보호하면서도 AI 코딩 도구를 활용할 수 있게 해줍니다.
