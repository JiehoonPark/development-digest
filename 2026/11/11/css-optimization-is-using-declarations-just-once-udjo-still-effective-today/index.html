CSS 최적화 기법 UDJO, 2024년에도 여전히 유효할까?

CSS Optimization: Is Using Declarations Just Once (UDJO) Still Effective Today?

📅 2026-11-11📰 CSS-Tricks
frontend

CSS 최적화 기법 UDJO, 2024년에도 여전히 유효할까?

CSS 최적화는 묘하게 다루기 어려운 주제입니다. 압축(minification) 같은 건 이미 도구가 다 갖춰진 뻔한 영역처럼 보이지만, 동시에 "CSS 최적화는 이제 할 만큼 다 했다"고 단정짓기도 섣부릅니다. 거의 매일 진화하는 언어를 두고 그런 주장을 하기는 어렵죠. 이 글에서는 무려 18년 전부터 존재해온 기법 하나를 다시 꺼내봅니다. 바로 UDJO(Using Declarations Just Once), 선언을 한 번만 사용하기입니다.

UDJO란 무엇인가

UDJO는 "반복하지 말라(DRY, Don't Repeat Yourself)"는 원칙에서 영감을 받은 기법입니다. 동일한 선언이 여러 곳에서 반복될 때 이를 찾아내 하나의 규칙으로 합치는 방식으로 동작합니다.

예를 들어 display: flex가 두 군데 이상에서 반복된다고 합시다.

.example {
  display: flex;
}
.sample {
  display: flex;
}

이걸 다음처럼 합치는 겁니다.

.example,
.sample {
  display: flex;
}

이 기법의 실제 효과는 두 가지 변수에 좌우됩니다. 하나는 중복 제거가 얼마나 똑똑하게 이뤄지는지(선택자를 바꿔도 정말 안전한지), 다른 하나는 선택자 길이입니다. 전자는 유지보수성 향상 여부를, 후자는 파일 크기 절감 폭을 결정합니다. 더 자세한 메커니즘은 필자의 이전 글 "DRY CSS"에서 다뤘습니다. 이 글에서 던지는 질문은 하나입니다 — UDJO는 오늘날에도 여전히 효과적이고 유의미한가?

도구로 더 똑똑하게 중복 제거하기

막상 이 질문에 답하려고 하면 현실적인 문제에 부딪힙니다. 사이트가 복잡하고 기존 스타일시트에 중복 제거가 전혀 안 되어 있다면, UDJO를 수작업으로 적용하는 건 엄청난 작업량이 됩니다.

이 작업 시간을 줄이기 위해 필자는 직접 도구를 만들었습니다. 처음에는 수작업으로 스타일시트를 점검하는 것만큼 완전할 수 있을지 의문이었지만, 적어도 상당수의 반복은 도구로도 충분히 잡아낼 수 있을 거라 판단했습니다. 그 결과물이 CSS Dedup입니다. 이 도구는 반복을 찾아낼 뿐 아니라 안전하게 최적화할 수 있는 부분을 실제로 중복 제거까지 해줍니다(관련 문서가 있는데, 핵심은 중복 제거가 선택자의 위치에 영향을 미치며 이는 캐스케이드 동작 방식과 맞물려 있다는 점입니다). 이를 통해 실제 데이터를 뽑아볼 수 있었습니다.

실제로 중복 제거할 게 남아 있을까?

먼저 임의로 선정한 20개 웹사이트를 분석했습니다. CSS Dedup을 이용해 두 가지 옵션으로 파일 크기 변화를 측정했는데요, 하나는 '확실하게 안전한(provably safe)' 것만 적용한 경우, 다른 하나는 '파일 크기가 줄어드는 경우에 한해서만' 공격적으로(probably safe) 적용한 경우입니다. 전자는 중복 제거의 "자연스러운" 결과를 보여주고, 후자는 전송 크기 절감까지 원하는 사이트 운영자에게 실질적으로 의미 있는 결과를 보여줍니다. UDJO는 유지보수성과 성능을 동시에 개선할 수 있는 기법이기 때문입니다.

중요한 전제가 있습니다. 이 수치들만으로 CSS의 품질을 평가할 수는 없습니다. 선택자 길이와, 해당 중복 제거가 실제로 유지보수성을 높이는지 여부에 따라 결과가 달라지기 때문입니다. 또한 이 실험은 압축(compression) 적용 이후의 변화는 다루지 않았는데, 이 부분도 추가로 검증해볼 가치가 있습니다.

데이터에서 읽을 수 있는 것들을 정리하면 다음과 같습니다.

  • 20개 사이트 모두에서 선언 중복을 줄일 수 있었습니다.
  • 18개 사이트에서는 선언 중복을 줄이는 것이 오히려 파일 크기 증가로 이어졌습니다(선택자가 반복되고, 그 선택자가 절약된 선언보다 더 길기 때문입니다).
  • 하지만 모든 사이트에서, 파일 크기 절감이 보장되는 경우만 골라 중복을 제거하는 방식으로는 선언 중복을 줄이면서도 크기를 줄일 수 있었습니다.

UDJO가 오늘날에도 여전히 유효한가라는 질문에 대한 답은 "그렇다"입니다. 심지어 파일 크기 절감까지 가능합니다.

UDJO는 CSS 최적화 기법으로서 얼마나 효과적인가

앞서 언급했듯 UDJO의 효과는 반복의 종류와 선택자 길이에 크게 좌우됩니다. 하지만 이는 관리가 가능한 변수입니다. CSS Dedup 같은 도구는 선언의 사용 맥락을 구분하지 않는다는 점에서 다소 투박하지만, 성능상의 이득만 취하도록 설정을 조정하는 것도 가능합니다.

이번 글에서 수집한 데이터가 보여주듯, 대부분의 경우에서 파일 크기 절감이 가능합니다. 이는 안전한 변경만을 기반으로 한 결과이기 때문에, 저비용 성능 최적화 수단이라 할 수 있습니다. 특히 압축(minify)된 결과물에 적용할 때 더욱 그렇습니다. 물론 gzip이나 Brotli 같은 추가 압축 효과와 함께 놓고 봐야겠지만, 액면가 기준으로도 중복 제거는 CSS 크기를 줄일 수 있음을 보여줍니다.

CSS 최적화, 유지보수성, 성능에 관심 있는 사람이라면 UDJO를 CSS 접근 전략의 일부로 고려해볼 만합니다. 다만 이 기법은 그동안 비주류였고 도구 역시 새로 나온 것이라, 직접 검토하고 테스트하고 탐구해보기를 권합니다. CSS 최적화에 한계가 왔다고 말하기는 아직 이른 것 같습니다.

정리

  • UDJO는 "선언을 한 번만 사용하라"는 원칙으로, 반복되는 CSS 선언을 하나의 규칙으로 합치는 18년 된 DRY 기반 최적화 기법입니다.
  • 단순히 모든 중복을 합치면 선택자 길이 때문에 오히려 파일 크기가 늘어날 수 있습니다(조직 사이트 20곳 중 18곳, 개발자 사이트 10곳 중 5곳에서 증가).
  • 하지만 "파일 크기가 줄어드는 경우에만" 중복 제거를 적용하도록 전략을 조정하면, 테스트한 모든 사이트에서 예외 없이 크기 절감 효과를 얻을 수 있었습니다.
  • 실무에서는 CSS Dedup 같은 도구로 안전하게 제거 가능한 중복을 먼저 식별하고, 압축(minify) 전 단계에서 선택적으로 적용하는 것이 저비용·고효율 최적화 전략이 될 수 있습니다. 단, gzip/Brotli 같은 후속 압축 효과까지 함께 고려해서 판단해야 합니다.
💡
CSS 번들이 비대해지는 상황에서 유지보수성과 전송 크기를 동시에 개선할 수 있는 저비용 최적화 기법과 실제 데이터 기반 효과를 확인할 수 있어, CSS 아키텍처와 빌드 파이프라인을 다루는 프론트엔드 개발자에게 실질적인 참고가 됩니다.
