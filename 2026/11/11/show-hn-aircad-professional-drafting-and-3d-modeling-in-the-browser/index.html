Aircad: 브라우저에서 완성하는 전문가급 2D 드래프팅·3D 모델링, 그리고 승인 기반 AI 에이전트

Show HN: Aircad – Professional drafting and 3D modeling in the browser

📅 2026-11-11📰 Hacker News (Top)
frontend

브라우저에서 돌아가는 CAD 툴이라고 하면 보통 "장난감 수준이겠지"라는 선입견이 먼저 듭니다. 하지만 Hacker News에 올라온 Aircad는 AutoCAD 수준의 2D 도면 작성과 Rhino 급 NURBS 솔리드 모델링을 웹 앱 하나로 묶고, 여기에 AI 에이전트와 실시간 멀티플레이어 협업까지 얹은 제품입니다. 이번 글에서는 Show HN 소개 페이지에 나온 내용을 바탕으로 Aircad가 어떤 기능을 어떻게 구성했는지 정리해보겠습니다.

설치 없이 바로 쓰는 전문가용 CAD

Aircad의 첫 번째 지향점은 "브라우저만 열면 된다"는 것입니다. 별도 설치 과정 없이 항상 최신 버전으로 작업할 수 있고, 모든 변경 사항은 버전 히스토리로 기록됩니다. 기존 DWG 파일을 레이아웃·블록·치수까지 그대로 가져올 수 있어서 AutoCAD 사용자가 바로 넘어오기 쉽게 설계되었습니다.

핵심 작업 공간은 2D 드래프팅과 3D 솔리드 모델링을 한 앱에서 처리하도록 되어 있습니다.

  • 익숙한 드래프팅 도구: trim, split, extend, stretch, arc, hatch, block, layer 등 기존 CAD 사용자에게 친숙한 명령어를 커맨드라인 입력과 스냅 기능으로 그대로 지원합니다.
  • NURBS 기반 솔리드 모델링: boolean, fillet, shell, loft, sweep 같은 전형적인 솔리드 모델링 연산을 제공합니다.
  • Push/Pull 모델링: 면을 선택해서 밀고 당기는 방식으로 정밀하게 형상을 수정할 수 있습니다.
  • 내장 블록 라이브러리: 문, 창문, 가구, 배관 부품을 Imperial·Metric 단위로 기본 제공하며, 팀이 만든 블록도 공유해서 쓸 수 있습니다.

도면 안에서 직접 작동하는 AI 에이전트

Aircad가 가장 공들여 소개하는 부분은 AI 에이전트입니다. 사용자가 커맨드라인이나 Agents 패널에서 자연어로 질문하거나 수정을 요청하면, 에이전트가 실제 도면 위에서 작업을 수행합니다.

소개 페이지에 나온 예시가 인상적인데, 계단 도면에 대해 "이 계단이 건축 코드(IRC)를 만족하나요?"라고 물으면 에이전트는 다음과 같이 답합니다.

  • 바닥에서 바닥까지 높이 9′-4″(112″)를 14단으로 나누면 단당 8″인데, IRC 기준 상한은 7¾″이므로 기준 초과
  • 디딤판(tread)은 11″로 최소 기준 10″를 충족
  • 112 ÷ 7.75 = 14.45이므로 15단으로 재설계하면 단당 7.47″로 기준을 만족
  • 위쪽 계단참(landing)은 고정하고 아래쪽에 한 단을 추가하는 방식으로, 아래쪽 계단참 깊이(최소 36″)와 헤드룸(최소 6′-8″)을 재검토해야 함

사용자가 "고쳐줘"라고 답하면 에이전트는 실제로 Stairs 레이어에 선 1개를 추가하고, 선 3개를 재구성하고, 치수 1개를 수정하는 식으로 변경 내역을 요약해서 보여줍니다. 그리고 변경 사항은 도면 위에 하이라이트된 "초안(draft)" 상태로 표시되며, 사용자가 Apply(적용) 또는 Discard(취소)를 눌러야 실제로 반영됩니다. 즉 AI가 임의로 도면을 수정해버리는 게 아니라, 항상 사용자 승인을 거치는 구조입니다.

모델 선택도 사용자가 할 수 있는데, Auto·Claude·GPT·Gemini·DeepSeek·GLM 등 여러 모델 중에서 고를 수 있습니다. 에이전트는 드래프팅·모델링·명령어 작성뿐 아니라 모델을 이미지로 렌더링하거나 뷰포트에서 바로 렌더링하는 작업까지 돕습니다. 스레드는 파일에 저장되고 사용자 개인에게만 비공개로 유지되며, AI 기능 자체는 전적으로 선택 사항이라 쓰지 않아도 Aircad의 모든 기능을 이용할 수 있습니다.

하나의 파일, 실시간 멀티플레이어 협업

두 번째 축은 협업입니다. Aircad는 이메일로 파일을 주고받거나 "final_v3" 같은 파일명이 생기는 상황을 없애는 것을 목표로, 모든 도면을 하나의 소스로 관리합니다.

  • 멀티플레이어 편집: 링크 하나로 공유하면 모두가 같은 파일에서 동시에 작업하고, 누가 어디서 작업 중인지 실시간으로 볼 수 있습니다.
  • 최신 리비전 유지: 한 사람이 변경하면 그 변경 사항이 모두에게 즉시 반영됩니다.
  • 도면 위 댓글: 피드백이 이메일에 흩어지지 않고 해당 지점에 핀으로 고정되어, 도면이 바뀌어도 맥락이 유지됩니다.
  • 리뷰 내장: 댓글, 레드라인 표시, 마크업된 PDF가 모두 Aircad 안에서 처리되어 별도 리뷰 툴 구독이 필요 없습니다.
  • 권한 제어: 링크 공유 시 편집 가능/보기 전용 권한을 지정할 수 있습니다.

버전 관리도 이 협업 구조의 연장선입니다. 모든 파일은 무제한 버전 히스토리를 가지며, 누가 언제 무엇을 바꿨는지 활동 피드로 기록됩니다. 두 버전을 비교하면 추가·변경·삭제된 요소가 도면 위에 색으로 표시되고, 히스토리의 특정 시점에서 포크해 실험해볼 수도 있습니다(원본은 그대로 유지). 물론 이전 버전으로 복원하는 것도 가능합니다.

도면을 아름답게 문서화하는 주석 기능

CAD 도면 품질은 결국 주석(annotation)에서 갈린다는 관점에서, Aircad는 치수·GD&T·인출선(leader)·텍스트·테이블을 임의 축척의 뷰포트가 있는 레이아웃 위에 배치할 수 있게 했고, 출력했을 때 화면과 동일하게 나오도록 신경 썼습니다.

  • 모든 치수 타입 지원: 선형, 각도, 반지름, 지름, 호 길이, ordinate, baseline, continue 치수를 지원하며, 설계가 바뀌어도 치수가 해당 형상을 따라가도록 되어 있습니다.
  • GD&T와 인출선: feature control frame을 단독으로 또는 인출선과 함께 배치할 수 있고, 노트·콜아웃용 인출선도 지원합니다.
  • 텍스트, 테이블, 타이틀 블록: 스타일이 적용된 텍스트, 부품 목록용 테이블, 속성을 가진 타이틀 블록을 제공하며, 스타일을 통해 도면 세트 전체의 일관성을 유지합니다.
  • 뷰 스타일: 해칭이 들어간 단면도, 모델에서 추출한 은선 처리, 선 굵기, 그림자, 물리 기반 재질(PBR)을 지원하고, 프린트 미리보기가 실제 PDF 출력과 일치합니다.

파일 호환성과 성능

Aircad는 DWG·DXF를 레이아웃·블록·치수까지 포함해서 가져올 수 있고, Rhino(.3dm), STEP, glTF, SVG도 불러올 수 있습니다. 내보내기는 DWG·DXF·PDF(도면)와 STL·OBJ(모델)를 지원합니다.

성능 면에서는 한 파일에 25만 개 이상의 엔티티를 넣을 수 있다고 소개하는데, 실제 예시로 "Bundled Tower"라는 108층, 38,510개의 편집 가능한 솔리드로 구성된 모델을 들고 있습니다. 수천 개의 솔리드가 화면에 떠 있어도 팬·줌·오빗이 부드럽게 유지되고, 반복되는 부품이나 블록은 로드 부담을 거의 늘리지 않는다고 합니다. 한 부품을 수정하면 그 부품만 업데이트되어 큰 파일도 작은 파일처럼 빠르게 반응하며, boolean·edge fillet·loft·sweep·Make2D 같은 무거운 연산은 백그라운드에서 처리되어 도면 작업이 끊기지 않고 Esc로 중단할 수도 있습니다. 화면 분할, 뷰 스타일 변경, 프린트 미리보기 전환 시에도 모델을 다시 로드하지 않습니다.

JavaScript로 커맨드를 직접 만드는 스크립팅 API

프론트엔드 개발자 관점에서 가장 흥미로운 부분은 스크립팅 API입니다. Aircad는 내장 명령어가 쓰는 것과 동일한 API를 JavaScript로 노출하는데, 스냅이 적용되는 입력, 라이브 프리뷰, 옵션, 단일 undo 스텝까지 모두 지원합니다. 작성한 커맨드는 파일 안에 저장하거나 팀과 공유할 수 있고, 직접 작성하는 대신 AI 에이전트에게 설명해서 작성을 맡길 수도 있습니다.

소개 페이지에는 "중심을 찍고, 드래그로 링의 반지름을 미리보기와 함께 설정하고, 튜브 반지름을 설정하는 Torus 커맨드" 예시가 나와 있습니다.

import { BRep, Curve, Plane } from "aircad";
export const manifest = {
  name: "Torus",
  kind: "command",
  capabilities: ["document:read", "document:write"],
  inputs: {
    center: { type: "point", prompt: "Pick the center" },
    radius: { type: "length", prompt: "Major radius" },
    tube: { type: "length", prompt: "Tube radius" },
  },
  api: 1,
};
export default async function main(cad) {
  const center = await cad.input.point("center");
  // Draw the ring while the pointer moves.
  const ring = cad.display.show();
  const radius = await cad.input.length("radius", {
    from: center,
    onChange: (r) => ring.set(Curve.circle(Plane.at(center), r)),
  });
  const tube = await cad.input.length("tube");
  return cad.doc.add(BRep.torus(Plane.at(center), radius, tube));
}

manifest에 입력값 타입과 프롬프트, 필요한 권한(capabilities)을 선언하고, main 함수 안에서 포인터 입력과 미리보기를 비동기로 조합하는 구조입니다. 스크립트는 네트워크 접근이 없는 샌드박스 환경에서 실행되도록 설계되어 있어, 팀원이 작성한 커맨드를 공유받아 써도 보안 측면에서 안전하다고 소개합니다.

정리

Aircad는 "브라우저에서 돌아가는 CAD"라는 틀을 단순한 2D 드로잉 툴 수준이 아니라, DWG 호환 드래프팅, NURBS 솔리드 모델링, 25만+ 엔티티를 다루는 성능, 실시간 멀티플레이어 협업, 그리고 승인 기반으로 동작하는 AI 에이전트까지 묶어서 하나의 제품으로 만들었습니다.

  • 기존 DWG 워크플로우를 깨지 않으면서 커맨드라인 기반 드래프팅과 push/pull 솔리드 모델링을 웹에서 지원합니다.
  • AI 에이전트는 건축 코드 검토 같은 전문적인 판단까지 수행하지만, 모든 변경은 Apply/Discard를 거쳐야 실제 도면에 반영되는 "초안" 구조로 설계되어 신뢰성을 확보합니다.
  • 버전 히스토리, 포크, 비교, 복원 기능이 Google Docs 같은 협업 문서 도구의 경험을 CAD 도메인에 그대로 가져왔습니다.
  • JavaScript 기반 스크립팅 API는 내장 명령어와 동일한 레벨의 API를 노출해서, 팀이 필요한 커맨드를 직접 만들고 공유할 수 있게 합니다.

프론트엔드 개발자 입장에서는 무거운 솔리드 모델링 연산을 백그라운드로 분리하면서도 UI 반응성을 유지하는 아키텍처, 그리고 권한 선언 기반의 샌드박스 스크립팅 API 설계가 특히 참고할 만한 지점입니다.
