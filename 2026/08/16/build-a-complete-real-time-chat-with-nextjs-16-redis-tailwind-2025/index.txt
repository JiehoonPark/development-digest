15:T2997,<p>실시간 채팅 앱을 밑바닥부터 만들어보는 튜토리얼은 많지만, 실무에서 실제로 쓰는 컨벤션과 최신 스택을 함께 짚어주는 콘텐츠는 흔치 않습니다. 이번에 소개할 영상은 Next.js 최신 버전, Redis, Tailwind CSS, 그리고 ElysiaJS를 조합해 &quot;10분 후 자동 소멸하는&quot; 프라이빗 채팅방을 만드는 과정을 처음부터 끝까지 다룹니다. 단순히 기능 구현에 그치지 않고, 폴더 구조를 어떻게 잡는지, 상수 이름은 왜 대문자로 쓰는지 같은 실무 컨벤션까지 함께 설명하는 점이 특징입니다.</p>
<h3>이 프로젝트가 만드는 것</h3>
<p>이 튜토리얼에서 만드는 앱은 단순한 채팅 데모가 아니라, Signal이나 Telegram처럼 프라이버시를 최우선으로 설계한 1:1 채팅 서비스입니다. 핵심 기능은 다음과 같습니다.</p>
<ul>
<li>사용자가 채팅방을 생성하면 커스텀 React 훅을 통해 자동으로 사용자명이 부여됩니다.</li>
<li>방을 만들면 곧바로 2인 전용 프라이빗 채팅에 입장하며, 세 번째 사용자가 접근을 시도하면 에러가 발생해 참여할 수 없습니다.</li>
<li>생성 후 10분이 지나면 방이 자동으로 파괴되고, 데이터베이스에 저장된 모든 메시지가 완전히 삭제됩니다.</li>
<li>화면 상단의 버튼을 눌러 언제든 수동으로 방을 폭파시킬 수도 있는데, 이 경우에도 메시지 삭제와 참여자 강제 퇴장이 즉시 이루어집니다.</li>
<li>메시지는 실시간으로 오갑니다. 한쪽에서 엔터를 치면 상대방 화면에 즉시 반영됩니다.</li>
</ul>
<h3>왜 이 기술 스택인가</h3>
<p>이번 빌드에서 눈여겨볼 부분은 백엔드 선택입니다. 표준 Next.js API 라우트 대신 <strong>ElysiaJS</strong>라는 오픈소스 프레임워크를 사용해 Next.js 백엔드를 작성합니다. ElysiaJS는 타입 세이프한 API를 빠르고 효율적으로 만들 수 있게 해주는 라이브러리로, 표준 API 라우트를 직접 작성하는 것보다 훨씬 쾌적한 개발 경험을 제공한다고 강조합니다. 이 과정에서 미들웨어 작성법, 타입 안전성 확보 방법, 프런트엔드에서 백엔드로 호출하는 방식까지 단계별로 다루며, 최종적으로 Vercel에 배포 가능한 형태로 완성합니다.</p>
<p>또한 실시간 통신과 방 자동 소멸 로직에는 Redis가 활용되고, 라우팅에서는 Next.js의 다이나믹 라우트 패턴을 실습하며 익힙니다.</p>
<h3>프로젝트 초기 설정</h3>
<p>먼저 터미널에서 프로젝트를 생성할 위치로 이동한 뒤, 패키지 매니저로 <code>bun</code>을 사용해 새 프로젝트를 초기화합니다. <code>npm</code>, <code>yarn</code> 등 어떤 패키지 매니저를 쓰든 상관없습니다.</p>
<pre><code class="language-bash">cd Desktop
bunx create-next-app@latest</code></pre>
<p>프로젝트 이름은 <code>real-time-chat</code>으로 지정합니다. 이후 나오는 설정 프롬프트에서는 기본값(recommended defaults)을 그대로 쓰지 않고 직접 커스터마이징하는 것을 권장하는데, 기본 설정 중 한 가지 옵션이 마음에 들지 않기 때문입니다. 선택한 옵션은 다음과 같습니다.</p>
<ul>
<li>TypeScript: Yes</li>
<li>ESLint: Yes</li>
<li>React Compiler: Yes</li>
<li>Tailwind CSS: Yes</li>
<li><strong><code>src</code> 디렉터리 사용: Yes</strong> (기본값은 No이지만, 코드베이스가 더 깔끔해지기 때문에 명시적으로 Yes를 선택)</li>
<li>App Router: Yes</li>
<li>Import alias 커스터마이징: No</li>
</ul>
<p><code>src</code> 디렉터리를 켜는 부분이 바로 기본값과 다르게 설정하는 이유였던 옵션입니다.</p>
<p>프로젝트 생성 후에는 다음과 같이 폴더로 이동해 에디터를 엽니다.</p>
<pre><code class="language-bash">cd real-time-chat
cursor .</code></pre>
<p>VS Code를 쓴다면 물론 그대로 사용해도 무방합니다. 패키지는 이미 설치되어 있으므로 바로 개발 서버를 실행할 수 있습니다.</p>
<pre><code class="language-bash">bun dev</code></pre>
<p><code>localhost</code>에 접속하면 Next.js 기본 시작 화면이 뜨는데, 이는 프로젝트 세팅이 정상적으로 완료되었다는 신호입니다.</p>
<h3>폰트 설정: JetBrains Mono 적용하기</h3>
<p>가장 먼저 손대는 부분은 스타일링입니다. 기본으로 제공되는 Geist 폰트 대신, 모노스페이스 계열의 <strong>JetBrains Mono</strong>를 적용합니다. <code>src/app/layout.tsx</code>에서 기본 Geist 폰트 임포트를 제거하고 <code>next/font/google</code>에서 <code>JetBrains_Mono</code>를 직접 불러옵니다.</p>
<pre><code class="language-tsx">import { JetBrains_Mono } from &quot;next/font/google&quot;;

const jetBrainsMono = JetBrains_Mono({
  variable: &quot;--font-jetbrains-mono&quot;,
  subsets: [&quot;latin&quot;],
});</code></pre>
<p>여기서 <code>variable</code>은 CSS 변수명을 지정하는 값으로, <code>--font-jetbrains-mono</code>처럼 이름을 짓는 것이 관례입니다. <code>subsets</code>에는 <code>latin</code>을 지정해 어떤 문자 집합을 로드할지 정합니다.</p>
<p>이렇게 생성한 폰트 객체의 <code>variable</code> 클래스를 <code>body</code> 태그에 적용합니다. 기존 Geist 관련 클래스는 제거하고 새 변수만 남깁니다.</p>
<pre><code class="language-tsx">&lt;body className={jetBrainsMono.variable}&gt;</code></pre>
<p>하지만 이것만으로는 폰트가 실제로 적용되지 않습니다. <code>globals.css</code>에서 <code>body</code>의 <code>font-family</code>를 이 CSS 변수를 참조하도록 바꿔줘야 합니다.</p>
<pre><code class="language-css">body {
  font-family: var(--font-jetbrains-mono);
}</code></pre>
<p>이 설정을 저장하고 브라우저를 새로고침하면 화면 전체 폰트가 JetBrains Mono로 바뀌어 훨씬 세련된 느낌을 줍니다. 이 폰트 설정이 앱 전체의 시각적 베이스라인이 됩니다.</p>
<h3>초기 레이아웃 구성</h3>
<p>폰트 설정이 끝나면 곧바로 루트 페이지의 레이아웃 작업에 들어갑니다. 이 과정에서 에디터 생산성을 높여주는 팁 두 가지가 소개됩니다.</p>
<ul>
<li><strong>Emmet: Balance Outward</strong> 단축키를 <code>Cmd+M</code>에 바인딩해두면, 커서가 위치한 div 전체를 시작부터 끝까지 한 번에 선택할 수 있어 특정 블록을 통째로 지우거나 교체할 때 유용합니다.</li>
<li><code>Shift + Alt + O</code>는 파일 내 import 문을 정렬하고 사용하지 않는 import를 자동으로 제거해줍니다.</li>
</ul>
<p>이 단축키를 활용해 기본 루트 div를 지우고 <code>main</code> 태그로 교체합니다.</p>
<pre><code class="language-tsx">&lt;main className=&quot;flex min-h-screen flex-col items-center justify-center p-4&quot;&gt;</code></pre>
<p><code>min-h-screen</code>은 <code>100vh</code>에 대응하는 값이며, 내부 요소를 세로로 정렬하고 화면 중앙에 배치하도록 구성했습니다.</p>
<p>그 안에는 로비(lobby) 폼 전체를 감싸는 컨테이너 div를 넣습니다.</p>
<pre><code class="language-tsx">&lt;div className=&quot;w-full max-w-md space-y-8&quot;&gt;</code></pre>
<p>이 컨테이너 내부에 실제 카드 형태의 폼 박스를 만듭니다.</p>
<pre><code class="language-tsx">&lt;div className=&quot;border border-zinc-800 bg-zinc-900/50 p-6 backdrop-blur-md&quot;&gt;</code></pre>
<p><code>bg-zinc-900/50</code>에서 <code>/50</code>은 배경색의 투명도를 나타내며, <code>backdrop-blur-md</code>로 배경에 블러 효과를 더해 카드가 은은하게 떠 보이도록 만듭니다.</p>
<p>그 다음 내부에는 <code>space-y-5</code>, <code>space-y-2</code> 클래스를 가진 div들을 중첩해서 방 생성(Create Room) 관련 요소들의 수직 간격을 정리합니다. 처음에는 임시로 &quot;create room&quot;이라는 텍스트만 넣어 레이아웃이 제대로 렌더링되는지 확인한 뒤, 이를 실제 폼 요소로 교체합니다.</p>
<ul>
<li>자동 생성된 <code>label</code> 태그의 <code>htmlFor</code> 속성은 제거하고, <code>className=&quot;flex items-center text-zinc-500&quot;</code>을 지정합니다.</li>
<li>라벨 텍스트는 &quot;your identity&quot;로, 사용자가 접속할 때 사용할 이름을 나타낸다는 의미를 담습니다.</li>
</ul>
<p>이 시점에서 Tailwind IntelliSense 확장 프로그램은 클래스에 마우스를 올릴 때마다 큰 팝업이 화면을 가려 작업을 방해하기 때문에, 튜토리얼 진행 중에는 잠시 비활성화하고 작업하는 것도 하나의 팁으로 소개됩니다.</p>
<p>이후 영상은 사용자 식별을 위한 입력 필드와 방 생성 버튼 등 폼 구성을 이어서 다루는데, 이 지점까지가 이번에 확인 가능한 초기 셋업과 레이아웃 기초 작업의 범위입니다.</p>
<h3>정리</h3>
<ul>
<li>이 프로젝트는 Next.js 최신 버전, Tailwind CSS, Redis, ElysiaJS를 조합해 10분 후 자동 소멸하는 프라이빗 2인 채팅 앱을 만드는 실전 튜토리얼입니다.</li>
<li>방마다 커스텀 훅으로 사용자명을 자동 부여하고, 실시간 메시지 전송, 수동/자동 방 파괴, 3인 이상 접근 차단 같은 프라이버시 중심 기능을 구현합니다.</li>
