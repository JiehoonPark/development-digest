16:T25ac,<h2>JS와 CSS 사이의 벽을 허무는 라이브러리, Props For</h2>
<p>CSS만으로 스크롤에 반응하는 애니메이션을 만드는 건 여전히 쉽지 않습니다. 스크롤 기반 애니메이션은 브라우저 지원이 점점 나아지고는 있지만 아직 완벽하지 않고, 스크롤 트리거 애니메이션은 아예 CSS만으로는 구현이 안 됩니다. 이번 글에서는 Adam Argyle이 만든 <code>props for</code>라는 라이브러리를 통해, JavaScript 한 줄만으로 마우스 포인터 위치, 스크롤 상태, 뷰포트 크기 같은 값들을 CSS 커스텀 프로퍼티로 실시간 전달해서 이런 문제를 해결하는 방법을 살펴보겠습니다.</p>
<h3>props for가 하는 일</h3>
<p>지난 글에서 CSS에 가능한 한 많은 정보를 넘겨주는 것이 좋은 전략이라고 이야기한 적이 있는데요, 문제는 어떤 값들은 JavaScript 없이 CSS만으로 얻어내기가 상당히 번거롭다는 점입니다. props for는 바로 이 지점을 해결해줍니다.</p>
<p>FPS, 뷰포트 크기, 스크롤 속도, 인풋의 색상 값, 커서 위치 등 다양한 값들이 실시간으로 CSS 커스텀 프로퍼티로 전달됩니다. 그것도 굉장히 간단한 설정만으로, 그리고 꽤 성능 좋게 동작합니다. &quot;JS knows, now CSS knows&quot;라는 문구가 이 라이브러리의 핵심을 잘 요약해줍니다.</p>
<h3>설치와 기본 사용법</h3>
<p>시작하는 방법은 매우 간단합니다.</p>
<pre><code>npm install props-for</code></pre>
<p>프로젝트 구성 방식에 따라 몇 가지 설치 옵션이 있지만, 어떤 방식을 택하든 사용법 자체는 쉽습니다. JavaScript 쪽에서는 다음과 같이 import 한 줄만 추가하면 됩니다.</p>
<pre><code class="language-js">import 'props-for/auto';</code></pre>
<p>그다음 HTML에서 원하는 요소에 <code>data-props-for</code> 속성을 추가하고, 어떤 값들을 추적할지 나열해주면 됩니다. 예를 들어 포인터의 로컬 위치를 추적하고 싶다면 <code>pointer-local</code> 같은 값을 지정하는 식입니다.</p>
<p>이렇게 설정하면 개발자 도구에서 해당 요소에 다음과 같은 커스텀 프로퍼티가 실시간으로 붙는 걸 확인할 수 있습니다.</p>
<ul>
<li><code>--pointer-local-x-ratio</code>, <code>--pointer-local-y-ratio</code>: 요소 내에서 포인터의 X, Y 위치를 비율로 표시</li>
<li><code>--pointer-inside</code>: 포인터가 요소 위에 올라가 있는지 여부 (일종의 hover 감지)</li>
</ul>
<h3>성능 걱정은 넣어둬도 된다</h3>
<p>&quot;이렇게 계속 값을 추적하면 성능에 문제가 생기지 않을까?&quot;라는 걱정이 들 수 있는데요, props for는 이 부분을 잘 처리해뒀습니다. 요소가 화면 밖으로 스크롤되어 벗어나면 더 이상 해당 값을 추적하지 않습니다. 즉, 화면에 보이는 요소에 대해서만 추적이 이뤄지기 때문에 불필요하게 처리 자원을 낭비하지 않습니다. Adam이 성능 최적화에 많은 신경을 쓴 결과입니다.</p>
<h3>포인터 위치로 그라디언트 움직이기</h3>
<p>실제 데모에서는 카드 위에 마우스를 올렸을 때 빛나는 효과가 마우스를 따라다니는 그라디언트를 구현했습니다. 기존에 SVG 텍스처, 배경 그라디언트, radial-gradient로 만든 하이라이트 효과가 있는 카드에서, X와 Y 좌표 값이 폴백(fallback) 값으로만 채워져 있던 부분을 props for가 제공하는 값으로 대체합니다.</p>
<p>여기서 중요한 특징 하나는, props for가 전달하는 값은 항상 단위 없는(unitless) 숫자라는 점입니다. 이는 의도적인 설계로, 개발자가 원하는 방식대로 자유롭게 단위를 붙여 활용할 수 있게 하기 위함입니다. 예를 들어 퍼센트 값으로 쓰고 싶다면 <code>calc()</code>로 100%를 곱해주면 됩니다.</p>
<pre><code class="language-css">--x: calc(var(--pointer-local-x-ratio) * 100%);
--y: calc(var(--pointer-local-y-ratio) * 100%);</code></pre>
<p>이렇게만 하면 별도의 JavaScript 로직 없이 마우스를 따라 그라디언트가 움직이는 효과가 완성됩니다. (실제 데모에서는 마우스가 카드에서 멀리 벗어났을 때 값이 과도하게 튀지 않도록 <code>clamp()</code>도 함께 사용했습니다.)</p>
<h3>live 값과 const 값의 차이</h3>
<p>props for에는 두 가지 종류의 커스텀 프로퍼티가 있습니다.</p>
<ul>
<li><strong>live 값</strong> (예: <code>--live-visible</code>): 계속해서 실시간으로 업데이트됩니다.</li>
<li><strong>const 값</strong> (예: <code>--const-has-entered</code>): 한 번 값이 정해지면 이후로는 바뀌지 않습니다.</li>
</ul>
<p>예를 들어 요소가 처음 화면에 들어왔을 때 <code>--const-has-entered</code>는 0에서 1로 바뀐 뒤 그대로 유지됩니다. 반면 <code>--live-visible</code>은 요소가 화면에 보이는 동안 1, 화면 밖으로 나가면 다시 0으로 바뀌는 식으로 계속 값이 변동합니다.</p>
<p>이 두 값의 차이는 용도가 명확히 갈립니다. 스크롤에 따라 반복적으로 반응하는 애니메이션을 만들고 싶다면 live 값을, 한 번 등장한 뒤에는 다시 사라졌다 나타나도 애니메이션이 재생되지 않길 원한다면 const 값을 쓰면 됩니다.</p>
<h3>스크롤에 반응하는 &quot;twist-in&quot; 애니메이션 만들기</h3>
<p>이 값들을 활용해서 카드가 스크롤에 따라 비스듬한 각도로 등장했다가 제자리로 돌아오는 &quot;twist-in&quot; 효과를 만들 수 있습니다.</p>
<p>먼저 opacity와 live-visible을 연결해 간단한 페이드인부터 시작합니다.</p>
<pre><code class="language-css">.twist-in {
  opacity: var(--live-visible);
  transition: opacity 5s; /* 데모용으로 길게, 실제로는 짧게 */
}</code></pre>
<p>live-visible 값을 쓰면 요소가 화면에서 벗어날 때마다 다시 사라졌다가 재진입 시 페이드인이 반복되는데요, 이 반복 동작이 필요 없다면 const 값을 쓰는 게 더 적합합니다. 다만 데모 목적으로는 반복되는 편이 보여주기 좋아서 live 값을 그대로 사용했습니다.</p>
<p>다음으로 각도를 주기 위해 <code>transform</code>을 추가합니다. 여기서 핵심 아이디어는 live-visible 값을 뒤집은 보조 변수를 만드는 것입니다.</p>
<pre><code class="language-css">--is-visible: calc(1 - var(--live-visible));</code></pre>
<p>이렇게 하면 요소가 보이는 상태(<code>--live-visible: 1</code>)일 때 <code>--is-visible</code>은 0이 되고, 보이지 않는 상태(<code>--live-visible: 0</code>)일 때는 1이 됩니다. 이 값을 각도에 곱해주면, 화면 밖에 있을 때는 각도가 적용되고 화면에 들어오면 각도가 0으로 풀리면서 정면을 향하는 효과를 만들 수 있습니다.</p>
<pre><code class="language-css">--twist-y: -25deg;
--twist-x: -8deg;

transform:
  rotateY(calc(var(--twist-y) * var(--is-visible)))
  rotateX(calc(var(--twist-x) * var(--is-visible)));
transition: transform 5s;</code></pre>
<p>마지막으로 카드마다 방향을 다르게 주기 위해 <code>--twist-y</code>와 <code>--twist-x</code>를 개별 카드에서 오버라이드했습니다. 예를 들어 어떤 카드는 <code>-25deg</code>/<code>-8deg</code>, 다른 카드는 반대로 <code>25deg</code>/<code>8deg</code>를 줘서 스크롤을 내릴 때마다 카드들이 서로 다른 방향에서 비틀리며 등장하도록 만들었습니다. transition 시간도 5초 같은 데모용 값 대신 실제로는 0.75초 정도로 훨씬 스냅감 있게 조정해서 사용하면 됩니다.</p>
<h3>정리</h3>
<ul>
<li><strong>props for</strong>는 Adam Argyle이 만든 라이브러리로, 포인터 위치·스크롤 속도·뷰포트 크기·요소의 가시성 여부 등 JavaScript에서만 접근 가능했던 값들을 CSS 커스텀 프로퍼티로 실시간 전달해줍니다.</li>
<li>설치는 <code>npm install props-for</code> 후 <code>import 'props-for/auto'</code> 한 줄, HTML에서는 <code>data-props-for</code> 속성으로 원하는 값을 지정하는 것만으로 끝납니다.</li>
<li>요소가 화면 밖으로 나가면 자동으로 추적을 멈추기 때문에 성능 부담이 크지 않습니다.</li>
<li>전달되는 값은 항상 단위 없는 숫자이므로 <code>calc()</code>로 원하는 단위(%, deg 등)를 자유롭게 붙여 쓸 수 있습니다.</li>
<li><strong>live</strong> 값(계속 갱신)과 <strong>const</strong> 값(한 번만 갱신)을 구분해서 제공하므로, 반복 재생되는 스크롤 반응 애니메이션과 한 번만 실행되는 등장 애니메이션을 용도에 맞게 골라 만들 수 있습니다.</li>
<li><code>1 - var(--live-visible)</code> 같은 보조 계산으로 값을 뒤집어 활용하면, &quot;화면 밖에서는 각도가 적용되고 화면에 들어오면 각도가 풀리는&quot; 식의 트랜지션 로직을 옵저버나 스크롤 이벤트 리스너 없이 순수 CSS 트랜지션만으로 구현할 수 있습니다.</li>
