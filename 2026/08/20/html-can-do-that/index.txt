13:T2968,<p>HTML은 한때 JavaScript의 전유물이었던 영역들을 하나둘씩 흡수해왔습니다. 개발자 Chris Burnell이 HTML Day 2026 행사 기간 동안 한 시간 만에 만든 페이지에서 시작된 이 정리는, 이제 순수 HTML만으로 구현 가능한 다양한 동적 기능들을 실제 예제와 함께 보여줍니다. 다만 저자는 이후 업데이트를 통해, 이 기능들 중 일부는 브라우저 구현이 아직 미흡하거나 접근성 요구사항을 전혀 충족하지 못한다는 점을 명확히 밝히고 있습니다. 화려해 보인다고 무조건 가져다 쓰기보다는, 각 기능의 한계와 접근성 이슈를 정확히 이해한 뒤 신중하게 도입하는 것이 이 글의 핵심 메시지입니다.</p>
<h3>popover 속성</h3>
<p><code>popover</code>와 <code>popovertarget</code>(그리고 <code>popovertargetaction</code>) 속성만으로 라이트 디스미스(바깥 클릭 시 닫힘), Esc 키로 닫기, z-index 관리 없이 최상단 레이어에 올라가는 팝오버를 구현할 수 있습니다. JavaScript 없이 브라우저가 알아서 처리해주는, 웹 표준 담당자들과 브라우저 개발자들의 노력 덕분에 가능해진 기능입니다.</p>
<pre><code class="language-html">&lt;button popovertarget=&quot;example-popover&quot;&gt;Toggle popover&lt;/button&gt;
&lt;div id=&quot;example-popover&quot; popover&gt;
&lt;p&gt;No JavaScript, just modern browser magic, thanks to the wonderful folks speccing for the web and building our browsers!&lt;/p&gt;
&lt;button popovertarget=&quot;example-popover&quot; popovertargetaction=&quot;hide&quot;&gt;Close&lt;/button&gt;
&lt;/div&gt;</code></pre>
<h3>dialog 요소</h3>
<p><code>popover</code>와 비슷한 방식이지만, 이번에는 모달 다이얼로그 박스를 위한 전용 요소인 <code>&lt;dialog&gt;</code>를 사용합니다. <code>&lt;form method=&quot;dialog&quot;&gt;</code>로 닫고 <code>popover</code> 속성으로 여는 방식은 순수 HTML만으로 구현됩니다.</p>
<pre><code class="language-html">&lt;button popovertarget=&quot;example-dialog&quot;&gt;Toggle &amp;lt;dialog&amp;gt; popover&lt;/button&gt;
&lt;dialog id=&quot;example-dialog&quot; popover&gt;
&lt;p&gt;Closed with just HTML via &lt;code&gt;&amp;lt;form method=&quot;dialog&quot;&amp;gt;&lt;/code&gt;, opened with the &lt;code&gt;popover&lt;/code&gt; attribute.&lt;/p&gt;
&lt;button popovertarget=&quot;example-dialog&quot; popovertargetaction=&quot;hide&quot;&gt;Close&lt;/button&gt;
&lt;/dialog&gt;</code></pre>
<p>참고로 이 글의 취지와는 다소 어긋나지만, JavaScript로 dialog를 다루는 방법도 함께 소개하고 있습니다. <code>.showModal()</code>로 열고 <code>.close()</code>로 닫는 방식입니다.</p>
<pre><code class="language-html">&lt;button id=&quot;example-dialog-js-open&quot;&gt;Open dialog&lt;/button&gt;
&lt;dialog id=&quot;example-dialog-js&quot;&gt;
&lt;p&gt;This one is opened with &lt;code&gt;.showModal()&lt;/code&gt; and closed with &lt;code&gt;.close()&lt;/code&gt;, both called from JavaScript.&lt;/p&gt;
&lt;button id=&quot;example-dialog-js-close&quot;&gt;Close&lt;/button&gt;
&lt;/dialog&gt;</code></pre>
<pre><code class="language-js">document.getElementById(&quot;example-dialog-js-open&quot;).addEventListener(&quot;click&quot;, () =&gt; {
document.getElementById(&quot;example-dialog-js&quot;).showModal()
})
document.getElementById(&quot;example-dialog-js-close&quot;).addEventListener(&quot;click&quot;, () =&gt; {
document.getElementById(&quot;example-dialog-js&quot;).close()
})</code></pre>
<p>아래에서 다룰 <code>command</code> / <code>commandFor</code> 기능을 활용하면 dialog 요소를 여닫는 또 다른 방법도 가능하며, 이는 향후 다른 비-JS 기능에도 유용하게 쓰일 예정입니다.</p>
<h3>name 속성을 공유하는 details 그룹</h3>
<p><code>&lt;details&gt;</code> 요소들에 동일한 <code>name</code> 속성을 부여하면 배타적으로 동작하는 아코디언이 만들어집니다. 하나를 열면 나머지는 자동으로 닫힙니다.</p>
<pre><code class="language-html">&lt;details name=&quot;example-group&quot;&gt;
&lt;summary&gt;First&lt;/summary&gt;
&lt;p&gt;Open the second one and watch this close on its own.&lt;/p&gt;
&lt;/details&gt;
&lt;details name=&quot;example-group&quot;&gt;
&lt;summary&gt;Second&lt;/summary&gt;
&lt;p&gt;First one’s hidden now.&lt;/p&gt;
&lt;/details&gt;</code></pre>
<h3>command와 commandfor</h3>
<p><code>command</code>와 <code>commandfor</code> 속성을 이용하면 스크립트 없이도 여러 버튼으로 하나의 popover를 제어할 수 있습니다. 현재 안정적으로 지원되는 값은 <code>show-modal</code>, <code>close</code>, <code>request-close</code>, <code>toggle-popover</code>, <code>show-popover</code>, <code>hide-popover</code> 정도이며, 앞으로 값을 증가/감소시키거나, 미디어 요소를 제어하거나, 텍스트를 복사하는 등의 invoker 기능이 추가로 지원될 예정입니다.</p>
<pre><code class="language-html">&lt;button command=&quot;show-popover&quot; commandfor=&quot;example-command-popover&quot;&gt;Open&lt;/button&gt;
&lt;button command=&quot;hide-popover&quot; commandfor=&quot;example-command-popover&quot;&gt;Close&lt;/button&gt;
&lt;dialog id=&quot;example-command-popover&quot; popover&gt;
&lt;p&gt;&lt;code&gt;show-popover&lt;/code&gt; opens this and &lt;code&gt;hide-popover&lt;/code&gt; closes it!&lt;/p&gt;
&lt;button command=&quot;hide-popover&quot; commandfor=&quot;example-command-popover&quot;&gt;Close&lt;/button&gt;
&lt;/dialog&gt;</code></pre>
<h3>loading=&quot;lazy&quot;</h3>
<p>이미지에 <code>loading=&quot;lazy&quot;</code>를 붙이면 뷰포트 근처에 다다를 때까지 로딩을 지연시킵니다. <code>IntersectionObserver</code>를 직접 구현할 필요가 전혀 없습니다.</p>
<pre><code class="language-html">&lt;img src=&quot;/images/avatar@2x.jpeg&quot; loading=&quot;lazy&quot; width=&quot;200&quot; height=&quot;200&quot; alt=&quot;a photo portait of Chris Burnell’s face&quot;&gt;</code></pre>
<h3>hidden until-found</h3>
<p>프래그먼트 링크를 통해 이동하면 숨겨진 섹션이 드러나는 기능입니다. 브라우저가 <code>hidden=&quot;until-found&quot;</code> 속성을 자동으로 제거해줍니다. 다만 이 기능은 아직 꽤 최신 기능이라, 브라우저 기본 검색 기능과는 잘 맞물리지만 스크린 리더의 검색 기능과는 그리 잘 어울리지 않는다는 점에 유의해야 합니다. 그래도 언젠가 요긴하게 쓸 수 있는 기능으로 기억해둘 만합니다.</p>
<pre><code class="language-html">&lt;a href=&quot;#example-until-found&quot;&gt;Jump to hidden content&lt;/a&gt;
&lt;div id=&quot;example-until-found&quot; hidden=&quot;until-found&quot;&gt;
&lt;p&gt;Yahaha! You found me!&lt;/p&gt;
&lt;/div&gt;</code></pre>
<h3>색상, 날짜/시간, 범위 입력</h3>
<p>컬러 피커, 범위 슬라이더, 날짜 피커가 브라우저에 내장되어 있습니다.</p>
<pre><code class="language-html">&lt;label&gt;Colour &lt;input type=&quot;color&quot; value=&quot;#5f8aa6&quot; autocomplete=&quot;off&quot;&gt;&lt;/label&gt;
&lt;label&gt;Range &lt;input type=&quot;range&quot; min=&quot;0&quot; max=&quot;100&quot; value=&quot;50&quot; autocomplete=&quot;off&quot;&gt;&lt;/label&gt;
&lt;label&gt;Date &lt;input type=&quot;date&quot; autocomplete=&quot;off&quot;&gt;&lt;/label&gt;</code></pre>
<p>다만 이들 요소는 아직 다소 미완성인 느낌이 있습니다. 앞으로 몇 년간 폼 요소들이 더 다듬어지길 기대하지만, 현재 시점에서 브라우저 구현은 여전히 부족한 부분이 많습니다. 브라우저마다 기본 스타일이 크게 다르고, 접근성 경험도 상당히 열악하기 때문에 사용에는 매우 신중을 기해야 합니다.</p>
<h3>datalist</h3>
<p><code>&lt;datalist&gt;</code>를 사용하면 별도의 드롭다운 라이브러리 없이도 네이티브 자동완성 제안을 구현할 수 있습니다.</p>
<pre><code class="language-html">&lt;label&gt;Favourite HTML element &lt;input type=&quot;text&quot; id=&quot;example-datalist-input&quot; list=&quot;example-datalist&quot; autocomplete=&quot;off&quot;&gt;&lt;/label&gt;
&lt;datalist id=&quot;example-datalist&quot;&gt;
&lt;option value=&quot;a&quot;&gt;
&lt;option value=&quot;abbr&quot;&gt;
&lt;option value=&quot;address&quot;&gt;
&lt;!-- ... --&gt;
&lt;/datalist&gt;</code></pre>
<p>다만 입력 타입별 지원 상태가 여전히 들쭉날쭉하고, 브라우저 구현에도 여러 문제가 있습니다. Adrian Roselli의 &quot;Under-Engineered Comboboxen&quot; 글을 참고할 만하며, 저자는 현재로서는 이 기능 사용을 아예 보류하고 앞으로 개선되는지 지켜볼 것을 권하고 있습니다.</p>
<h3>정리</h3>
<ul>
<li><code>popover</code>, <code>dialog</code>, <code>details name</code>, <code>command</code>/<code>commandfor</code> 같은 속성들 덕분에 라이트 디스미스, 모달, 아코디언, 다중 버튼 제어 같은 UI 패턴을 JavaScript 없이도 구현할 수 있게 되었습니다.</li>
<li><code>loading=&quot;lazy&quot;</code>는 이미지 지연 로딩을, <code>hidden until-found</code>는 검색 시 콘텐츠 자동 노출을 스크립트 없이 처리해줍니다.</li>
<li>색상/날짜/범위 input과 <code>datalist</code> 같은 폼 관련 기능은 편리해 보이지만, 브라우저별 스타일 차이와 접근성 문제가 여전히 심각해 실무 도입 시 각별한 주의가 필요합니다. 특히 <code>datalist</code>는 지원 범위가 들쭉날쭉해 당장 사용을 보류하고 지켜보는 편이 낫다는 것이 원저자의 조언입니다.</li>
<li>새 HTML 기능이 나왔다고 해서 무조건 프로덕션에 쓸 준비가 된 것은 아니며, 각 기능의 브라우저 지원 현황과 접근성 실태를 반드시 확인한 뒤 &quot;가능한 한 접근성 있게&quot; 사용해야 합니다.</li>
