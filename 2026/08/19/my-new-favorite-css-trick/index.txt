13:T225c,<p>CSS로 border-radius를 다루다 보면 늘 아쉬운 지점이 있습니다. 요소가 뷰포트나 부모 요소의 가장자리에 딱 붙었을 때, 둥근 모서리가 자연스럽게 각져 보이면 좋겠다는 생각이 드는 순간이죠. Kevin Powell이 소개한 이번 트릭은 바로 이 문제, 즉 &quot;요소가 화면 끝에 닿으면 border-radius가 스스로 꺼지는&quot; 효과를 CSS 계산식만으로 구현하는 방법입니다. 코드 몇 줄로 꽤 복잡해 보이는 문제를 우아하게 풀어내는 과정을 정리해봤습니다.</p>
<h3>기본 아이디어와 한계</h3>
<p>가장 먼저 떠올릴 수 있는 방법은 그냥 고정된 <code>border-radius</code> 값을 주는 것입니다.</p>
<pre><code class="language-css">.element {
  border-radius: 20px;
}</code></pre>
<p>하지만 이렇게 하면 요소 크기와 무관하게 radius가 고정되어 있어서, 우리가 원하는 &quot;가장자리에 닿으면 사라지는&quot; 동작을 전혀 만들 수 없습니다. 그래서 요소의 크기에 따라 반응하는 radius가 필요한데, 이때 흔히 쓰는 방법이 퍼센트 단위입니다.</p>
<pre><code class="language-css">.element {
  border-radius: 50%;
}</code></pre>
<p>문제는 두 가지입니다. 첫째, 완벽한 정사각형이 아닌 경우 퍼센트 기반 radius는 종종 이상한 타원형 모양을 만들어냅니다. 둘째, 더 치명적인 문제인데, 퍼센트 방식은 우리가 원하는 것과 정반대로 동작합니다. 요소가 커질수록 radius도 커지고, 작아질수록 radius도 작아지죠. 하지만 우리가 원하는 건 요소가 전체 너비를 다 채웠을 때(뷰포트 가장자리에 닿았을 때) radius가 0이 되고, 그렇지 않을 때는 radius가 살아있는 동작입니다. 즉 방향을 완전히 뒤집어야 합니다.</p>
<h3>뷰포트 단위를 이용한 역산 공식</h3>
<p>CSS에는 이렇게 &quot;뒤집힌&quot; 값을 직접 만들어주는 단위가 없습니다. 하지만 약간의 수학을 이용하면 이 문제를 해결할 수 있습니다. 핵심 아이디어는 <code>100vw</code>(뷰포트 전체 너비)에서 요소의 <code>100%</code>(요소 자신의 너비)를 빼는 것입니다.</p>
<pre><code class="language-css">.element {
  border-radius: calc(100vw - 100%);
}</code></pre>
<p>이게 왜 작동하는지 숫자로 살펴보면 이해가 쉽습니다. 예를 들어 <code>100vw</code>가 1000px이라고 가정해봅시다.</p>
<ul>
<li>요소 너비가 뷰포트의 50%라면, radius는 <code>1000px - 500px = 500px</code></li>
<li>요소가 조금 더 커져서 뷰포트의 75%가 되면, radius는 <code>1000px - 750px = 250px</code></li>
<li>요소가 뷰포트 가장자리에 거의 닿아 100%에 가까워지면, radius는 <code>1000px - 1000px</code>에 가까워져 거의 0이 됩니다</li>
</ul>
<p>즉 요소가 커질수록 radius는 점점 작아지고, 가장자리에 닿는 순간 0에 수렴하는 정확히 우리가 원하던 동작이 만들어집니다.</p>
<h3>문제 1: 요소가 작아질 때 radius가 폭주한다</h3>
<p>이 공식만으로는 새로운 문제가 생깁니다. 요소가 작아질수록 <code>100vw - 100%</code>의 값은 계속 커지기 때문에, radius가 한없이 커져버립니다. 이건 우리가 원하는 동작이 아니죠. 이 문제는 <code>clamp()</code>로 간단히 해결할 수 있습니다.</p>
<pre><code class="language-css">.element {
  border-radius: clamp(0px, calc(100vw - 100%), 50px);
}</code></pre>
<p>이제 요소가 작아지면 radius는 커지다가 50px에서 멈추고, 가장자리에 가까워지면 여전히 0에 수렴합니다.</p>
<h3>문제 2: 가장자리 근처에서 애매하게 찌그러지는 구간</h3>
<p>두 번째 문제는 가장자리 바로 근처에서 radius가 부드럽게 줄어들다가 0으로 넘어가는 게 아니라, 아예 즉각적으로 0으로 &quot;뚝&quot; 전환되길 원한다는 점입니다. 이 전환이 매끄럽게 일어나면 오히려 가장자리 근처에서 어중간하게 눌린 듯한 모양이 나와버립니다.</p>
<p>이를 해결하려면 <code>clamp()</code>의 가운데 값(계산된 radius)이 사실상 두 가지 상태 중 하나만 갖도록 만들어야 합니다. 즉 값이 &quot;충분히 크거나&quot; 또는 &quot;0이거나&quot; 둘 중 하나여야지, 그 사이를 부드럽게 지나가면 안 됩니다. 이를 위해 계산식에 지수를 넣어주면, 값이 0에서 조금만 벗어나도 순식간에 엄청나게 커지도록 만들 수 있습니다.</p>
<pre><code class="language-css">.element {
  border-radius: clamp(0px, calc(pow((100vw - 100%), 2) * 1px), 50px);
}</code></pre>
<p>이렇게 하면 계산된 값은 사실상 &quot;거의 0&quot;이거나 &quot;clamp의 최댓값을 넘어설 만큼 거대한 값&quot; 둘 중 하나로 수렴합니다. 결과적으로 가장자리에 닿는 순간 radius가 즉각 0으로 전환되면서, 우리가 원했던 &quot;스위치가 켜지고 꺼지는&quot; 듯한 딱 떨어지는 동작이 완성됩니다.</p>
<h3>문제 3: 스크롤바 때문에 100vw가 어긋난다</h3>
<p>여기까지 오면 꽤 그럴듯해 보이지만, 실전에서는 또 하나의 함정이 있습니다. 바로 스크롤바입니다. 대부분의 페이지에는 세로 스크롤바가 있고, 이 스크롤바가 고정형(fixed)일 경우 <code>100vw</code>는 스크롤바 너비를 포함하지 않습니다. 즉 요소는 실제로 스크롤바 안쪽 끝까지만 늘어나는데, <code>100vw</code>는 그보다 더 큰 값을 가리키기 때문에 요소가 절대 &quot;100vw에 도달&quot;하지 못하고, 결과적으로 radius가 완전히 0이 되는 순간이 오지 않게 됩니다.</p>
<p>다행히 이 문제는 비교적 최근 브라우저 기능으로 해결할 수 있습니다. <code>scrollbar-gutter: stable</code>을 사용하면 스크롤바가 차지하는 공간을 레이아웃 계산에 미리 반영해서, 고정 스크롤바가 있는 브라우저·OS 환경에서도 이 어긋남을 없앨 수 있습니다. 다만 브라우저 지원이 완벽하지는 않다는 점은 참고해야 합니다.</p>
<pre><code class="language-css">html {
  scrollbar-gutter: stable;
}</code></pre>
<h3>문제 4: 뷰포트가 아니라 부모 요소를 기준으로 감지하고 싶다면</h3>
<p>지금까지의 방식은 뷰포트 가장자리를 기준으로 동작합니다. 하지만 실제로는 뷰포트가 아니라 특정 부모 컨테이너의 가장자리에 닿았을 때 radius가 사라지길 원하는 경우가 더 많습니다. 이때는 부모 요소를 컨테이너 쿼리 컨테이너로 지정하고, <code>vw</code> 대신 컨테이너 쿼리 단위(<code>cqw</code>)를 사용하면 됩니다.</p>
<pre><code class="language-css">.parent {
  container-type: inline-size;
}

.element {
  border-radius: clamp(0px, calc(pow((100cqw - 100%), 2) * 1px), 50px);
}</code></pre>
<p>이 방식의 장점은, 만약 상위에 정의된 컨테이너가 없다면 컨테이너 쿼리 단위가 자동으로 뷰포트를 기준으로 대체되어 동작한다는 점입니다. 즉 컨테이너가 있든 없든 어떤 상황에서도 무리 없이 동작하는 유연한 코드가 됩니다.</p>
<h3>정리</h3>
<ul>
<li>요소가 커질수록 radius가 커지는 퍼센트 방식은 방향이 반대라 그대로 쓸 수 없고, <code>calc(100vw - 100%)</code>처럼 뷰포트 너비에서 요소 크기를 빼는 역산 공식을 쓰면 요소가 가장자리에 닿을수록 radius가 0에 가까워지는 동작을 만들 수 있습니다.</li>
<li>요소가 작아질 때 radius가 무한정 커지는 문제는 <code>clamp()</code>로 최댓값을 제한해 해결하고, 가장자리 근처에서 어중간하게 찌그러지는 전환 구간은 계산식에 지수를 넣어 값이 &quot;거의 0&quot;이거나 &quot;충분히 큰 값&quot; 둘 중 하나로만 수렴하도록 만들어 해결합니다.</li>
<li>고정 스크롤바가 있는 페이지에서는 <code>100vw</code>가 실제 요소 가용 너비와 어긋나므로, <code>scrollbar-gutter: stable</code>로 이 오차를 보정해줘야 합니다.</li>
<li>뷰포트가 아니라 특정 부모 요소를 기준으로 이 효과를 적용하고 싶다면 <code>container-type</code>과 컨테이너 쿼리 단위(<code>cqw</code>)를 사용하면 되고, 이 방식은 컨테이너가 없을 때도 뷰포트를 기준으로 자연스럽게 폴백됩니다.</li>
