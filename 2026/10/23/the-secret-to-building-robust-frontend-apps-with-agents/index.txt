14:T125d,<p>AI 에이전트에게 프론트엔드 코드를 맡겨본 개발자라면 한 번쯤 느꼈을 겁니다. 에이전트가 작성한 React 컴포넌트는 처음엔 잘 동작하는 것 같다가도, 조금만 복잡한 상태가 얽히면 금세 엣지 케이스를 놓치고 버그투성이가 되곤 합니다. Matt Pocock은 이 문제를 해결하는 데 리듀서(reducer)와 상태 머신(state machine) 패턴이 놀라울 정도로 효과적이라고 말합니다. 이 글에서는 왜 리듀서 패턴이 에이전트와 함께 일할 때 특히 빛을 발하는지 살펴보겠습니다.</p>
<h3>리듀서가 하는 일</h3>
<p>리듀서는 간단히 말하면 지속적인 상태(persistent state)와, 그 상태를 변화시키는 일련의 액션(action)으로 구성됩니다. 예를 들어 카메라 썸네일 기능을 다룬다고 하면 다음과 같은 액션들이 있을 수 있습니다.</p>
<pre><code class="language-ts">// 액션 예시
{ type: 'OPEN_CAMERA' }
{ type: 'CLOSE_CAMERA' }
{ type: 'PHOTO_CAPTURED' }</code></pre>
<p>이 액션들은 전부 프론트엔드 UI에서 실제로 발생할 수 있는 이벤트입니다. 사용자가 버튼을 눌렀을 때, 혹은 어떤 작업이 실패했을 때 트리거될 수 있는 것들이죠. 리듀서는 이런 액션을 입력으로 받아서 새로운 상태를 반환하는 함수일 뿐입니다. 아주 기본적인 수준에서 보면 이런 식입니다.</p>
<pre><code class="language-ts">// OPEN_CAMERA 액션이 들어오면
{ cameraOpen: true }

// CLOSE_CAMERA 액션이 들어오면
{ cameraOpen: false }</code></pre>
<h3>UI와 로직을 분리한다는 것의 의미</h3>
<p>이 패턴의 핵심은 사용자 인터페이스와 그 UI를 제어하는 로직을 완전히 분리한다는 데 있습니다. 예를 들어 <code>thumbnailStateReducer</code> 같은 함수가 있다면, 이 함수는 브라우저 바깥에서 독립적으로 테스트할 수 있습니다. 실제 UI를 렌더링하거나 DOM을 조작할 필요 없이 순수한 함수 입출력만으로 검증이 가능하기 때문에, 테스트 속도도 매우 빠릅니다.</p>
<p>그 결과 실제 화면 쪽 코드는 정말 단순해집니다. 썸네일 페이지에서 버튼을 클릭하면 단순히 <code>onClick</code>에서 <code>dispatch(OPEN_CAMERA)</code>를 호출하는 식이죠. React 컴포넌트 자체는 아무런 판단도 하지 않는, 말 그대로 &quot;멍청한&quot; 코드가 됩니다. 프론트엔드 로직 대부분이 리듀서라는 한 곳에 집중되기 때문에, 전체 로직을 테스트하기도 쉽고 수정하기도 쉬우며, 모든 상태 전환이 어떻게 맞물려 돌아가는지 한눈에 파악하기도 쉬워집니다.</p>
<h3>에이전트와 함께 쓸 때 체감되는 차이</h3>
<p>Matt는 에이전트가 수정한 코드에 리듀서가 들어있는 페이지를 작업할 때 확연한 차이를 느낀다고 말합니다. 리듀서 기반으로 짜인 코드는 전체적으로 훨씬 견고하게 느껴지고, 대부분의 엣지 케이스가 이미 처리되어 있다는 인상을 받는다는 것입니다. 이는 리듀서라는 구조 자체가 &quot;어떤 상태에서 어떤 액션이 들어왔을 때 어떻게 반응해야 하는가&quot;를 명시적으로 나열하도록 강제하기 때문입니다. 에이전트 입장에서도 이런 명시적인 구조가 있으면 누락된 케이스를 찾아내거나 새로운 케이스를 추가하기가 훨씬 수월해집니다.</p>
<p>이런 경험 때문에 그는 이미 진행 중이던 과거 프로젝트들을 다시 열어서 리듀서의 개수를 적극적으로 늘리고 있다고 밝혔습니다. 상태와 로직이 뒤섞여 컴포넌트 안에 흩어져 있던 코드를, 리듀서라는 단일 지점으로 모으는 리팩토링을 진행하고 있는 셈입니다.</p>
<h3>정리</h3>
<ul>
<li>리듀서는 지속적인 상태와 그 상태를 바꾸는 액션들의 집합으로 구성되며, 액션이 들어오면 새로운 상태를 반환하는 순수 함수입니다.</li>
<li>리듀서를 쓰면 UI와 로직이 분리되어, 리듀서 함수만 따로 브라우저 밖에서 빠르게 테스트할 수 있습니다.</li>
<li>UI 컴포넌트는 <code>dispatch</code>만 호출하는 단순한 역할로 남고, 실제 로직은 리듀서 한 곳에 집중되어 테스트·수정·전체 파악이 쉬워집니다.</li>
<li>AI 에이전트가 코드를 수정할 때도 리듀서 구조가 있으면 엣지 케이스 처리가 훨씬 견고해지는 것을 체감할 수 있으며, 이는 기존 프로젝트에 리듀서를 추가로 도입할 만한 이유가 됩니다.</li>
