via React Blog
🔥오늘의 화제frontend

React 팀이 지난주 공개한 치명적 RCE 취약점(React2Shell) 패치 검증 과정에서 서비스 거부(DoS, CVSS 7.5)와 소스 코드 노출(CVSS 5.3) 취약점이 추가로 발견됐습니다. react-server-dom-webpack/parcel/turbopack의 19.0.0~19.2.3 버전이 영향을 받으며, 안전 버전은 19.0.4, 19.1.5, 19.2.4입니다. 이전 패치(19.0.3, 19.1.4, 19.2.3)를 이미 적용했더라도 불완전했으므로 재업데이트가 필요하며, DoS 패치는 2026년 1월 26일 한 차례 더 보완되었습니다.

💡

RSC는 왜 번들러와 통합될까?
via Dan Abramov (overreacted)
frontend

React Server Components는 단순한 데이터 직렬화가 아니라 상호작용 가능한 컴포넌트의 코드 자체를 서버에서 클라이언트로 전송해야 합니다. Dan Abramov는 이 글에서 모듈을 직렬화하는 여러 방식의 한계를 짚고, 결국 번들링이 필요한 이유와 Parcel·Webpack·Vite 바인딩이 수행하는 세 가지 역할(빌드 시 청크 생성, 서버의 모듈 참조 생성, 클라이언트의 모듈 로딩)을 설명합니다. 마지막으로 react-server-dom-* 패키지가 제공하는 serialize/deserialize API와 Parcel의 renderRSC/fetchRSC 예시를 통해 실제 구현 수준까지 살펴봅니다.

💡
RSC를 도입하거나 커스텀 번들러 통합을 다뤄야 하는 프론트엔드 개발자에게, 이 직렬화/역직렬화와 번들러 바인딩 구조를 이해하는 것은 RSC 동작을 디버깅하고 최적화하는 데 핵심적인 토대가 됩니다.

via Hacker News (Top)
frontend

한 개발자가 상용 SaaS 제품 marketyour.games를 C 언어와 CGI, SQLite만으로 구축한 경험을 공유합니다. OpenBSD의 BCHS 스택(OpenBSD, C, httpd, SQLite)을 사용해 프레임워크, 템플릿 엔진, 컨테이너, 별도 DB 서버 없이 결제·이메일·인증 기능을 갖춘 제품을 만들었고, 빌드 의존성은 libcurl과 libsodium 단 두 개뿐입니다. 2004년에 표준화된 뒤 변하지 않은 CGI 명세와 현대 커널의 프로세스 포킹 최적화 덕분에, CGI를 버린 2000년대 초반의 이유들이 더 이상 유효하지 않다고 주장합니다.

💡

via Kevin Powell (CSS)
▶영상frontend

Kevin Powell이 Adam Argyle과 함께 진행한 'CSS 패스트 머니' 퀴즈 코너로, 좋아하는 색상 값·색상 포맷·CSS 속성·단위·항상 찾아보는 속성에 대해 즉석에서 답하고 이를 커뮤니티 설문 결과와 비교합니다. OKLCH가 색상 포맷 1위를 차지하고, display가 선호 속성 1위, rem이 선호 단위 1위, grid가 가장 문법을 헷갈리는 속성 1위로 꼽히는 등 흥미로운 결과가 나왔습니다. Rebecca Purple이 색상 값 1위를 차지한 점도 눈에 띕니다.
