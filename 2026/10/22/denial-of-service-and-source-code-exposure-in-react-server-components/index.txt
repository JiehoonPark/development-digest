18:T2fad,<p>React 팀이 지난주 발표한 치명적 보안 취약점(React2Shell로 불리는 원격 코드 실행 취약점) 패치를 검증하는 과정에서, 보안 연구자들이 그 패치 자체를 우회하려는 시도를 하다가 React Server Components(RSC)에서 두 가지 추가 취약점을 발견했습니다. 다행히 이번 취약점들은 원격 코드 실행(RCE)으로 이어지지는 않으며, 기존 React2Shell 패치는 여전히 유효합니다. 하지만 서비스 거부(DoS)와 소스 코드 노출이라는 별도의 심각한 문제가 확인된 만큼, RSC를 사용하는 프로젝트라면 반드시 최신 버전으로 업데이트해야 합니다.</p>
<h3>새로 공개된 취약점 개요</h3>
<p>이번에 공개된 취약점은 두 종류입니다.</p>
<ul>
<li><strong>서비스 거부(DoS) - 심각도 High</strong>: CVE-2025-55184, CVE-2025-67779, CVE-2026-23864 (CVSS 7.5)</li>
<li><strong>소스 코드 노출 - 심각도 Medium</strong>: CVE-2025-55183 (CVSS 5.3)</li>
</ul>
<p>심각도를 고려할 때 즉시 업그레이드할 것을 권장합니다.</p>
<p>여기서 중요한 점은, 이전에 공개됐던 패치(19.0.3, 19.1.4, 19.2.3)가 <strong>불완전</strong>했다는 사실입니다. 즉 지난주 공지에 따라 이미 업데이트를 마쳤더라도, 다시 한번 업데이트가 필요합니다. 업그레이드 절차는 이전 공지 글에 안내된 내용을 그대로 따르면 됩니다.</p>
<h3>즉시 조치가 필요한 범위</h3>
<p>이번 취약점들은 CVE-2025-55182(지난주 공개된 RCE 취약점)과 동일한 패키지, 동일한 버전 범위에 존재합니다. 영향을 받는 버전은 다음과 같습니다.</p>
<ul>
<li><code>react-server-dom-webpack</code></li>
<li><code>react-server-dom-parcel</code></li>
<li><code>react-server-dom-turbopack</code></li>
</ul>
<p>위 패키지들의 19.0.0, 19.0.1, 19.0.2, 19.0.3, 19.1.0, 19.1.1, 19.1.2, 19.1.3, 19.2.0, 19.2.1, 19.2.2, 19.2.3 버전이 모두 영향을 받습니다. 수정 사항은 19.0.4, 19.1.5, 19.2.4 버전에 백포트됐으니, 위 패키지를 사용 중이라면 즉시 해당 버전으로 업그레이드해야 합니다.</p>
<p>지난번과 마찬가지로, 앱의 React 코드가 서버를 사용하지 않는다면 이번 취약점의 영향을 받지 않습니다. 또한 RSC를 지원하는 프레임워크, 번들러, 번들러 플러그인을 사용하지 않는 앱 역시 영향권 밖입니다.</p>
<p>React 팀은 다음과 같이 설명합니다. 치명적인 CVE가 공개되면 보안 연구자들이 관련 코드 경로를 면밀히 살펴보며 초기 완화 조치를 우회할 수 있는 변종 공격 기법을 찾는 일이 흔하다는 겁니다. 이는 JavaScript 생태계만의 문제가 아니라 업계 전반에서 반복되는 패턴으로, 예컨대 Log4Shell 사태 이후에도 커뮤니티가 최초 패치를 검증하는 과정에서 추가 CVE들이 보고된 바 있습니다. 후속 취약점 공개가 당혹스러울 수 있지만, 이는 일반적으로 대응 체계가 건강하게 작동하고 있다는 신호로 볼 수 있습니다.</p>
<h3>영향을 받는 프레임워크와 번들러</h3>
<p>일부 React 프레임워크와 번들러는 취약한 React 패키지를 직접 의존하거나, peer dependency로 가지고 있거나, 내부에 포함하고 있습니다. 영향을 받는 프레임워크와 번들러는 다음과 같습니다.</p>
<p><code>next</code>, <code>react-router</code>, <code>waku</code>, <code>@parcel/rsc</code>, <code>@vite/rsc-plugin</code>, <code>rwsdk</code></p>
<p>업그레이드 절차는 역시 이전 공지 글을 참고하면 됩니다.</p>
<h3>호스팅 제공업체의 임시 완화 조치</h3>
<p>지난번과 동일하게, React 팀은 여러 호스팅 제공업체와 협력해 임시 완화 조치를 적용했습니다. 다만 이는 어디까지나 임시방편이므로, 이에 의존하지 말고 반드시 직접 업데이트를 진행해야 합니다.</p>
<h3>React Native 사용자를 위한 안내</h3>
<p>React Native를 모노레포 없이 사용하고 <code>react-dom</code>을 쓰지 않는 경우라면, <code>package.json</code>에 React 버전이 고정(pinned)되어 있을 것이므로 별도 조치가 필요 없습니다.</p>
<p>반면 React Native를 모노레포 환경에서 사용 중이라면, 아래 패키지가 설치되어 있는지 확인하고 해당 패키지만 업데이트해야 합니다.</p>
<ul>
<li><code>react-server-dom-webpack</code></li>
<li><code>react-server-dom-parcel</code></li>
<li><code>react-server-dom-turbopack</code></li>
</ul>
<p>이 패키지들만 업데이트하면 되고, <code>react</code>와 <code>react-dom</code>까지 업데이트할 필요는 없으므로 React Native에서 흔히 발생하는 버전 불일치 오류는 걱정하지 않아도 됩니다. 자세한 내용은 관련 이슈를 참고하기 바랍니다.</p>
<h3>CVE-2026-23864: 추가로 발견된 다중 DoS 취약점</h3>
<ul>
<li><strong>Base Score</strong>: 7.5 (High)</li>
<li><strong>공개일</strong>: 2026년 1월 26일</li>
</ul>
<p>보안 연구자들은 기존 RSC 패치에도 불구하고 여전히 추가적인 DoS 취약점이 남아 있음을 발견했습니다. 이 취약점은 특별히 조작된 HTTP 요청을 Server Function 엔드포인트로 보내는 방식으로 트리거되며, 취약한 코드 경로와 애플리케이션 설정, 코드 구성에 따라 서버 크래시, 메모리 부족(OOM) 예외, 과도한 CPU 사용 등을 유발할 수 있습니다.</p>
<p>1월 26일 공개된 패치가 이 DoS 취약점들을 완화합니다. 특히 주목할 점은, CVE-2025-55184를 해결하기 위해 애초에 발표됐던 패치가 <strong>불완전했다</strong>는 사실입니다. 이로 인해 이전 버전들이 여전히 취약한 상태로 남아 있었으며, 19.0.4, 19.1.5, 19.2.4 버전만이 안전합니다.</p>
<h3>CVE-2025-55184, CVE-2025-67779: 서비스 거부(DoS)</h3>
<ul>
<li><strong>Base Score</strong>: 7.5 (High)</li>
</ul>
<p>보안 연구자들은 임의의 Server Functions 엔드포인트로 악의적인 HTTP 요청을 조작해 전송하면, React가 이를 역직렬화(deserialize)하는 과정에서 무한 루프가 발생해 서버 프로세스가 멈추고 CPU를 소진하게 된다는 사실을 발견했습니다. 주목할 점은, 앱이 React Server Function 엔드포인트를 전혀 구현하지 않았더라도 RSC를 지원하는 한 여전히 이 취약점에 노출될 수 있다는 것입니다.</p>
<p>이는 공격자가 사용자의 서비스 접근을 차단하고, 서버 환경의 성능에 영향을 미칠 수 있는 공격 경로를 만들어 냅니다. 오늘 발표된 패치는 무한 루프를 방지함으로써 이를 완화합니다.</p>
<h3>CVE-2025-55183: 소스 코드 노출</h3>
<ul>
<li><strong>Base Score</strong>: 5.3 (Medium)</li>
</ul>
<p>한 보안 연구자는 취약한 Server Function으로 악의적인 HTTP 요청을 보내면 해당 Server Function의 소스 코드가 안전하지 않은 방식으로 반환될 수 있다는 사실을 발견했습니다. 이 취약점을 악용하려면, 인자(argument)를 명시적으로든 암묵적으로든 문자열화(stringify)해서 노출하는 Server Function이 존재해야 합니다. 예를 들어 다음과 같은 코드가 있다고 해보겠습니다.</p>

<h3>정리</h3>
<ul>
<li>지난주 발표된 React2Shell(RCE) 패치 자체는 여전히 유효하지만, 그 패치를 검증하는 과정에서 DoS 취약점 3건(CVE-2025-55184, CVE-2025-67779, CVE-2026-23864)과 소스 코드 노출 취약점 1건(CVE-2025-55183)이 추가로 발견됐습니다.</li>
<li><code>react-server-dom-webpack</code>, <code>react-server-dom-parcel</code>, <code>react-server-dom-turbopack</code>의 19.0.x(~19.0.3), 19.1.x(~19.1.3), 19.2.x(~19.2.3) 버전이 모두 영향을 받으며, 19.0.4 / 19.1.5 / 19.2.4로 업그레이드해야 안전합니다.</li>
<li>지난주 공지에 따라 이미 19.0.3, 19.1.4, 19.2.3으로 업데이트했더라도 그 패치는 <strong>불완전</strong>했으므로, 다시 한번 업데이트가 필요합니다.</li>
<li>DoS 취약점은 조작된 HTTP 요청이 역직렬화 과정에서 무한 루프를 유발해 서버를 마비시키는 방식이며, Server Function을 직접 구현하지 않았더라도 RSC를 지원하는 앱이라면 영향을 받을 수 있습니다.</li>
<li>소스 코드 노출 취약점은 Server Function의 인자를 문자열화해 반환하는 패턴이 있을 때, 함수 본문에 하드코딩된 시크릿까지 노출될 수 있다는 점에서 위험합니다. 런타임 환경 변수는 영향을 받지 않지만, 코드에 시크릿을 하드코딩하는 습관 자체를 점검할 필요가 있습니다.</li>
