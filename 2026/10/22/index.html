RSC는 왜 번들러와 통합되는가
via Dan Abramov (overreacted)
💡알면 좋은 정보frontend

React Server Components는 React 트리를 직렬화/역직렬화하는 두 패키지(react-server, react-client)로 구성되지만, 이들이 npm에 그대로 배포되지 않는 이유는 모듈 시스템 통합이 빠져있기 때문입니다. RSC는 데이터뿐 아니라 컴포넌트 코드 자체도 전송해야 하는데, 코드를 문자열로 직접 보내거나 파일 경로를 하나씩 참조하는 방식은 비효율적이거나 워터폴을 유발합니다. 이 문제를 해결하기 위해 RSC는 Parcel, Webpack, Vite 같은 번들러와 바인딩을 맺어 빌드 시 청크를 생성하고 서버-클라이언트 간 모듈 전송 방법을 정의합니다.

💡
RSC를 사용하는 Next.js, Parcel RSC 등의 프레임워크가 왜 특정 번들러에 강하게 의존하는지, 그리고 'use client' 경계가 빌드 과정에서 실제로 어떻게 처리되는지를 이해하는 데 필수적인 내부 동작 원리를 다룬다.

clamp()의 매직 넘버 문제, progress()로 해결하기
via Kevin Powell (CSS)
▶영상frontend

CSS clamp()로 유체 타이포그래피를 만들 때 중간값과 구간 설정이 매직 넘버가 되어 스케일 간 타이밍이 어긋나는 문제를 progress() 함수로 해결하는 방법을 다룹니다. progress()는 0~1 사이 단위 없는 값을 반환해 예측 가능한 최소/최대 범위를 만들 수 있고, pow()와 결합하면 지수적인 타입 스케일도 쉽게 구현할 수 있습니다. 아직 progress()의 브라우저 지원이 걱정된다면 tan(atan2()) 트릭으로 동일한 효과를 오늘 당장 적용할 수 있습니다.

💡
반응형 타이포그래피를 유지보수 가능한 CSS로 설계하는 방법을 제시하므로, 디자인 시스템이나 타입 스케일을 다루는 프론트엔드 개발자에게 실무적으로 바로 적용할 수 있는 패턴입니다.
