SVAR Gantt 2.8 출시: React·Svelte·Vue용 스케줄링 엔진 고도화와 실시간 협업 기능

SVAR Gantt v2.8 for React, Svelte, Vue: upgraded scheduling engine & live updates

📅 2026-10-22📰 Echo JS
frontendtypescript

SVAR 팀이 React, Vue, Svelte용 Gantt 차트 컴포넌트의 새 버전인 2.8을 발표했습니다. 이번 업데이트의 핵심은 스케줄링 엔진을 단순한 "표시 레이어"에서 실제 프로젝트 매니저가 다루는 스케줄링 시나리오를 처리할 수 있는 수준으로 끌어올렸다는 점인데요. 이 글에서는 SVAR Gantt PRO에 추가된 스케줄링 엔진 고도화 내용과 리소스 플래닝, 프로젝트 트래킹 기능, 그리고 무료 MIT 에디션에 추가된 기능까지 순서대로 정리해보겠습니다.

업그레이드된 스케줄링 엔진

2.8 버전에서 가장 큰 변화는 자동 스케줄링(auto-scheduling) 로직의 전면 개편입니다.

네 가지 의존성 타입 전체 지원

기존에는 Finish-to-Start(FS) 링크만 자동 스케줄링을 지원했지만, 이번 버전부터는 Start-to-Start(SS), Finish-to-Finish(FF), Start-to-Finish(SF)까지 네 가지 링크 타입 모두에서 자동 스케줄링이 동작합니다. 각 링크 타입에는 lag(지연 시간)도 적용할 수 있고, 네 가지 타입 모두 날짜·슬랙(slack)·크리티컬 패스 계산에 영향을 줍니다. 즉, 실제 프로젝트에서 흔히 발생하는 "작업이 겹치는" 상황을 그대로 반영할 수 있게 된 것입니다. 연결된 태스크가 변경되면 엔진이 종속 태스크의 날짜를 자동으로 재계산합니다.

수동(Manual) 태스크와 비활성(Inactive) 태스크

유연성을 높이기 위해 태스크를 자동 스케줄링 대상에서 제외하는 두 가지 모드가 추가됐습니다. Manual 태스크는 위치가 고정되어 자동 스케줄링이 절대 이동시키지 않지만, 사용자가 직접 드래그하는 것은 가능합니다. 이를 통해 이미 확정된 작업과 아직 계획 중인 작업을 구분할 수 있습니다.

Inactive 태스크는 취소되었거나 보류된 작업을 나타냅니다. inactiveTasks 기능을 켜면 그리드와 에디터에서 비활성 태스크를 지원하며, 특정 태스크를 비활성화하려면 inactive 필드를 true로 설정하면 됩니다. 비활성 처리된 태스크는 차트에는 계속 표시되지만 스케줄링, 크리티컬 패스, 리소스 부하, 진행률 추적 계산에서는 제외됩니다. 작업이 재개되면 다시 활성화할 수 있습니다.

스케줄링 제약조건(Constraints)

플래닝 도구라면 응당 지원해야 할 6가지 제약 타입이 추가됐습니다: "이 날짜 이후 시작(SNET)", "이 날짜 이전 시작(SNLT)", "반드시 이 날짜에 시작(MSO)", "이 날짜 이후 종료(FNET)", "이 날짜 이전 종료(FNLT)", "반드시 이 날짜에 종료(MFO)"입니다. 각 태스크의 constraint 필드에 snet, snlt, fnet, fnlt, mso, mfo 값과 날짜를 함께 지정하는 방식입니다.

이 제약조건들은 스케줄링 계산의 입력값으로 취급됩니다. schedule={{ auto: true }}로 자동 스케줄링을 켜면 링크뿐 아니라 제약조건까지 함께 고려해서 일정이 짜이므로, 납기일이나 계약상 마일스톤을 기준으로 플랜이 수립되고 수동으로 조정할 필요가 줄어듭니다. 제약조건은 다른 태스크 데이터처럼 서버에 저장되기 때문에 새로고침해도 유지되고 프로젝트와 함께 이동합니다.

스케줄링 충돌 처리

제약조건이나 링크가 충족될 수 없는 상황이 발생하면, 이제 사용자가 원인을 추측할 필요가 없습니다. 충돌 목록(conflict list)에 어떤 태스크가 영향을 받았고 무엇이 막고 있는지 표시되며, 원클릭으로 태스크 재조정, 이동, 제약조건 삭제, 링크 삭제 중 하나를 선택해 바로 해결할 수 있습니다.

데드라인

각 태스크에는 데드라인을 설정할 수 있습니다. 이는 FNLT 제약조건과 달리 일정 자체를 구속하지 않는 목표 종료일입니다. 차트에 플래그로 표시되며, 태스크가 지연되면 경고 표시로 바뀌어 타임라인 상에서 바로 어떤 태스크가 기한을 놓칠지 확인할 수 있습니다. deadline 필드로 데드라인을 설정하고, deadlines 속성으로 차트에 데드라인 플래그를 활성화합니다.

수천 개 태스크에서도 빠른 성능

자동 스케줄링과 크리티컬 패스 계산 시나리오의 성능을 최적화했습니다. 이제 자동 스케줄링을 켠 상태에서도 수천 개의 태스크를 다루는 프로젝트에서 성능이 잘 유지됩니다. 사용자가 태스크를 드래그하면 연결된 모든 태스크가 재계산되어 함께 이동하는데, 의존성이 많은 대형 프로젝트에서도 드래그와 편집이 부드럽게 동작합니다. 실제로 10만 개 태스크 규모의 자동 스케줄링 데모도 제공됩니다.

리소스 플래닝 강화

리소스 기반 스케줄링

schedule.resourceCalendars로 활성화하는 리소스 기반 스케줄링도 동일한 엔진의 일부입니다. 태스크의 날짜는 태스크 캘린더(없으면 전역 캘린더로 대체)와 배정된 담당자들의 리소스 캘린더를 조합해 계산됩니다. 태스크 캘린더가 허용하는 날이면서 배정된 리소스 중 최소 한 명이라도 가용하면 작업이 진행되는 방식이라, 한 사람이 휴가를 가더라도 태스크 전체가 멈추지 않습니다.

리소스 히스토그램

히스토그램은 일종의 용량(capacity) 차트로, 과다 배정된 인력과 기간을 셀마다 흩어진 시간 숫자를 읽는 것보다 훨씬 빠르게 한눈에 파악할 수 있게 해줍니다. 툴팁이 제공되고 차트의 줌 레벨에 맞춰 조정되기 때문에, 프로젝트 기간을 다양한 단위로 봐도 업무량을 쉽게 이해할 수 있습니다.

드래그 앤 드롭 배정

목록이나 리소스 로드 뷰에서 사람을 태스크로 드래그해 배정할 수 있고, 태스크를 리소스 그룹 간에 이동시켜 재배정하는 것도 가능합니다. 태스크마다 폼을 입력하는 대신 몇 번의 드래그만으로 인력 배치가 끝나며, 배정 정보가 바로 스케줄링 엔진에 반영되기 때문에 작업하는 동안 날짜와 로드 뷰가 함께 업데이트됩니다.

프로젝트 트래킹과 편집 기능

진행률 라인(Progress Line)

각 태스크의 보고된 진행률을 오늘 또는 선택한 특정 날짜(상태 기준일)와 비교해주는 진행률 라인이 추가됐습니다. progressLine 속성으로 활성화하며, 어떤 태스크가 일정보다 앞서 있고 어떤 태스크가 뒤처져 있는지 한눈에 보여줘 프로젝트 전반의 상태를 빠르게 파악할 수 있습니다.

S-커브

sCurve 기능(scheduled, earned, baseline 세 가지 커브 타입)을 사용하면 누적 계획치, 실적치, 베이스라인 진행률을 타임라인 위에 곡선으로 표시할 수 있습니다. 각 곡선은 0%에서 100%까지 상승하며, 값은 호버 시 표시됩니다. 데이터를 따로 내보내 외부에서 차트를 그릴 필요 없이, 컴포넌트 안에서 계획과 실제를 프로젝트 전체 기간에 걸쳐 비교할 수 있습니다.

보조 그리드 패널

상태나 비용 같은 태스크 상세 정보를 메인 그리드의 컬럼이 아니라 타임라인 오른쪽의 별도 그리드 패널(section: "subGrid"로 지정하는 컬럼)에 표시할 수 있게 됐습니다. 덕분에 메인 태스크 테이블은 가독성을 유지하면서도 추가 필드를 바로 확인할 수 있습니다. 패널은 크기 조절, 축소, 숨김이 가능하며 좁은 화면에서도 레이아웃이 자연스럽게 적응합니다.

플레이스홀더 행

이제 그리드 맨 아래에 플레이스홀더 행이 추가되어 태스크를 빠르게 추가할 수 있습니다. placeholderRow 속성을 켜면 실제 태스크들 아래에 빈 행이 생기는데, 사용자는 태스크 에디터를 열지 않고도 인라인 편집 가능한 그리드 셀을 채우거나, 차트에서 직접 드래그해서 태스크를 그리는 방식으로 새 태스크를 만들 수 있습니다. 기존에 지원하던 "드래그로 일정 그리기" 인터랙션이 아직 스케줄되지 않은 태스크에도 동일하게 적용되는 셈입니다.

리소스·배정 정보를 포함한 내보내기

PDF, PNG, Excel 내보내기와 MS Project 임포트/익스포트에 리소스와 배정 정보가 포함됩니다. 프로젝트 파일에 일정뿐 아니라 리소스 배정 정보까지 함께 담기기 때문에, 팀 구성을 수작업으로 다시 만들지 않고도 다른 도구로 프로젝트를 옮길 수 있습니다.

무료 오픈소스 에디션에 추가된 기능

MIT 라이선스로 제공되는 무료 에디션에도 세 가지 주요 기능이 추가됐습니다.

포함형 종료일(Inclusive End Dates)

기본적으로 SVAR Gantt는 태스크 종료일을 "다음 날의 시작"으로 표시해왔습니다. 새로 추가된 inclusiveEnd 속성을 사용하면 비즈니스 사용자들이 날짜를 세는 방식대로 태스크를 표시할 수 있는데요, 월요일에 시작하는 5일짜리 태스크를 "월요일부터 토요일까지"가 아니라 "월요일부터 금요일까지"로 보여줄 수 있습니다. 이 규칙은 그리드, 태스크 에디터, 툴팁에도 동일하게 적용됩니다.

외부에서 태스크 드래그하기

외부 태스크 목록이 있다면 이를 Gantt 차트로 드래그해서 백로그 항목을 계획된 작업으로 바꿀 수 있습니다. 드롭된 태스크는 드롭 대상이 된 태스크 옆에 배치되며, 대상이 요약(summary) 태스크라면 그 안에 배치됩니다. 태스크를 다시 입력하거나 링크를 재구성할 필요 없이 백로그가 곧바로 플랜이 되는 셈입니다.

서버 실시간 업데이트

이번 릴리스에서 새로 도입된 RemoteEvents 서비스는 다른 사용자가 저장한 변경 사항을 Gantt 차트에 실시간으로 반영해, 협업 작업을 가능하게 합니다. 여러 사용자가 동시에 같은 프로젝트를 편집하면서 페이지 새로고침 없이 서로의 변경 사항을 실시간으로 확인할 수 있습니다. 연결이 끊어지면 이벤트 스트림이 자동으로 재연결을 시도하고 데이터를 다시 불러와야 한다는 신호를 보내기 때문에, 네트워크가 불안정한 환경에서도 세션이 유지됩니다.

설치 및 체험

SVAR Gantt는 React, Vue, Svelte 세 가지 버전 모두 GitHub에 공개되어 있습니다. 무료 MIT 에디션은 다음과 같이 npm으로 설치할 수 있습니다.

npm install @svar-ui/react-gantt
npm install @svar-ui/vue-gantt
npm install @svar-ui/svelte-gantt

PRO 에디션은 네 가지 링크 타입 전체 지원, 6가지 제약조건 타입, 데드라인, 리소스 캘린더 기반 날짜 계산을 포함한 업그레이드된 스케줄링 엔진을 제공하며, 30일 무료 체험판으로 사용해볼 수 있습니다.

정리

SVAR Gantt 2.8은 "보여주는" 간트 차트에서 "계산하는" 스케줄링 엔진으로의 전환을 보여주는 업데이트입니다.

  • 스케줄링 엔진 고도화: FS뿐 아니라 SS, FF, SF까지 네 가지 링크 타입 전체에서 자동 스케줄링과 크리티컬 패스 계산이 동작하고, 6가지 제약조건과 리소스 캘린더 기반 스케줄링까지 지원하면서 실제 PM 업무에 필요한 로직을 대부분 커버합니다.
  • 대규모 프로젝트 대응: 자동 스케줄링과 크리티컬 패스 계산 성능을 최적화해 10만 개 태스크 규모에서도 드래그·편집이 부드럽게 동작합니다.
  • 리소스 플래닝 실용성 강화: 리소스 히스토그램과 드래그 앤 드롭 배정으로 과다 배정을 시각적으로 즉시 확인하고, 몇 번의 드래그만으로 인력을 재배치할 수 있습니다.
  • 협업 지원: RemoteEvents 기반 실시간 업데이트로 다중 사용자 편집과 네트워크 재연결까지 지원해, 단일 사용자용 도구를 넘어 팀 협업 도구로 확장됐습니다.
  • 무료 에디션도 함께 개선: 포함형 종료일, 외부 드래그, 실시간 업데이트 등은 MIT 라이선스로도 사용할 수 있어, PRO 전환 없이도 체감 가능한 개선을 얻을 수 있습니다.
