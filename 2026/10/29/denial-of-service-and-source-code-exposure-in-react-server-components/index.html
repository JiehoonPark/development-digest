React Server Components, RCE 패치 이후 DoS·소스 코드 노출 취약점 추가 발견

Denial of Service and Source Code Exposure in React Server Components

📅 2026-10-29📰 React Blog
frontend

React 생태계에 또 한 번 보안 경보가 울렸습니다. 지난주 공개된 React Server Components(RSC)의 치명적 원격 코드 실행(RCE) 취약점 — 일명 "React2Shell" — 패치를 검증하던 보안 연구자들이, 그 패치 자체를 우회하려는 과정에서 두 건의 추가 취약점을 발견했습니다. 다행히 이번에 새로 발견된 취약점들은 RCE로 이어지지는 않으며, 기존 React2Shell 패치는 여전히 유효합니다. 다만 서비스 거부(DoS)와 소스 코드 노출이라는 별개의 위험이 있어 즉각적인 추가 업데이트가 필요합니다.

무엇이 공개되었나

이번에 공개된 취약점은 다음 두 종류입니다.

  • 서비스 거부(DoS) - 심각도 High: CVE-2025-55184, CVE-2025-67779, CVE-2026-23864 (CVSS 7.5)
  • 소스 코드 노출 - 심각도 Medium: CVE-2025-55183 (CVSS 5.3)

React 팀은 심각도를 고려해 즉시 업그레이드할 것을 권고하고 있습니다. 특히 주의할 점은, 이전 포스트에서 안내했던 19.0.3, 19.1.4, 19.2.3 버전의 패치가 불완전했다는 사실입니다. 즉 이전 취약점 대응으로 이미 업데이트를 마쳤더라도, 다시 한번 업데이트해야 합니다.

영향받는 패키지와 버전

이번 취약점들은 지난주 공개된 CVE-2025-55182와 동일한 패키지·버전에 존재합니다. 대상 버전은 19.0.0, 19.0.1, 19.0.2, 19.0.3, 19.1.0, 19.1.1, 19.1.2, 19.1.3, 19.2.0, 19.2.1, 19.2.2, 19.2.3이며, 해당되는 패키지는 다음과 같습니다.

  • react-server-dom-webpack
  • react-server-dom-parcel
  • react-server-dom-turbopack

수정 사항은 19.0.4, 19.1.5, 19.2.4에 백포트되었습니다. 위 패키지를 사용 중이라면 즉시 이 버전들 중 하나로 업그레이드해야 합니다.

기존과 마찬가지로, 앱의 React 코드가 서버를 사용하지 않는다면 이번 취약점의 영향을 받지 않습니다. 또한 RSC를 지원하는 프레임워크, 번들러, 번들러 플러그인을 사용하지 않는다면 역시 영향이 없습니다.

영향을 받는 프레임워크와 번들러 목록은 next, react-router, waku, @parcel/rsc, @vite/rsc-plugin, rwsdk입니다. 이들 중 취약한 React 패키지에 의존하거나, peer dependency로 포함하거나, 내장하고 있던 경우가 해당됩니다.

> 참고: 치명적인 CVE가 공개된 이후 후속 취약점이 발견되는 것은 업계에서 흔히 나타나는 패턴입니다. 중대한 취약점이 공개되면 연구자들은 인접한 코드 경로를 면밀히 조사하며 초기 완화 조치를 우회할 수 있는 변종 공격 기법을 탐색합니다. 이는 JavaScript 생태계만의 현상이 아니라, 예를 들어 Log4Shell 사태 이후에도 추가 CVE들이 보고되며 커뮤니티가 최초 수정안을 검증했던 것과 같은 맥락입니다. 추가 공개가 번거로울 수는 있지만, 대체로 건강한 대응 주기의 신호로 볼 수 있습니다.

호스팅 제공업체 완화 조치 및 React Native

React 팀은 기존과 마찬가지로 여러 호스팅 제공업체와 협력해 임시 완화 조치를 적용했습니다. 다만 이 조치에만 의존해서는 안 되며, 반드시 직접 업데이트를 진행해야 합니다.

React Native 사용자 중 모노레포를 사용하지 않거나 react-dom을 사용하지 않는 경우, package.json에 React 버전이 고정되어 있으므로 추가 조치가 필요 없습니다. 모노레포 환경에서 React Native를 사용 중이라면, 설치되어 있는 경우에 한해 react-server-dom-webpack, react-server-dom-parcel, react-server-dom-turbopack 패키지만 업데이트하면 됩니다. react와 react-dom까지 업데이트할 필요는 없으므로, React Native에서 흔히 발생하는 버전 불일치 오류를 일으키지 않습니다.

취약점 상세 분석

CVE-2026-23864 — 추가 DoS (High, CVSS 7.5)

1월 26일 공개된 이 취약점은, 보안 연구자들이 RSC에 여전히 존재하던 DoS 취약점을 추가로 발견한 사례입니다. 특별히 조작된 HTTP 요청을 Server Function 엔드포인트로 전송함으로써 서버 크래시, OOM(Out-of-Memory) 예외, 혹은 과도한 CPU 사용을 유발할 수 있습니다. 실제 영향 범위는 트리거된 취약한 코드 경로, 애플리케이션 설정, 애플리케이션 코드에 따라 달라집니다.

흥미로운 점은, 원래 CVE-2025-55184를 수정하기 위해 내놓았던 패치가 사실 불완전했다는 것입니다. 이로 인해 이전 버전들이 여전히 취약한 상태로 남아 있었고, 19.0.4, 19.1.5, 19.2.4 버전에서만 안전하게 수정되었습니다. 1월 26일 공개된 패치가 이 DoS 취약점들을 완화합니다.

CVE-2025-55184, CVE-2025-67779 — 서비스 거부 (High, CVSS 7.5)

보안 연구자들은 Server Functions 엔드포인트로 전송 가능한 악의적인 HTTP 요청을 조작해, React가 이를 역직렬화(deserialize)할 때 무한 루프를 유발하고 서버 프로세스를 멈추게 하며 CPU를 소진시킬 수 있다는 점을 발견했습니다. 중요한 점은, 애플리케이션이 명시적으로 React Server Function 엔드포인트를 구현하지 않았더라도, RSC를 지원하기만 하면 여전히 취약할 수 있다는 것입니다.

이는 공격자가 사용자의 서비스 접근을 차단하고, 서버 환경에 성능상 악영향을 미칠 수 있는 공격 경로를 만들어냅니다. 금번 패치는 무한 루프 발생을 원천 차단해 이를 완화합니다.

CVE-2025-55183 — 소스 코드 노출 (Medium, CVSS 5.3)

악의적인 HTTP 요청을 취약한 Server Function에 전송하면, 해당 Server Function의 소스 코드가 안전하지 않게 반환될 수 있다는 점이 발견되었습니다. 이 취약점이 성립하려면, 문자열화된 인자를 명시적으로든 암묵적으로든 노출하는 Server Function이 존재해야 합니다. 예를 들면 다음과 같은 코드입니다.

'use server';
export async function serverFunction(name) {
  const conn = db.createConnection('SECRET KEY');
  const user = await conn.createUser(name);
  return { id: user.id, message: `Hello, ${name}!` }
}

공격자는 다음과 같은 형태로 소스 코드를 유출시킬 수 있습니다.

0:{"a":"$@1","f":"","b":"Wy43RxUKdxmr5iuBzJ1pN"}
1:{"id":"tva1sfodwq","message":"Hello, async function(a){console.log(\"serverFunction\");let b=i.createConnection(\"SECRET KEY\");return{id:(await b.createUser(a)).id,message:`Hello, ${a}!`}}!"}

보시다시피 함수 본문에 하드코딩된 "SECRET KEY" 문자열이 그대로 노출되는 것을 확인할 수 있습니다. 오늘 공개된 패치는 Server Function의 소스 코드가 문자열화되는 것을 막아 이를 방지합니다.

다만 React 팀은 다음 사항을 분명히 안내하고 있습니다.

  • 노출될 수 있는 것은 소스 코드에 하드코딩된 시크릿뿐입니다. process.env.SECRET과 같은 런타임 시크릿은 영향을 받지 않습니다.
  • 노출 범위는 해당 Server Function 내부 코드로 한정되지만, 번들러의 인라이닝(inlining) 정도에 따라 다른 함수들까지 포함될 수 있습니다.
  • 반드시 프로덕션 번들을 기준으로 검증해야 합니다.

감사 인사

React 팀은 소스 코드 유출을 제보한 Andrew MacPherson(AndrewMohawk), DoS 취약점을 제보한 GMO Flatt Security Inc의 RyotaK, Bitforest Co., Ltd.의 Shinsaku Nomura에게 감사를 표했습니다. 또한 추가 DoS 취약점을 제보한 Winfunc Research의 Mufeed VH, Joachim Viide, GMO Flatt Security Inc의 RyotaK, Tencent Security YUNDING LAB의 Xiangwei Zhang에게도 감사 인사를 전했습니다.

정리

  • 지난주 공개된 RSC 치명적 RCE 취약점(React2Shell) 패치를 검증하던 과정에서, DoS 3건(CVE-2025-55184, CVE-2025-67779, CVE-2026-23864, CVSS 7.5)과 소스 코드 노출 1건(CVE-2025-55183, CVSS 5.3)이 추가로 발견되었습니다. RCE로 이어지지는 않지만 심각도가 높아 즉시 조치가 필요합니다.
  • 핵심 유의사항은 이전에 배포된 19.0.3, 19.1.4, 19.2.3 패치가 불완전했다는 점입니다. 이미 업데이트했더라도 19.0.4, 19.1.5, 19.2.4로 재업데이트해야 합니다.
  • 영향받는 패키지는 react-server-dom-webpack, react-server-dom-parcel, react-server-dom-turbopack이며, next, react-router, waku, @parcel/rsc, @vite/rsc-plugin, rwsdk 등 RSC를 지원하는 프레임워크·번들러를 사용 중이라면 간접적으로 영향을 받을 수 있습니다.
  • DoS 취약점은 Server Function 엔드포인트를 명시적으로 구현하지 않아도 RSC 지원 자체만으로 공격 대상이 될 수 있으므로, "우리는 Server Function을 안 쓴다"는 생각으로 안심해서는 안 됩니다.
  • 소스 코드 노출 취약점은 함수 인자를 문자열화해 반환하는 Server Function에서 발생하며, 소스에 하드코딩된 시크릿(예: API 키)이 노출될 위험이 있습니다. 시크릿은 환경 변수로 관리하고, 프로덕션 번들 기준으로 검증하는 습관이 필요합니다.
  • 호스팅 제공업체의 임시 완화 조치는 보조 수단일 뿐, 직접 패키지 업데이트가 유일하게 신뢰할 수 있는 해결책입니다.
💡
RSC를 사용하는 Next.js, React Router 등 프레임워크 기반 서비스를 운영 중인 프론트엔드/풀스택 개발자라면, 서비스 다운타임과 민감 정보(API 키 등) 유출로 직결될 수 있는 이번 취약점들을 즉시 점검하고 패치 버전으로 업그레이드해야 합니다.
