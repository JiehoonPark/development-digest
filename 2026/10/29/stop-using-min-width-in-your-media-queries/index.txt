18:T193b,<p>CSS 미디어 쿼리를 작성하다 보면 <code>min-width</code>, <code>max-width</code>를 조합해서 복잡한 조건을 만들어야 하는 순간이 많습니다. 특히 Bootstrap 소스코드를 열어보면 <code>767.98px</code>처럼 끝자리가 <code>.98</code>로 떨어지는 기이한 숫자들을 발견하게 되는데요. 이번 글에서는 이런 어색한 숫자가 왜 생기는지, 그리고 이를 말끔히 해결해주는 CSS 미디어 쿼리 범위 문법(Media Query Range Syntax)에 대해 정리해봅니다.</p>
<h3>왜 .98 같은 어색한 숫자가 필요했을까</h3>
<p>Bootstrap을 비롯한 많은 CSS 프레임워크의 미디어 쿼리를 보면 <code>max-width: 767.98px</code> 같은 값을 자주 보게 됩니다. 이런 소수점 값이 존재하는 이유는 크게 두 가지입니다.</p>
<p>첫째, 고해상도(DPI) 디스플레이 환경에서는 서브픽셀 단위의 값이 계산 과정에서 등장할 수 있습니다. 둘째, 브라우저 확대/축소(zoom) 시에도 예상치 못한 값이 튀어나오는 경우가 있습니다. 이런 환경에서 <code>min-width</code>와 <code>max-width</code> 구간이 정확히 맞물리지 않으면 두 미디어 쿼리 사이에 빈틈이 생기거나 반대로 겹쳐버리는 문제가 발생합니다. 그래서 개발자들은 안전하게 구간이 딱 맞아떨어지도록 하기 위해 일부러 이런 어색한 숫자를 끼워 넣어야 했습니다. 작동은 하지만, 누가 봐도 직관적이지 않은 해법이었던 셈이죠.</p>
<h3>CSS 미디어 쿼리 범위 문법의 등장</h3>
<p>이 문제는 사실 CSS 차원에서 이미 오래전에 해결되었습니다. 바로 <strong>미디어 쿼리 범위 문법</strong>(Media Query Range Syntax)입니다. 예전에도 이 문법을 다룬 영상이 있었지만, 당시에는 브라우저 지원이 충분치 않아 실무에 쓰기는 어려웠습니다. 하지만 이제는 상황이 달라졌습니다. 2023년 3월부터 모든 주요 브라우저에서 지원되면서 &quot;베이스라인(baseline)&quot; 수준, 즉 사실상 어디서나 쓸 수 있는 기능이 되었습니다.</p>
<p>이 문법을 쓰면 <code>min-width: 600px</code> 대신 아래처럼 부등호를 그대로 쓸 수 있습니다.</p>
<pre><code class="language-css">@media (width &gt; 600px) {
  /* ... */
}</code></pre>
<p>프로그래밍 배경이 있는 개발자라면 이 표기가 <code>min-width</code>보다 훨씬 직관적으로 느껴질 겁니다. 숫자와 부등호만 보면 조건이 바로 읽히니까요.</p>
<h3>min-width와 완전히 똑같이 쓰려면</h3>
<p>다만 한 가지 짚고 넘어가야 할 점이 있습니다. <code>min-width: 600px</code>은 600px을 <strong>포함</strong>하지만, <code>width &gt; 600px</code>은 600px을 포함하지 않습니다. 둘이 완전히 동일한 동작을 하길 원한다면 &quot;이상&quot;을 의미하는 비교 연산자를 쓰면 됩니다.</p>
<pre><code class="language-css">@media (width &gt;= 600px) {
  /* ... */
}</code></pre>
<p>이렇게 작성하면 기존의 <code>min-width: 600px</code>과 정확히 동일하게 동작합니다.</p>
<h3>범위(range) 조건 만들기</h3>
<p>Bootstrap 예제처럼 특정 구간만 타겟팅하고 싶을 때도 이 문법이 유용합니다. 사실 범위를 지정해야 하는 상황이 자주 있는 건 아니지만, 필요하다면 아래처럼 한 줄로 작성할 수 있습니다.</p>
<pre><code class="language-css">@media (567px &lt;= width &lt; 668px) {
  /* ... */
}</code></pre>
<p>이 코드는 &quot;너비가 567px 이상이면서 668px보다 작다&quot;는 의미입니다. 읽고 보면 논리적으로는 이해가 되지만, 막상 직접 작성하려고 하면 머릿속이 복잡해지는 게 사실입니다. 개인적으로는 이런 식으로 쓰는 걸 선호하지 않지만, 분명히 동작은 하는 문법입니다. 참고로 부등호와 등호를 섞는 방식은 자유롭게 조합할 수 있어서, 상황에 맞게 <code>&gt;</code>, <code>&gt;=</code>, <code>&lt;</code>, <code>&lt;=</code>를 원하는 대로 써도 됩니다.</p>
<h3>and로 조건을 나눠 쓰는 방법</h3>
<p>범위 문법의 한 줄짜리 표기가 부담스럽다면, 기존처럼 <code>and</code>로 조건을 나눠 쓰는 방법도 여전히 유효합니다.</p>
<pre><code class="language-css">@media (width &gt; 600px) and (width &lt; 900px) {
  /* ... */
}</code></pre>
<p>이 방식은 한 줄 범위 표기보다 읽기가 한결 편하면서도 동작은 동일합니다. 실제로 대부분의 개발자들은 익숙함과 가독성 때문에 이 <code>and</code> 방식을 선호할 가능성이 높습니다. 어떤 방식을 택하든 결과는 같으니, 본인이 더 편하게 읽고 쓸 수 있는 쪽을 고르면 됩니다.</p>
<h3>컨테이너 쿼리에서도 동일하게 적용</h3>
<p>이 범위 문법은 컨테이너 쿼리(container query)에서도 그대로 사용할 수 있습니다. 사실 두 기능은 함께 도입되었기 때문에, 컨테이너 쿼리를 지원하는 브라우저라면 이 범위 문법도 당연히 지원됩니다. 따라서 컨테이너 쿼리를 쓰는 환경이라면 굳이 <code>min-width</code>/<code>max-width</code> 조합을 고집할 이유 없이 이 새로운 문법을 적극적으로 사용해도 무방합니다.</p>
<h3>정리</h3>
<ul>
<li>Bootstrap 등에서 보이는 <code>767.98px</code> 같은 어색한 숫자는 고해상도 디스플레이의 서브픽셀 값이나 브라우저 줌으로 인한 간극 문제를 막기 위한 임시방편이었습니다.</li>
<li>CSS 미디어 쿼리 범위 문법(<code>width &gt; 600px</code>, <code>width &gt;= 600px</code> 등)은 2023년 3월부터 모든 주요 브라우저에서 지원되어 이제 실무에서 안심하고 쓸 수 있습니다.</li>
<li><code>min-width: 600px</code>과 완전히 동일하게 동작시키려면 <code>width &gt;= 600px</code>을 쓰면 됩니다.</li>
<li>범위 지정은 <code>567px &lt;= width &lt; 668px</code>처럼 한 줄로도 가능하지만 가독성이 떨어질 수 있으니, <code>(width &gt; 600px) and (width &lt; 900px)</code>처럼 <code>and</code>로 나눠 쓰는 편이 더 읽기 쉽습니다.</li>
<li>이 문법은 컨테이너 쿼리와 함께 도입되어 동일하게 지원되므로, 컨테이너 쿼리를 쓸 때도 그대로 적용 가능합니다.</li>
