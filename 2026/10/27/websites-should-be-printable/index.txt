13:T18e6,<h2>웹사이트는 인쇄 가능해야 한다</h2>
<p>요즘 종이 문서를 많이 읽는다는 개발자 Brennen Puth가 자신의 블로그를 CTRL-P로 인쇄해보고 충격을 받은 이야기를 풀어놓았습니다. 노트북 화면으로 읽는 것도 좋아하지만, 인쇄된 문서에 직접 마킹하며 읽을 때 집중이 훨씬 잘 된다는 그는, 자신이 쓴 글도 독자들이 원하는 매체로 편하게 즐길 수 있게 해주고 싶었다고 합니다. 이 글은 그 과정에서 발견한 문제와 CSS로 해결한 방법을 담고 있습니다.</p>
<h3>막상 인쇄해보니</h3>
<p>웹 디자인의 역사를 보면 인쇄 지원은 한때 꽤 중요한 주제였습니다. CTRL-P 한 번이면 프린터 드라이버가 협조해주는 한 어떤 웹페이지든 인쇄할 수 있죠. 저자는 별다른 작업 없이도 자기 블로그가 그럭저럭 인쇄될 거라 생각하고 테스트해봤는데, 결과는 기대 이하였습니다.</p>
<p>내용 자체는 다 보였지만:</p>
<ul>
<li>텍스트 크기가 2단계쯤 너무 컸고</li>
<li>헤더는 인쇄하면 흉하게 나왔으며</li>
<li>링크는 흑백으로 인쇄되니 희미한 회색으로 보여 &quot;도저히 봐줄 수 없는&quot; 수준이었습니다.</li>
</ul>
<h3>인쇄 가능하게 만들기</h3>
<p>다행히 웹 커뮤니티는 예전부터 HTML 페이지를 인쇄용으로 스타일링하는 방법을 CSS에 마련해두었습니다. <code>@media print</code> 같은 선택자를 활용하면 되는데, 저자가 실제로 자신의 페이지에 적용한 스니펫은 다음과 같습니다.</p>
<pre><code class="language-css">.onlyPrint {
  display: none;
}

@media print {
  .noPrint {
    display: none;
  }
  .onlyPrint {
    display: inline;
  }
  p,
  ol {
    font-size: 12pt;
  }
  h3, h4 {
    font-size: 13pt;
  }
  h2 {
    font-size: 14pt;
  }
  h1 {
    font-size: 16pt;
  }
  .giallo {
    border: 3px solid black;
  }
  .giallo-l {
    font-size: 11pt;
  }
  a {
    color: black !important;
  }
}</code></pre>
<p>이 스니펫이 하는 일을 순서대로 정리하면 다음과 같습니다.</p>
<ul>
<li><strong><code>onlyPrint</code></strong>: 인쇄본에만 등장하는 요소를 표시하는 클래스입니다. 저자는 이걸로 부제목 아래에 작은 저자 표기를 추가했습니다.</li>
<li><strong><code>noPrint</code></strong>: 인쇄본에서 제외할 요소를 숨기는 클래스입니다. 저자는 헤더가 인쇄하면 너무 보기 흉해서 이 클래스를 붙였습니다.</li>
<li><strong>폰트 크기 조정</strong>: 매우 중요한 부분입니다. 저자의 웹사이트는 가변 크기(variable-scale) 텍스트를 쓰는데, 이게 인쇄하면 아주 보기 안 좋았습니다. 12pt가 비교적 널리 받아들여지는 본문 크기라 이걸 기준으로 삼았고, 헤더는 조금 더 크게 잡았습니다.</li>
<li><strong><code>.giallo</code> / <code>.giallo-l</code> 조정</strong>: 코드 블록을 위한 설정입니다. 사실 이런저런 조정을 거친 뒤에도 코드 블록은 여전히 가장 보기 흉한 부분이라고 합니다. 코드 블록이 페이지 경계에서 잘리지 않고 한 덩어리로 나오길 원하는데, 아직 해결책을 찾지 못했다며 혹시 아는 사람이 있으면 알려달라고 적었습니다.</li>
<li><strong>링크 색상</strong>: 화면에서는 파란 링크를 좋아하지만, 흑백으로 인쇄하면 보기 흉합니다. 그래서 <code>a { color: black !important; }</code>로 다른 텍스트와 같은 색으로 맞췄습니다.</li>
</ul>
<p>저자는 이 CSS를 누구든 자유롭게 가져다 써도 좋다며, 더 많은 웹페이지가 인쇄를 고려해서 만들어지길 바란다고 덧붙였습니다.</p>
<h3>왜 이렇게까지 해야 할까</h3>
<p>이렇게 자신의 사이트를 최적화해보고 나서, 저자는 인쇄를 우선순위에 두지 않는 개발자들의 입장도 이해하게 됐다고 말합니다. 인쇄 시 보여줄 것과 숨길 것을 제대로 조정하는 데만 아침 시간을 상당히 썼고, 자신의 사이트는 그다지 복잡하지도 않은데 말이죠. 요즘 웹페이지를 정기적으로 인쇄하는 사람이 얼마나 될지도 의문이라며, 어쩌면 자기 혼자뿐일지도 모른다고 농담 섞어 말합니다.</p>
<p>그럼에도 불구하고, 웹사이트의 콘텐츠가 텍스트 위주라면 사람들이 선호하는 매체로 그 내용을 경험할 수 있게 해주는 것은 결코 나쁜 일이 아니라고 강조합니다. 디지털 매체는 유연성이 크고, 좋은 소프트웨어로 가는 길은 개발자가 사용자에게 베푸는 작은 친절들로 포장되어 있다는 겁니다. 언젠가 누군가는 이 친절을 발견하고 잠깐이나마 미소 지을 것이고, 그거면 충분히 가치 있다고 글을 맺습니다.</p>
<p>저자는 이후 2026년 10월 26일 수정 글을 통해, 이 포스트가 Hacker News와 lobste.rs 메인에 오른 사실을 친구에게 전해 들었다며 즐거워했습니다. CSS에 몇 가지 결함이 있다는 지적도 받았지만, 이 글이 더 많은 사람들이 인쇄라는 매체를 진지하게 고민하는 계기가 되길 바란다는 말로 마무리했습니다.</p>
<h3>정리</h3>
<ul>
<li>CTRL-P로 웹페이지를 인쇄했을 때 텍스트 크기, 헤더 디자인, 링크 색상 등이 화면용 스타일 그대로 나오면 가독성이 크게 떨어집니다.</li>
<li><code>@media print</code> 미디어 쿼리와 <code>onlyPrint</code>/<code>noPrint</code> 같은 유틸리티 클래스를 활용하면, 인쇄본 전용 요소를 추가하거나 화면용 요소(헤더 등)를 제거할 수 있습니다.</li>
<li>본문 12pt, 헤더는 13~16pt 수준으로 폰트 크기를 재조정하고, 링크 색상을 검정으로 바꾸는 것만으로도 인쇄 품질이 크게 개선됩니다.</li>
<li>코드 블록이 페이지 경계에서 끊기지 않고 한 덩어리로 출력되게 하는 문제는 저자도 명확한 해결책을 찾지 못한 미해결 과제로 남아 있습니다.</li>
<li>모든 사용자가 인쇄를 하는 건 아니지만, 텍스트 중심 콘텐츠라면 인쇄라는 매체까지 배려하는 것이 사용자를 향한 작은 친절이 될 수 있습니다.</li>
