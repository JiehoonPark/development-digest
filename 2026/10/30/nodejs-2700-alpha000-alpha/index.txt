18:T2746,<p>Node.js 27이 알파 버전으로 첫 모습을 드러냈습니다. 아직 정식 출시 전 단계지만, V8 엔진 메이저 업그레이드와 다수의 SEMVER-MAJOR(호환성 깨지는) 변경 사항이 포함되어 있어 미리 살펴볼 가치가 있는데요. 이번 글에서는 2026년 10월 29일 공개된 Node.js 27.0.0-alpha.0.0.0 릴리스 노트를 바탕으로, V8 업데이트 내용과 주요 Breaking Change들을 정리해보겠습니다.</p>
<h3>V8 15.6 업그레이드</h3>
<p>Node.js 26에서 사용되던 V8 14.6이 이번 버전에서 <strong>V8 15.6.75.13</strong>으로 올라갑니다. Joyee Cheung이 #65161, #66537, #66601 PR을 통해 주도한 작업이며, 변경 폭이 상당히 큽니다.</p>
<h4>기본 활성화되는 새 언어 기능</h4>
<p>별도 플래그 없이 바로 사용할 수 있는 기능들입니다.</p>
<ul>
<li><code>Math.sumPrecise()</code></li>
<li><code>Intl.Locale.prototype.variants</code></li>
<li><code>Iterator.prototype.join()</code></li>
<li><code>Iterator.prototype.includes()</code></li>
<li><code>Iterator.zip()</code>, <code>Iterator.zipKeyed()</code></li>
</ul>
<h4>플래그 뒤에 숨겨진 실험적 기능</h4>
<ul>
<li><code>import defer</code> — <code>--js-defer-import-eval</code></li>
<li>Immutable ArrayBuffer — <code>--js-immutable-arraybuffer</code></li>
<li>RegExp buffer boundaries — <code>--js-regexp-buffer-boundaries</code></li>
</ul>
<h4>메모리 관련 변경</h4>
<p><code>--max-old-space-size</code>를 지정하지 않으면, 기본 힙 크기 제한이 <strong>물리 메모리의 절반</strong>(256MB~4GB 사이로 clamp)으로 바뀝니다. 또한 <code>Buffer</code>와 <code>ArrayBuffer</code> 인스턴스가 차지하는 메모리도 이제 힙 제한에 포함되어 계산됩니다. 기존 기본값에 의존해서 메모리 설정을 하지 않았던 애플리케이션이라면, 이번 업그레이드 후 <code>--max-old-space-size</code>를 명시적으로 설정해두는 것이 안전합니다.</p>
<h4>직렬화 포맷 변경</h4>
<p><code>v8.serialize()</code>, <code>structuredClone()</code>, <code>postMessage()</code>가 새로운 직렬화 포맷을 사용합니다. 이 포맷은 구버전 Node.js에서는 읽을 수 없습니다. 또한 <code>v8.cachedDataVersionTag()</code>와 컴파일 캐시도 이제 V8 메이저 버전이 바뀔 때뿐 아니라 Node.js의 V8 패치 버전이 바뀔 때마다 함께 변경됩니다.</p>
<h4>관찰 가능한 동작 변화</h4>
<ul>
<li>Math 메서드들이 LLVM의 libm을 사용하게 되어, 마지막 비트 단위에서 결과가 달라질 수 있습니다.</li>
<li>동일한 <code>--random-seed</code>를 사용해도 <code>Math.random()</code> 시퀀스가 달라집니다.</li>
<li><code>error.stack</code>이 더 이상 프로토타입 체인을 통해 조회되지 않습니다.</li>
<li><code>await</code> 발생 시 마이크로태스크 수가 줄어듭니다.</li>
<li><code>Array.prototype.sort()</code>가 대용량 배열에서 PowerSort 알고리즘을 사용하며, 여전히 안정 정렬(stable sort)을 유지합니다.</li>
</ul>
<h4>힙 스냅샷과 WebAssembly</h4>
<p>힙 스냅샷에 내부 객체, 숫자 값, 전체 스크립트 소스가 포함되도록 바뀌면서, 스냅샷을 찍는 데 걸리는 시간이 약 2배, 파일 크기도 약 2배로 늘어납니다.</p>
<p>WebAssembly 쪽에서는 asm.js가 더 이상 WebAssembly로 컴파일되지 않으며, <code>--experimental-wasm-&lt;name&gt;</code> 형태의 플래그는 <code>--wasm-&lt;name&gt;</code>으로 이름이 바뀌었습니다.</p>
<p>V8 14.6에서 15.6 사이의 전체 변경 로그는 추후 별도로 공개될 예정입니다.</p>
<h3>암호화(Crypto)·OpenSSL 관련 대규모 정리</h3>
<p>이번 릴리스는 OpenSSL과 crypto 모듈에 대한 대대적인 정리 작업을 포함합니다. 대부분 Filip Skokan이 작업했습니다.</p>
<ul>
<li><strong>OpenSSL 4.1.0</strong>으로 업그레이드하며, 이제 <strong>OpenSSL 3 이상만 지원</strong>합니다(빌드 요구사항 변경).</li>
<li>번들된 FIPS provider 빌드가 제거되었습니다.</li>
<li>레거시 OpenSSL 코드 경로와 <code>ncrypto</code>의 레거시 OpenSSL 백엔드가 제거되었습니다.</li>
<li>OpenSSL 엔진(engine) 기반 지원이 <code>crypto</code>, <code>https</code>, <code>tls</code> 전반에서 종료됩니다.</li>
<li>digest의 출력 인코딩과 update의 입력 인코딩에 대한 유효성 검사가 추가되어, <code>Cipher</code>/<code>Decipher</code>의 <code>update()</code> 호출 시 <code>inputEncoding</code> 검증이 강화됩니다.</li>
<li>Web Crypto의 버퍼 파라미터에서 resizable backing store를 거부합니다.</li>
<li>초기화되지 않은 상태로 DH <code>computeSecret()</code>을 호출하면 예외가 발생합니다.</li>
<li><code>Hmac.digest()</code>를 두 번 이상 호출하는 것이 런타임 deprecated(DEP) 처리됩니다.</li>
<li>DEP0093, DEP0198, DEP0203, DEP0204가 End-of-Life 단계로 넘어갑니다.</li>
</ul>
<h3>HTTP / HTTP2 동작 변경</h3>
<p>HTTP 서버를 운영하는 입장에서 눈여겨볼 변경이 여러 건 있습니다.</p>
<ul>
<li>헤더 크기 제한을 초과하는 응답은 거부됩니다.</li>
<li><code>new</code> 없이 인스턴스화하는 것이 런타임 deprecated 처리됩니다.</li>
<li><strong>기본 <code>keepAliveTimeout</code>이 65초로 증가</strong>합니다(Tim Perry 기여, #62782).</li>
<li><code>req.headers</code>가 이제 null prototype을 갖게 됩니다.</li>
<li>요청이 끝난(finish) 이후 <code>addTrailers</code>를 호출하면 거부됩니다.</li>
<li>HTTP2의 기본 윈도우 크기가 증가합니다.</li>
</ul>
<h3>네트워크·DNS·파일시스템 변경</h3>
<ul>
<li><code>dgram</code>: 리터럴 IP 주소에 대해서는 커스텀 lookup을 건너뜁니다.</li>
<li><code>dns</code>: 역방향 조회(reverse lookup) 시 더 이상 hosts 파일을 참조하지 않습니다.</li>
<li><code>net</code>: family autoselection 시도가 경합(race) 방식으로 바뀌며, 동일 소켓에 <code>listen</code>을 여러 번 호출하면 예외가 발생합니다. 실험적인 <code>net/promises</code> API도 추가됩니다.</li>
<li><code>fs</code>: <code>glob</code>이 네이티브로 구현되며, <code>prefix</code>가 Buffer일 때 <code>mkdtemp</code>가 Buffer를 반환하도록 바뀝니다.</li>
</ul>
<h3>모듈 생명주기 관련 변경</h3>
<ul>
<li><code>domain</code> 모듈이 런타임 deprecated 처리되며, 내부적으로 <code>AsyncLocalStorage</code> 기반으로 포팅됩니다.</li>
<li><code>async_hooks</code>의 레거시 <code>AsyncLocalStorage</code> 구현이 제거됩니다.</li>
<li><code>test_runner</code>도 <code>async_hooks</code> 대신 <code>AsyncLocalStorage</code>를 사용하도록 바뀝니다.</li>
<li><code>tls</code>의 <code>_tls_*</code> 내부 모듈이 End-of-Life로 처리됩니다.</li>
<li><code>lib</code>의 <code>_http_*</code> 내부 모듈이 deprecated 처리됩니다.</li>
<li><code>zlib</code> 클래스들이 모던 문법으로 전환되며 DEP0184가 종료됩니다.</li>
<li><code>--no-experimental-websocket</code> CLI 플래그가 제거됩니다.</li>
</ul>
<h3>기타 주목할 변경</h3>
<ul>
<li><code>src,lib</code>: James M Snell이 <code>--allow-env</code> 권한 플래그를 추가했습니다(#66132). Node.js의 Permission Model이 환경 변수 접근까지 세밀하게 제어할 수 있도록 확장되는 흐름입니다.</li>
<li><code>build</code>: Intel macOS 지원이 experimental 단계로 다운그레이드됩니다.</li>
<li><code>repl</code>: <code>vm</code> 대신 inspector를 사용하도록 바뀝니다.</li>
<li><code>npm</code>이 <strong>12.1.0</strong>으로 업그레이드됩니다.</li>
<li><code>stream</code>: map iterator가 조기 종료될 때 source를 destroy하도록 수정됩니다.</li>
</ul>
<p>이 외에도 <code>SEMVER-MAJOR</code> 라벨이 붙은 커밋이 수십 건에 달하는데, 대부분 V8 업그레이드 작업을 위한 내부 빌드 패치(illumos 지원, Windows 빌드 수정, cherry-pick 등)와 OpenSSL 전환 관련 세부 작업들입니다.</p>
<h3>정리</h3>
<p>Node.js 27 알파는 V8 15.6으로의 메이저 업그레이드와 OpenSSL 3+/4.1.0 전환, 그리고 수십 건의 SEMVER-MAJOR 변경을 한꺼번에 담고 있는 무거운 릴리스입니다. 아직 알파 단계이므로 프로덕션 적용은 시기상조지만, 다음 사항들은 미리 체크해두는 것이 좋습니다.</p>
<ul>
<li><strong>메모리 설정</strong>: <code>--max-old-space-size</code>를 명시적으로 지정하지 않았다면, 힙 크기 기본값 계산 방식이 바뀌고 Buffer/ArrayBuffer도 힙 제한에 포함되므로 메모리 사용 패턴을 다시 점검해야 합니다.</li>
<li><strong>직렬화 호환성</strong>: <code>v8.serialize()</code>, <code>structuredClone()</code>, <code>postMessage()</code>의 포맷이 바뀌어 구버전 Node.js와 데이터를 주고받는 환경이라면 영향이 있을 수 있습니다.</li>
<li><strong>crypto/OpenSSL 의존 코드</strong>: OpenSSL 1.x를 전제로 한 코드나 엔진 기반 API, 레거시 인코딩 처리를 사용 중이라면 마이그레이션이 필요합니다.</li>
