자바스크립트 대신 CSS로 해결하는 6가지 기능

📅 2026-10-07📰 Kevin Powell (CSS)🎬 Video

자바스크립트 대신 CSS로 해결하는 6가지 기능

프론트엔드 개발을 하다 보면 자바스크립트로 해결하던 문제들이 사실은 CSS 한두 줄로 끝낼 수 있는 경우가 많습니다. 이번 글에서는 "너무 최신이라 실무에 못 쓴다"는 핀잔을 듣지 않을 만큼 브라우저 지원이 충분히 성숙한 CSS 기능들을 소개합니다. 모두 실무에서 바로 적용 가능한, 검증된 기능들입니다.

1. 스크롤 마진으로 스무스 스크롤 보정하기

scroll-behavior: smooth를 쓰면서 고정 헤더가 앵커 타겟을 가리는 문제를 자바스크립트로 오프셋을 계산해 해결하는 경우를 많이 봅니다. 하지만 이건 CSS만으로 충분합니다.

타겟 요소에 scroll-margin을 지정하면 됩니다. 예를 들어 scroll-margin-block(상하 여백)을 사용하면, 중간 섹션을 클릭했을 때 제목이 가려지지 않고 제대로 보이게 됩니다. 맨 아래로 이동할 때도 20의 viewport 마진이 일정하게 유지됩니다. ID를 섹션에 걸든 제목에 직접 걸든 똑같이 잘 동작합니다.

단, 스무스 스크롤을 쓸 거라면 prefers-reduced-motion 미디어 쿼리로 감싸주는 것이 좋습니다. 모션을 끈 사용자에게는 스크롤이 즉시 점프하되, scroll-margin은 그대로 유지되어 타겟 제목이 가려지지 않습니다. 전정기관 문제가 있는 사용자가 멀미를 느끼지 않도록 배려하는 차원입니다.

브라우저 지원도 훌륭합니다. scroll-behavior는 4년 넘게 지원되었고, :target은 거의 태초부터 존재했던 기능이라 안심하고 써도 됩니다.

2. 스크롤 스냅으로 가로 스크롤러 구현하기

가로 스크롤러를 만들 때 CSS Grid(혹은 Flexbox, 둘 다 괜찮습니다)로 레이아웃을 잡은 뒤 scroll-snap-type을 추가하면 끝입니다. 이 기능을 위해 상당히 복잡한 자바스크립트를 작성한 사례를 본 적이 있을 정도로, 많은 개발자들이 이를 직접 구현하려 합니다.

단, 두 가지는 반드시 설정해야 동작합니다.

  • 부모 요소: scroll-snap-type
  • 자식 요소: scroll-snap-align

scroll-snap-type은 두 개의 값을 받습니다. 첫 번째는 축(inline/block 또는 x/y), 두 번째는 스냅 강도(mandatory 또는 proximity)입니다. 어떤 조합이 맞는지는 사용 사례에 따라 직접 테스트해보는 걸 추천합니다. 정렬 값은 start, center, end 등으로 간단합니다.

이렇게 설정하면 스크롤하다가 손을 떼는 순간 다음 아이템으로 스냅됩니다. 데스크톱에서는 그럭저럭이지만, 모바일에서 스와이프할 때는 경험이 상당히 좋습니다. 웹 앱이나 캐러셀류 UI에 넣기 좋은 기능이고, 브라우저 지원도 매우 안정적입니다.

3. :user-valid / :user-invalid로 폼 검증하기

폼 검증에서 blur 이벤트를 감지하고 touched 클래스를 붙이는 식의 패턴을 많이 봅니다. 이렇게 하는 이유는 이해가 갑니다. 기존 :valid/:invalid 가상 클래스는 사용자가 아무것도 입력하지 않은 시점에도 폼을 검증해버리기 때문입니다. required 속성이 붙은 빈 입력 필드는 처음부터 :invalid 상태가 되어버리는데, 이는 사용자 경험 측면에서 최악입니다.

이 문제는 :user-valid와 :user-invalid로 해결됩니다. 사용자가 필드에 들어갔다가 아무것도 안 쓰고 나가면 아무 일도 일어나지 않습니다. 하지만 값을 입력하면 그때부터 :user-valid 혹은 :user-invalid가 적용됩니다.

예를 들어 minlength를 설정한 비밀번호 필드에 짧은 값을 입력하면 :user-invalid가 걸리고, 제출을 시도하면 브라우저가 자동으로 어떤 조건이 틀렸는지 알려줍니다. 자바스크립트 코드는 전혀 필요 없습니다. 참고로 이런 에러 메시지는 커스터마이징도 가능한데, 이 부분은 자바스크립트 API가 필요하므로 별도 영상에서 다룬다고 합니다.

더 나아가 pattern 속성에 정규식을 넣어서 검증 조건을 세밀하게 지정할 수도 있습니다. 예를 들어 문자와 숫자가 섞여야 유효하도록 패턴을 걸면, 조건을 만족하는 순간 :user-valid로 전환됩니다.

중요한 전제가 하나 있습니다. 이건 "CSS로 폼 검증을 끝내라"는 뜻이 아닙니다. blur 이벤트를 감지해서 직접 클래스를 토글하는 방식의 1차 방어선을 CSS로 대체하라는 의미입니다. 사용자가 제출 버튼을 누른 후에는 반드시 서버 사이드 검증을 거쳐야 합니다. CSS는 그 역할을 대신할 수 없습니다.

브라우저 지원은 현재 baseline widely available 상태로, 약 2년 반 전부터 모든 브라우저 엔진에 들어가 있습니다. 사용자층에 따라 한 번 더 확인하는 게 좋겠지만, 실무에 쓰기에 충분히 안전한 시점입니다.

4. :focus-visible로 불필요한 포커스 링 제거하기

자바스크립트 이야기는 아니지만 짚고 넘어갈 만한 팁입니다. 버튼이나 메뉴를 클릭했을 때 기본 포커스 링이 나타나는 걸 싫어해서 outline: none 혹은 focus: 0 식으로 포커스 스타일을 아예 지워버리는 경우가 많습니다. 마우스로 클릭했을 때 링이 보이는 게 거슬린다는 이유에서죠.

하지만 키보드 사용자에게는 포커스 링이 반드시 필요합니다. 해결책은 :focus 대신 :focus-visible을 쓰는 것입니다. 이는 이미 브라우저의 기본(user agent) 동작으로 자리 잡았습니다. 키보드로 탭 이동을 하면 포커스 링이 정상적으로 나타나지만, 마우스로 클릭하면 링이 나타나지 않습니다. (단, 상호작용 방식과 요소 종류에 따라 브라우저가 판단을 달리하는 세부 사항이 있는데, 이는 별도 영상에서 더 자세히 다룬다고 합니다.)

이미 브라우저들의 기본 동작이 이렇게 전환되었고, 지원도 훌륭하므로 :focus 대신 :focus-visible을 사용하는 걸 권장합니다.

5. lh 단위로 텍스트 영역 높이를 줄 수에 맞추기

디자이너가 "텍스트 영역이 정확히 3줄 높이여야 한다"고 요구할 때, 보통 매직 넘버로 픽셀 값을 때려 맞추곤 합니다. 그런데 나중에 폰트 크기를 바꿔야 한다는 요청이 오면 그 매직 넘버를 처음부터 다시 계산해야 하는 번거로움이 생깁니다.

여기서 lh 단위(line height 단위)를 쓰면 이 문제가 깔끔하게 해결됩니다. height: 3lh처럼 지정하면 항상 정확히 3줄 높이를 유지하며, 폰트 크기를 늘리거나 줄여도 자동으로 그에 맞춰 커지고 작아집니다. 이런 계산을 자바스크립트로 하려면 상당한 코드가 필요한데, lh 단위 하나면 끝납니다.

다만 height 대신 min-height(논리적 속성으로는 min-block-size)로 설정하는 걸 권장합니다. 이렇게 최소값으로 잡아두는 이유는 다음에 소개할 field-sizing 속성과 함께 쓰기 위해서입니다.

lh 단위는 baseline widely available 상태로 약 2년간(모든 브라우저 엔진에는 작년 11월부터) 사용 가능했으므로 안심하고 써도 됩니다.

6. field-sizing으로 입력 필드 자동 크기 조절하기

사용자가 텍스트 영역에 박스 크기보다 많은 줄을 입력했을 때, 입력 내용에 맞춰 박스가 자동으로 커지게 하는 기능은 예전에는 구현하기 꽤 까다로웠습니다. 이제는 field-sizing 속성 한 줄이면 해결됩니다.

다만 이 기능은 아직 "newly available" 단계로, 모든 브라우저 엔진에 들어간 지 3개월밖에 되지 않았습니다. lh처럼 완전히 안정된 기능은 아니지만, 점진적 향상(progressive enhancement) 관점에서 적용해볼 만한 가치가 있는 기능입니다.

정리

이번에 살펴본 기능들을 정리하면 다음과 같습니다.

  • scroll-margin + :target: 스무스 스크롤 시 고정 헤더에 가려지는 문제를 자바스크립트 오프셋 계산 없이 해결. prefers-reduced-motion과 함께 쓰면 접근성까지 챙길 수 있음
  • scroll-snap-type / scroll-snap-align: 가로 스크롤러의 스냅 동작을 복잡한 자바스크립트 없이 구현. 모바일 스와이프 경험이 특히 좋음
  • :user-valid / :user-invalid: blur 이벤트 감지 로직을 대체하는 1차 방어선. 단, 서버 사이드 검증을 대체하는 것은 아님
  • :focus-visible: 마우스 클릭 시엔 숨기고 키보드 탐색 시엔 보여주는 포커스 링을 기본 브라우저 동작으로 활용
  • lh 단위와 field-sizing: 텍스트 영역의 줄 수 기반 높이 계산과 자동 크기 조절을 CSS만으로 처리

이 기능들의 공통점은 모두 "자바스크립트 없이도 충분히, 혹은 더 잘 해결되는" 문제들이라는 점입니다. 특히 폼 검증과 포커스 스타일은 접근성과도 직결되는 부분이라, 기존에 자바스크립트로 처리하고 있었다면 한 번쯤 CSS 네이티브 기능으로 대체할 수 있는지 점검해볼 가치가 있습니다.

💡
자바스크립트로 구현하던 UI 로직을 네이티브 CSS로 대체하면 코드량과 유지보수 부담을 줄이면서도 접근성(reduced-motion, 키보드 포커스)까지 자연스럽게 개선할 수 있어, 실무에서 바로 적용 가능한 성숙도 높은 기능들을 아는 것이 중요하다.
