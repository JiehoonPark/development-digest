13:T20f4,<h2>Ultra Fast, 써보니 정말 미쳤다 (좋은 쪽도 나쁜 쪽도)</h2>
<p>OpenAI가 공개한 코드 생성 모드 'Ultra Fast'를 실제로 써봤습니다. Astra 같은 모델로 상상을 초월하는 속도로 코드를 뽑아내는 동시에, 레이트 리밋과 청구서도 그만큼 빠르게 태워버리더군요. 실제 사용 영상과 비용 데이터를 바탕으로 이 기능이 어떤 경험을 주고, 얼마나 비싼지, 그리고 지금 누가 써야 하는지를 정리해봤습니다.</p>
<h3>실시간으로 코드가 완성되는 트립한 경험</h3>
<p>Lakeb로 급하게 만든 앱에 &quot;라이트 모드로 바꾸고 좀 더 재밌게 만들어줘&quot;라고 요청하면, 화면이 실시간으로 업데이트되는 걸 지켜볼 수 있습니다. 모든 게 진짜 실시간입니다. 페이지 스크린샷을 찍으려고 하는 순간 이미 작업이 끝나 있을 정도입니다.</p>
<p>이런 속도는 실질적으로 쓸모가 많습니다.</p>
<ul>
<li>라이브 프로토타이핑</li>
<li>모델과 함께 호흡을 맞추며 작업하기</li>
<li>더 빠른 작업 처리</li>
<li>사용자에게 훨씬 즉각적으로 느껴지는 경험 제공</li>
<li>사람이 조작하는 것보다 더 빠르게 느껴지는 컴퓨터 사용(computer use)</li>
</ul>
<p>문제는 이 속도의 대가가 터무니없이 비싸다는 점입니다.</p>
<h3>가격표가 말해주는 현실</h3>
<p>Astra는 원래도 출력 토큰 100만 개당 50달러로 저렴한 편은 아니었습니다. 그런데 Ultra Fast 모드로 전환하면 이 가격이 100만 토큰당 300달러까지 뛰어오릅니다. 만약 컨텍스트가 긴 프로젝트라면(제발 그러지 않기를) 100만 토큰당 450달러까지 올라갑니다.</p>
<p>캐시 비용도 심각합니다. 캐시 읽기 비용이 100만 토큰당 6달러로, 일반 모델의 평범한 읽기보다도 비싸졌고, 캐시 쓰기 비용은 100만 토큰당 75달러로 믿기 힘든 수준입니다.</p>
<p>실제로 겪은 사례도 있습니다. 100줄도 안 되는 PR 두 개를 Ultra Fast로 리뷰하는 데 <strong>600달러</strong>가 들었습니다. 단 두 개의 작은 PR 리뷰에 600달러라는 걸 생각해보면, 이게 얼마나 비정상적인 가격인지 체감이 될 겁니다.</p>
<h3>월 500달러 요금제도 2시간 만에 바닥난다</h3>
<p>OpenAI는 월 500달러짜리 Ultra Fast 플랜도 내놓았습니다. 이 플랜은 주당 약 1,000달러어치 사용량을 제공하는데, Ultra Fast로 쓰면 이걸 소진하는 데 걸리는 시간이 <strong>2.1시간</strong>에 불과합니다. 즉, OpenAI가 상당한 손해를 감수하며 보조금을 주고 있는 구조입니다.</p>
<p>실제로 영상 녹화 전 사용량 한도를 38%로 리셋한 상태에서 테스트해봤습니다.</p>
<ul>
<li>빠른 빌드 요청(38초 소요) → 38%에서 37%로 하락 (1% 소진)</li>
<li>&quot;라이트 모드로 바꾸고 재밌게&quot; 요청(16초 소요) → 추가 소진</li>
</ul>
<p>1분도 안 되는 작업에 1%가 날아간 셈입니다. 이후 칸반 앱 + 라이브 채팅 기능을 실시간으로 하나씩 추가하면서, 다크 모드 전환, 게스트 채팅 비활성화, 이미지 첨부 기능, 로그인 전용 설정 등 여러 작은 변경을 연달아 요청했습니다. 이 과정이 끝난 뒤 사용량은 37%에서 34%로 떨어졌습니다. 몇 가지 작은 기능 변경만으로 500달러 플랜의 3%를 써버린 겁니다.</p>
<h3>Ultra Fast에서는 '도구 호출 시간'이 병목이 된다</h3>
<p>흥미로운 점은, 추론 시간이 10분에서 30초로 줄어들면 이전에는 무시해도 됐던 다른 작업 시간들이 갑자기 전체 작업 시간의 큰 비중을 차지하게 된다는 겁니다. 예전에는 토큰 생성이 10분 걸리고 git 명령이나 빌드가 30초 걸리면, 그 30초는 무시할 만한 비율이었습니다. 하지만 추론이 30초로 줄어들면, 도구 호출에 걸리는 30초가 전체 실행 시간을 두 배로 늘리는 셈이 됩니다.</p>
<p>그래서 실제로 시스템 프롬프트를 바꿔서, 미리보기 브라우저를 직접 조작하지 말고 코드만 바꾸라고 지시했습니다. 중요하지 않은 도구 호출로 시간을 낭비하지 않게 하기 위해서입니다. 예를 들어 &quot;상단 네비게이션의 불필요한 공간을 모두 제거해줘&quot;라고 요청했을 때, 실제로 <strong>11초</strong> 만에 변경이 완료되는 걸 확인했습니다.</p>
<p>Astra 같은 모델은 중간에 방향을 트는 지시(steering)에도 강한 편이라, 작업 도중에 &quot;다크 모드를 기본값으로&quot;, &quot;게스트는 채팅 못하게&quot; 같은 지시를 계속 던져도 동시에 처리해버립니다. 다크 모드 변경은 5초 만에 끝났습니다. 이렇게 모델이 작업하는 동안 계속 요청을 쏟아부으며 조종하는 경험은, 예전에 직접 코드를 짜던 시절 코드와 결과물 사이를 오가며 느꼈던 '플로우 상태'와 비슷한 느낌을 줍니다.</p>
<h3>실제 비용 비교: 61 Soul vs Ultra Fast</h3>
<p>작업 하나를 마친 후, 같은 스레드를 표준 API 가격(Aster 기준)으로 계산했을 때와 비교해봤습니다.</p>
<ul>
<li>표준 Aster API 가격 기준: <strong>7.72달러</strong></li>
<li>Ultra Fast 실제 청구액: <strong>46.32달러</strong></li>
<li>같은 작업을 6.1 Soul(GPT 계열 다른 모델로 추정)로 처리했을 경우: <strong>110달러</strong></li>
</ul>
<p>즉, 6.1 Soul의 정상 속도로 처리하면 110달러가 들 작업을, Ultra Fast로는 그보다 훨씬 저렴한 46.32달러에 끝냈지만, 이는 표준 Astra 가격의 <strong>40배가 넘는 금액</strong>입니다. 이 숫자는 한편으로는 6.1 Soul이 얼마나 가성비가 좋은 모델인지를 보여주지만, 동시에 Ultra Fast의 비용이 얼마나 비정상적인지도 동시에 보여줍니다.</p>
<h3>OpenAI 직원들조차 통제받는 비용</h3>
<p>흥미롭게도 OpenAI 직원들은 원래 무제한 추론을 쓸 수 있었지만, 최근에는 Ultra Fast 사용 전 작업마다 승인을 받아야 한다고 합니다. 직원들조차 컴퓨팅 제약에 걸릴 정도로 비용이 심각하다는 뜻입니다. 이 사실이 알려지며 다소 안도감을 느꼈다고 하네요.</p>
<p>실제로 Primeagen도 500달러 플랜을 구매해 Ultra Fast 옵션을 보고 바로 써봤다가, 한 시간 만에 한도의 절반 이상을 태워버린 사례가 있었습니다. 이는 '사용자에게 다이얼을 쥐어주면 끝까지 돌려버린다'는 문제와 맞닿아 있습니다. 최대 reasoning 레벨 옵션을 줬을 때와 똑같은 문제가, 속도 다이얼에서도 반복되고 있는 셈입니다. OpenAI가 이런 선택지를 그렇게 쉽게 클릭할 수 있게 만든 것부터가 설계상 아쉬운 부분입니다.</p>
<h3>정리</h3>
<ul>
<li><strong>Ultra Fast는 체감 속도 면에서 혁명적입니다.</strong> 실시간으로 코드가 완성되는 걸 지켜보며 계속 지시를 덧붙이는 작업 방식은 과거의 코딩 플로우 상태와 유사한 몰입감을 줍니다.</li>
<li><strong>하지만 비용은 비정상적입니다.</strong> 출력 토큰 기준 100만 개당 50달러에서 300달러(긴 컨텍스트는 450달러)로 치솟고, 캐시 쓰기는 100만 토큰당 75달러에 달합니다. 작은 PR 리뷰 두 건에 600달러가 청구된 사례가 이를 잘 보여줍니다.</li>
<li><strong>월 500달러 플랜도 2.1시간이면 소진됩니다.</strong> OpenAI가 상당한 보조금을 투입하고 있음에도 실사용에는 턱없이 부족한 한도입니다.</li>
<li><strong>속도가 빨라지면 병목이 이동합니다.</strong> 추론 시간이 줄면 도구 호출, 빌드, git 명령 같은 '부수 작업' 시간이 상대적으로 커지므로, 이런 작업을 최소화하는 방향으로 시스템 프롬프트를 조정할 필요가 있습니다.</li>
