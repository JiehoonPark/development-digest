13:T33b9,<p>React 19.3가 npm에 배포되었습니다. 지난해 실험적 API로 소개됐던 View Transitions와 Fragment Refs가 이번 릴리스에서 정식으로 stable API가 되었고, 그 외에도 React DOM의 Trusted Types 지원, Server Components에서 <code>&lt;Context&gt;</code>를 직접 렌더링할 수 있는 기능 등이 추가되었습니다. 이 글에서는 이번 릴리스의 핵심인 View Transitions와 Fragment Refs가 실제로 어떻게 동작하는지 예제 코드와 함께 정리해보겠습니다.</p>
<h3>View Transitions</h3>
<p>새로 추가된 <code>&lt;ViewTransition&gt;</code> 컴포넌트는 브라우저의 View Transition API를 이용해 엘리먼트가 등장(enter), 퇴장(exit), 이동, 크기 변경될 때 애니메이션을 적용할 수 있게 해줍니다. 사용법은 간단한데, 애니메이션을 주고 싶은 UI를 <code>&lt;ViewTransition&gt;</code>으로 감싸기만 하면 됩니다.</p>
<pre><code class="language-jsx">import { ViewTransition } from 'react';

{isShowing &amp;&amp; (
  &lt;ViewTransition&gt;
    &lt;Component /&gt;
  &lt;/ViewTransition&gt;
)}</code></pre>
<p>이렇게 해두면 Transition으로 표시된 업데이트가 자식 컴포넌트의 스타일을 바꾸거나, ViewTransition을 마운트/언마운트시킬 때마다 React가 자동으로 애니메이션을 실행합니다.</p>
<p>React는 트리가 어떻게 변했는지에 따라 실행할 애니메이션 종류를 결정합니다.</p>
<ul>
<li><strong>enter</strong>: <code>&lt;ViewTransition&gt;</code>이 새로 추가될 때</li>
<li><strong>exit</strong>: <code>&lt;ViewTransition&gt;</code>이 제거될 때</li>
<li><strong>update</strong>: <code>&lt;ViewTransition&gt;</code>의 자식이 스타일이나 콘텐츠가 바뀔 때</li>
<li><strong>share</strong>: 이름이 지정된 <code>&lt;ViewTransition&gt;</code>이 한 곳에서 제거되고 다른 곳에 추가될 때</li>
</ul>
<p>여기서 중요한 점은, Transition으로 표시되지 않은 업데이트는 애니메이션을 트리거하지 않는다는 것입니다. 이런 업데이트는 긴급한 것으로 간주되어 즉시 화면에 반영되어야 하기 때문입니다. 반면 <code>startTransition</code> 안의 상태 업데이트, <code>&lt;Suspense&gt;</code>가 콘텐츠를 드러내는 시점, <code>useDeferredValue</code>로 인한 업데이트는 모두 View Transition 애니메이션을 유발합니다.</p>
<p>기본적으로 <code>&lt;ViewTransition&gt;</code>은 부드러운 크로스페이드로 애니메이션됩니다. View Transition Class를 전달하고 CSS에서 애니메이션을 정의하거나, Web Animations API를 사용해 이벤트 props(<code>onEnter</code>, <code>onExit</code>, <code>onShare</code>, <code>onUpdate</code>)로 명령형으로 애니메이션을 트리거하는 방식으로 커스터마이징할 수도 있습니다.</p>
<p>현재 <code>&lt;ViewTransition&gt;</code>은 DOM에서만 동작하며, React Native 등 다른 플랫폼 지원은 작업 중입니다.</p>
<h4>addTransitionType으로 애니메이션 세분화하기</h4>
<p>같은 상태 업데이트라도 상황에 따라 다른 애니메이션을 적용하고 싶을 때가 있습니다. 예를 들어 캐러셀에서 세 번째 슬라이드로 앞으로 이동할 때는 오른쪽에서 왼쪽으로, 뒤로 이동할 때는 왼쪽에서 오른쪽으로 애니메이션이 재생되어야 하는데, 두 경우 모두 <code>currentSlide</code>를 3으로 설정하는 동일한 상태 업데이트입니다.</p>
<p>이럴 때는 상태 업데이트와 함께 <code>addTransitionType</code>을 호출해서 해당 Transition이 발생한 원인에 대한 정보를 추가로 전달할 수 있습니다.</p>
<pre><code class="language-js">function nextSlide() {
  startTransition(() =&gt; {
    addTransitionType('next');
    setCurrentSlide(c =&gt; c + 1);
  });
}

function previousSlide() {
  startTransition(() =&gt; {
    addTransitionType('previous');
    setCurrentSlide(c =&gt; c - 1);
  });
}</code></pre>
<p>그리고 이 타입에 따라 서로 다른 애니메이션을 지정할 수 있습니다.</p>
<pre><code class="language-jsx">&lt;ViewTransition
  enter={{
    'next': 'from-right',
    'previous': 'from-left',
  }}
  exit={{
    'next': 'to-left',
    'previous': 'to-right',
  }}&gt;
  &lt;Page /&gt;
&lt;/ViewTransition&gt;</code></pre>
<p>React는 모든 Transition Type을 엘리먼트에 브라우저 view transition type으로도 추가하기 때문에, CSS에서 <code>:active-view-transition-type(...)</code> 셀렉터로 애니메이션 범위를 지정할 수도 있습니다.</p>
<h4>Suspense와 함께 fallback, 이미지, 폰트 애니메이션하기</h4>
<p>View Transitions의 가장 흥미로운 점 중 하나는 Suspense와의 통합입니다. Suspense 경계를 <code>&lt;ViewTransition&gt;</code>으로 감싸면, 자식이 로딩을 마치고 콘텐츠를 드러낼 때도 애니메이션을 적용할 수 있습니다.</p>
<pre><code class="language-jsx">&lt;ViewTransition&gt;
  &lt;Suspense fallback={&lt;Loading /&gt;}&gt;
    &lt;Component /&gt;
  &lt;/Suspense&gt;
&lt;/ViewTransition&gt;</code></pre>
<p>자식 로딩이 끝나면 React는 fallback에서 최종 콘텐츠로 전환되는 update 애니메이션을 트리거합니다.</p>
<p>다만 이렇게만 설정하면 문제가 하나 있습니다. 이미 로드가 끝난 콘텐츠를 다시 보여줄 때도(즉 캐시된 상태에서도) 매번 들어오고 나가는 애니메이션이 재생되는 것입니다. 일반적으로 Suspense와 함께 쓰는 애니메이션은 아껴서 사용할 때 가장 효과적이며, 즉시 나타나야 할 캐시된 UI에는 피하는 게 좋습니다.</p>
<p>Suspense로 좋은 UX를 만들기 위한 원칙은 다음과 같습니다.</p>
<ul>
<li>fallback은 애니메이션 없이 즉시 나타나야 한다</li>
<li>fallback에서 최종 콘텐츠로 바뀔 때는 애니메이션이 있어야 한다</li>
<li>suspend되지 않는 자식은 애니메이션 없이 즉시 나타나야 한다</li>
</ul>
<p>이렇게 하면 이미 로드된 상태에서는 앱이 빠릿빠릿하게 느껴지면서, fallback에서 최종 콘텐츠로 전환될 때만 애니메이션으로 매끄러움을 더할 수 있습니다. 이를 위해 update를 제외한 모든 애니메이션을 비활성화할 수 있습니다.</p>
<pre><code class="language-jsx">&lt;ViewTransition update=&quot;auto&quot; default=&quot;none&quot;&gt;
  &lt;Suspense fallback={&lt;Fallback /&gt;}&gt;
    &lt;Component /&gt;
  &lt;/Suspense&gt;
&lt;/ViewTransition&gt;</code></pre>
<p>이렇게 설정하면 버튼을 누르자마자 fallback이 즉시 나타나 UI가 사용자 액션에 바로 반응하는 느낌을 주고, 비디오가 한 번 로드된 이후에는 토글이 즉각적으로 일어납니다.</p>
<p>View Transitions는 fallback 애니메이션뿐 아니라, 이미지나 폰트가 로딩될 때 Suspense를 트리거하도록 opt-in하는 수단이기도 합니다. 이를 통해 이미지나 폰트가 로딩 완료되는 시점에 따라 제각각 깜빡이며 나타나는 브라우저의 기본 동작을 피하고, 컴포넌트가 필요로 하는 모든 리소스를 고려한 조율된 로딩 시퀀스를 만들 수 있습니다. 이미지나 폰트를 <code>&lt;ViewTransition&gt;</code> 안에 넣어 Suspense를 트리거하도록 하면 됩니다.</p>
<pre><code class="language-jsx">&lt;ViewTransition&gt;
  &lt;Suspense fallback={&lt;Fallback /&gt;}&gt;
    &lt;img src={imageSrc} /&gt;
    &lt;style href={fontSrc} precedence=&quot;default&quot;&gt;
      {`@font-face {
        font-family: 'Fancy';
        src: url(${fontSrc}) format('truetype');
        font-display: swap;
      }`}
    &lt;/style&gt;
  &lt;/Suspense&gt;
&lt;/ViewTransition&gt;</code></pre>
<h3>Fragment Refs</h3>
<p>컴포넌트의 DOM 노드에 대해 더 낮은 수준의 제어가 필요할 때—예를 들어 이벤트 리스너를 붙이거나, 가시성을 관찰하거나, 포커스를 옮길 때—보통은 ref를 사용합니다. 하지만 ref 사용이 까다로운 상황이 있습니다.</p>
<ul>
<li>단일 부모 없이 형제 엘리먼트 그룹을 렌더링하는 컴포넌트</li>
<li><code>ref</code> prop을 다른 엘리먼트로 전달하지 않는 컴포넌트</li>
</ul>
<pre><code class="language-jsx">function Component() {
  return (
    {posts.map(post =&gt; (
      &lt;Heading key={post.id}&gt;
        {post.title}
      &lt;/Heading&gt;
    ))}
  )
}</code></pre>
<p>이럴 때 ref를 담기 위해 래퍼 <code>&lt;div&gt;</code>를 추가하는 방법도 있지만, 이는 컴포넌트의 스타일이나 레이아웃을 깨뜨릴 수 있습니다. 또한 컴포넌트가 ref prop을 노출하지 않는다면 해당 컴포넌트를 수정해야 하는데, 직접 제어할 수 없는 외부 라이브러리 컴포넌트라면 이마저도 불가능합니다.</p>
<p>Fragment Refs는 컴포넌트가 무엇을 렌더링하든 상관없이 동작하는, 자주 쓰이는 DOM 메서드 묶음을 제공해 이 문제를 해결합니다. 19.3부터는 <code>&lt;Fragment&gt;</code>에 직접 ref를 전달해서 사용할 수 있는데, 이 ref는 <code>FragmentInstance</code>를 반환하며, 이를 통해 Fragment의 DOM 자식들을 다룰 수 있습니다.</p>
<pre><code class="language-jsx">function Component() {
  const fragmentRef = useRef(null);
  useEffect(() =&gt; {
    const fragmentInstance = fragmentRef.current;
    fragmentInstance.focus();
  }, []);
  return (
    &lt;Fragment ref={fragmentRef}&gt;
      {posts.map(post =&gt; (
        &lt;Heading key={post.id}&gt;
          {post.title}
        &lt;/Heading&gt;
      ))}
    &lt;/Fragment&gt;
  )
}</code></pre>
<p><code>FragmentInstance</code>는 자식들의 DOM 구조를 바꾸지 않고, 자식들을 하나의 그룹으로 취급해 다음과 같은 메서드를 제공합니다.</p>
<ul>
<li><code>addEventListener</code>, <code>removeEventListener</code>, <code>dispatchEvent</code>: 1차 자식들의 이벤트를 관리</li>
<li><code>focus</code>, <code>focusLast</code>, <code>blur</code>: 중첩된 자식들 사이에서 깊이 우선으로 포커스를 이동</li>
<li><code>observeUsing</code>, <code>unobserveUsing</code>: <code>IntersectionObserver</code>나 <code>ResizeObserver</code>를 연결</li>
<li><code>getClientRects</code>, <code>getRootNode</code>, <code>compareDocumentPosition</code>, <code>scrollIntoView</code>: Fragment의 1차 자식들을 측정하고 스크롤</li>
</ul>
<p>즉, Fragment Refs를 사용하면 다른 컴포넌트의 내부를 수정하거나 기존 DOM 구조를 바꾸지 않고도 해당 컴포넌트에 동작을 붙일 수 있습니다.</p>
<h3>그 외 추가 사항</h3>
<p>이번 릴리스에는 React DOM에서 브라우저의 Trusted Types를 지원하는 기능과, Server Components 안에서 <code>&lt;Context&gt;</code>를 직접 렌더링할 수 있는 기능도 함께 포함되었습니다. 자세한 사용법과 변경 이력은 공식 Changelog를 참고하시기 바랍니다.</p>
<h3>정리</h3>
<ul>
<li><strong>View Transitions</strong>: <code>&lt;ViewTransition&gt;</code> 컴포넌트가 실험적 API를 거쳐 19.3에서 정식 stable이 되었습니다. Transition으로 표시된 업데이트에 대해 enter/exit/update/share 네 가지 애니메이션을 자동으로 판단해 실행하며, 기본은 크로스페이드이고 CSS나 Web Animations API로 커스터마이징할 수 있습니다.</li>
<li><strong>addTransitionType</strong>: 동일한 상태 업데이트라도 발생 원인(예: 캐러셀의 다음/이전 이동)에 따라 다른 애니메이션을 지정할 수 있는 API입니다.</li>
<li><strong>Suspense 연동</strong>: fallback에서 최종 콘텐츠로의 전환, 이미지·폰트 로딩 조율에 View Transition을 활용할 수 있습니다. 단, 캐시된 콘텐츠까지 매번 애니메이션되지 않도록 <code>update=&quot;auto&quot; default=&quot;none&quot;</code> 같은 설정으로 불필요한 애니메이션을 억제하는 것이 UX상 중요합니다.</li>
<li><strong>Fragment Refs</strong>: <code>&lt;Fragment ref={...}&gt;</code>로 <code>FragmentInstance</code>를 얻어, 단일 부모 노드 없이도 포커스 이동, 이벤트 처리, Intersection/Resize 관찰, 스크롤 등을 수행할 수 있습니다. 래퍼 <code>&lt;div&gt;</code> 추가나 외부 컴포넌트 수정 없이 DOM 제어가 가능해졌다는 점이 핵심입니다.</li>
<li>이 외에도 React DOM의 Trusted Types 지원과 Server Components에서의 <code>&lt;Context&gt;</code> 직접 렌더링이 19.3에 포함되었습니다.</li>
</ul>
