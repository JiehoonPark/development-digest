18:T3665,<p>웹 표준의 미래를 결정하는 'Interop' 프로젝트가 2027년 버전을 준비하고 있습니다. 이 글에서는 Josh W. Comeau가 실제로 투표한 CSS 신기능 상위 항목들을 살펴보면서, 앞으로 1~2년 안에 우리가 마주하게 될 CSS가 어떤 모습일지 미리 들여다봅니다.</p>
<h3>Interop이란 무엇인가</h3>
<p>지난 몇 년간 Google, Apple, Microsoft, Mozilla를 비롯해 Igalia, Bocoup 같은 조직들이 힘을 합쳐 <strong>Interop</strong>이라는 프로젝트를 진행해왔습니다. 목적은 단순합니다. 웹 기술의 브라우저 간 지원 수준을 끌어올리는 것인데요, 성과가 꽤 놀랍습니다. 특정 기능이 Interop의 포커스 영역으로 지정되면, 1년 안에 모든 주요 브라우저에서 거의 100%에 가까운 지원률을 달성하는 경우가 많습니다.</p>
<p>대표적인 사례가 <strong>CSS Subgrid</strong>입니다. Subgrid는 CSS Grid를 확장해 완전히 새로운 레이아웃을 가능하게 하는 강력한 기능인데, 2019년 Firefox에 먼저 구현된 이후 한동안 다른 브라우저들은 별다른 움직임이 없었습니다. 그러다 2023년 Interop에 포함되면서, 그해가 끝날 무렵에는 모든 모던 브라우저에서 폭넓게 사용 가능해졌습니다.</p>
<p>2026년 말에 접어들면서 Interop 2027을 준비하는 작업이 한창 진행 중이고, Mozilla 팀은 개발자들이 가장 원하는 기능에 투표할 수 있는 랭킹 시스템을 만들었습니다. 이 투표 데이터를 바탕으로 내년 Interop에 어떤 기능을 포함할지 결정한다고 하는데요, 이 글에서는 저자가 투표한 상위 기능들을 하나씩 짚어보겠습니다.</p>
<h3>1. CSS 함수(CSS functions)</h3>
<p>&gt; 2026년 10월 기준: Chrome 155, Edge 154에서 지원 / Firefox 157, Safari 27 미지원</p>
<p>가장 흥미로운 제안 중 하나는 CSS에 <strong>함수</strong>를 추가하자는 것입니다.</p>
<pre><code class="language-css">/* Define a function: */
@function --gradient-to-transparent(--color, --direction: bottom) {
result: linear-gradient(
to var(--direction),
var(--color),
transparent;
);
}

/* Invoke it: */
.elem {
background: --gradient-to-transparent(red);
}

/* …which produces: */
.elem {
background: linear-gradient(
to bottom,
red,
transparent;
);
}</code></pre>
<p>JavaScript에 익숙하다면 상당히 친숙하게 느껴질 문법입니다. <code>@function</code>으로 새 함수를 정의하고, <code>result</code>로 반환값을 지정합니다.</p>
<p>이 기능으로 할 수 있는 재미있는 일이 정말 많은데, 저자가 가장 관심 있어 하는 활용법은 극좌표계와 직교좌표계를 서로 변환하는 것입니다. 이는 저자의 Whimsical Animations 강의에서 반복적으로 등장하는 개념이라고 합니다.</p>
<pre><code class="language-css">@function --translate-polar(--angle, --distance) {
result: translate(
calc(cos(var(--angle)) * var(--distance)),
calc(sin(var(--angle)) * var(--distance))
);
}

/* Move this element 100px at a 45° angle: */
.particle {
transform: --translate-polar(45deg, 100px);
}</code></pre>
<p>거의 SF 소설에 나올 법한 기능처럼 느껴지지만, 이미 Chromium 계열 브라우저에 구현되어 있고, Interop 2027에 포함된다면 생각보다 빨리 폭넓게 사용 가능해질 가능성이 높습니다.</p>
<h3>2. corner-shape로 만드는 베벨과 스퀴클</h3>
<p>&gt; 2026년 10월 기준: Chrome 155, Edge 154에서 지원 / Firefox 157, Safari 27 미지원</p>
<p>기존에는 <code>border-radius</code>로 DOM 노드의 모서리를 둥글게 만들었습니다. 이 속성은 사실상 각 모서리에 사분원을 추가해 네 변을 연결하는 방식입니다.</p>
<p><code>corner-shape</code> 속성은 네 변을 연결하는 또 다른 방식들을 제공합니다. 대표적으로 <code>squircle</code>, <code>bevel</code>, <code>notch</code>, <code>scoop</code> 같은 옵션들이 있습니다.</p>
<pre><code class="language-css">.box {
border-radius: 16px;

&amp;.squircle {
corner-shape: squircle;
}
&amp;.bevel {
corner-shape: bevel;
}
&amp;.notch {
corner-shape: notch;
}
&amp;.scoop {
corner-shape: scoop;
}
}</code></pre>
<p>처음 이 속성을 접했을 때 가장 기대했던 건 <code>squircle</code>이었습니다. 스퀴클은 초타원(superellipse) 알고리즘을 이용해 더 부드럽고 완만한 모서리를 만드는 방식으로, Apple이 오래전부터 디자인에 활용해온 형태입니다.</p>
<p>그런데 막상 <code>corner-shape</code>를 직접 써보니 <code>bevel</code> 쪽을 훨씬 자주 쓰게 되더라는데요. 비디오 게임이나 SF풍 UI를 만들 때 특히 유용합니다. 저자는 진행 중인 사이드 프로젝트에 <code>corner-shape: bevel</code>을 대거 활용하고 있다고 합니다.</p>
<p>사실 <code>clip-path</code>나 mask로도 비슷한 모양은 만들 수 있었습니다. 하지만 이들과 달리 <code>corner-shape</code>는 실제로 border-box 자체의 모양을 바꾸기 때문에, border, outline, box-shadow가 바뀐 모서리 모양을 정확히 따라갑니다.</p>
<p>2026년 10월 현재 Firefox와 Safari에서는 아직 지원하지 않지만, 점진적 향상(progressive enhancement) 관점에서는 지금 바로 사용해도 무방한 속성입니다.</p>
<h3>3. border-shape로 열리는 무한한 가능성</h3>
<p>&gt; 2026년 10월 기준: Chrome 155, Edge 154에서 지원 / Firefox 157, Safari 27 미지원</p>
<p><code>corner-shape</code>와 별개로, <code>border-shape</code>라는 제안도 있습니다. 이는 좀 더 저수준의 기능으로, 테두리 모양을 직접 그릴 수 있게 해줍니다.</p>
<p>이 속성에 대해서는 저자가 최근 뉴스레터에서 자세히 다뤘기 때문에 여기서는 요약만 짚습니다. <code>border-shape</code>는 직선, 호(arc), 베지어 곡선을 조합해 원하는 모양의 테두리를 자유롭게 만들 수 있게 해주는 기능입니다.</p>
<p>저자는 이 속성을 활용해 상단에 커다란 원형 스쿱(scoop)이 파인 카드를 만든 사례를 소개합니다. <code>corner-shape</code>와 마찬가지로 이 속성 역시 요소의 실제 border box를 바꾸기 때문에, border/outline/shadow가 모양을 정확히 따라갑니다. 흰색 border와 검은색 outline을 추가해 위와 같은 효과를 만들어냈다고 합니다.</p>
<p>더 나아가 서로 다른 border 모양 사이를 애니메이션으로 전환하는 것도 가능합니다.</p>
<h3>4. 앵커 기반 컨테이너 쿼리(Anchored Container Queries)</h3>
<p>&gt; 2026년 10월 기준: Chrome 155, Edge 154에서 지원 / Firefox 157, Safari 27 미지원</p>
<p>저자는 최근 가장 주목받는 모던 CSS 기능 중 하나인 Anchor Positioning에 관한 블로그 글을 발행한 바 있습니다. 이 기능은 실제로 Interop 2026에서 우선순위로 다뤄졌고, 현재는 폭넓게 사용 가능합니다.</p>
<p>Anchor Positioning API는 한 요소를 다른 요소에 '앵커링'할 수 있게 해줍니다. 예를 들어 떠 있는 툴팁을 트리거 요소에 앵커링하면, 트리거가 페이지 어디에 있든 툴팁이 항상 그 위치를 따라다니게 만들 수 있습니다.</p>
<p>직접 이런 문제를 풀어본 적이 있다면 알겠지만, 생각보다 까다로운 문제입니다. 예를 들어 툴팁을 앵커 위에 띄우고 싶은데, 만약 앵커가 뷰포트 상단 근처에 있다면 어떻게 해야 할까요?</p>
<p>기존 Anchor Positioning API는 이 문제를 CSS만으로 풀 수 있는 대부분의 도구를 제공했습니다. 폴백(fallback) 위치를 지정할 수 있어서, 타겟 요소가 앵커 위쪽에 들어갈 공간이 없으면 자동으로 아래쪽으로 뒤집히도록 할 수 있습니다.</p>
<p>다만 한 가지 빠진 게 있었는데, 바로 타겟이 실제로 '뒤집혔는지' 여부를 알 방법이 없었다는 점입니다. CSS만으로는 타겟 요소가 앵커 위에 있는지 아래에 있는지, 기본 위치를 쓰고 있는지 폴백 위치를 쓰고 있는지 확인할 수 없었습니다. 툴팁의 경우 보통 앵커를 가리키는 작은 돌출부(꼬리)를 붙이고 싶기 때문에 이게 문제가 됩니다.</p>
<p>Anchor Positioning API의 'Level 2' 버전에는 타겟 요소가 폴백 위치를 사용 중인지 확인할 수 있는 새로운 형태의 컨테이너 쿼리가 포함되어 있습니다. 자세한 내용은 저자의 Anchor Positioning 블로그 글이나 Interop 2027 제안서에서 확인할 수 있습니다.</p>
<h3>5. CSS inherit() 함수</h3>
<p>이 제안은 솔직히 저자도 처음 들어본 것이었고, 현재 어떤 브라우저에도 구현되어 있지 않습니다. caniuse에도 등록되어 있지 않을 정도로 초기 단계인데요, 그럼에도 보자마자 꼭 필요하다고 느꼈다고 합니다.</p>
<p>CSS의 <code>inherit</code> 키워드는 원래 상속되지 않는 속성이라도 부모로부터 값을 물려받을 수 있게 해줍니다.</p>
<pre><code class="language-css">main {
  border: 3px dashed red;
}
p {
  border: inherit;
}</code></pre>
<p>값을 재사용하는 유용한 트릭이지만, 막상 제대로 동작하지 않는 상황을 자주 마주치게 됩니다. 예를 들어 중첩된 border-radius를 다뤄야 하는 경우를 생각해봅시다.</p>
<pre><code class="language-css">main {
  border: 2px solid red;
  border-radius: 16px;
}
p {
  border: inherit;
  border-radius: inherit;
}</code></pre>
<p>중첩된 border-radius가 시각적으로 올바르게 보이려면, 안쪽 요소의 radius는 바깥쪽보다 더 작은 값으로 줄여야 합니다. 즉, 상속받은 값을 그대로 쓰고 싶은 게 아니라 <strong>변형해서</strong> 쓰고 싶은 상황입니다.</p>
<p>여기서 제안된 <code>inherit()</code> 함수가 등장합니다. 이 함수는 상속된 값을 가져온 뒤 <code>calc()</code>로 수정할 수 있게 해줍니다.</p>
<pre><code class="language-css">p {
  border-radius: calc(inherit() - 4px);
}</code></pre>
<p>아직 매우 초기 단계인 제안이라 Interop 2027에 포함될지는 미지수지만, 언젠가 이 기능이 실제로 도입되면 좋겠다는 게 저자의 바람입니다. 상당히 유용해 보이는 기능입니다.</p>
<h3>6. 스크롤 트리거 애니메이션</h3>
<p>&gt; 2026년 10월 기준: Chrome 155, Edge 154에서 지원 / Firefox 157, Safari 27 미지원</p>
<p>저자의 이전 글인 scroll-driven animations에서는 스크롤에 따라 키프레임 애니메이션을 스크러빙하는 방법을 다뤘습니다. 예를 들어 요소가 뷰포트를 지나가는 동안 서서히 페이드 인 되도록 만들 수 있습니다.</p>
<p>Scroll-driven animations는 Interop 2026에 포함되어 이미 모든 브라우저에 성공적으로 구현되었습니다. 그런데 이와 별개로 <strong>스크롤 트리거 애니메이션(scroll-triggered animations)</strong>이라는 제안도 있습니다.</p>
<p>스크롤 트리거 애니메이션의 목표는, 사용자가 특정 지점까지 스크롤했을 때 마치 근접 센서가 작동하듯 키프레임 애니메이션을 한 번 트리거하는 것입니다. 트리거된 이후에는 지정된 지속 시간 동안 애니메이션이 평소처럼 재생됩니다.</p>
<p>현재도 JavaScript의 <code>IntersectionObserver</code> API를 이용하면 스크롤 트리거 애니메이션을 구현할 수 있지만, 번거로운 작업입니다. scroll-driven과 scroll-triggered 애니메이션은 각각 쓰임새가 다르기 때문에, 둘 다 CSS만으로 처리할 수 있게 되면 훨씬 편리해질 것으로 기대됩니다.</p>
<h3>정리</h3>
<p>이 글에서 살펴본 여섯 가지 기능은 모두 Interop 2027 투표에 오른 항목들로, 이미 Chrome/Edge 계열에서는 구현이 끝났거나 진행 중인 경우가 많습니다. 핵심을 정리하면 다음과 같습니다.</p>
<ul>
<li><strong>Interop 프로젝트</strong>는 주요 브라우저 벤더들이 협력해 CSS 신기능의 크로스 브라우저 지원을 빠르게 끌어올리는 프로그램으로, 한 번 포커스 영역에 선정되면 1년 내 거의 전 브라우저 지원이 이루어지는 경우가 많습니다.</li>
<li><strong>CSS 함수(<code>@function</code>)</strong>는 반복되는 계산 로직(극좌표 변환 등)을 CSS 안에서 재사용 가능한 형태로 추출할 수 있게 해주는 기능입니다.</li>
<li><strong><code>corner-shape</code>와 <code>border-shape</code></strong>는 기존 <code>border-radius</code>의 한계를 넘어 베벨, 노치, 스쿱, 자유 곡선 형태의 모서리/테두리를 만들 수 있게 하며, 실제 border-box 자체를 바꾸기 때문에 shadow/outline도 모양을 정확히 따라갑니다.</li>
<li><strong>Anchor Positioning Level 2</strong>는 툴팁처럼 폴백 위치로 뒤집히는 요소의 현재 위치 상태를 컨테이너 쿼리로 감지할 수 있게 해, 방향에 따른 꼬리 스타일링 같은 문제를 CSS만으로 해결할 길을 엽니다.</li>
<li><strong><code>inherit()</code> 함수</strong>와 <strong>스크롤 트리거 애니메이션</strong>은 아직 초기 단계이거나 JS로만 우회 구현 가능한 기능이지만, CSS가 상속값 가공과 스크롤 이벤트 트리거까지 선언적으로 흡수해가는 방향성을 보여줍니다.</li>
</ul>
