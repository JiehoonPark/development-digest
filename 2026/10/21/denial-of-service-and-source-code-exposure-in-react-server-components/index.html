React Server Components, RCE 패치 이후 DoS·소스 코드 노출 취약점 추가 발견

Denial of Service and Source Code Exposure in React Server Components

📅 2026-10-21📰 React Blog
frontendbackend

React 팀이 지난주 발표한 치명적인 RCE 취약점(React2Shell)에 대한 패치를 검증하는 과정에서, 보안 연구자들이 해당 패치를 우회하려는 시도 중 두 건의 추가 취약점을 발견해 공개했습니다. 이번에 공개된 취약점들은 원격 코드 실행(RCE)으로 이어지지는 않지만, 서비스 거부(DoS)와 소스 코드 노출이라는 심각한 문제를 안고 있어 즉시 업데이트가 필요합니다. 특히 지난주에 이미 패치를 적용한 사용자라도 그 패치 자체가 불완전했기 때문에 다시 한번 업데이트해야 한다는 점이 핵심입니다.

무엇이 공개되었나

이번에 공개된 취약점은 다음과 같습니다.

  • 서비스 거부(DoS) - 높음: CVE-2025-55184, CVE-2025-67779, CVE-2026-23864 (CVSS 7.5)
  • 소스 코드 노출 - 중간: CVE-2025-55183 (CVSS 5.3)

가장 중요한 점은, 앞서 배포됐던 패치들이 취약하다는 것입니다. 만약 이미 19.0.3, 19.1.4, 19.2.3으로 업데이트했다면 이는 불완전한 패치이므로 다시 업데이트해야 합니다.

이 취약점들은 CVE-2025-55182(지난주 공개된 RCE 취약점)와 동일한 패키지·버전 범위에 존재합니다. 영향을 받는 범위는 다음 패키지의 19.0.0, 19.0.1, 19.0.2, 19.0.3, 19.1.0, 19.1.1, 19.1.2, 19.1.3, 19.2.0, 19.2.1, 19.2.2, 19.2.3 버전입니다.

  • react-server-dom-webpack
  • react-server-dom-parcel
  • react-server-dom-turbopack

수정 사항은 19.0.4, 19.1.5, 19.2.4로 백포트되었습니다. 위 패키지를 사용 중이라면 즉시 해당 수정 버전으로 업그레이드해야 합니다.

지난번과 마찬가지로, 앱의 React 코드가 서버를 사용하지 않는다면 이 취약점의 영향을 받지 않습니다. 마찬가지로 React Server Components를 지원하는 프레임워크, 번들러, 번들러 플러그인을 사용하지 않는다면 역시 영향이 없습니다.

React 팀은 치명적인 CVE 공개 이후 후속 취약점이 발견되는 것이 흔한 패턴이라고 설명합니다. 심각한 취약점이 공개되면 연구자들이 인접한 코드 경로를 면밀히 살펴보면서 초기 패치를 우회할 수 있는 변형된 공격 기법을 찾기 때문입니다. 이는 JavaScript 생태계만의 현상이 아니라 업계 전반에서 나타나는 패턴으로, 예를 들어 Log4Shell 사태 이후에도 커뮤니티가 최초 패치를 검증하는 과정에서 추가 CVE들이 보고된 바 있습니다. 이런 추가 공개가 번거롭게 느껴질 수 있지만, 일반적으로는 건강한 대응 사이클의 신호로 볼 수 있다고 덧붙였습니다.

영향을 받는 프레임워크와 번들러

일부 React 프레임워크와 번들러는 취약한 React 패키지에 직접 의존하거나, peer dependency로 포함하고 있었습니다. 영향을 받는 프레임워크·번들러는 다음과 같습니다.

  • Next.js
  • React Router
  • Waku
  • @parcel/rsc
  • @vite/rsc-plugin
  • rwsdk

업그레이드 절차는 지난 포스트의 안내를 참고하면 됩니다.

호스팅 프로바이더 임시 조치와 React Native

지난번과 마찬가지로 React 팀은 여러 호스팅 프로바이더와 협력해 임시 완화 조치를 적용했습니다. 다만 이는 임시방편일 뿐이므로 여기에 의존하지 말고 반드시 직접 업데이트해야 합니다.

React Native 사용자 중 모노레포를 쓰지 않거나 react-dom을 사용하지 않는 경우, package.json에 React 버전이 고정되어 있다면 별도 조치가 필요하지 않습니다.

React Native를 모노레포 환경에서 사용 중이라면, 다음 패키지가 설치되어 있는 경우에 한해 해당 패키지만 업데이트하면 됩니다.

  • react-server-dom-webpack
  • react-server-dom-parcel
  • react-server-dom-turbopack

이 조치만으로 보안 권고 사항을 충족할 수 있으며, react와 react-dom까지 업데이트할 필요는 없으므로 React Native에서 발생하는 버전 불일치 오류를 유발하지 않습니다.

취약점 상세 내역

High Severity: 다중 서비스 거부 (CVE-2026-23864)

  • Base Score: 7.5 (High)
  • 공개일: 2026년 1월 26일

보안 연구자들은 React Server Components에 여전히 추가적인 DoS 취약점이 존재한다는 사실을 발견했습니다. 이 취약점은 특수하게 조작된 HTTP 요청을 Server Function 엔드포인트로 전송함으로써 트리거되며, 취약한 코드 경로와 애플리케이션 구성, 코드에 따라 서버 크래시, 메모리 부족 예외, 과도한 CPU 사용 등을 유발할 수 있습니다.

1월 26일 배포된 패치가 이 DoS 취약점들을 완화합니다. 참고로 CVE-2025-55184를 해결하기 위한 최초 패치는 불완전했으며, 이로 인해 이전 버전들이 여전히 취약한 상태로 남아 있었습니다. 19.0.4, 19.1.5, 19.2.4 버전은 안전합니다.

High Severity: 서비스 거부 (CVE-2025-55184, CVE-2025-67779)

  • Base Score: 7.5 (High)

보안 연구자들은 악의적으로 조작한 HTTP 요청을 어떤 Server Functions 엔드포인트로든 전송할 수 있으며, React가 이를 역직렬화(deserialize)하는 과정에서 무한 루프가 발생해 서버 프로세스가 멈추고 CPU를 소진하게 만들 수 있다는 사실을 발견했습니다. 앱이 React Server Function 엔드포인트를 별도로 구현하지 않았더라도, React Server Components를 지원하기만 하면 여전히 취약할 수 있습니다.

이는 공격자가 사용자의 서비스 접근을 차단하고, 서버 환경 전체의 성능에 영향을 미칠 수 있는 공격 벡터를 만들어냅니다. 이번에 배포된 패치는 해당 무한 루프를 방지함으로써 이 문제를 완화합니다.

Medium Severity: 소스 코드 노출 (CVE-2025-55183)

  • Base Score: 5.3 (Medium)

한 보안 연구자는 취약한 Server Function으로 악의적인 HTTP 요청을 보내면 해당 Server Function의 소스 코드가 안전하지 않은 방식으로 반환될 수 있음을 발견했습니다. 이 공격이 성립하려면 명시적으로든 암묵적으로든 문자열화(stringified)된 인자를 노출하는 Server Function이 존재해야 합니다.

'use server';
export async function serverFunction(name) {
  const conn = db.createConnection('SECRET KEY');
  const user = await conn.createUser(name);
  return { id: user.id, message: `Hello, ${name}!` }
}

공격자는 다음과 같은 형태로 정보를 유출시킬 수 있습니다.

0:{"a":"$@1","f":"","b":"Wy43RxUKdxmr5iuBzJ1pN"}
1:{"id":"tva1sfodwq","message":"Hello, async function(a){console.log(\"serverFunction\");let b=i.createConnection(\"SECRET KEY\");return{id:(await b.createUser(a)).id,message:`Hello, ${a}!`}}!"}

보시다시피 함수 본문에 하드코딩된 'SECRET KEY' 문자열이 그대로 응답에 노출되는 것을 확인할 수 있습니다. 오늘 배포된 패치는 Server Function 소스 코드가 문자열화되는 것을 방지합니다.

다만 이 취약점을 통해 노출될 수 있는 것은 소스 코드에 하드코딩된 비밀값(secret)에 한정됩니다. process.env.SECRET과 같은 런타임 시크릿은 영향을 받지 않습니다. 또한 노출 범위는 해당 Server Function 내부 코드로 제한되지만, 번들러의 인라이닝(inlining) 정도에 따라 다른 함수들까지 포함될 수 있습니다. 반드시 프로덕션 번들을 기준으로 검증해야 합니다.

크레딧

정리

  • 지난주 공개된 React2Shell RCE 취약점에 대한 패치는 여전히 유효하지만, 그 패치를 검증하는 과정에서 DoS 3건(CVE-2025-55184, CVE-2025-67779, CVE-2026-23864)과 소스 코드 노출 1건(CVE-2025-55183)이 추가로 발견되었습니다.
  • 가장 중요한 실무 포인트는 "이미 업데이트했으니 끝"이 아니라는 점입니다. 19.0.3, 19.1.4, 19.2.3으로 업데이트했더라도 그 패치 자체가 불완전했으므로, react-server-dom-webpack/react-server-dom-parcel/react-server-dom-turbopack을 19.0.4, 19.1.5, 19.2.4로 다시 업데이트해야 합니다.
  • DoS 취약점은 조작된 HTTP 요청이 역직렬화 과정에서 무한 루프를 유발해 서버를 멈추게 하며, Server Function을 명시적으로 정의하지 않았더라도 RSC를 지원하는 환경이면 영향을 받을 수 있습니다.
  • 소스 코드 노출 취약점은 Server Function이 인자를 문자열 형태로 응답에 포함할 때 발생하며, 함수 내부에 하드코딩된 비밀값이 유출될 수 있습니다. process.env와 같은 런타임 시크릿은 대상이 아니지만, 코드에 민감한 값을 직접 박아 넣는 관행 자체를 재점검할 필요가 있습니다.
  • Next.js, React Router, Waku, @parcel/rsc, @vite/rsc-plugin, rwsdk 등 RSC를 사용하는 프레임워크·번들러 사용자는 모두 영향 범위에 포함되므로, 서버를 사용하지 않는 순수 클라이언트 앱이 아니라면 지금 바로 버전을 확인하고 업그레이드해야 합니다.
💡
RSC 기반 서비스를 운영 중인 팀이라면 이미 한 번 패치했더라도 재확인이 필요한 사안으로, 서버 다운과 소스 코드·시크릿 유출로 직결될 수 있어 즉각적인 버전 점검이 요구됩니다.
