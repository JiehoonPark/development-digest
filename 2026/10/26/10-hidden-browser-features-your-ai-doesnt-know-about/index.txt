16:T291c,<p>브라우저는 매년 조용히 새로운 기능을 추가하지만, 정작 개발자들은 이를 모르고 지나치는 경우가 많습니다. 이 글에서는 React Conf에 소개된 영상을 바탕으로, AI 코드 어시스턴트도 잘 모를 법한 브라우저 내장 기능들을 살펴봅니다. 체크아웃 버튼 중복 클릭을 막는 락(Lock) API부터 모바일에서 유용한 공유·진동·화면 잠금 방지 기능, 그리고 클립보드 API까지 코드와 함께 정리했습니다.</p>
<h3>가장 과소평가된 기능: Web Locks API</h3>
<p>가장 먼저 소개할, 그리고 개인적으로 가장 흥미로운 기능은 브라우저에 내장된 <strong>락(Lock)</strong> 기능입니다. 이름 그대로 특정 함수를 잠가서, 동일한 이름의 락을 가진 요청 중 단 하나만 동시에 실행되도록 보장해주는 기능입니다.</p>
<p>체크아웃 페이지를 떠올려보면 이해가 쉽습니다. 결제 버튼을 눌렀는데 처리에 시간이 걸리는 상황에서, 사용자가 실수로 버튼을 두 번 클릭하거나 아예 다른 탭에서 똑같은 요청을 보낼 수도 있습니다. 락을 걸어두면 이런 중복 실행을 원천적으로 막을 수 있습니다.</p>
<h4>동작 방식</h4>
<p>두 개의 탭에 동일한 이름의 락(&quot;checkout lock&quot;)을 걸어두면, 한쪽 탭에서 <strong>exclusive(배타적) 요청</strong>을 실행하는 동안 다른 탭의 요청은 대기(pending) 상태가 됩니다. 먼저 실행 중이던 락이 끝나야 비로소 대기 중이던 요청이 실행됩니다.</p>
<p>옵션으로 <code>ifAvailable</code>을 체크하면, 이미 락이 잡혀 있을 경우 대기하지 않고 즉시 &quot;unavailable&quot; 상태로 종료됩니다. 체크아웃처럼 중복 요청 자체를 아예 무시해야 하는 상황에 적합합니다.</p>
<p>반대로 <strong>shared(공유) 락</strong>을 사용하면 여러 요청이 동시에 실행될 수 있습니다. 서로 충돌 없이 동시 편집이 가능해야 하는 경우에 유용합니다.</p>
<p>이 외에도 몇 가지 흥미로운 동작이 가능합니다.</p>
<ul>
<li><strong>steal(탈취)</strong>: 이미 실행 중인 락을 강제로 빼앗아올 수 있습니다. 상대방이 실행하던 작업은 그대로 중단되고 락이 넘어옵니다.</li>
<li><strong>abort(취소)</strong>: AbortController를 연동해 대기 중이거나 실행 중인 락 요청을 즉시 취소할 수 있습니다.</li>
</ul>
<h4>코드 구현</h4>
<p>이 기능의 핵심은 <code>navigator.locks.request</code> 단 하나의 API로 끝납니다.</p>
<pre><code class="language-js">navigator.locks.request('lock-name', options, async (lock) =&gt; {
  // 락을 획득했을 때 실행할 코드
});</code></pre>
<ul>
<li>첫 번째 인자는 락의 <strong>이름</strong>입니다. 동일한 이름을 쓰는 요청끼리만 서로 락이 걸립니다.</li>
<li>두 번째 인자는 옵션 객체이며, 다음과 같은 속성을 가질 수 있습니다.</li>
<li><code>ifAvailable</code>: true/false</li>
<li><code>steal</code>: true/false</li>
<li><code>signal</code>: AbortController의 signal을 전달해 중간에 취소 가능</li>
<li><code>mode</code>: <code>'exclusive'</code> 또는 <code>'shared'</code></li>
</ul>
<pre><code class="language-js">const controller = new AbortController();

navigator.locks.request('lock-name', { signal: controller.signal }, async (lock) =&gt; {
  // ...
});

controller.abort(); // 락 요청을 즉시 취소</code></pre>
<p>콜백 함수에는 락 정보(<code>lock.mode</code>, <code>lock.name</code>)가 전달됩니다. 다만 주의할 점이 있는데, <code>ifAvailable: true</code>로 설정해도 콜백 함수 자체는 항상 호출됩니다. 단지 락을 실제로 획득하지 못했을 경우 <code>lock</code> 인자가 <code>null</code>로 전달될 뿐입니다. 따라서 콜백 안에서 먼저 락 획득 여부를 확인하고, 획득하지 못했다면 바로 <code>return</code>하는 방식으로 처리해야 합니다. 이 함수는 비동기 함수이므로 <code>await</code>와 함께 사용하면 됩니다.</p>
<p>또한 <code>navigator.locks.query()</code>를 호출하면 현재 걸려 있는 모든 락의 상태를 확인할 수 있습니다. 어떤 락이 <strong>held</strong>(실행 중)이고 어떤 락이 <strong>pending</strong>(대기 중)인지 손쉽게 파악할 수 있어서, 직접 큐를 구현할 필요 없이 대기열 관리를 간단하게 처리할 수 있습니다.</p>
<p>이 API는 과소평가된 기능이라고 생각하는데요, 보통은 개발자가 직접 구현해야 하는 동시성 제어 로직을 브라우저가 기본으로 제공해주기 때문입니다. 게다가 이미 3~4년 전부터 모든 주요 브라우저에서 사용 가능하기 때문에 호환성 걱정 없이 바로 써도 됩니다.</p>
<h3>모바일에서 빛을 발하는 기능들</h3>
<p>다음 세 가지는 구현 자체는 간단하지만, 특히 모바일 환경에서 진가를 발휘하는 기능들입니다.</p>
<h4>Web Share API</h4>
<p>버튼을 클릭하면 해당 플랫폼의 네이티브 공유 기능이 그대로 열립니다. 데스크톱 웹에서는 단순한 팝업 정도로 보이지만, 모바일에서 실행하면 우리가 평소 앱에서 보던 익숙한 공유 시트가 그대로 뜹니다. 즉, 별도의 네이티브 앱 없이도 웹에서 바로 공유 기능을 구현할 수 있다는 뜻입니다.</p>
<pre><code class="language-js">navigator.share({
  title: '제목',
  text: '설명',
  url: 'https://example.com',
});</code></pre>
<p>필자의 블로그 글마다 달려 있는 공유 버튼도 바로 이 API로 구현된 것으로, 제목·링크·URL·이미지 정보까지 전달되어 사용자가 원하는 앱으로 바로 공유할 수 있습니다.</p>
<h4>Vibration API</h4>
<p>브라우저에서 직접 디바이스를 진동시킬 수 있는 기능입니다. 당연히 데스크톱에서는 동작하지 않지만, 모바일에서는 실제로 진동이 울립니다.</p>
<pre><code class="language-js">navigator.vibrate(100); // 100ms 동안 한 번 진동
navigator.vibrate([100, 200]); // 100ms 진동 후 200ms 간격을 두고 다시 진동</code></pre>
<p>단일 숫자를 넘기면 해당 시간만큼 한 번 진동하고, 배열을 넘기면 진동과 정지 구간을 번갈아 설정할 수 있습니다.</p>
<h4>Wake Lock API</h4>
<p>화면이 자동으로 꺼지는 것을 막아주는 기능입니다. 필자는 최근 긴 시간에 걸쳐 데이터를 입력해야 하는 애플리케이션을 만들면서 이 기능을 사용했는데, 데이터 입력 페이지에 진입하면 화면 잠금을 막고, 페이지를 벗어나면 다시 잠금이 가능하도록 해제하는 식으로 활용했습니다.</p>
<pre><code class="language-js">const wakeLock = await navigator.wakeLock.request('screen');

// 필요 없어지면 해제
wakeLock.release();</code></pre>
<p><code>request('screen')</code>을 호출하는 시점부터 화면이 잠기지 않고, <code>release()</code>를 호출하면 다시 정상적으로 화면이 잠길 수 있게 됩니다. 다른 탭 등 외부 요인으로 락이 해제될 때를 대비해 이벤트 리스너를 등록할 수도 있어서, 상태 동기화도 어렵지 않게 처리할 수 있습니다.</p>
<h4>브라우저 지원 현황</h4>
<p>Share API와 Wake Lock API는 모든 주요 브라우저에서 100% 사용 가능하지만, Vibration API는 Chromium 기반 브라우저에서만 지원되며 Firefox와 Safari에서는 사용할 수 없다는 점을 기억해야 합니다.</p>
<h3>컬러 피커와 클립보드</h3>
<p>마지막으로 비교적 많이 알려진 기능이지만, 다시 한번 짚어볼 만한 것들입니다. <code>&lt;input type=&quot;color&quot;&gt;</code>를 사용하면 브라우저 내장 컬러 피커가 바로 열려서, 원하는 색상을 선택해 어디서든 입력값으로 활용할 수 있습니다.</p>
<p>클립보드 복사/붙여넣기도 브라우저 API로 간단히 구현됩니다.</p>
<pre><code class="language-js">navigator.clipboard.writeText(text);</code></pre>
<p>이 함수 하나로 원하는 텍스트를 클립보드에 기록할 수 있고, 색상 값을 바꿔서 복사 버튼을 누르면 변경된 값이 그대로 클립보드에 반영되어 붙여넣기할 수 있습니다.</p>
<h3>정리</h3>
<ul>
<li><strong>Web Locks API</strong>(<code>navigator.locks.request</code>)는 동일한 이름의 작업이 동시에 실행되는 것을 막아주는 기능으로, 체크아웃 중복 클릭 방지처럼 직접 구현하기 번거로운 동시성 제어를 브라우저가 대신 처리해줍니다. <code>exclusive</code>/<code>shared</code> 모드, <code>ifAvailable</code>, <code>steal</code>, <code>signal</code>(AbortController) 옵션을 조합해 다양한 큐잉·락 전략을 구현할 수 있고, <code>navigator.locks.query()</code>로 현재 락 상태(held/pending)를 조회할 수도 있습니다. 이미 3~4년간 전 브라우저에서 지원되는 안정적인 API입니다.</li>
<li><strong>Web Share API</strong>(<code>navigator.share</code>)는 네이티브 앱 없이도 모바일의 공유 시트를 그대로 띄워줍니다.</li>
<li><strong>Vibration API</strong>(<code>navigator.vibrate</code>)는 단일 시간 또는 배열로 진동 패턴을 지정할 수 있지만, Chromium 계열 브라우저에서만 동작합니다.</li>
<li><strong>Wake Lock API</strong>(<code>navigator.wakeLock.request('screen')</code>)는 특정 화면에서 자동 화면 잠금을 방지하고, <code>release()</code>로 해제할 수 있어 장시간 데이터 입력 등의 시나리오에 유용합니다.</li>
