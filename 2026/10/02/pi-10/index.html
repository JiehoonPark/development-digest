Pi 1.0 출시: 미니멀 에이전트 하네스의 진화와 새로운 패키지 Pi Durable

Pi 1.0

📅 2026-10-02📰 Hacker News (Top)
frontendtypescript

Earendil이 자사의 에이전트 하네스(agent harness) Pi의 정식 버전인 Pi 1.0을 출시했습니다. 전 세계 수십만 명이 매주 사용하고 있는 이 도구는, 수개월간 쌓인 이슈와 PR 피드백을 바탕으로 안정화 작업을 거쳐 이번에 1.0으로 올라섰는데요. 동시에 Pi의 철학을 터미널 밖, 코딩 에이전트 바깥의 영역으로 확장하는 실험적 패키지 Pi Durable도 함께 공개했습니다. 이 글에서는 Pi 1.0에 새로 들어간 기능들과, Pi Durable이 왜 별도 패키지로 분리되어 나왔는지를 정리해봅니다.

Pi가 지키려는 미니멀리즘

Pi는 "미니멀한 도구"라는 정체성으로 알려져 있습니다. 에이전틱 툴링 생태계는 매주 새로운 패턴과 기능이 쏟아지지만, Earendil 팀은 그 변화의 상당수가 오래 살아남지 못한다고 봅니다. 그래서 Pi는 어떤 기능이든 바로 받아들이지 않고, 그 기능이 실제로 입증될 때까지 기다린 다음에야 채택을 검토합니다. 이때 기준은 "그 기능이 가져오는 실질적인 효용 대 그것이 더하는 복잡성"의 저울질입니다. 이런 채택 프로세스가 Codemode와 MCP(Model Context Protocol)의 관계에 어떻게 적용되었는지는 Earendil이 별도 글로 다룬 바 있습니다.

이번 Pi 1.0은 바로 이 프로세스의 결과물입니다. 그동안 Pi는 각 주요 프로바이더의 최신 모델을 모두 지원하면서 전 세계 개발자들의 일상적인 코딩 에이전트로 자리 잡았고, 그 위에 다양한 에이전틱 애플리케이션을 쌓아올릴 수 있는 "초유연한(supermalleable)" 기반 역할을 해왔습니다. Pi 1.0에서는 여기에 다음 기능들이 새로 추가됩니다.

  • Codemode: MCP에 대한 네이티브 지원, 그리고 Jev나 이미지 모델처럼 LLM이 아닌 모델에 대한 지원
  • 가상 모델(virtual model)을 위한 익스텐션 지원
  • 지연 도구 로딩(Deferred tool loading)
  • Anthropic 모델을 위한 캐시 워밍(Cache warming)
  • 대화 중간 시스템 메시지 (지금까지의 트랜스크립트를 인지한 상태에서 프롬프트와 도구 구성을 바꾸는 기능)
  • 새로운 TUI 테마
  • 기본값으로 적용된 풀스크린 모드

Earendil 팀은 이 기능들을 몇 달에 걸쳐 검토하면서, 실제로 벽에 던져서 붙는 것들만 남겼다고 설명합니다. 그 과정에서 떨어져 나간 아이디어의 목록은 채택된 것보다 훨씬 길었다고 하는데요. 이렇게 걸러진 기능들을 한꺼번에 써보면 Pi가 한 단계 크게 도약한 느낌이 들면서도, 여전히 Pi 특유의 단순함을 잃지 않는다는 것이 팀의 설명입니다.

새 기능이 실제로 맞물리는 방식

각 기능 이름만 보면 추상적으로 느껴지지만, 이들은 서로 맞물려 하나의 워크플로를 만들어냅니다. Earendil이 제시한 데모 시나리오를 따라가 보면 흐름이 좀 더 명확해집니다.

먼저 Codemode를 활용하면 Pi는 일주일치 커밋 로그를 짧은 요약으로 압축하는 스크립트를 직접 작성해 실행합니다. LLM이 매 단계 함수 호출을 하는 대신, 코드를 써서 한 번에 처리하는 방식이죠.

더 나아가 Pi는 스스로 익스텐션을 작성하기도 합니다. 예시로 든 시나리오에서는, 계획(planning) 단계는 Claude Opus가 맡고 구현(implementation) 단계는 GPT 계열 모델이 맡는 가상 모델(virtual model)을 Pi가 직접 만들어내는데, 이때 두 단계 사이의 전환 시점을 판단하는 역할은 LLM이 아닌 모델인 Jev가 담당합니다. 이렇게 만든 익스텐션을 적용하려면 Pi를 재시작해 새 세션을 연 뒤 새로 추가된 라우터/auto 모델을 선택하면 됩니다. 실제 흐름은 다음과 같습니다.

  • 계획(planning)은 Claude Opus가 수행
  • Jev가 구현 단계로 넘어갈 시점을 포착해 GPT 6 Luna에게 작업을 넘김
  • ! 명령으로 완성된 스크립트를 실행
  • /session 명령으로 모델별 비용과 캐시 사용량을 분석

이 흐름에서 지연 도구 로딩은 필요한 시점에만 도구 정의를 불러와 불필요한 컨텍스트 낭비를 줄여주고, Anthropic 모델에 대한 캐시 워밍은 긴 세션에서 반복되는 프롬프트의 지연과 비용을 낮춰줍니다. 대화 중간 시스템 메시지는 지금까지 오간 트랜스크립트를 인지한 상태로 프롬프트나 도구 구성을 바꿀 수 있게 해주는데, 이는 위 시나리오처럼 계획에서 구현으로 역할이 전환되는 순간 시스템 지시를 갱신하는 데 쓰입니다.

터미널 밖으로: Pi Durable

Pi를 다듬어오는 과정에서 Earendil 팀은 한 가지를 깨달았습니다. Pi가 가진 특성 중 일부는 사람들이 실제로 쓰고 싶어하는 방식과 맞지 않았다는 것입니다. Earendil은 Pi의 미니멀리즘과 AI를 자유자재로 다루는 방식을, 코딩 에이전트의 범위 너머 그리고 터미널 바깥으로도 가져가고 싶어했습니다. 즉 Pi가 다양한 인터페이스(surface)에서 접근 가능해야 하고, 더 길게 이어지는 대화와 작업을 지원해야 한다는 것이죠. 한마디로 Pi는 더 "내구성(durable)" 있는 소프트웨어가 되어야 했습니다.

하지만 이를 위해 Pi 본체의 미니멀한 뿌리를 억지로 비틀어 다른 것으로 만들기보다는, 이 작업을 별도의 새 패키지로 분리해 오늘 함께 출시했습니다. 바로 Pi Durable입니다. Pi Durable은 장시간 실행되는 에이전틱 애플리케이션을 만들기 위한 새로운 기반(substrate)으로, 이런 애플리케이션을 만드는 개발자와 그 사용자 모두가 기저의 지능(intelligence)을 뛰어난 정교함으로 다루고 조종할 수 있게 해줍니다. Pi의 핵심 원칙인 미니멀리즘과 초유연성(supermalleability)을 그대로 공유하면서도, 이 원칙들을 새로운 차원으로 확장한 것이 특징입니다. Pi Durable을 어떻게 설계했는지에 대한 상세한 내용은 Earendil의 Mario가 별도 글로 다루고 있습니다.

설치 및 배포

Earendil은 Pi를 통해 인간의 주체성(human agency)을 강화하는 소프트웨어와 오픈 프로토콜을 만든다는 미션 아래 설립된 회사입니다. 이번 Pi 1.0과 Pi Durable 역시 그 연장선에 있는 결과물이며, 팀은 커뮤니티의 피드백을 계속 공개적으로 받아 함께 다듬어가겠다는 입장을 밝혔습니다.

Pi 1.0은 아래 명령으로 오늘부터 바로 설치할 수 있습니다.

curl -fsSL https://pi.dev/install.sh | sh

Windows에서는 다음과 같이 설치합니다.

powershell -c "irm https://pi.dev/install.ps1 | iex"

Pi Durable은 실험적 패키지로 npm을 통해 제공됩니다.

npm install @earendil-works/pi-durable @earendil-works/pi-ai @earendil-works/chord

두 프로젝트 모두 MIT 라이선스로 배포되며, 문서는 pi.dev에서, 소스 코드는 github.com/earendil-works/pi에서 확인할 수 있습니다.

정리

  • Pi 1.0은 "검증된 것만 천천히 채택한다"는 원칙을 지키며 Codemode(MCP 및 Jev·이미지 모델 같은 비LLM 모델 네이티브 지원), 가상 모델용 익스텐션 지원, 지연 도구 로딩, Anthropic 모델 캐시 워밍, 대화 중간 시스템 메시지, 새 TUI 테마, 기본 풀스크린 모드를 추가했습니다.
  • 이 기능들은 개별로도 의미가 있지만, "계획은 Claude Opus·구현은 GPT 계열·전환 판단은 Jev"처럼 서로 조합되어 하나의 가상 모델 워크플로를 만들어낼 때 진가를 발휘합니다.
  • Pi 본연의 미니멀리즘을 지키면서도 더 길게 이어지는 작업과 다양한 인터페이스 지원이 필요하다는 요구를 반영해, 별도의 실험적 패키지 Pi Durable을 분리 출시했습니다. 이는 Pi의 원칙을 공유하되 더 "내구성 있는" 에이전틱 애플리케이션을 위한 기반입니다.
  • Pi와 Pi Durable 모두 MIT 라이선스의 오픈소스이며, curl 스크립트 혹은 npm 설치로 바로 사용해볼 수 있습니다.

CLI 기반 코딩 에이전트를 실무에 쓰고 있거나 자체 에이전틱 툴을 만들고 있다면, Codemode를 통한 MCP/비LLM 모델 네이티브 지원과 가상 모델 익스텐션 패턴, 그리고 장시간 실행 애플리케이션을 위한 Pi Durable의 설계 방향을 참고할 만합니다.

💡
CLI 기반 코딩 에이전트나 자체 에이전틱 도구를 만드는 프론트엔드/풀스택 개발자에게, 기능을 신중히 걸러 채택하는 Pi의 설계 철학과 Codemode·가상 모델·Pi Durable 같은 구체적 패턴은 실무에 바로 참고할 수 있는 사례입니다.
