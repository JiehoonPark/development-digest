React Server Components에서 발견된 치명적 보안 취약점(CVSS 10.0), 즉시 업그레이드 필요
via React Blog
🔥오늘의 화제frontend

React Server Components의 react-server-dom-webpack, react-server-dom-parcel, react-server-dom-turbopack 패키지(19.0~19.2.0)에서 인증되지 않은 원격 코드 실행이 가능한 CVSS 10.0 등급의 치명적 취약점(CVE-2025-55182)이 발견되었습니다. Server Function을 직접 쓰지 않아도 RSC를 지원하는 프레임워크를 사용 중이면 영향을 받을 수 있으며, Next.js·React Router·Waku·RedwoodSDK 등 주요 프레임워크 전반이 영향을 받았습니다. React 팀은 신고 4일 만에 19.0.1, 19.1.2, 19.2.1 버전으로 패치를 공개했고, 이후 추가로 DoS 및 소스 코드 노출 취약점도 발견되어 계속 패치가 진행 중입니다.

💡
RSC 기반 프로덕션 서비스를 운영하는 프론트엔드/풀스택 개발자라면 CVSS 10.0 등급의 원격 코드 실행 취약점에 노출되어 있을 가능성이 높으므로, 사용 중인 패키지 버전을 즉시 점검하고 업그레이드해야 합니다.

React 19.3 출시: View Transitions와 Fragment Refs가 정식 기능으로
via React Blog
🔥오늘의 화제frontend

React 19.3이 npm에 배포되면서 작년 실험적 API로 소개됐던 View Transitions와 Fragment Refs가 정식 안정 기능이 됐습니다. View Transitions는 <ViewTransition> 컴포넌트로 enter/exit/update/share 애니메이션을 자동 처리하며, addTransitionType으로 동일 상태 업데이트에 다른 애니메이션을 지정하고 Suspense와 결합해 fallback·이미지·폰트 로딩까지 조율할 수 있습니다. Fragment Refs는 <Fragment ref={...}>를 통해 단일 부모가 없는 형제 그룹이나 ref를 노출하지 않는 컴포넌트에도 focus, 이벤트, Observer, 측정 등 공통 DOM 작업을 적용할 수 있게 합니다. 이 외에 React DOM의 Trusted Types 지원과 Server Components에서 <Context> 직접 렌더링 지원도 추가됐습니다.

💡
불필요한 래퍼 엘리먼트나 서드파티 라이브러리 수정 없이도 정교한 전환 애니메이션과 저수준 DOM 제어를 React 표준 API만으로 구현할 수 있게 되어, 애니메이션/로딩 UX 품질과 코드 유지보수성을 동시에 높일 수 있다.

RSC는 왜 번들러와 통합되는가
via Dan Abramov (overreacted)
frontend

React Server Components는 단순히 데이터가 아니라 코드 자체를 서버에서 클라이언트로 직렬화해야 하는 독특한 과제를 안고 있습니다. 코드를 문자열로 통째로 보내거나 모듈을 파일 단위로 하나씩 로드하는 방식은 비효율적이거나 워터폴을 유발하기 때문에, RSC는 Webpack·Parcel·Vite 같은 번들러와 바인딩을 맺어 이 문제를 해결합니다. Dan Abramov가 react-server/react-client 내부 구조와 serialize/deserialize API를 예시 코드로 짚어가며 그 원리를 설명합니다.

💡
RSC를 단순히 프레임워크 기능으로만 쓰는 게 아니라 내부 동작 원리까지 이해하면, Next.js 같은 프레임워크가 왜 특정 번들러에 의존하는지, 'use client' 경계가 왜 필요한지를 근본적으로 파악할 수 있어 디버깅과 아키텍처 설계에 도움이 됩니다.

CSS 애니메이션이 JS보다 부드러운 진짜 이유: 메인 스레드와 Web Animations API
via Josh W. Comeau
frontend

CSS 애니메이션이 JavaScript 애니메이션보다 부드러운 이유는 연산 비용 때문이 아니라 실행 스레드의 차이 때문입니다. CSS 트랜지션/키프레임은 메인 스레드와 분리된 별도 스레드에서 실행되지만, requestAnimationFrame 기반 JS 애니메이션은 React의 DOM 업데이트나 fetch 파싱 등과 메인 스레드를 공유합니다. Motion(구 Framer Motion)은 Web Animations API를 활용해 이 문제를 피하는 반면, GSAP은 더 강력한 기능을 위해 메인 스레드 실행을 택하는 트레이드오프를 취합니다.

💡
애니메이션 라이브러리를 선택할 때 '성능'의 실체가 무엇인지 정확히 이해하면, 스피너나 전환 효과가 버벅이는 문제를 근본적으로 진단하고 올바른 도구를 고를 수 있다.
