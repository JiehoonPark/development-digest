React 19.3 출시: View Transitions와 Fragment Refs가 정식 기능으로

React 19.3

📅 2026-10-28📰 React Blog
frontend

React 19 기능 중 "실험적"이라는 딱지를 달고 있던 두 가지가 드디어 정식 버전으로 승격됐습니다. 작년에 실험적 API로 소개됐던 View Transitions와 Fragment Refs가 React 19.3에서 안정 버전으로 npm에 배포됐는데요. 이번 글에서는 이 두 기능이 실제로 어떻게 동작하는지, 그리고 이번 릴리스에 함께 포함된 다른 변경 사항들은 무엇인지 정리해보겠습니다.

View Transitions

새로 추가된 <ViewTransition> 컴포넌트는 브라우저의 View Transition API를 활용해 엘리먼트가 나타나거나(enter), 사라지거나(exit), 이동하거나, 크기가 바뀔 때 애니메이션을 적용할 수 있게 해줍니다. UI의 일부를 애니메이션 대상으로 만들고 싶다면 그냥 <ViewTransition>으로 감싸면 됩니다.

import { ViewTransition } from 'react';

{isShowing && (
  <ViewTransition>
    <Component />
  </ViewTransition>
)}

이렇게 해두면, Transition으로 표시된 업데이트가 자식 컴포넌트의 스타일을 바꾸거나 ViewTransition을 마운트/언마운트시킬 때마다 React가 해당 변화를 애니메이션으로 처리합니다.

React는 트리가 어떻게 바뀌었는지에 따라 어떤 애니메이션을 실행할지 스스로 판단합니다.

  • enter: <ViewTransition>이 새로 추가될 때
  • exit: <ViewTransition>이 제거될 때
  • update: <ViewTransition>의 자식이 스타일이나 내용이 바뀔 때
  • share: 이름이 붙은 <ViewTransition>이 한 곳에서 제거되고 다른 곳에 추가될 때

여기서 중요한 점은, Transition으로 표시되지 않은 업데이트는 애니메이션이 트리거되지 않는다는 겁니다. 이런 업데이트는 긴급하게 즉시 UI에 반영돼야 하기 때문입니다. 반대로 startTransition 안의 상태 업데이트, <Suspense>가 콘텐츠를 드러낼 때, useDeferredValue로 인한 업데이트는 모두 View Transition 애니메이션을 유발합니다.

기본적으로 <ViewTransition>은 부드러운 크로스페이드로 애니메이션됩니다. View Transition Class를 전달하고 CSS로 애니메이션을 정의하거나, Web Animations API를 사용해 이벤트 prop(onEnter, onExit, onShare, onUpdate)으로 명령형으로 애니메이션을 트리거할 수도 있습니다.

현재 <ViewTransition>은 DOM에서만 동작하며, React Native 등 다른 플랫폼 지원은 작업 중이라고 합니다.

addTransitionType으로 애니메이션 커스터마이징하기

같은 상태 업데이트라도 상황에 따라 다른 애니메이션을 쓰고 싶을 때가 있습니다. 예를 들어 캐러셀을 앞으로 넘겨서 세 번째 슬라이드로 이동할 때는 오른쪽에서 왼쪽으로, 뒤로 넘길 때는 왼쪽에서 오른쪽으로 애니메이션돼야 하는데, 두 경우 모두 currentSlide를 3으로 설정하는 동일한 상태 업데이트입니다.

이럴 때 상태 업데이트와 함께 addTransitionType을 호출하면 해당 Transition이 왜 발생했는지에 대한 추가 정보를 넘길 수 있습니다.

function nextSlide() {
  startTransition(() => {
    addTransitionType('next');
    setCurrentSlide(c => c + 1);
  });
}
function previousSlide() {
  startTransition(() => {
    addTransitionType('previous');
    setCurrentSlide(c => c - 1);
  });
}

그리고 이 Transition 타입에 따라 서로 다른 애니메이션을 지정할 수 있습니다.

<ViewTransition
  enter={{
    'next': 'from-right',
    'previous': 'from-left',
  }}
  exit={{
    'next': 'to-left',
    'previous': 'to-right',
  }}>
  <Page />
</ViewTransition>

React는 모든 Transition Type을 브라우저의 view transition type으로 엘리먼트에 추가하기 때문에, CSS에서 :active-view-transition-type(...)을 사용해 애니메이션의 범위를 지정할 수도 있습니다.

Suspense와 함께 fallback, 이미지, 폰트 애니메이션하기

View Transitions의 가장 흥미로운 부분 중 하나는 Suspense와의 통합입니다. Suspense 경계를 <ViewTransition>으로 감싸면 자식이 드러날 때 애니메이션을 적용할 수 있습니다.

<ViewTransition>
  <Suspense fallback={<Loading />}>
    <Component />
  </Suspense>
</ViewTransition>

자식 로딩이 끝나면 React가 fallback에서 최종 콘텐츠로 넘어가는 update 애니메이션을 트리거합니다.

하지만 여기엔 함정이 있습니다. 이미 로드된 콘텐츠인데도 다시 보여줄 때마다 영상이 매번 들어오고 나가는 애니메이션이 반복되고, 처음 fallback이 나타날 때도 페이드인되는 걸 볼 수 있습니다. 일반적으로 Suspense와 함께 쓰는 애니메이션은 꼭 필요한 곳에만 아껴서 쓰고, 이미 캐시돼서 즉시 보여질 수 있는 UI에는 쓰지 않는 게 좋습니다.

Suspense로 애니메이션할 때 좋은 UX를 위한 원칙은 다음과 같습니다.

  • fallback은 애니메이션 없이 즉시 나타나야 한다
  • fallback은 애니메이션과 함께 최종 콘텐츠로 업데이트돼야 한다
  • suspend되지 않는 자식은 애니메이션 없이 즉시 나타나야 한다

이렇게 하면 이미 로드된 상태에서는 앱이 즉각 반응하는 느낌을 주면서, fallback에서 최종 콘텐츠로 넘어갈 때만 애니메이션으로 매끄럽게 처리할 수 있습니다. 앞의 예제를 고치려면 update를 제외한 모든 애니메이션을 비활성화하면 됩니다.

<ViewTransition update="auto" default="none">
  <Suspense fallback={<Fallback />}>
    <Component />
  </Suspense>
</ViewTransition>

이렇게 하면 버튼을 누르는 순간 fallback이 즉시 나타나 사용자 액션에 즉각 반응하는 느낌을 주고, 영상이 이미 로드된 다음에는 토글이 즉시 이뤄집니다. 원하는 효과에 따라 다른 패턴도 쓸 수 있으니 공식 문서의 Suspense 애니메이션 가이드를 참고하는 게 좋습니다.

fallback 애니메이션 외에도, View Transitions는 이미지나 폰트가 로드되는 동안 Suspense를 트리거하도록 opt-in하는 수단이기도 합니다. 브라우저 기본 동작대로라면 이미지나 폰트는 로드가 끝나는 시점에 따라 제각각 깜빡이며 나타나는데, 이를 피하고 컴포넌트가 필요로 하는 모든 리소스를 고려한 조율된 로딩 시퀀스를 만들 수 있습니다. 이미지나 폰트를 <ViewTransition> 안에 넣어두면 로딩 중에 Suspense가 트리거됩니다.

<ViewTransition>
  <Suspense fallback={<Fallback />}>
    <img src={imageSrc} />
    <style href={fontSrc} precedence="default">
      {`@font-face {
        font-family: 'Fancy';
        src: url(${fontSrc}) format('truetype');
        font-display: swap;
      }`}
    </style>
  </Suspense>
</ViewTransition>

이렇게 하면 데이터, 이미지, 폰트가 모두 로드될 때까지 컴포넌트 전체가 suspend 상태로 기다리게 만들 수 있습니다. 이미지·폰트·스타일시트 로딩 대기에 대한 더 자세한 내용은 Suspense 문서에서 확인할 수 있습니다.

Fragment Refs

컴포넌트의 DOM 노드를 더 낮은 수준에서 제어해야 할 때—예를 들어 이벤트 리스너를 붙이거나, 가시성을 관찰하거나, 포커스를 옮겨야 할 때—보통은 ref를 사용합니다. 하지만 다음과 같은 상황에서는 이게 까다로워집니다.

  • 단일 부모 없이 형제 엘리먼트 그룹을 렌더링하는 컴포넌트
  • ref prop을 다른 엘리먼트로 전달하지 않는 컴포넌트
function Component() {
  return (
    {posts.map(post => (
      <Heading key={post.id}>
        {post.title}
      </Heading>
    ))}
  )
}

ref를 걸기 위해 <div> 같은 래퍼를 추가하는 방법도 있지만, 이는 컴포넌트의 스타일이나 레이아웃을 망가뜨릴 수 있습니다. 게다가 컴포넌트가 ref prop을 노출하지 않는다면 해당 컴포넌트를 직접 수정해야 하는데, 직접 제어할 수 없는 외부 라이브러리의 컴포넌트라면 아예 불가능한 경우도 있습니다.

Fragment Refs는 이런 문제를 해결하기 위해, 어떤 React 컴포넌트가 무엇을 렌더링하든 상관없이 사용할 수 있는 공통 DOM 메서드 집합을 제공합니다. 19.3부터는 ref를 <Fragment>에 직접 전달해서 사용할 수 있습니다. 이 ref는 FragmentInstance를 제공하며, 이걸로 Fragment의 DOM 자식들을 다룰 수 있습니다.

function Component() {
  const fragmentRef = useRef(null);
  useEffect(() => {
    const fragmentInstance = fragmentRef.current;
    fragmentInstance.focus();
  }, []);
  return (
    <Fragment ref={fragmentRef}>
      {posts.map(post => (
        <Heading key={post.id}>
          {post.title}
        </Heading>
      ))}
    </Fragment>
  )
}

FragmentInstance는 자식들의 DOM 구조를 바꾸지 않으면서 이들을 하나의 그룹처럼 다룰 수 있게 해줍니다.

  • addEventListener, removeEventListener, dispatchEvent: 1단계 자식들에 대한 이벤트 관리
  • focus, focusLast, blur: 중첩된 자식들 사이에서 깊이 우선(depth-first)으로 포커스 이동
  • observeUsing, unobserveUsing: IntersectionObserver나 ResizeObserver 연결
  • getClientRects, getRootNode, compareDocumentPosition, scrollIntoView: Fragment의 1단계 자식들에 대한 측정 및 스크롤

즉, Fragment Refs를 사용하면 다른 컴포넌트의 내부 구현을 수정하거나 이미 만들어진 DOM 구조를 바꾸지 않고도 그 컴포넌트에 동작을 추가로 연결할 수 있습니다. 공식 블로그에서는 자식이 화면에 들어오고 나갈 때마다 콜백을 호출하는 InView 컴포넌트를 onChange prop과 함께 구현하는 예제도 소개하고 있습니다.

그 외 변경 사항

이번 릴리스에는 위 두 가지 외에도 몇 가지가 더 포함됐습니다.

  • React DOM: 브라우저의 Trusted Types를 지원합니다.
  • React Server Components: <Context>를 Server Component 안에서 직접 렌더링할 수 있게 됐습니다.

자세한 변경 내역은 공식 Changelog에서 확인할 수 있습니다.

정리

React 19.3은 지난해 실험적으로 공개됐던 두 가지 기능을 정식으로 안정화한 릴리스입니다.

  • View Transitions는 <ViewTransition> 컴포넌트로 브라우저 View Transition API를 감싸서, enter/exit/update/share 네 가지 상황에 따라 자동으로 애니메이션을 적용합니다. startTransition, <Suspense> reveal, useDeferredValue로 인한 업데이트만 애니메이션 대상이 되며, addTransitionType을 쓰면 같은 상태 업데이트라도 원인에 따라 다른 애니메이션(예: 캐러셀 좌/우 이동)을 지정할 수 있습니다.
  • Suspense와 결합하면 fallback에서 최종 콘텐츠로 넘어가는 전환을 자연스럽게 만들 수 있지만, 이미 로드된 콘텐츠까지 불필요하게 애니메이션되지 않도록 update="auto" default="none" 같은 패턴으로 범위를 제한하는 게 중요합니다. 같은 원리로 이미지나 폰트를 <ViewTransition>과 <Suspense>로 감싸면 리소스 로딩까지 조율된 시퀀스로 관리할 수 있습니다.
  • Fragment Refs는 <Fragment ref={...}>를 통해 단일 부모가 없는 형제 그룹이나 ref를 노출하지 않는 외부 컴포넌트에도 focus·이벤트·Observer·측정/스크롤 같은 공통 DOM 작업을 적용할 수 있게 해줍니다. 불필요한 래퍼 <div> 없이도 저수준 DOM 제어가 가능해진다는 점에서 실용적입니다.
  • 이 외에 React DOM의 Trusted Types 지원, React Server Components에서 <Context> 직접 렌더링 지원도 함께 추가됐습니다.

인터랙션 애니메이션과 로딩 UX를 세밀하게 다듬어야 하는 프로젝트라면 View Transitions를, 서드파티 컴포넌트나 복잡한 레이아웃에서 DOM 제어가 필요했던 프로젝트라면 Fragment Refs를 눈여겨볼 만합니다.

💡
불필요한 래퍼 엘리먼트나 서드파티 라이브러리 수정 없이도 정교한 전환 애니메이션과 저수준 DOM 제어를 React 표준 API만으로 구현할 수 있게 되어, 애니메이션/로딩 UX 품질과 코드 유지보수성을 동시에 높일 수 있다.
