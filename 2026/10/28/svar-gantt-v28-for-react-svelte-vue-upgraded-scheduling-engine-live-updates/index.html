SVAR Gantt v2.8 공개: React·Vue·Svelte용 스케줄링 엔진과 실시간 협업 기능 강화

SVAR Gantt v2.8 for React, Svelte, Vue: upgraded scheduling engine & live updates

📅 2026-10-28📰 Echo JS
frontend

SVAR는 React, Vue, Svelte용 Gantt 차트 컴포넌트를 만드는 팀인데요, 최근 공개한 v2.8은 단순한 업데이트를 넘어 제품의 성격 자체를 바꾸는 릴리스입니다. 그동안 SVAR Gantt PRO가 "일정을 보여주는 차트"였다면, 이번 버전부터는 실제 프로젝트 매니저들이 마주치는 복잡한 스케줄링 시나리오를 엔진 차원에서 처리할 수 있게 됐습니다. 이 글에서는 v2.8에 새로 들어온 스케줄링 엔진, 리소스 플래닝, 프로젝트 트래킹 기능과 오픈소스(MIT) 에디션에 추가된 기능들을 정리해보겠습니다.

업그레이드된 스케줄링 엔진

이번 릴리스의 핵심은 자동 스케줄링 엔진의 전면 개편입니다.

4가지 의존성 타입 전체 지원: 기존에는 Finish-to-Start(FS) 링크만 자동 스케줄링을 지원했는데, 2.8부터는 Start-to-Start(SS), Finish-to-Finish(FF), Start-to-Finish(SF)까지 모든 링크 타입에서 자동 스케줄링이 동작합니다. 각 링크 타입마다 지연(lag)도 적용할 수 있고, 네 가지 타입 모두 작업 날짜, 여유 시간(slack), 크리티컬 패스 계산에 반영됩니다. 실제 프로젝트에서 흔히 발생하는 "겹쳐서 진행되는 작업"을 그대로 모델링할 수 있다는 뜻입니다. 연결된 작업 하나가 바뀌면 엔진이 그에 종속된 작업들의 날짜를 자동으로 다시 계산합니다.

수동(Manual) 및 비활성(Inactive) 작업: 모든 작업이 자동 스케줄링의 대상이 되길 원하지 않을 때를 위해 두 가지 모드가 추가됐습니다. 수동 작업은 자동 스케줄링이 절대 건드리지 않고 위치가 고정되지만, 사용자가 드래그로 직접 옮기는 것은 가능합니다. 확정된 작업과 아직 계획 중인 작업을 구분하는 용도죠. 비활성 작업은 취소되었거나 보류된 작업을 나타냅니다. inactiveTasks 기능을 켜고 작업의 inactive 필드를 true로 설정하면 되는데, 차트에는 계속 보이지만 스케줄링, 크리티컬 패스, 리소스 부하, 진행률 추적에서는 제외됩니다. 작업이 재개되면 언제든 다시 활성화할 수 있습니다.

스케줄링 제약 조건(Constraints): 프로젝트 관리 도구라면 기본적으로 지원해야 할 6가지 제약 타입이 추가됐습니다. "다음 날짜 이후 시작(SNET)", "다음 날짜 이전 시작(SNLT)", "지정 날짜에 반드시 시작(MSO)", "다음 날짜 이후 종료(FNET)", "다음 날짜 이전 종료(FNLT)", "지정 날짜에 반드시 종료(MFO)"입니다. 작업별로 constraint 필드에 snet, snlt, fnet, fnlt, mso, mfo 값과 날짜를 함께 지정합니다. schedule={{ auto: true }}로 자동 스케줄링을 켜면 이 제약 조건이 링크와 함께 계산에 반영되므로, 수동으로 조정하지 않아도 납기일이나 계약상 마일스톤을 기준으로 계획이 자동으로 짜여집니다. 제약 조건도 다른 작업 데이터처럼 서버에 저장되기 때문에 새로고침 후에도 유지됩니다.

충돌 처리: 제약 조건이나 링크를 동시에 만족시킬 수 없는 상황이 생기면, 차트는 사용자가 원인을 추측하게 두지 않습니다. 충돌 목록(conflict list)이 어떤 작업이 영향을 받는지, 무엇이 막고 있는지 보여주고, 원클릭으로 해결할 수 있는 옵션(작업 재일정, 이동, 제약 제거, 링크 제거)을 제공합니다.

데드라인: 각 작업에 목표 종료일을 의미하는 데드라인을 지정할 수 있는데, FNLT 제약과 달리 일정 자체를 구속하지는 않습니다. 차트에 깃발 아이콘으로 표시되며, 작업이 늦어지면 경고 표시로 바뀝니다. deadline 필드로 설정하고 deadlines 속성으로 차트에 표시를 활성화합니다.

대규모 작업 성능 최적화: 자동 스케줄링과 크리티컬 패스 계산 성능이 대폭 개선되어, 자동 스케줄링을 켠 상태에서도 수천 개의 작업을 매끄럽게 다룰 수 있습니다. 작업을 드래그하면 연결된 작업들이 모두 재계산되어 함께 이동하는데, 의존성이 많은 대형 프로젝트에서도 드래그와 편집이 끊김 없이 동작합니다. 실제로 10만 개 작업으로 만든 자동 스케줄링 데모도 공개됐습니다.

리소스 플래닝 강화

스케줄링 엔진과 함께 리소스 관리 기능도 확장됐습니다.

리소스 기반 스케줄링: schedule.resourceCalendars로 활성화하는 기능으로, 작업 날짜가 작업 캘린더(없으면 전역 캘린더)와 배정된 인원의 리소스 캘린더를 조합해 계산됩니다. 작업 캘린더가 허용하고 배정된 인원 중 최소 한 명이라도 근무 가능한 날이면 작업이 진행되므로, 한 사람의 휴가 때문에 작업 전체가 멈추는 일이 없습니다.

리소스 히스토그램: 인원별 작업 부하를 용량(capacity) 차트 형태로 보여줘서, 셀마다 흩어진 시간 숫자를 읽는 것보다 과부하 인원과 기간을 한눈에 파악할 수 있습니다. 툴팁이 지원되고 차트 줌 레벨에 맞춰 자동 조정되므로 프로젝트 기간이 달라져도 워크로드를 쉽게 파악할 수 있습니다.

드래그 앤 드롭 배정: 목록이나 리소스 부하 뷰에서 인원을 작업에 드래그로 배정할 수 있고, 작업을 리소스 그룹 사이로 옮겨서 재배정할 수도 있습니다. 작업마다 폼을 채우는 대신 몇 번의 드래그로 인력 배치가 끝나고, 배정 정보가 스케줄링 엔진에 바로 반영되므로 날짜와 부하 뷰가 동시에 업데이트됩니다.

프로젝트 트래킹과 편집 기능

프로그레스 라인: 각 작업의 실제 진행률을 오늘 날짜(또는 지정한 기준일)와 비교해 보여주는 기능으로, progressLine 속성으로 켤 수 있습니다. 어떤 작업이 일정보다 앞서 있고 어떤 작업이 뒤처졌는지 한눈에 파악할 수 있습니다.

S-curve: sCurve 기능(scheduled, earned, baseline 커브 타입)을 사용하면 계획, 실제, 기준선(baseline) 진행률의 누적값을 타임라인 위에 곡선으로 표시합니다. 각 곡선은 0%에서 100%까지 상승하며 값은 호버 시 표시됩니다. 데이터를 따로 내보내 외부 도구로 차트를 그릴 필요 없이 컴포넌트 안에서 계획과 실제를 비교할 수 있습니다.

서브 그리드 패널: 상태나 비용 같은 작업 세부 정보를 메인 그리드의 컬럼이 아니라 타임라인 오른쪽의 별도 그리드 패널(section: "subGrid")로 분리해서 보여줄 수 있습니다. 작업 테이블은 간결하게 유지하면서 추가 필드는 한눈에 확인할 수 있는 구조인데, 패널은 크기 조절, 접기, 숨기기가 가능하고 좁은 화면에서도 레이아웃이 알아서 조정됩니다.

플레이스홀더 행: 그리드 맨 아래에 빈 행이 추가되는 placeholderRow 속성을 통해, 작업 에디터를 열지 않고도 인라인 편집 가능한 셀을 채우거나 차트에 직접 그려서 새 작업을 빠르게 만들 수 있습니다. 작업이 없는 행을 가로질러 드래그해서 일정을 지정하는, 기존에 있던 드래그-투-스케줄 인터랙션도 동일하게 작동합니다.

리소스/배정 정보 포함 익스포트: PDF, PNG, Excel 내보내기와 MS Project 가져오기/내보내기에 리소스와 배정 정보가 포함됩니다. 프로젝트 파일이 일정뿐 아니라 팀 구성 정보까지 함께 담기 때문에, 다른 도구로 옮길 때 팀 설정을 수작업으로 다시 만들 필요가 없습니다.

오픈소스(MIT) 에디션의 신규 기능

무료 MIT 에디션에도 중요한 업데이트 세 가지가 추가됐습니다.

포함형 종료일(Inclusive End Dates): 기존에는 작업 종료일이 다음 날의 시작 시점으로 표시됐는데, 새로 추가된 inclusiveEnd 속성을 사용하면 업무 사용자들이 날짜를 세는 방식대로 표시할 수 있습니다. 예를 들어 월요일에 시작하는 5일짜리 작업을 "월요일부터 토요일까지"가 아니라 "월요일부터 금요일까지"로 보여주는 식입니다. 이 규칙은 그리드, 작업 에디터, 툴팁에도 동일하게 적용됩니다.

외부에서 작업 드래그하기: 별도의 작업 목록이 있다면 이를 Gantt 차트로 드래그해서 백로그 항목을 계획된 작업으로 바로 전환할 수 있습니다. 드롭한 작업은 대상 작업 옆에 배치되거나, 대상이 요약(summary) 작업이면 그 안에 들어갑니다. 작업을 다시 입력하거나 링크를 새로 만들 필요 없이 백로그가 바로 계획으로 바뀌는 셈입니다.

서버 실시간 업데이트: 이번 릴리스에 새로 도입된 RemoteEvents 서비스는 다른 사용자가 저장한 변경 사항을 Gantt에 실시간으로 반영해서 공동 작업을 가능하게 합니다. 여러 사용자가 같은 프로젝트를 편집하면서 페이지 새로고침 없이 서로의 변경 사항을 실시간으로 볼 수 있습니다. 연결이 끊기면 이벤트 스트림이 자동으로 재연결되고 데이터를 다시 불러와야 한다는 신호를 보내므로, 불안정한 네트워크 환경에서도 세션이 유지됩니다.

설치 방법

MIT 라이선스 무료 에디션은 npm으로 바로 설치할 수 있습니다.

npm install @svar-ui/react-gantt
npm install @svar-ui/vue-gantt
npm install @svar-ui/svelte-gantt

PRO 에디션은 30일 무료 체험판으로 모든 신규 기능을 테스트해볼 수 있습니다. Svelte, React, Vue 세 가지 버전 모두 GitHub에서 확인할 수 있습니다.

정리

  • SVAR Gantt v2.8은 FS/SS/FF/SF 4가지 링크 타입 전체에 대한 자동 스케줄링과 크리티컬 패스 계산을 지원하면서, 수동/비활성 작업, 6종 제약 조건, 데드라인, 충돌 자동 감지까지 더해 단순 시각화 도구에서 실질적인 스케줄링 엔진으로 발전했습니다.
  • 리소스 캘린더 기반 작업 날짜 계산, 리소스 히스토그램, 드래그 앤 드롭 배정 기능으로 리소스 플래닝이 한층 강화됐고, 수천~수만 개 작업 규모에서도 자동 스케줄링 성능이 개선됐습니다.
  • 프로그레스 라인, S-curve, 서브 그리드 패널, 플레이스홀더 행, 리소스 포함 익스포트 등 프로젝트 트래킹·편집 편의 기능도 다수 추가됐습니다.
  • 무료 MIT 에디션에도 포함형 종료일, 외부 드래그 앤 드롭, 실시간 서버 업데이트(RemoteEvents) 기능이 새로 들어와 협업 시나리오를 지원합니다.
  • React, Vue, Svelte용 Gantt 컴포넌트를 찾고 있고 복잡한 일정 관리(의존성, 제약 조건, 리소스 배정)가 필요한 프로젝트라면, PRO 에디션의 30일 무료 체험판으로 이번 업데이트를 직접 확인해볼 만합니다.
💡
React/Vue/Svelte 환경에서 단순 시각화를 넘어 실제 프로젝트 관리 수준의 의존성·제약·리소스 스케줄링이 필요한 팀이라면, 직접 엔진을 구현하지 않고도 즉시 쓸 수 있는 선택지가 된다는 점에서 의미가 큽니다.
