React Server Components 치명적 보안 취약점(CVE-2025-55182) 긴급 패치 안내
via React Blog
🔥오늘의 화제frontend

React Server Function 엔드포인트의 페이로드 디코딩 과정에서 CVSS 10.0의 인증되지 않은 원격 코드 실행 취약점(CVE-2025-55182)이 발견되어 React 팀이 긴급 패치를 배포했습니다. react-server-dom-webpack, react-server-dom-parcel, react-server-dom-turbopack의 19.0~19.2.0 버전이 영향을 받으며, Next.js, React Router, Waku, Redwood SDK 등 RSC를 지원하는 주요 프레임워크 전반이 영향권에 있습니다. Server Function을 직접 구현하지 않았더라도 RSC를 지원하는 환경이면 취약할 수 있어 즉시 업그레이드가 권고됩니다.

💡
RSC를 사용하는 프로덕션 서비스라면 인증 절차 없이 서버가 원격 코드 실행 공격에 노출될 수 있는 최고 위험도 취약점이므로, 사용 중인 프레임워크와 번들러 버전을 즉시 점검하고 패치해야 합니다.

React 컴포넌트를 URL로 공유 가능하게 만드는 올바른 방법
via Sam Selikoff
▶영상frontend

검색 가능한 테이블 컴포넌트를 예시로, useEffect를 이용해 React state를 URL에 동기화하는 흔한 방식이 뒤로가기/앞으로가기 버그를 유발하는 과정을 보여줍니다. 근본 원인은 URL과 React state라는 두 개의 진실의 원천이 동시에 존재하는 것이며, 해결책은 React state를 제거하고 useSearchParams로 URL에서 값을 직접 파생시키는 것입니다. 이 패턴은 다크모드, 로컬 스토리지, GPS 위치 등 앱 외부 상태를 다룰 때도 동일하게 적용됩니다.

💡
URL 상태 동기화는 실무에서 매우 흔한 요구사항이지만 잘못 구현하면 브라우저 내비게이션이 깨지는 눈에 띄지 않는 버그로 이어지기 쉬우므로, 진실의 원천을 하나로 유지하는 사고방식은 React 앱의 안정성에 직접적인 영향을 준다.
