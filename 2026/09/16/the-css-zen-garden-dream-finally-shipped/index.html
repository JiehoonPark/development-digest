CSS Zen Garden의 꿈, 드디어 프로덕션에서 실현되다

The CSS Zen Garden dream, finally shipped

📅 2026-09-16📰 Hacker News (Top)
frontend

2008년, 대학을 갓 졸업했을 무렵 Dave Shea의 CSS Zen Garden을 처음 만났습니다. 하나의 HTML 파일을 오직 CSS만으로 완전히 다른 모습으로 바꿔낼 수 있다는 것을 보여준 프로젝트였는데요. 콘텐츠와 완전히 분리된 깔끔하고 재사용 가능한 디자인, 그 꿈의 편린을 처음 본 순간이었습니다.

문제는 실제 클라이언트 작업을 시작하는 순간 그 꿈이 무너졌다는 겁니다. CSS 변수도 없었고, 당시 CSS 속성만으로는 정교한 디자인을 온전히 표현할 수 없어서 서버 사이드 처리, 이미지, 테이블 기반 레이아웃, 그리고 온갖 편법에 의존해야 했습니다. 브라우저마다 렌더링 방식이 달라서 작업 시간의 상당 부분은 하나의 디자인을 모든 브라우저에서 동일하게 보이도록 맞추는 데 쓰였습니다. Zen Garden은 이론적으로 무엇이 가능한지 보여줬지만, 실제 프로덕션은 완전히 다른 이야기였습니다.

이 간극을 메우는 데 거의 20년이 걸렸고, 그마저도 대부분은 최근 몇 년 사이에 이루어졌습니다. Custom Properties 덕분에 브라우저가 직접 이해하는 변수를 쓸 수 있게 됐고, Grid와 Flexbox는 매체의 본질과 싸우지 않는 레이아웃을 가능하게 했습니다. 2008년에는 없었던 속성들이 이제 존재할 뿐 아니라, 충분히 일관되게 구현되어 있어서 더 이상 브라우저 차이를 우회하는 게 아니라 그 스펙 자체를 기준으로 디자인할 수 있게 됐습니다.

Firefox.com을 네이티브 CSS로 다시 짓다

이 간극은 이제 완전히 닫혔습니다. 프리프로세서와 각종 편법에 의존해야 했던 작업들을 이제는 모던 CSS가 네이티브로 처리해줍니다. Mozilla, 그리고 Lincoln Loop 팀과 함께 진행한 Firefox.com 리빌드 프로젝트에서, 필자는 전체 시스템을 프리프로세서 없이 순수한 모던 CSS만으로 구축했습니다.

Custom Properties는 디자인 파일에서 바로 추출(export)되고, 네이티브 CSS는 단 한 번만 작성되며 별도의 편법이 필요 없습니다. 이렇게 작성된 CSS는 모든 모던 브라우저에서 동작하고, 레거시 브라우저를 위해서는 최소한의 브랜드 스타일시트를 별도로 제공해 기본적인 접근성과 브랜드 아이덴티티만 유지하도록 했습니다.

이 프로젝트에서는 70개 이상의 컴포넌트와 25개의 페이지 템플릿으로 구성된 디자인 시스템을 구축했고, 이를 Wagtail 컴포넌트로 구현해 콘텐츠 팀이 엔지니어의 도움 없이도 페이지를 조립할 수 있도록 했습니다. 현재 이 사이트는 19개 로케일을 지원하고 있습니다.

그럼에도 남은 하나의 예외, PostCSS

한 가지 솔직하게 밝혀둘 부분이 있습니다. 실제로 프로덕션에는 PostCSS가 들어갔는데, 딱 하나의 역할만 맡고 있습니다. 바로 @import 구문을 인라인으로 풀어주는 작업입니다. 네이티브 @import는 일부 브라우저에서 여전히 성능 특성이 좋지 않은데, 이 정도 규모의 사이트에서는 아키텍처의 순수성보다 성능이 더 중요한 문제였습니다. 다만 작성되는 CSS 자체는 여전히 순수한 네이티브 CSS입니다. 어떤 구문도 유효성이나 의미를 갖기 위해 빌드 단계에 의존하지 않습니다. 빌드는 단지 브라우저가 순차적으로 요청했을 파일들을 미리 하나로 평탄화(flatten)해줄 뿐입니다.

이 구분은 누군가 어떤 프로젝트를 두고 "빌드 스텝이 없다"고 말할 때 꼭 짚어봐야 할 지점입니다. 중요한 건 우리가 작성하는 소스 코드가 브라우저가 실제로 이해하는 언어인지, 아니면 컴파일이 되어야만 존재 의미를 갖는 방언(dialect)인지 여부입니다.

이 작업이 특별했던 이유

Zen Garden이 그렸던 꿈이 마침내 프로덕션에서 실현된 셈입니다. 그것도 웹 표준을 이끌어온 대표 조직인 Mozilla와 함께 해냈다는 점이 큰 의미로 다가왔습니다. Firefox.com은 브라우저에 관한 사이트이고, 20년 동안 웹 플랫폼을 옹호해온 바로 그 조직이 그 플랫폼을 활용해 만든 사이트입니다. 정말로 플랫폼이 준비됐는지 검증하기에 이보다 더 적합한 곳은 없었을 겁니다.

그리고 결론부터 말하면, 준비되어 있었습니다.

이 여정에서 사고방식을 형성해준 이들에게 빚을 지고 있습니다. Nicole Sullivan, Rachel Andrew, Jen Simmons, Chris Coyier, 그리고 Mozilla 프로젝트를 연결해준 Kasey Kelly, 고향 선배인 Eric Meyer까지. 이들의 작업은 한 세대의 개발자들에게 CSS를 하나의 '시스템'으로 사고하도록 가르쳐줬습니다.

변하지 않는 흐름

이번 작업을 관통하는 하나의 흐름이 있습니다. 팀이 빠르게 움직이면서도 일관성을 유지할 수 있게 해주는 디자인 시스템이라는 주제인데요, 그 빌딩 블록이 순수 CSS든, Tailwind든, shadcn/ui든 본질은 다르지 않습니다. 도구는 몇 년마다 바뀌지만, 변하지 않는 가치는 하나입니다. 바로 '올바른 방법'이 곧 '쉬운 방법'이 되는 시스템, 그리고 디자이너의 결정이 프로덕션에 도달하기까지 세 번씩 번역을 거치지 않아도 되는 시스템의 가치입니다.

정리

  • 2008년 CSS Zen Garden이 보여준 "CSS만으로 완전한 디자인 분리"라는 이상은 당시 브라우저 환경과 CSS 명세의 한계 때문에 실제 프로덕션에서는 구현 불가능했습니다.
  • Custom Properties, Grid, Flexbox가 안정적으로 자리잡으면서 이 간극이 최근 몇 년 사이 실질적으로 메워졌고, Firefox.com 리빌드는 이를 증명하는 실전 사례입니다.
  • 70개 이상 컴포넌트, 25개 템플릿, 19개 로케일 규모의 사이트를 프리프로세서 없이 네이티브 CSS만으로 구축했고, 콘텐츠 팀이 Wagtail 컴포넌트를 통해 엔지니어 없이 페이지를 조립할 수 있는 구조를 만들었습니다.
  • 유일한 예외는 @import 인라인화를 위한 PostCSS 사용이었는데, 이는 성능 최적화를 위한 빌드 단계일 뿐 CSS 문법 자체에는 영향을 주지 않는다는 점에서 "노 빌드"의 진짜 의미(브라우저가 이해하는 언어로 작성했는가)를 짚어볼 필요가 있습니다.
  • 결국 핵심은 특정 도구(순수 CSS, Tailwind, shadcn/ui 등)가 아니라, 올바른 선택이 곧 쉬운 선택이 되고 디자이너의 의도가 왜곡 없이 프로덕션까지 전달되는 디자인 시스템 자체에 있습니다.
💡
프리프로세서와 각종 CSS 편법에 익숙한 프론트엔드 개발자라면, 모던 CSS 명세만으로 대규모 다국어 사이트와 디자인 시스템을 실제로 구축할 수 있다는 실전 사례를 통해 자신의 스택을 재점검할 계기를 얻을 수 있습니다.
