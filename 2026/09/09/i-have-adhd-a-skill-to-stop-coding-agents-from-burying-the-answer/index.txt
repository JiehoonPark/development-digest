<h3>10가지 규칙</h3>
<p>이 스킬의 핵심은 <code>SKILL.md</code>에 정리된 10개의 규칙입니다. 원문에 명시된 항목은 다음과 같습니다.</p>
<ul>
<li>다음 행동을 먼저 제시한다 (Lead with the next action)</li>
<li>여러 단계로 이루어진 작업은 번호를 매긴다 (Number multi-step tasks)</li>
<li>구체적인 다음 단계 하나로 마무리한다 (End with one concrete next step)</li>
<li>곁가지를 억제한다 (Suppress tangents)</li>
<li>매 턴마다 현재 상태를 다시 알려준다 (Restate state every turn)</li>
<li>시간 추정은 구체적으로 한다 — &quot;조금&quot;이 아니라 몇 분 단위로 (Specific time estimates)</li>
<li>성과를 눈에 보이게 한다 (Make wins visible)</li>
<li>에러는 담담하게 전달한다 (Matter-of-fact errors)</li>
<li>목록은 5개 항목으로 제한한다 (Cap lists at 5 items)</li>
<li>서두, 요약 반복, 마무리 인사를 넣지 않는다 (No preamble. No recap. No closers.)</li>
</ul>
<p>이 규칙들은 저자가 밝히듯 J. Russell Ramsay와 Anthony L. Rostain의 저서 <em>The Adult ADHD Tool Kit</em>에서 아이디어를 빌려왔습니다. 다만 원래는 사람이 하루 일정을 조직화하는 데 쓰이는 원칙인데, 이를 &quot;LLM이 어떻게 응답해야 하는가&quot;에 맞게 변형한 것이라고 설명합니다.</p>
<h3>설치와 커스터마이징</h3>
<p>설치는 CLI 프롬프트에 아래 문구를 붙여넣는 방식으로 이루어집니다.</p>

<pre><code>claude plugin uninstall i-have-adhd # drop the upstream copy first:

<h3>정리</h3>
<ul>
<li><code>i-have-adhd</code>는 코딩 에이전트의 응답에서 &quot;칭찬 → 배경 설명 → 완곡한 제안 → 곁가지 → 마무리 인사&quot;라는 전형적인 군더더기 구조를 걷어내고, 실행 가능한 다음 행동을 첫 문장에 배치하도록 강제하는 스킬입니다.</li>
<li>핵심 규칙은 10가지로, 행동을 먼저 제시하고, 다단계 작업은 번호를 매기며, 목록은 5개로 제한하고, 서두·요약·마무리 인사를 없애는 것이 골자입니다.</li>

<li>규칙은 <code>SKILL.md</code> 하나로 정의되어 있어 포크 후 자신의 워크플로우에 맞게 쉽게 변형해서 재설치할 수 있습니다.</li>
