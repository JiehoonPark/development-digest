15:T1582,<p>CSS를 오래 써온 개발자라도 매번 MDN을 열어봐야 하는 속성들이 있습니다. Kevin Powell이 진행하는 프론트엔드 버전 &quot;Family Feud&quot;에서는 실제로 개발자 100명에게 &quot;항상 문법을 찾아봐야 하는 CSS 속성이 뭔가요?&quot;라고 물어본 설문 결과를 두고 퀴즈를 진행했는데요. Michael Andreuzza가 추측을 하고 Kevin이 실제 순위를 공개하는 방식으로 진행된 이 대화에서, 실무 개발자들이 여전히 어려워하는 CSS 문법이 무엇인지 흥미로운 인사이트를 얻을 수 있었습니다.</p>
<h3>압도적 1위: Grid</h3>
<p>Michael이 가장 먼저 떠올린 답은 grid였고, 특히 <code>grid-template-areas</code> 같은 문법을 예로 들었습니다. 실제로 이 답이 설문에서 1위를 차지했습니다. Grid 관련 답변들은 하나의 그룹으로 묶였는데, 그만큼 grid-template-columns, grid-template-areas 같은 문법이 직관적이지 않고 매번 찾아봐야 한다는 공감대가 크다는 뜻이겠죠.</p>
<h3>의외의 2위: 그라디언트(Gradients)</h3>
<p>Michael이 그다음으로 언급한 건 그라디언트 문법이었는데, Kevin은 &quot;이건 의외였다&quot;면서도 실제로 2위에 오른 답이라고 밝혔습니다. <code>linear-gradient()</code>, <code>radial-gradient()</code> 등의 문법에서 색상 정지점(color stop)의 순서와 각도 표기 방식이 헷갈리기 쉬운 부분인데, 개발자들 사이에서 grid 다음으로 많이 검색되는 문법이라는 점이 흥미롭습니다.</p>
<h3>순위에 들지 못한 답변들</h3>
<p>퀴즈 형식답게 오답도 여럿 나왔습니다.</p>
<ul>
<li><strong>상대 색상 문법(relative color syntax) / color-mix()</strong>: Michael은 최신 CSS 색상 문법을 유력한 답으로 꼽았지만, 실제로는 Top 10에도 들지 못했습니다. Kevin은 &quot;다들 나보다 색상 문법을 잘 다루나 보다&quot;며 놀라워했습니다.</li>
<li><strong>margin/padding 축약형(top-right-bottom-left 순서)</strong>: 초보자들이 헷갈릴 법한 답이었고 설문에 일부 답변이 있었지만, Top 10에는 들지 못했습니다.</li>
<li><strong>transform / translate</strong>: Michael의 마지막 추측이었지만, Top 5에는 들지 못했다고 확인됐습니다.</li>
<li>그 외에도 <code>interpolate-size</code>, <code>allow-discrete</code> 같은 키워드 값들이나, <code>justify-content</code>/<code>align-items</code>의 값 종류, 포지셔닝 관련 답변들이 소수 있었지만 순위권에는 들지 못했습니다. 다만 Grid가 상위권이라면 Flexbox도 비슷한 이유로 자주 언급됐을 거라는 두 사람의 추측도 있었습니다.</li>
</ul>
<h3>배경(background) 축약형</h3>
<p>두 사람이 순위 하위권부터 공개하기 시작하면서 나온 답은 background 축약 속성이었습니다. 이는 그라디언트와 비슷한 맥락으로, 설문 응답 중 상당수가 사실 background 축약형 문법을 언급한 것으로 나타났습니다. <code>background: color image position/size repeat origin clip attachment</code> 처럼 여러 값을 한 줄에 순서대로 나열해야 하는데, 이 순서를 지키지 못하면 스타일이 깨지기 때문에 실무에서 계속 검색해보게 되는 속성이라는 데 두 사람 모두 공감했습니다.</p>
<h3>진짜 의외의 상위권: box-shadow</h3>
<p>Kevin이 가장 예상치 못했다고 밝힌 답은 box-shadow였습니다. 순위권에 들 거라고 전혀 생각하지 못했는데 실제로는 상위에 랭크되어 있었다고 하는데요. 이유를 짚어보면 명확합니다. <code>box-shadow</code>는 X 오프셋, Y 오프셋, blur 반경, spread 반경, 그리고 색상까지 값 4~5개를 순서대로 나열해야 하는 속성입니다. 값의 개수도 많고 순서를 외우기도 애매해서, 매번 문법을 다시 찾아보게 되는 대표적인 속성이라는 데 두 사람 모두 고개를 끄덕였습니다.</p>
<h3>정리</h3>
<p>이번 퀴즈에서 확인된 핵심은, CSS에서 개발자들이 어려워하는 지점이 새롭고 실험적인 기능이 아니라 여러 값을 정해진 순서로 나열해야 하는 축약형(shorthand) 문법에 몰려 있다는 점입니다.</p>
<ul>
<li><strong>1위 Grid</strong>, <strong>2위 그라디언트</strong>가 확인됐고, <strong>background 축약형</strong>과 <strong>box-shadow</strong>도 상위권에 올랐습니다.</li>
<li>반면 relative color syntax, margin/padding 축약형, transform/translate처럼 비교적 최신이거나 익숙하다고 여겨질 만한 문법들은 오히려 순위 밖이었습니다.</li>
<li>공통점은 grid-template-areas, gradient의 color stop, background의 다중 값 순서, box-shadow의 X/Y/blur/spread/color 순서처럼 &quot;값이 여러 개고 순서가 중요한&quot; 문법일수록 검색 빈도가 높다는 것입니다.</li>
</ul>
