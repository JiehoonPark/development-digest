채팅을 위해 만들어진 차트: dbt Charts가 BI를 다시 언번들링하는 방법

Charts built for Chat

📅 2026-09-15📰 Hacker News (Top)
frontend

AI 에이전트에게 "이 데이터로 차트 좀 만들어줘"라고 채팅으로 요청하면, 자연스러운 대시보드가 뚝딱 만들어지는 시대가 왔습니다. 하지만 그렇게 만들어진 결과물을 들여다보면 HTML, CSS, JavaScript에 차트 라이브러리 몇 개, 여기에 React나 Streamlit 앱까지 뒤섞인 파일 더미인 경우가 많은데요. dbt Labs가 오픈소스로 공개한 dbt Charts는 이 문제를 정면으로 다룹니다. "채팅으로 만든 대시보드도 거버넌스가 가능해야 한다"는 문제의식에서 출발해, 대시보드를 선언형 YAML 언어로 표현하는 새로운 접근을 제시합니다.

에이전트 시대, BI 도구는 왜 삐걱거리는가

에이전트에게 리포트를 하나 만들어달라고 하면 기본적으로 여러 파일이 딸려 나옵니다. HTML, CSS, JavaScript는 물론이고 차트 라이브러리 몇 개, 그리고 라이브 서비스가 필요해지는 순간 React나 Streamlit 앱까지 붙습니다. 문제는 결과값을 원본 데이터까지 추적하려면 여러 언어와 파일을 넘나들어야 한다는 점입니다. 사람이 감사(audit)하기도 느리고, 에이전트 입장에서도 매번 코드를 수정할 때마다 시간과 토큰을 잡아먹습니다.

반대로 기존 BI 도구들은 UI 중심 앱에 코파일럿을 얹는 방식을 택했습니다. 이 방식은 AI를 통제된 레일 위에 두긴 하지만, 그 레일이 너무 좁습니다. 에이전트는 UI가 노출하는 기능 안에서만 움직일 수 있으니까요.

결국 지금 우리에게 남은 선택지는 두 가지뿐입니다. 코드의 자유로움 대신 지저분함을 감수하거나, BI 도구의 통제 대신 좁은 기능 범위를 감수하거나. dbt Charts는 이 사이에서 제3의 선택지를 만들려는 시도입니다.

BI의 언번들링, 그 다음 단계

dbt Labs 창업자 Tristan Handy는 최근 글 "BI's Second Unbundling"에서 BI 도구의 역사를 이렇게 정리합니다. 데이터 업계 초창기 BI 도구는 풀스택이었습니다. 데이터 수집, 변환, 컴퓨팅, 캐싱, 시맨틱, 시각화, 인증까지 모든 것이 하나의 제품 안에서 이루어졌죠. MicroStrategy나 Cognos 같은 도구는 단순한 시각화 도구가 아니라 통합 데이터 플랫폼이었습니다.

그러다 2015년에서 2022년 사이 모던 데이터 스택이 등장하면서, BI 번들 안에 있던 인프라 레이어들이 하나씩 뜯겨 나가 전문 인프라로 독립했습니다. 컴퓨팅은 빅5 클라우드로, 수집(ingestion)은 Fivetran으로, 변환(transformation)은 dbt로 넘어갔죠. 그 결과 BI 도구에 남은 건 시각화, 대화형 분석 인터페이스, (가끔은) 시맨틱 정의, 인증·접근 관리, 웹 호스팅이었습니다.

이렇게 언번들링을 겪고도 남은 게 지금 우리가 아는 BI 도구이고, 그중에서도 가장 큰 비중을 차지하는 게 차트입니다. 차트가 UI 안에 계속 남아 있었던 데는 이유가 있습니다. 대부분의 사람에게는 YAML을 쓰는 것보다 클릭하는 게 더 빠르니까요. 하지만 이제 점점 더 많은 차트가 사람이 아니라 에이전트에 의해 만들어지고 있습니다. 프론트엔드와 모든 것의 사용자가 점점 채팅 에이전트로 바뀌면서 이 선호도가 뒤집힙니다. 에이전트는 코드, SQL, Git에는 능숙하지만 남이 만든 UI 앞에서는 서투릅니다. 그러니 차트도 에이전트가 일하는 곳, 즉 코드로 옮겨가야 한다는 것이 dbt Charts의 논리입니다.

차트를 BI 도구 밖으로

dbt Charts는 BI 언번들링의 다음 단계로, 차트를 BI 도구에서 떼어내 코드 안으로, 정확히는 새로운 구조화된 YAML 언어 안으로 옮깁니다. 파일 하나로 완전한 인터랙티브 대시보드를 선언할 수 있고, 그 파일은 사람이 감사하기 쉬운 형태를 유지합니다. 에이전트와 자유롭게 채팅해서 만든 결과물이 코드의 자유로움을 가지면서도 읽기 쉬운 상태로 남는 것이죠.

이 언어에서 SQL은 여전히 "어떤 데이터를 보고 싶은가(WHAT)"를 선언하는 역할을 맡고, 이를 YAML로 감싸서 "어떻게 보고 싶은가(HOW)"를 선언합니다. dbt Labs는 이 언어를 몇 가지 핵심적이고 확장 가능한 요소들로 오랜 시간 다듬었다고 밝히는데요. 표현할 수 있는 것은 깊으면서도, 조직화하고 읽기는 쉽게 만들었다는 겁니다. YAML이 감싸는 것은 SQL만이 아닙니다. 산문은 Markdown이 담당하고, dbt에서처럼 변수와 매크로는 Jinja가 담당합니다.

간단한 예시를 보면 변수(UI 필터) 하나, 쿼리 하나, 차트 하나로 구성됩니다.

variables:
  status:
    column: main.documents.status
queries:
  doc_growth: |
    SELECT DATE_TRUNC('month', created_at) AS month,
           SUM(COUNT(*)) OVER (ORDER BY month)
           AS num_docs
    FROM main.documents
    WHERE {{ filter('status', status) }}
    GROUP BY 1
charts:
  growth:
    title: Documents created, all time
    type: area
    query: doc_growth
    x: month
    y: num_docs
rows:
  - growth

이 파일 하나가 대시보드 전체입니다. CLI는 이 보드 파일을 정적 SVG로 렌더링할 수도 있고, HTML, PNG, PDF, 심지어 터미널로도 렌더링할 수 있습니다. 로컬 노트북이든 CI 환경이든 상관없고, 여러 보드 파일이 모인 폴더를 사이트로 서빙할 수도 있습니다.

dct render charts/documents.yml --format svg # or html, png, pdf, terminal
dct serve

이 몇 안 되는 요소들이 표현할 수 있는 범위는 상당히 깊습니다. 현재 1,100개가 넘는 설정 옵션이 존재하고, 16가지 차트 타입과 이들을 조합해 만드는 복합 차트도 지원합니다. 잘 만들어진 언어답게 복잡한 레이아웃과 시각적 표현도 소화할 수 있죠.

다만 이런 옵션을 일일이 손으로 설정할 일은 드뭅니다. 스타일은 계층적으로 상속됩니다. 차트는 보드로부터, 보드는 테마로부터 스타일을 물려받고, 테마는 한 줄만 바꾸면 전환됩니다. 보드는 다른 보드를 extends로 확장할 수도 있어서, 회사의 표준 스타일이나 표준 리포트를 한 번 작성해두면 어디서든 상속해서 쓸 수 있습니다. 덕분에 보드 파일은 짧게 유지되고, 테마 적용 비용도 낮아집니다.

dbt와의 깊은 통합

dbt Charts를 dbt 프로젝트 없이 단독으로 쓸 수도 있지만, dbt 프로젝트와 함께 쓸 때 더 많은 것이 열립니다. 차트 레이어가 변환 레이어 바로 위에 놓이기 때문에, 통합이 깊을수록 두 레이어를 함께 바꾸기가 쉬워집니다.

dbt Charts를 사용하면 charts/ 디렉터리가 models/ 디렉터리와 같은 Git 저장소 안에 나란히 위치합니다. 그러면 모델 하나를 바꾸고 그에 딸린 차트를 바꾸는 작업이 하나의 브랜치, 하나의 CI 실행을 통해 배포되고, 문제가 있으면 프로덕션에 도달하기 전에 걸러집니다.

your_dbt_project/
  .git/
  dbt_project.yml
  models/
  charts/ # new folder in a dbt repo for your dashboards
    revenue.yml

쿼리는 ref()를 통해 모델에 접근하고, 이는 dbt 매니페스트를 통해 해석됩니다. 즉 모델 이름이 바뀌거나 컬럼이 사라지면, dbt run으로 웨어하우스를 다시 빌드하기 전에 해당 문제를 일으킨 풀 리퀘스트 단계에서 이미 실패합니다.

dbt parse && dct validate charts/

dbt Semantic Layer 지원도 예정되어 있어서, 보드가 SQL을 다시 작성하지 않고도 프로젝트에 정의된 메트릭을 그대로 사용할 수 있게 될 예정입니다. (관련 논의는 dbt-labs/dbt-charts#1 이슈에서 진행 중입니다.)

채팅을 위해 설계된 검증 시스템

에이전트는 생각보다 상황 인지 능력이 떨어질 때가 많아서, 촘촘한 피드백 루프가 있을 때 가장 잘 작동합니다. dbt Charts는 YAML과 SQL을 모두 엄격하게 검증하고, 누군가 보드를 보기 전에 문제를 미리 잡아내는 광범위한 시각화 체크 기능을 제공합니다.

$ dct render charts/revenue.yml
WARN-BAR-BAND-WIDTH-TOO-NARROW
  182 bands x 2 series across 640px
  Fix: roll up to a coarser grain.

WARN-TABLE-COLUMNS-OVERFLOW
  Table needs 980px but only 640px is available.
  Fix: drop columns or widen the slot.

가령 640px 너비에 182개 밴드와 시리즈 2개를 욱여넣으려 하면 막대가 너무 좁아진다고 경고하고, 테이블이 필요로 하는 폭이 실제 사용 가능한 폭보다 넓으면 컬럼을 줄이거나 슬롯을 넓히라고 알려주는 식입니다. 이런 검증 루프는 사람이 아니라 에이전트가 반복적으로 코드를 고치는 워크플로우에 특히 유용합니다.

디자인: 대시보드 시대 이전으로 거슬러 올라가기

dbt Labs는 dbt Charts가 dbt가 그랬던 것처럼 이 레이어의 오픈 표준 언어가 되기를 바란다고 밝힙니다. 사람과 AI가 함께 만들어가는 미래를 염두에 두고 설계했고, 흔한 대시보드 그리드처럼 보이지 않기를 원했습니다. 이를 위해 데이터 그래픽 디자이너이자 저자, 역사학자인 RJ Andrews를 영입해 차트 디자인을 맡겼습니다. 그가 가진 차트 역사에 대한 이해가 결과물을 새롭게 느껴지게 만드는 요소로, 대시보드 시대를 넘어 사람들이 정성껏 손으로 차트를 그리던 시절의 감각까지 참고했다고 합니다.

많은 도구들이 카드와 박스로 정렬을 흉내 내지만, 그 대가로 시각적 노이즈가 늘고 공간이 낭비됩니다. dbt Charts 팀은 모든 차트의 간격, 크기, 레이아웃을 개별적으로도, 이웃한 차트와의 관계에서도 세심하게 조율했습니다. 그 결과물은 지금의 BI보다 한 단계 위처럼 느껴지는 응집력 있는 차트 시스템이라고 소개합니다.

dbtCharts.com: dbt Charts 위에 지어진 BI 플랫폼

오픈소스 언어와 함께 dbt Labs는 dbtCharts.com도 퍼블릭 베타로 공개했습니다. 이는 "나머지 BI"를 담당하는 호스팅 플랫폼입니다. 차트 부분이 오픈소스 언어로 빠져나갔으니, 플랫폼에 남은 건 주로 호스팅, 접근 제어, UI입니다. 이런 요소들은 본질적으로 언번들링이 어렵거나, 적어도 언번들링해서는 안 되는 부분이라 오픈소스 언어 위에 플랫폼이 이를 처리하는 구조입니다.

플랫폼은 웨어하우스에 연결되고, 대화형 분석(conversational analytics), 마무리 작업을 위한 비주얼 에디터, 버전 히스토리, 그리고 사용자·그룹 단위 권한이 적용된 공유 기능을 제공합니다. 덕분에 보드를 읽는 사람이 웨어하우스 로그인 계정을 따로 가질 필요가 없습니다.

그리고 물론 이 차트들은 채팅을 위해 만들어졌습니다. 플랫폼은 일급 대화형 분석 기능을 갖추고 있는데, Claude나 ChatGPT처럼 작동하되 웨어하우스에는 읽기 전용 권한으로만 접근하고, 전문 분석가 수준의 스킬과 도구가 내장되어 있습니다. 차트와 채팅하면서 탐색하다가 언제든 클릭해서 세부 조정을 하고 보드를 저장할 수 있습니다.

이 플랫폼이 오픈소스 언어 위에 지어졌기 때문에, 채팅으로 만든 변경이든 비주얼 에디터로 만든 변경이든 코드로 직접 만든 변경이든 모두 같은 YAML 파일로 귀결되고, 이는 Git 저장소에 그대로 반영됩니다. 어디에도 락인(lock-in)이 없다는 게 핵심입니다. 같은 보드가 노트북에서도, CI에서도, 플랫폼 위에서도 똑같이 동작하고, 팀은 별도의 숨겨진 데이터 스택을 만들지 않고도 에이전트를 손에 쥔 채 셀프 서브 방식으로 일할 수 있습니다.

시작해보기

dbt Charts 언어는 Apache 2.0 라이선스로 오픈소스 공개되었습니다. 계정을 만들지 않아도 로컬에서 보드를 작성, 렌더링, 서빙할 수 있습니다. 직접 설치하거나, 코딩 에이전트에게 한 줄만 던져주면 됩니다.

Terminal:
uv tool install dbt-charts

Claude / AI:
Make charts of this with dbt Charts. Start with: uv tool install dbt-charts && dct skills intro
  • 코드: github.com/dbt-labs/dbt-charts
  • 문서: docs.dbtCharts.com
  • 호스팅 BI: dbtCharts.com
  • 커뮤니티: dbt Community Slack의 #dbt-charts 채널

dbt Charts는 아직 1.0 이전 버전이라 문법이 계속 바뀌고 있습니다. 다만 문법이 바뀌더라도 파싱 과정에서 보드가 자동으로 마이그레이션되기 때문에, 지금 작성한 보드도 계속 렌더링이 가능하도록 보장한다고 밝히고 있습니다.

정리

  • 에이전트가 데이터 리포트를 만드는 시대가 오면서, 기존 방식(코드 더미로 흩어지는 자유형 생성 vs UI에 갇힌 BI 코파일럿) 둘 다 한계를 드러내고 있습니다.
  • dbt Charts는 차트를 BI 도구에서 떼어내 선언형 YAML 언어로 코드화합니다. SQL로 "무엇을" 볼지 정의하고 YAML로 "어떻게" 보여줄지 정의하는 구조이며, 1,100개 이상의 설정 옵션과 16가지 차트 타입, 스타일 상속·테마·extends를 지원합니다.
  • dbt 프로젝트와 통합하면 charts/ 디렉터리가 models/와 같은 저장소에 위치해 하나의 CI/PR 흐름으로 검증되고, ref()를 통해 모델 변경 시 즉시 실패하도록 만들 수 있습니다.
  • 렌더링 시 막대 밴드 폭이 너무 좁거나 테이블 컬럼이 넘치는 등의 시각화 문제를 자동으로 경고해, 에이전트가 반복적으로 수정하는 워크플로우에 최적화되어 있습니다.
  • dbtCharts.com은 이 오픈소스 언어 위에 호스팅, 접근 제어, 대화형 분석, 비주얼 에디터를 얹은 플랫폼으로, 채팅·에디터·코드 어떤 경로로 수정하든 결국 같은 Git 저장소의 YAML로 귀결되어 락인 없이 셀프 서브 분석이 가능합니다.

프론트엔드 개발자 입장에서는 "AI 에이전트가 만든 UI/시각화 결과물을 어떻게 코드베이스에 편입시키고 검증할 것인가"라는 문제의 한 해법으로 참고할 만합니다. 특히 선언형 스키마 + 정적 검증 + Git 기반 워크플로우 조합은 차트뿐 아니라 에이전트가 생성하는 다른 UI 산출물에도 적용해볼 수 있는 패턴입니다.
