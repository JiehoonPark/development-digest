15:T30ef,<p>React 팀이 지난주 공개한 치명적 보안 취약점(React2Shell, CVE-2025-55182)의 패치를 검증하던 보안 연구자들이, 그 과정에서 두 건의 추가 취약점을 발견해 공개했습니다. 다행히 이번에 새로 발견된 취약점들은 원격 코드 실행(RCE)으로는 이어지지 않으며, 지난주 배포된 React2Shell 패치는 여전히 RCE 방어에 유효합니다. 다만 서비스 거부(DoS)와 소스 코드 노출이라는 별개의 심각한 문제가 드러났고, 이후 1월 26일에는 기존 DoS 패치 자체가 불완전했다는 사실까지 추가로 밝혀지면서 재차 업데이트가 이뤄졌습니다.</p>
<h3>새로 공개된 취약점 요약</h3>
<p>이번에 공개된 취약점은 다음과 같습니다.</p>
<ul>
<li><strong>서비스 거부(DoS) - 심각도 High</strong>: CVE-2025-55184, CVE-2025-67779, CVE-2026-23864 (CVSS 7.5)</li>
<li><strong>소스 코드 노출 - 심각도 Medium</strong>: CVE-2025-55183 (CVSS 5.3)</li>
</ul>
<p>React 팀은 이 취약점들의 심각도를 고려해 즉시 업그레이드할 것을 권고하고 있습니다.</p>
<p>특히 주의할 점은, 지난주 배포됐던 최초 패치(19.0.3, 19.1.4, 19.2.3)가 이번에 발견된 취약점들에 대해서는 불완전하다는 것입니다. 즉, 지난주 이미 업데이트를 마쳤더라도 다시 한번 업데이트가 필요합니다. 게다가 1월 26일에는 CVE-2025-55184의 최초 패치조차 DoS를 완전히 막지 못했다는 사실이 추가로 확인되어, 19.0.4, 19.1.5, 19.2.4 버전에서야 비로소 안전하다고 확인됐습니다.</p>
<h3>즉시 조치가 필요한 이유</h3>
<p>이번 취약점들은 지난주 공개된 CVE-2025-55182와 동일한 패키지·동일한 버전 범위에 존재합니다. 영향을 받는 버전은 다음과 같습니다.</p>
<ul>
<li>19.0.0, 19.0.1, 19.0.2, 19.0.3</li>
<li>19.1.0, 19.1.1, 19.1.2, 19.1.3</li>
<li>19.2.0, 19.2.1, 19.2.2, 19.2.3</li>
</ul>
<p>영향을 받는 패키지는 다음 세 가지입니다.</p>
<ul>
<li><code>react-server-dom-webpack</code></li>
<li><code>react-server-dom-parcel</code></li>
<li><code>react-server-dom-turbopack</code></li>
</ul>
<p>패치는 19.0.4, 19.1.5, 19.2.4로 백포트되었으며, 위 패키지를 사용 중이라면 즉시 이 버전들로 업그레이드해야 합니다.</p>
<p>지난번과 마찬가지로, 앱이 서버를 사용하지 않는 순수 클라이언트 React 코드라면 영향을 받지 않습니다. 또한 React Server Components를 지원하는 프레임워크·번들러·번들러 플러그인을 사용하지 않는 앱도 영향권 밖입니다.</p>
<p>&gt; 치명적인 CVE가 공개되면 후속 취약점이 뒤따르는 것은 흔한 일입니다. 심각한 취약점이 공개되면 연구자들이 인접한 코드 경로를 면밀히 조사하면서, 최초 완화 조치를 우회할 수 있는 변형 공격 기법을 찾아내려 시도하기 때문입니다. 이는 JavaScript 생태계만의 일이 아니라 업계 전반에서 반복되는 패턴입니다. 예를 들어 Log4Shell 사태 이후에도 커뮤니티가 최초 패치를 파고들면서 추가 CVE들이 보고된 바 있습니다. 후속 공개가 당혹스러울 수는 있지만, 일반적으로는 건강한 대응 사이클의 신호로 봐야 합니다.</p>
<h3>영향받는 프레임워크와 번들러</h3>
<p>일부 React 프레임워크와 번들러는 취약한 React 패키지에 직접 의존하거나, peer dependency로 가지고 있거나, 내부에 포함하고 있었습니다. 영향을 받는 프레임워크·번들러는 다음과 같습니다.</p>
<ul>
<li>Next.js (<code>next</code>)</li>
<li><code>react-router</code></li>
<li>Waku (<code>waku</code>)</li>
<li><code>@parcel/rsc</code></li>
<li><code>@vite/rsc-plugin</code></li>
<li><code>rwsdk</code></li>
</ul>
<p>업그레이드 절차는 지난주 공개된 원본 취약점 공지 글의 안내를 참고하면 됩니다.</p>
<h3>호스팅 제공자의 완화 조치</h3>
<p>지난번과 마찬가지로 React 팀은 여러 호스팅 제공자와 협력해 임시 완화 조치를 적용했습니다. 다만 이는 어디까지나 임시 방편이며, 이 완화 조치에 의존해서는 안 되고 반드시 즉시 업데이트해야 합니다.</p>
<h3>React Native 사용자 대응</h3>
<p>React Native를 모노레포 없이 사용하고 있고 <code>react-dom</code>을 사용하지 않는다면, <code>package.json</code>에 React 버전이 고정되어 있을 것이므로 추가 조치가 필요하지 않습니다.</p>
<p>React Native를 모노레포 환경에서 사용 중이라면, 아래 패키지가 설치되어 있는 경우에 한해 해당 패키지만 업데이트하면 됩니다.</p>
<ul>
<li><code>react-server-dom-webpack</code></li>
<li><code>react-server-dom-parcel</code></li>
<li><code>react-server-dom-turbopack</code></li>
</ul>
<p>보안 권고 대응을 위해서는 이것으로 충분하며, <code>react</code>와 <code>react-dom</code>까지 업데이트할 필요는 없습니다. 따라서 React Native에서 흔히 발생하는 버전 불일치 오류가 발생하지 않습니다.</p>
<h3>심각도 High: 다수의 DoS 취약점 (CVE-2026-23864)</h3>
<ul>
<li><strong>CVE</strong>: CVE-2026-23864</li>
<li><strong>Base Score</strong>: 7.5 (High)</li>
<li><strong>날짜</strong>: 2026년 1월 26일</li>
</ul>
<p>보안 연구자들이 React Server Components에 여전히 추가적인 DoS 취약점이 남아있음을 발견했습니다. 이 취약점들은 Server Function 엔드포인트에 특수하게 조작된 HTTP 요청을 보내는 방식으로 트리거되며, 취약한 코드 경로가 어떤 것인지, 애플리케이션 설정과 코드가 어떤지에 따라 서버 크래시, 메모리 부족 예외, 과도한 CPU 사용 등으로 이어질 수 있습니다.</p>
<p>1월 26일 공개된 패치가 이 DoS 취약점들을 완화합니다.</p>
<p>&gt; <strong>추가 패치가 공개됨</strong>: CVE-2025-55184의 DoS를 해결하기 위한 최초 패치가 불완전했습니다. 이로 인해 이전 버전들은 여전히 취약한 상태로 남아있었으며, 19.0.4, 19.1.5, 19.2.4 버전이 안전한 버전입니다.</p>
<h3>심각도 High: 서비스 거부 (CVE-2025-55184, CVE-2025-67779)</h3>
<ul>
<li><strong>CVE</strong>: CVE-2025-55184, CVE-2025-67779</li>
<li><strong>Base Score</strong>: 7.5 (High)</li>
</ul>
<p>보안 연구자들은 임의의 Server Functions 엔드포인트로 악의적으로 조작된 HTTP 요청을 보낼 수 있으며, React가 이를 역직렬화할 때 무한 루프가 발생해 서버 프로세스가 멈추고 CPU를 소진시킬 수 있음을 발견했습니다. 앱이 별도로 React Server Function 엔드포인트를 구현하지 않았더라도, React Server Components를 지원하기만 하면 여전히 취약할 수 있습니다.</p>
<p>이는 공격자가 사용자들의 서비스 접근을 차단하고, 서버 환경 전반의 성능에 영향을 줄 수 있는 공격 벡터를 만들어냅니다.</p>
<p>당시 공개된 패치는 무한 루프를 방지하는 방식으로 이 문제를 완화했습니다. (단, 앞서 언급했듯 이 패치는 이후 불완전한 것으로 밝혀졌습니다.)</p>
<h3>심각도 Medium: 소스 코드 노출 (CVE-2025-55183)</h3>
<ul>
<li><strong>CVE</strong>: CVE-2025-55183</li>
<li><strong>Base Score</strong>: 5.3 (Medium)</li>
</ul>
<p>한 보안 연구자는 취약한 Server Function에 악의적인 HTTP 요청을 보내면, 해당 Server Function의 소스 코드가 안전하지 않은 방식으로 반환될 수 있음을 발견했습니다. 이 취약점을 악용하려면, 문자열화된 인자를 명시적 또는 암묵적으로 노출하는 Server Function이 존재해야 합니다. 다음은 취약한 예시 코드입니다.</p>
<pre><code class="language-jsx">'use server';export async function serverFunction(name) { const conn = db.createConnection('SECRET KEY'); const user = await conn.createUser(name); return { id: user.id, message: `Hello, ${name}!` }}</code></pre>
<p>공격자는 다음과 같은 형태의 응답을 통해 정보를 유출할 수 있습니다.</p>
<pre><code>0:{&quot;a&quot;:&quot;$@1&quot;,&quot;f&quot;:&quot;&quot;,&quot;b&quot;:&quot;Wy43RxUKdxmr5iuBzJ1pN&quot;}1:{&quot;id&quot;:&quot;tva1sfodwq&quot;,&quot;message&quot;:&quot;Hello, async function(a){console.log(\&quot;serverFunction\&quot;);let b=i.createConnection(\&quot;SECRET KEY\&quot;);return{id:(await b.createUser(a)).id,message:`Hello, ${a}!`}}!&quot;}</code></pre>
<p>당시 공개된 패치는 Server Function 소스 코드가 문자열화되는 것을 막아 이 문제를 방지합니다.</p>
<p>&gt; 소스 코드 내에 하드코딩된 시크릿만 노출될 수 있습니다. <code>process.env.SECRET</code>처럼 런타임에 주입되는 시크릿은 영향을 받지 않습니다. 노출되는 코드의 범위는 해당 Server Function 내부 코드로 한정되지만, 번들러의 인라이닝 정도에 따라 다른 함수까지 포함될 수 있습니다. 반드시 프로덕션 번들을 기준으로 직접 검증해야 합니다.</p>

<h3>기여자 안내</h3>
<p>소스 코드 노출 문제를 제보한 Andrew MacPherson(AndrewMohawk), DoS 취약점을 제보한 GMO Flatt Security Inc의 RyotaK와 Bitforest Co., Ltd.의 Shinsaku Nomura에게 감사드립니다. 또한 추가 DoS 취약점을 제보한 Winfunc Research의 Mufeed VH, Joachim Viide, GMO Flatt Security Inc의 RyotaK, Tencent Security YUNDING LAB의 Xiangwei Zhang에게도 감사드립니다.</p>
<h3>정리</h3>
<ul>
<li>지난주 공개된 React2Shell(CVE-2025-55182) 패치 검증 과정에서 DoS 3건(CVE-2025-55184, CVE-2025-67779, CVE-2026-23864)과 소스 코드 노출 1건(CVE-2025-55183)이 추가로 발견됐습니다. RCE로 이어지지는 않지만 심각도는 각각 High(7.5), Medium(5.3)입니다.</li>
<li>지난주 배포된 19.0.3, 19.1.4, 19.2.3은 불완전한 패치이며, 1월 26일에 밝혀진 바로는 CVE-2025-55184에 대한 최초 대응조차 불완전했습니다. 최종적으로 안전한 버전은 <strong>19.0.4, 19.1.5, 19.2.4</strong>입니다.</li>
<li>영향받는 패키지는 <code>react-server-dom-webpack</code>, <code>react-server-dom-parcel</code>, <code>react-server-dom-turbopack</code>이며, Next.js, react-router, Waku, @parcel/rsc, @vite/rsc-plugin, rwsdk 등 이를 의존하는 프레임워크·번들러 사용자도 함께 확인이 필요합니다.</li>
<li>DoS는 조작된 HTTP 요청이 Server Function 엔드포인트에서 역직렬화될 때 무한 루프를 유발해 서버 프로세스를 마비시키는 방식이며, 소스 코드 노출은 인자를 문자열화해 반환하는 Server Function에서 함수 소스와 하드코딩된 시크릿이 새어나갈 수 있는 문제입니다.</li>
<li>서버 없이 순수 클라이언트 React만 사용하는 앱, 또는 RSC를 지원하지 않는 프레임워크/번들러를 쓰는 앱은 영향을 받지 않습니다. React Native는 모노레포 여부에 따라 대응 방식이 다르므로 별도 확인이 필요합니다.</li>
<li>호스팅 제공자의 임시 완화 조치가 있더라도 이를 신뢰하지 말고, 반드시 패키지 버전을 직접 업그레이드해야 합니다.</li>
