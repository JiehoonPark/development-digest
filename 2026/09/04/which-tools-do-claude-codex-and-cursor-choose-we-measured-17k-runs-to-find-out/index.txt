15:T317a,<p>AI 코딩 에이전트에게 &quot;이메일 보내는 기능 추가해줘&quot;라고 요청하면, 실제로 어떤 서드파티 서비스를 골라줄까요? Claude Code, Codex, Cursor는 각자 다른 답을 내놓을까요, 아니면 비슷한 선택을 할까요? Armature 팀은 이 질문에 답하기 위해 17,000회에 가까운 실험을 설계하고 실행했습니다. 실제 코드베이스를 흉내 낸 75개의 가짜 저장소, 4가지 페르소나, 3개의 샌드박스 프로바이더, 그리고 AI 심판까지 동원한 대규모 실증 연구인데요. 이 글에서는 그 실험 설계 방법과 핵심 발견들을 정리해봅니다.</p>
<h3>실험 설계: 어떻게 &quot;현실적인&quot; 테스트 환경을 만들었나</h3>
<h4>저장소 패널 구성</h4>
<p>연구팀은 우선 수천 개의 공개 GitHub 저장소를 분석해 프로그래밍 언어와 프레임워크, 서드파티 서비스, 배포 플랫폼, 팀 규모, 코드베이스 연식 등의 통계를 뽑아냈습니다. 그런데 오픈소스 저장소는 대기업보다 테크 스타트업이 훨씬 많이 공개하는 경향이 있고, 스택 구성도 서로 다르기 때문에 이 통계를 그대로 쓰면 편향이 생깁니다. 그래서 공개된 데이터를 기반으로 통계를 보정해 이상적인 패널 분포를 만들었습니다.</p>
<p>이렇게 도출한 분포에 맞춰 여러 코딩 에이전트를 동원해 실제와 유사한 저장소를 새로 생성했습니다. 마지막으로 코드베이스 일부와 특정 서드파티 서비스 구현을 의도적으로 제거한 변형본들을 만들어, 편향 없는 실험이 가능하도록 했습니다.</p>
<p>최종적으로 10개 언어에 걸쳐 75개의 저장소를 확보했으며, 모든 저장소에는 가짜 회사명, 가짜 git 히스토리, 가짜 API 키가 들어 있고, npm 같은 패키지 매니저 레지스트리와 대조 검증한 실제 lockfile이 포함되어 있습니다.</p>
<h4>실전형 태스크와 4가지 페르소나</h4>
<p>각 실험은 저장소 안에서 수행되는 실제 태스크이며, 다음 4가지 페르소나 중 하나가 요청합니다.</p>
<ul>
<li><strong>바이브 코더</strong>: 증상과 원하는 최종 상태만 설명하고, 도구 카테고리명은 거의 언급하지 않음</li>
<li><strong>주니어 엔지니어</strong>: 보통 원하는 상태와 카테고리명을 함께 언급</li>
<li><strong>시니어 엔지니어</strong>: 요구사항과 피해야 할 것을 더 정확하게 명시</li>
<li><strong>대기업 엔지니어</strong>: 컴플라이언스, 조달 절차 등 구체적인 제약조건까지 상세히 기술</li>
</ul>
<p>프롬프트는 대체로 간단하고 직접적이지만, 저장소와 페르소나에 맞춰 조금씩 변형했습니다. 그리고 20~25%의 케이스에서는 비용이나 사용량 언급을 추가해 그것이 최종 결과에 미치는 영향을 테스트했습니다.</p>
<p>이렇게 만들어진 프롬프트 변형은 총 1,163개로, 예를 들면 &quot;이제 우리가 생성하는 각 청구서가 사용자 이메일로 멋진 메시지와 함께 발송되도록 해야 해. 최선의 솔루션을 찾아서 구현해줘&quot; 같은 식입니다.</p>
<h4>러너와 샌드박스</h4>
<p>각 실험은 독립된 임시 샌드박스에서 실행됩니다. 샌드박스 선택이 결론에 영향을 주지 않는다는 것을 확인했지만, 만약을 위해 E2B, Blaxel, Daytona 세 개의 샌드박스 프로바이더를 번갈아 사용했습니다.</p>
<h4>루프 안의 &quot;시뮬레이션된 인간&quot;</h4>
<p>실제 대화는 프롬프트 한 번 던지고 에이전트가 방해 없이 끝까지 작업하는 경우가 드뭅니다. 그래서 연구팀은 루프 안에 &quot;시뮬레이션된 인간&quot;을 두었는데요, Gemini 3.7 Flash가 오케스트레이터 역할을 맡았습니다. 이를 통해 에이전트가 먼저 코드베이스를 분석해 최선의 솔루션을 추천하도록 하는, 더 현실적인 시나리오를 재현할 수 있었습니다. 이 단계에서 시뮬레이션된 인간은 항상 1순위 솔루션을 선택하거나, 에이전트에게 최선의 것을 골라 구현하라고 요청했습니다.</p>
<p>흥미로운 점은, 처음부터 질문 없이 바로 구현하라고 요청하면 에이전트가 특정 서드파티 솔루션을 쓸 권한을 물어볼 수 없어서 자체 구축(in-house)으로 편향되는 경향을 발견했다는 것입니다. 이 &quot;인간&quot;을 루프에 추가함으로써 업계 리더 및 클라우드 플랫폼 네이티브 솔루션의 압도적 우위가 완화되어 더 현실적인 그림이 나왔습니다. 예컨대 오브젝트 스토리지 실험에서, 에이전트가 항상 Amazon S3를 먼저 쓰던 세션들에서 Cloudflare R2가 이기기 시작했습니다.</p>
<h4>심판 역할</h4>
<p>또 다른 Gemini 3.7 Flash 인스턴스가 세션을 분석하는 심판 역할을 맡았습니다. 이 심판의 역할은 두 가지입니다.</p>
<ul>
<li>세션이 여러 기준에 비추어 유효한지 판단 (예: 저장소가 이미 특정 프로바이더를 &quot;미리 선택&quot;해둬서 결과가 편향되지 않았는지, 실제로 솔루션이 선택되었는지 — 예를 들어 옵저버빌리티 실험에서 플랫폼과 결합되지 않은 OpenTelemetry 단독 사용은 유효하지 않은 것으로 거부)</li>
<li>대화와 실제 코드 diff를 살펴보고 언급된 각 참가자(플레이어)와 최종 승자를 식별</li>
</ul>
<h3>무엇을 발견했나</h3>
<p>16,893회 실행 중 51개 코드베이스, 18개 섹터에 걸쳐 유효하고 공개할 준비가 된 5,292개 세션을 우선 추렸습니다. 나머지 1만여 개를 버린 것은 아니고 2차 공개 때 추가로 공유할 수도 있다고 밝혔습니다. 이번 1차 공개에서는 트레이스에 묻혀 있는 학습 내용 중 일부만 추출했으며, 앞으로도 계속 파고들어 흥미로운 인사이트를 공유할 예정입니다. 모든 트레이스는 이제 공개되어 있어 누구나 직접 분석해볼 수 있습니다. 아래는 첫 5가지 관찰 결과입니다.</p>
<h4>1. 에이전트마다 정보 소스가 다르고, 그래서 결론도 갈린다</h4>
<ul>
<li><strong>Cursor</strong>는 세션의 3분의 2에서 웹 검색에 기반해 결정을 내립니다.</li>
<li><strong>Codex</strong>는 거의 항상(94%의 세션) 웹 검색을 사용하며, 그중 10번 중 9번은 <code>site:</code> 같은 연산자로 신뢰할 수 있는 도메인에 집중하거나 특정 솔루션을 파고듭니다(예: <code>site:auth0.com password reset MFA social connections</code>).</li>
<li><strong>Claude Code</strong>는 주로 자체 사전지식(prior)에 의존하며 웹 검색은 약 30%의 경우에만 사용합니다. 다만 검색할 때는 Codex보다 3배 더 많은 페이지를 살펴봅니다. 샌드박스처럼 비교적 최신 섹터라 사전지식이 약한 분야에서는 웹 검색 비율이 약 80%까지 올라갔습니다.</li>
</ul>
<p>세 에이전트가 동일한 도구를 선택한 비율은 전체 셀의 42%에 불과했습니다. 예를 들어 음성 에이전트 카테고리에서 Claude Code는 Twilio를, Codex는 OpenAI Realtime API를(👀), Cursor는 Vapi를 선택했습니다.</p>
<p>또한 Claude Code는 Codex나 Cursor에 비해 자체 구축(in-house)을 거의 두 배 더 많이 선택했습니다(19% vs 10%).</p>
<h4>2. 저장소 컨텍스트가 결정적이다</h4>
<p>똑같은 요청이라도 프로그래밍 언어가 다른 4개 저장소에서 완전히 다른 이메일 프로바이더가 승리했습니다.</p>
<ul>
<li>TypeScript: Resend (89회 중 55회)</li>
<li>Python: Sendgrid (24회 중 22회)</li>
<li>Go: Postmark (24회 중 20회)</li>
<li>Java: Azure ACS (23회 중 22회)</li>
</ul>
<p>배포 플랫폼도 마찬가지입니다. Vercel은 TypeScript 저장소에서 승리하며(NextJS를 사용하는 경우엔 100% 승리), Python 저장소에서는 단 한 번도 추천되지 않았고 대신 Render가 압도했습니다.</p>
<h4>3. 많이 언급된다고 승리하는 건 아니다</h4>
<p>잘 알려진 서비스들이 거의 모든 대화에서 언급되지만 실제로는 선택되지 않는 경우가 많았습니다. 물론 현실에서는 인간의 개입으로 일부 결과가 다를 수 있지만, 다음과 같은 수치는 인상적입니다.</p>
<ul>
<li>결제 서비스 부문: PayPal은 139번 언급되었지만 단 한 번도 선택되지 않았습니다(그중 124번은 Stripe가 승리). Adyen도 175번 언급되었지만 단 3번만 선택되었습니다.</li>
<li><strong>LangChain</strong>은 194회로 가장 많이 언급된 프레임워크였지만 실제로 선택된 건 단 4회뿐이었습니다.</li>
<li><strong>Netlify</strong>는 152회 언급되었으나 배포 플랫폼으로 선택된 건 6회뿐이었습니다.</li>
<li><strong>Supabase</strong>는 242회 언급으로 가장 많이 거론된 데이터베이스였지만, 여전히 Neon에 크게 밀렸습니다.</li>
</ul>
<h4>4. 벤더 페이지의 사소한 정보가 선택을 뒤집는다</h4>
<ul>
<li>Mailgun은 에이전트가 무료 플랜에서 &quot;1일 보관 기간&quot;을 확인하면 Postmark에게 정기적으로 패배했습니다.</li>
<li>Supabase는 에이전트가 단순히 데이터베이스만 원하는데도 인증, 스토리지, 실시간 기능 등이 번들 가격제로 묶여 제시되면서 불필요한 BaaS 기능이 많다는 이유로 거의 항상 패배했습니다.</li>
<li>5,300개 세션 중 388개가 플랫폼 관리 부담을, 195개가 비용을 언급했습니다. 그런데 많은 경우 이는 실제로 결격 사유가 되는 데이터가 아니라, 정보가 제시되는 방식 자체가 원인이었습니다.</li>
</ul>
<h4>5. 압도적으로 지배된 시장, 치열하게 경합하는 시장</h4>
<ul>
<li><strong>결제</strong>: Stripe가 10번 중 9번 승리했고, EU 규제가 적용되는 특수 사례에서만 Paddle, Mollie 같은 특화 플레이어에게 밀렸습니다.</li>
<li><strong>데이터베이스</strong>: Neon이 66%로 승리했고, 그 뒤를 Azure, AWS 같은 클라우드 플랫폼 네이티브 솔루션이 이었습니다.</li>
<li><strong>파일 스토리지</strong>: Amazon S3가 45%로 지배적이었고, Azure와 GCP가 각각 20%로 뒤를 이었습니다.</li>
<li><strong>이메일</strong>: Resend와 Postmark가 각각 35.6%, 27.4%의 설치율로 근소하게 선두를 다퉜습니다.</li>
</ul>
