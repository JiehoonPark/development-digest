14:T2dae,<h2>JavaScript 대신 이 CSS 기능들을 써보세요</h2>
<p>프론트엔드 개발자라면 &quot;이 CSS 기능 멋지긴 한데, 너무 최신이라 실무에서 못 쓴다&quot;는 말을 자주 듣게 됩니다. 하지만 이번에 소개할 기능들은 다릅니다. 이미 브라우저 지원이 탄탄하고, 지금 당장 써도 안전한데도 여전히 많은 사람들이 JavaScript로 해결하고 있는 문제들입니다. 한두 줄의 CSS로 코드를 훨씬 간결하게 만들 수 있는 사례들을 하나씩 살펴보겠습니다.</p>
<h3>1. scroll-behavior: smooth와 scroll-margin</h3>
<p>앵커 링크로 부드럽게 스크롤 이동하는 기능, <code>scroll-behavior: smooth</code>로 이미 많이 쓰고 계실 텐데요. 문제는 이동한 후에 상단 고정 헤더 같은 요소가 타겟 콘텐츠를 가려버린다는 점입니다. 이 때문에 많은 개발자들이 오프셋을 직접 계산하는 JavaScript 코드를 작성하게 됩니다.</p>
<p>사실 이럴 필요가 없습니다. 타겟 요소에 <code>scroll-margin</code>만 추가하면 됩니다.</p>
<pre><code class="language-css">.target {
  scroll-margin-block: 20vh;
}</code></pre>
<p><code>scroll-margin</code>에 viewport 단위(top/bottom 기준)를 주면, 어디로 스크롤하든 항상 여백을 두고 이동합니다. ID는 섹션에 걸어도 되고 제목 자체에 걸어도 상관없이 잘 동작합니다.</p>
<p>한 가지 더 신경 쓸 부분은 <code>prefers-reduced-motion</code>입니다. 모션을 줄이고 싶어하는 사용자를 위해 다음과 같이 감싸주는 게 좋습니다.</p>
<pre><code class="language-css">@media (prefers-reduced-motion: no-preference) {
  html {
    scroll-behavior: smooth;
  }
}</code></pre>
<p>이렇게 하면 모션을 원치 않는 사용자에게는 스크롤이 즉시 이동하지만, <code>scroll-margin</code>은 그대로 적용되어 타겟이 가려지지 않습니다. 전정기관 문제가 있는 사용자를 배려하는 좋은 방법입니다.</p>
<p>브라우저 지원: <code>scroll-behavior</code>는 4년 넘게, <code>target</code>(앵커 이동)은 사실상 항상 지원되어 왔습니다. 안심하고 써도 됩니다.</p>
<h3>2. scroll-snap으로 만드는 가로 스크롤러</h3>
<p>가로 스크롤 UI를 만들 때, 이 부분에서 정말 과도한 JavaScript를 본 적이 있습니다. A/B 테스트 결과에 따라 어떤 라이브러리가 붙었는지에 따라 코드량이 천차만별인 경우도 있었는데요. 레이아웃 자체는 grid든 flexbox든 취향껏 쓰면 됩니다(평소 grid를 권장하는 편이지만 이번엔 둘 다 괜찮습니다). 핵심은 <code>scroll-snap-type</code>입니다.</p>
<p><code>scroll-snap</code>은 자동으로 동작하지 않고 두 가지를 반드시 설정해야 합니다. 부모에는 <code>scroll-snap-type</code>, 자식에는 <code>scroll-snap-align</code>을 넣어야 합니다.</p>
<pre><code class="language-css">.scroller {
  scroll-snap-type: x mandatory; /* 또는 proximity */
}

.scroller &gt; * {
  scroll-snap-align: center; /* start, end 등도 가능 */
}</code></pre>
<p><code>scroll-snap-type</code>은 두 값을 조합해야 합니다. 첫 번째는 축(inline/block 또는 x/y), 두 번째는 <code>mandatory</code>(반드시 스냅) 또는 <code>proximity</code>(가까울 때만 스냅)입니다. 상황에 맞게 실험해보면 됩니다. 정렬 값은 <code>start</code>, <code>center</code>, <code>end</code> 등으로 직관적입니다.</p>
<p>데스크톱 마우스 스크롤에서는 살짝 어색할 수 있지만, 모바일에서 스와이프할 때는 굉장히 자연스럽습니다. 웹 앱 등에 적용하기 좋은 기능이고, 브라우저 지원도 매우 탄탄합니다.</p>
<h3>3. :user-valid / :user-invalid로 하는 폼 검증</h3>
<p>폼 검증에서 JavaScript를 완전히 안 쓴다고 말하긴 어렵지만, <code>blur</code> 이벤트를 감지해서 <code>touched</code> 클래스를 붙이고 <code>:valid</code>/<code>:invalid</code>를 체크하는 패턴은 흔합니다. 이렇게 하는 이유는 명확합니다. <code>:valid</code>와 <code>:invalid</code>는 사용자가 아무것도 입력하지 않아도 폼을 즉시 검증해버리기 때문입니다. <code>required</code> 속성만 붙여도 빈 입력창이 전부 <code>:invalid</code> 상태가 되어버리죠. 사용자가 뭔가 하기도 전에 틀렸다고 알려주는 건 좋은 경험이 아닙니다.</p>
<p>이럴 때 <code>:user-valid</code>, <code>:user-invalid</code>를 쓰면 됩니다.</p>
<pre><code class="language-css">input:user-invalid {
  border-color: red;
}

input:user-valid {
  border-color: green;
}</code></pre>
<p>이 의사 클래스들은 사용자가 실제로 필드와 상호작용한 이후에만 반응합니다. 필드에 들어갔다가 아무것도 안 쓰고 나가면 상태가 바뀌지 않지만, 이름을 입력하면 <code>:user-valid</code>가 되고, <code>minlength</code>를 지정한 비밀번호 필드에 짧은 값을 넣으면 <code>:user-invalid</code>가 됩니다. 제출을 시도하면 브라우저가 왜 잘못됐는지까지 알려주는데, 이 모든 게 JavaScript 없이 이루어집니다. 이 에러 메시지는 커스터마이징도 가능한데, 이 부분은 JavaScript API가 필요하므로 별도 영상에서 다룬 바 있습니다.</p>
<p>더 나아가 <code>pattern</code> 속성에 정규식을 넣어 검증할 수도 있습니다.</p>
<pre><code class="language-html">&lt;input type=&quot;text&quot; pattern=&quot;(?=.*[a-zA-Z])(?=.*[0-9]).+&quot; /&gt;</code></pre>
<p>문자와 숫자가 섞여야 유효하도록 정규식을 걸면, 조건을 만족할 때만 <code>:user-valid</code>가 되어 사용자가 제출 가능 여부를 바로 인지할 수 있습니다.</p>
<p>여기서 오해하면 안 되는 게, &quot;CSS로 폼 검증을 끝내라&quot;는 얘기가 아닙니다. <code>blur</code> 이벤트 감지 후 <code>:valid</code>/<code>:invalid</code>를 체크하는 것 같은 1차 방어선을 CSS로 대체하라는 것이지, 서버 사이드 검증을 생략하라는 뜻이 아닙니다. 사용자가 제출 버튼을 누르면 반드시 서버 측 검증을 거쳐야 합니다.</p>
<p>브라우저 지원은 baseline widely available로, 약 2년 반 전부터 안정적으로 지원되고 있습니다. 사용자층에 따라 한 번 더 체크는 해보되, 실무에 써도 안전한 수준입니다.</p>
<h3>4. :focus 대신 :focus-visible</h3>
<p>CSS 기능은 아니지만 짚고 넘어갈 만한 보너스 팁입니다. 버튼이나 메뉴를 클릭했을 때 생기는 포커스 링이 거슬린다는 이유로 <code>outline: none</code>이나 <code>focus { outline: 0 }</code>으로 아예 없애버리는 경우가 많습니다. 디자이너나 상사가 &quot;왜 클릭했는데 이상한 링이 생기냐&quot;고 물으면 그냥 다 없애버리는 식이죠. 문제는 키보드로 탐색하는 사용자에게는 이 포커스 링이 반드시 필요하다는 점입니다.</p>
<p>해결책은 간단합니다. <code>:focus</code> 대신 <code>:focus-visible</code>을 쓰면 됩니다.</p>
<pre><code class="language-css">button:focus-visible {
  outline: 2px solid blue;
}</code></pre>
<p>이제 브라우저의 기본 동작(user agent default)과 동일하게, 키보드로 탭 이동해서 포커스가 갈 때는 링이 보이고, 마우스로 클릭했을 때는 링이 나타나지 않습니다. 상호작용 방식과 요소 종류에 따라 브라우저가 판단하는 로직이 조금씩 달라서 자세한 내용은 별도 영상에서 다룬 바 있지만, 결론적으로 <code>:focus</code> 대신 <code>:focus-visible</code>을 쓰는 편이 좋습니다. 이미 브라우저 에이전트들이 이 방식으로 전환되어 있고 지원도 탄탄합니다.</p>
<h3>5. lh 단위로 만드는 고정 줄 수 텍스트 영역</h3>
<p>디자이너가 &quot;이 텍스트 영역은 3줄 높이로 맞춰주세요&quot;라고 요청하면, 매직 넘버로 대충 높이를 맞춰놓기 쉽습니다. 그런데 나중에 폰트 크기를 바꿔달라고 하면 그 매직 넘버를 처음부터 다시 계산해야 합니다.</p>
<p>이럴 때 <code>lh</code> 단위(line height 단위)를 쓰면 됩니다.</p>
<pre><code class="language-css">textarea {
  min-height: 3lh;
}</code></pre>
<p><code>3lh</code>는 항상 &quot;3줄 분량의 높이&quot;를 의미하므로, 폰트 크기가 커지거나 작아져도 자동으로 늘어나거나 줄어듭니다. <code>lh</code> 단위는 CSS에서 저평가된 기능 중 하나입니다. 이 문제를 JavaScript로 해결하려면 높이를 직접 계산하는 로직이 필요한데, <code>3lh</code> 한 줄이면 끝입니다.</p>
<p>다만 이 값을 <code>height</code>가 아니라 <code>min-height</code>(또는 논리적 속성인 <code>min-block-size</code>)로 지정하는 게 좋습니다. 이유는 다음에 나올 <code>field-sizing</code> 때문입니다.</p>
<h3>6. field-sizing으로 자동 확장되는 텍스트 영역</h3>
<p>사용자가 텍스트 영역에 정해진 줄 수보다 더 많이 입력하면 박스가 함께 커지도록 만드는 건 예전부터 꽤 번거로운 작업이었습니다. 이제는 CSS 한 줄로 해결됩니다.</p>
<pre><code class="language-css">textarea {
  field-sizing: content;
}</code></pre>
<p><code>min-height: 3lh</code>와 <code>field-sizing: content</code>를 함께 쓰면, 기본적으로 3줄 높이를 유지하다가 사용자가 더 많이 입력하면 박스가 내용에 맞춰 자연스럽게 늘어납니다.</p>
<p>브라우저 지원 측면에서는 <code>lh</code> 단위가 baseline widely available 상태로 2년 정도 되었고(2023년 11월부터 모든 브라우저 엔진에 탑재), <code>field-sizing</code>은 상대적으로 최신이라 모든 엔진에 들어간 지 약 3개월 정도밖에 되지 않았습니다. 다만 점진적 향상(progressive enhancement) 관점에서 지금 도입해도 괜찮은 선택지입니다.</p>
<h3>정리</h3>
<ul>
<li><strong><code>scroll-margin</code></strong>으로 앵커 스크롤 시 헤더에 가려지는 문제를 해결하고, <code>prefers-reduced-motion</code>으로 모션 감소 사용자를 배려하세요.</li>
<li><strong><code>scroll-snap-type</code> + <code>scroll-snap-align</code></strong> 조합으로 복잡한 JavaScript 없이 가로 스크롤 스냅 UI를 만들 수 있습니다.</li>
