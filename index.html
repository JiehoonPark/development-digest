RSC는 왜 번들러와 통합되어야 할까
via Dan Abramov (overreacted)
frontend

React Server Components는 데이터뿐 아니라 코드(모듈) 자체를 서버에서 클라이언트로 전달해야 하는 특수한 직렬화 문제를 안고 있습니다. 모듈을 파일 단위로 하나씩 로드하면 워터폴이 발생하기 때문에, RSC는 Webpack·Parcel·Vite 같은 번들러와 바인딩을 맺어 빌드 시 청크를 생성하고 참조 기반으로 모듈을 주고받습니다. Dan Abramov는 이 글에서 react-server/react-client 내부 구조와 serialize/deserialize API가 실제로 어떻게 동작하는지 설명합니다.

💡
RSC 기반 프레임워크를 사용하거나 자체 통합을 구축하려는 프론트엔드 개발자에게, 왜 RSC가 특정 번들러에 종속적인지 그 내부 원리를 이해하면 디버깅과 커스텀 설정에 큰 도움이 됩니다.

Astro 개발자를 위한 RSC 이해하기
via Dan Abramov (overreacted)
frontend

Dan Abramov는 Astro의 Astro Components/Client Islands 모델과 React Server Components(RSC)의 Server/Client Components 모델이 멘탈 모델 측면에서 놀랍도록 유사하다고 설명합니다. 두 모델 모두 서버 전용 코드와 클라이언트 전용 코드를 나누고 데이터는 위에서 아래로 흐르지만, Astro는 `.astro` 파일이라는 별도 문법으로 세계를 나누는 반면 RSC는 `'use client'` 디렉티브 하나로 경계를 유동적으로 만듭니다. 이 유연성 덕분에 RSC는 Astro가 겪는 Islands 간 context 전달 불가, 전체 페이지 새로고침 필요 등의 한계를 해결하지만, 그 대가로 React 전체를 받아들여야 하는 학습 곡선이 생깁니다.

💡
Astro와 RSC를 비교해서 이해하면 '서버/클라이언트 경계'라는 최신 프론트엔드 아키텍처의 핵심 개념을 더 쉽게 체화할 수 있고, 두 접근법 중 자신의 프로젝트에 맞는 모델을 선택하는 기준을 세울 수 있습니다.

via Node.js Blog
backend

Node.js 24.22.0 LTS 'Krypton'이 공개되며 crypto 모듈이 OpenSSL Provider 기반 구조로 대폭 개편되고, crypto.parsePKCS12()와 범용 MAC API, SIV/GCM-SIV 모드가 추가됐습니다. node:util에는 throttle과 debounce, markPromiseAsHandled가 신규 내장됐고, perf_hooks의 Histogram API도 슬라이딩 윈도우와 CBOR export 등으로 확장됐습니다. sqlite의 StatementSync에는 close()와 Symbol.dispose()가 추가돼 리소스 관리가 쉬워졌으며, fs/http/http2 영역의 다수 버그 수정과 npm 11.19.1 업데이트도 포함됐습니다.

💡
Node.js 런타임에서 직접 제공하는 throttle/debounce, 보안 API 변경, 리소스 관리 API 추가는 백엔드뿐 아니라 Node 기반 빌드 도구·서버 사이드 렌더링 환경을 다루는 프론트엔드 개발자의 코드 작성 방식과 의존성 구성에도 영향을 준다.

패스키는 함정이 아니다: '패스키를 쓰지 말라'는 주장에 대한 반박
via Hacker News (Top)
frontend

최근 화제가 된 'Passkeys are a trap' 글은 증명(attestation) 기능이 결국 승인된 기기·OS로만 로그인을 제한하는 수단이 될 것이라며 패스키 대신 TOTP로 돌아가라고 주장한다. 패스키 라이브러리를 직접 개발한 보안 전문가 Scott Helme은 이 주장이 WebAuthn의 실제 동작 방식을 오해한 것이라며, 동기화 패스키는 애초에 증명을 하지 않고 증명 자체도 기기 모델 정보만 알려줄 뿐이며, 오히려 추천된 YubiKey가 증명을 적극 수행하는 기기라고 반박한다. TOTP는 피싱에 취약한 반면 패스키는 도메인 바인딩으로 피싱 자체가 불가능해 보안상 명백히 우위에 있다는 것이 핵심 논지다.

💡
WebAuthn과 패스키 인증 흐름을 다루는 프론트엔드/인증 담당 개발자에게 증명(attestation)의 정확한 동작 원리와 동기화 패스키의 보안 모델을 이해하는 것은 잘못된 정보에 기반한 설계 결정을 피하는 데 중요하다.
